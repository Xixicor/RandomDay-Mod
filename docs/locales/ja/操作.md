# アクティブ、準備済み、およびリカバリ状態の操作

> **正規の英語ソース:** [OPERATIONS.md](../../OPERATIONS.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


RandomDay は、将来のブートに備えてサンドボックス ファイルを変更します。実行中の Abiotic Factor セッションにすでにロードされているルールは変更されません。

このページには、オペレーターの決定と回復手順が記載されています。正規用語には [用語集](%E7%94%A8%E8%AA%9E%E9%9B%86.md) を使用し、パスの所有権には[ランタイム ファイル](%E3%83%A9%E3%83%B3%E3%82%BF%E3%82%A4%E3%83%A0_%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB.md)を、正確なスキーマとフィールドの意味には [実行時出力](%E3%83%A9%E3%83%B3%E3%82%BF%E3%82%A4%E3%83%A0%E5%87%BA%E5%8A%9B.md) を使用します。

<a id="distinguish-active-and-prepared-state"></a>
## アクティブな状態と準備された状態を区別する

準備されたプロファイルは、後の起動時にそのマーカーが読み取られるまでアクティブになりません。現在のセッションを説明するために、準備された family/day を使用しないでください。

使用する `web_export/today.html` は読みやすい概要に、`web_export/today.json` は正確な状態に使用されます。再起動を決定する前に、アクティブ マーカー、準備された ID、`prepared_ready`, `profile_status`、トランザクション結果、ロールバック結果、状態コミット結果を確認してください。

<a id="follow-the-normal-dedicated-server-sequence"></a>
## 通常の専用サーバー シーケンスに従います

| 前 | アクション | 後 |
|---|---|---|
| いいえ RandomDay マーカー | で始まる RandomDay が有効になりました。 | 現在のセッションは既存のルールを保持します。 RandomDay 日次注文を作成して保持し、最初の注文を準備します configured/random ポジションを準備します。 |
| 最初のポジションが準備されました | 再起動します。 | その日がアクティブになります。同じファミリー内の次の保存位置が準備されます。 |
| 中間位置がアクティブ | 準備したプロファイルを確認した後、再起動します。 | 準備された日がアクティブになり、次の保存された位置が準備されます。 |
| 最終ポジションがアクティブ | 次のファミリーを確認してから再開します。 | 別の対象となるファミリー オーダーの最初のポジションが有効になります。 |

`selected_run` は、構成されたファミリーを保持します。 `non_repeating_random_run` は、17 日間のポジション全体にわたってランダムに選択されたファミリーを維持し、適格なリストがなくなるまでファミリーの再利用を回避します。 `rotation_run` は、設定されたファミリーの順序に従います。 `cycle.day_progression_mode` ファミリの選択とは関係なく、曜日の順序を制御します。

新規インストールでは、常に 1 つのプロセスを準備し、その後のプロセスをアクティブ化する必要があります。これは、永続サーバー、一時サーバー、および手動サーバーに当てはまります。 singleplayer/LAN 世代

<a id="read-the-right-evidence"></a>
## 正しい証拠を読む

完全なプロファイル リファレンス[ランタイム ファイル マップ](%E3%83%A9%E3%83%B3%E3%82%BF%E3%82%A4%E3%83%A0_%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB.md) ローテーション状態、現在のステータスを確認するには、最後に正常に実行されたファイル、操作のバックアップ、エクスポート、およびすべてのフィールド グループ、スキーマ、空の状態、失敗の意味、保持ルールの`UE4SS.log`で幅広いプレイ スタイルを選択します。正確なゲームプレイとサンドボックスの値が必要な場合は、[ランタイム出力リファレンス](%E3%83%A9%E3%83%B3%E3%82%BF%E3%82%A4%E3%83%A0%E5%87%BA%E5%8A%9B.md)。正規の 6 状態の結果テーブルと次のアクション用のHTML と JSON エクスポートはソース状態を要約します。これらは、プロファイルがライブ ゲーム クライアントによって使用されたことを証明するものではありません。

場合 `prepared_ready` は `false` または `profile_status` は `degraded_state_persistence`、サンドボックスとローテーションの状態が一致するまでサーバーを停止したままにします。失敗した状態の永続性を伴う有効なサンドボックス書き込みは、健全な準備された移行ではありません。

<a id="respond-to-writer-outcomes"></a>
## ライターの結果に応答する

RandomDay は、兄弟ファイル内の新しいバイトを準備し、それらを読み取り、完全なサンドボックスを検証し、オリジナルが存在する場合は保持し、新しいファイルをプロモートし、再度読み取ります。本番環境のリードバックが同意した場合にのみ準備完了と報告されます。

プロモーションまたは本番環境の検証が失敗した場合、RandomDayはその操作によって保持されているファイルの復元を試みます。復元の失敗はハードストップです。サーバーを停止したままにして、繰り返し再起動するのではなく、手動で回復します。

<a id="respond-to-adapter-outcomes"></a>
## アダプターの結果に応答する

使用する [サポートされるアダプター](%E3%82%B5%E3%83%9D%E3%83%BC%E3%83%88%E3%81%95%E3%82%8C%E3%81%A6%E3%81%84%E3%82%8B%E3%82%A2%E3%83%80%E3%83%97%E3%82%BF.md#read-an-adapter-result)。治療`rollback_failed` をハードストップとして扱います。別途記録されたアダプタのバックアップが復元ソースとなります。

アダプターは、個別にインストールされた MOD にのみ影響します。準備された RandomDay サンドボックス プロファイルがアクティブになることはありません。

通常の起動では、アダプタの値はアクティブなプロファイルから選択されます。これは、別個にインストールされた MOD が同じ UE4SS 起動時に後で読み込まれる可能性があるためです。最初のブートストラップ中に、アクティブな RandomDay マーカーが存在しない場合、準備された開始日プロファイルが唯一の使用可能なマッピングになります。このタイミング ルールは次回再起動サンドボックスの境界とは別のものであり、他の MOD 自体の読み込み動作に依存します。

<a id="manual-recovery"></a>
## 手動回復

1. ゲームまたはサーバーを停止します。ファイルが開いている可能性がある間はファイルをリカバリしないでください。
2. 現在の `SandboxSettings.ini`, `runtime/` と `web_export/` を別の診断バックアップにコピーします。
3. `runtime/last_good/manifest.lua` と `runtime/backups/` の下の最新の関連エントリを検査します。 family/dayおよびハッシュが復元する状態と一致するファイルを選択します。
4. 選択した検証済みファイルを、設定されたプライマリ サンドボックス パスにコピーします。
5. 開始する前に、ファイルを読み返して完了していることを確認します。
6. 一度開始して、アクティブ マーカーと準備済み状態を検査します。エラー メッセージがないだけでリカバリが成功したとは考えないでください。

検証済みのバックアップが存在しない場合は、インストール前に作成されたオペレータ バックアップを復元します。 RandomDay 起動中に一度も読み取れなかったファイルを再構築することはできません。

<a id="account-for-control-panel-writes"></a>
## コントロール パネルの書き込みを考慮してください。

一部のサーバー パネルでは、`SandboxSettings.ini` RandomDay 書き込みが確認された後に別のツールで上書きされた場合、準備されたプロファイルを保存できません。 1 つの信頼できるサンドボックス ソースを構成し、Day 1 の繰り返しまたはトランジションの欠落を診断するときに、再起動の直前と直後にファイル マーカーを確認します。
