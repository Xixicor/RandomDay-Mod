# 構成

> **正規の英語ソース:** [CONFIGURATION.md](../../CONFIGURATION.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


主なオペレータ設定は次のとおりです。

```text
RandomDay/Scripts/ax_config/server.lua
```

ファイルをバックアップし、一度に 1 セクションを変更します。 Lua のブール値は小文字です `true` と `false`;文字列には引用符が必要です。リストのエントリにはカンマが必要です。次回の起動後、別の変更を行う前にステータス ページを読んでください。ソースから作業している寄稿者は、変更されたビルドをパッケージ化する前に、個別の[リリース検証](%E3%83%AA%E3%83%AA%E3%83%BC%E3%82%B9%E3%81%AE%E6%A4%9C%E8%A8%BC.md)チェックを使用できます。

手動で編集しないでください`.randomday_mode`, `.randomday_version`、生成されたプロファイル参照、`runtime/`、または `web_export/`。パッケージ ビルダーはパッケージ モードとバージョン マーカーを所有し、それらがリリース メタデータと一致していることを確認します。

以下のすべての設定は `RandomDay/Scripts/ax_config/server.lua`。テーブルは、編集可能な設定を、リリース所有の ID および予約された互換性フィールドから区別します。 Lua に存在するフィールドは、そのフィールドの変更がサポートされる動作であることを意味するものではありません。

<a id="choose-an-experience"></a>
## エクスペリエンスを選択してください

RandomDay には 2 つのパッケージがあります。1 つは各専用サーバー用、もう 1 つは singleplayer/LAN 手動コピー。専用パッケージには 2 つの動作モードがあります。これらのモードは設定であり、個別にダウンロードするものではありません。

| あなたの世界 | インストール | この動作を選択してください |
| --- | --- | --- |
| 定期的な再起動をまたいで 1 つのキャンペーンを継続的に実行する専用サーバー | 専用サーバー パッケージ | `persistent_dedicated` は、保存されたファミリーとプロフィールの順序を再開します。 |
| 個々のプレイ セッションのためにのみオープンされる専用サーバー | 同じ専用サーバー パッケージ | `temporary_dedicated` セッション間で安全に準備された次のプロファイルが保持されますが、新しいファミリー実行では設定された開始またはランダムな開始が使用される場合があります。 |
| シングルプレイヤーまたは LAN 世界 | Singleplayer/LAN パッケージ | `auto` は手動コピー動作を選択します。生成されたファイルをコピーする前にワールドを停止してください。 |

不明な場合は、`auto`パッケージは、そのインストール タイプに対して通常の動作を選択します。 [ファミリー ローテーション](%E3%83%95%E3%82%A1%E3%83%9F%E3%83%AA%E3%83%BC_%E3%83%AD%E3%83%BC%E3%83%86%E3%83%BC%E3%82%B7%E3%83%A7%E3%83%B3.md)で幅広いプレイ スタイルを選択します。正確なゲームプレイとサンドボックスの値が必要な場合は、[生成されたファミリー インデックス](%E3%83%97%E3%83%AD%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB/%E3%83%97%E3%83%AD%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB_%E3%83%89%E3%82%AD%E3%83%A5%E3%83%A1%E3%83%B3%E3%83%88.md)を使用します。次に、最初の日と進行状況を選択します。

- `start_day_mode="configured"` から始まります。`start_day`.
- `start_day_mode="random"` 新しいファミリー ランの開始時に有効な最初の日を 1 つ選択し、その選択を保持します。
- `day_progression_mode="sequential"` は 17 ポジションすべてをラップします。
- `day_progression_mode="non_repeating_random"` 毎日を 1 回だけ含む 1 つのシャッフル注文を保存します。

[回転](#rotation) の完全なプリセットを使用します。新規インストールの場合でも、選択した最初のプロファイルを準備するために 1 回開始し、その後そのプロファイルをアクティブ化するために 1 回開始する必要があります。

<a id="experience-mode"></a>
## エクスペリエンス モード

`experience.mode` は、このインストールの操作方法に名前を付けます。次回起動時の安全境界は弱まりません: Abiotic Factor はサンドボックス設定を読み込む前に UE4SS は RandomDayそのため、どのモードもすでに実行中のプロセスのルールを置き換えることはできません。

| 設定 | 出荷値 | サポートされている値 | 効果 |
|---|---:|---|---|
| `experience.mode` | `auto` | `auto`, `persistent_dedicated`, `temporary_dedicated`, `singleplayer_lan` | `auto` はパッケージから解決されます。専用パッケージはどちらかの専用モードを使用できます。手動コピー パッケージは `auto` または `singleplayer_lan`. |

- `persistent_dedicated` は保存されたままになります family/day 通常の長期サーバー再起動後の順序。
- `temporary_dedicated` は、制限付きプレイ セッション用に起動されるサーバーを記述します。準備された順序は引き続き保持されるため、ホストを停止しても次のセッションが自動的に再ロールされることはありません。
- `singleplayer_lan` は、制限された手動コピー出力のみを生成します。個人の保存フォルダーを検出したり編集したりすることはありません。

互換性のないpackage/experience 組み合わせはサンドボックスへの書き込み前に停止します。

<a id="recommended-presets"></a>
### 推奨プリセット

永続的な専用サーバー:

```lua
experience = { mode = "persistent_dedicated" }
cycle = {
    application_mode = "next_reboot_queue",
    cycle_length_days = 17,
    start_day_mode = "configured",
    start_day = 1,
    day_progression_mode = "sequential",
    bootstrap_day = 1,
    check_interval_ms = 0,
}
```

新しいファミリーの実行ごとに非反復順序が異なる一時的な専用セッション:

```lua
experience = { mode = "temporary_dedicated" }
cycle.start_day_mode = "random"
cycle.day_progression_mode = "non_repeating_random"
```

Singleplayer/LAN手動コピーではシングルプレイヤー パッケージが使用され、通常は `experience.mode="auto"` のままになります。次のファイルを生成する前に、同じ開始コントロールと進行コントロールを選択できます。ランタイム状態とロードされたワールドのプロファイルを調整したままにする場合は、別の世代を実行する前に、生成されたファイルを選択した停止ワールドにコピーします。

新規インストールでは、最初のプロセスは選択した開始日のみを準備できます。後のプロセスでアクティブ化されます。ランダムまたは設定された起動では、エンジンの読み込み順序はバイパスされません。

固定ビルダー実行の例:

```lua
profile_family = {
    mode = "selected_run",
    selected_family = "builder",
    default_family = "action",
    allowed_families = { "builder" },
    preserve_family_until_day_17 = true,
    reroll_only_after_day_17 = true,
    prevent_repeats_until_rotation_complete = true,
}
```

空または不明の適格なセットは、不完全なプロファイルを作成する代わりに、登録されたファミリーにフォールバックします。

|---|---|---|---|
| `paths.runtime_dir` | 文字列: `ue4ss/Mods/RandomDay/runtime` | ソース設定で読み取り専用。 | `init.lua`解決された mod-root `runtime/` パスに置き換えます。 |

| `paths.sandbox_candidates` | 文字列のリスト: 7 つの一般的な候補 | 順序付けされた専用サーバーのフォールバック候補。 | `init.lua` インストール由来の候補が先頭に追加されます。最初の既存のパスが優先されます。 |

| `paths.world_name` | 非標準の専用レイアウトの場合は、文字列または `nil`: `nil` | 一般的なミラー候補を導出するために使用される 1 つの安全なワールド フォルダー コンポーネント。 | 文字、数字、スペース以外のものを使用すると、`_`、または `-` 起動が停止します。シングルプレイヤー モードでは無視されます。 |
| `paths.sandbox_mirror_candidates` | 文字列のリスト: 空 | 正確なオプションのミラー ファイル。 | 対象となる各ミラーは独自のトランザクションを使用します。ミラー障害が発生してもプライマリの成功は変わりません。 |

`paths.sandbox_path_override` デフォルトは `nil`。オーバーライドなしの場合、RandomDay 最初に汎用をチェックします WindowsServer 検出された候補に固定された候補 RandomDay をインストールし、構成されている候補を確認します。存在しない場合は、サーバー インストールに解決される、インストールにアンカーされた最初の汎用候補が使用されます。

```text
AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini
```

このフォールバックは、プロセスの現在の作業ディレクトリからは解決されません。インストールで別のリテラル ファイルが使用されている場合にのみ、`sandbox_path_override` を設定します。ディレクトリではなく、1 つの `SandboxSettings.ini` を指定します。使用する前にサーバーを停止し、ファイルが目的のインストール内にあることを確認してください。

<a id="optional-mirrors"></a>
### オプションのミラー

`paths.write_sandbox_mirrors`は `true` として出荷されますが、ミラー パス リストは空で、 `paths.world_name` は `nil` です。したがって、出荷時のデフォルトでは追加のミラーは書き込まれません。インストールで解決されたプライマリ ターゲットのみを常に書き込む必要がある場合は、`false` に設定します。ミラー候補またはワールド名が設定されていない場合、どちらの値でもプライマリ サンドボックス ファイルのみが書き込まれます。

ミラーは、意図的に正確なエントリを `paths.sandbox_mirror_candidates` に追加するか、 `paths.world_name` を設定した場合にのみ適格になります。ミラーは、世界固有の 2 番目のサンドボックス パスを読み取るインストール用のベストエフォート型コピーです。これらは、正しいプライマリ パスを構成する代わりにはなりません。

ミラーを有効にする前に:

1. サーバーを停止します。
2. サーバーが読み取る正確なファイルを特定します。
3. ターゲットが目的のインストール内にあることを確認します。
4. バックアップします。
5. そのパスのみを追加します。
6. 準備後にミラー結果を確認します。

ミラーを使用しないオーバーライドの例:

```lua
paths = {
    runtime_dir = "ue4ss/Mods/RandomDay/runtime",
    web_export_dir = "ue4ss/Mods/RandomDay/web_export",
    sandbox_path_override = "<server-root>/AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini",
    sandbox_candidates = {},
    write_sandbox_mirrors = false,
    sandbox_mirror_required = false,
    world_name = nil,
    sandbox_mirror_candidates = {},
}
```

`<server-root>` はプレースホルダーです。ローカルで置き換えてください。マシン固有のパスは公開しないでください。

<a id="non-disableable-safety-locks"></a>
## 無効にできない安全ロック

| 設定 | 必須値 | 意味 |
|---|---:|---|
| `sandbox.backup_before_write` | `true` | 既存のプライマリ ファイルを置換する前に、検証済みのコピーを保存します。 |
| `sandbox.restore_last_good_on_failure` | `true` | 置換またはリードバックの失敗後に自動回復を試みます。 |
| `external_mods.patch_only_existing_keys` | `true` | 別の MOD のファイルに不明な設定を作成することを拒否します。 |
| `external_mods.backup_before_write` | `true` | サポートされているトランザクション アダプターの編集前にターゲット バイトを保持します。 |

RandomDay これら 4 つの値のいずれかが満たされていない場合、起動は拒否されます。 `true`これらは安全ロックであり、オペレータ トグルはサポートされていません。開発やトラブルシューティングの場合も含めて、これらを無効にしないでください。無効にすると、ライターとアダプターのテストで証明されたフェールクローズ境界が変更されます。

`sandbox.force_rewrite_every_supervision_tick` は通常の設定のままで、 `false` として出荷されるため、すでに一致しているサンドボックス ファイルは変更されません。ブール値を受け入れます。これを `true` に設定すると、同じプロセス所有の準備済みバイトが再度ライターを通過します。 family/day は進みません。書き込みを繰り返すと操作バックアップがさらに作成されるため、制限付きリカバリ テストにのみ使用してください。

<a id="optional-mod-adapters"></a>
## オプションの Mod アダプタ

| 設定 | 出荷値 | 意味 |
|---|---:|---|
| `external_mods.enabled` | `true` | 設定されたアダプタが個別にインストールされたターゲットを検査できるようにします。 |
| `external_mods.optional_by_default` | `true` | 欠落または互換性のないオプションの MOD はブロックされませんRandomDay. |
| `external_mods.patch_only_existing_keys` | `true` | 安全ロックが必要です。変更すると起動に失敗します。 |
| `external_mods.backup_before_write` | `true` | 安全ロックが必要です。変更すると起動に失敗します。 |
| `external_mods.adapters` | 4 つのパブリック アダプター ID | 制限事項 RandomDay-owned アダプターは実行できます。 |

アダプター ID をリストから削除すると、サードパーティの MOD を無効にしたりアンインストールしたりせずに、その統合だけを残すことができます。 singleplayer/LAN パッケージは、このリストに関係なくすべてのアダプタを無効にします。

`external_mods.optional_by_default=false` 以外の構成されたアダプタの結果は、`applied` または `already_current` 集計アダプタの結果に失敗します。プライマリ サンドボックス トランザクションはロールバックされません。 `true` オペレーターが統合を必要とするテスト済みの理由がない限り、出荷されたままにしておきます。

詳細については、[サポートされている Mod アダプター](%E3%82%B5%E3%83%9D%E3%83%BC%E3%83%88%E3%81%95%E3%82%8C%E3%81%A6%E3%81%84%E3%82%8B%E3%82%A2%E3%83%80%E3%83%97%E3%82%BF.md) 認識されたレイアウトと 6 つの考えられる結果。

<a id="optional-chaotic-spawn-engine-scope-fields"></a>
### オプションの Chaotic Spawn Engine スコープ フィールド

`world_scope` は 5 つのオプションを提供します RandomDay Chaotic Spawn Engine が認識された場合のみの拡張機能設定 `DynamicSpawns/SharedData.lua` レイアウトには、これらのフィールドがすでに含まれています。これは個別の MOD やダウンロードではありません。

| 設定 | 出荷値 | アダプター効果 |
|---|---:|---|
| `world_scope.enabled` | `true` | オプションのリクエストRandomDay 認識された内部のワールドスコープ ゲート DynamicSpawns レイアウト。 |
| `world_scope.affect_open_worlds` | `true` | ターゲット MOD が保護ワールド ルールを適用しない限り、オープン ワールドが含まれます。 |
| `world_scope.unknown_world_policy` | `allow` | リクエスト `allow` または `block`ターゲット MOD がワールドを分類できない場合。 |
| `world_scope.log_scope_decisions` | `true` | スコープ決定のために target-mod のログを要求します。 |
| `world_scope.protected_worlds` | 空のリスト | カンマ区切りの保護ワールド パターンをターゲット レイアウトに提供します。 |

これらの値はアダプターの入力であり、RandomDay's サンドボックス ライター。これらは、個別にインストールされた Chaotic Spawn Engine レイアウトに、タイプ、範囲、出荷時のプロファイルのデフォルト、および残りの不変値に関する完全なオプションのRandomDay フィールド セットとレポート `applied` または `already_current` Chaotic Spawn Engine は、実行時にこれらのフィールドを使用する責任を負い続けます。拡張フィールドのない通常のインストールは変更されません。

5 つの値はすべてアダプターの入力です。 `unknown_world_policy` は、文書化されたターゲット値のみを受け入れます。 `allow` または `block`;認識されないターゲット レイアウトはスキップされます。ドキュメントの例では `protected_worlds` を空にしておきます。オペレーターがローカル パターンを使用する場合、それらをスクリーンショット、問題、リリース アーティファクトに含めてはなりません。

<a id="player-messages"></a>
## プレーヤー メッセージ

出荷された専用サーバー構成により、コンパクトな参加通知と短い 1 日の回線が可能になります。最初のパスの前に 30 秒待機し、15 秒ごとに新しく参加したプレーヤーをチェックし、毎日のラインの前の参加通知の後は 10 秒待機します。

| 設定 | 出荷値 |
|---|---:|
| `player_message.enabled` | `true` |
| `player_message.log_on_startup` | `true` |
| `player_message.register_console_command` | `false` |
| `player_message.console_command` | `randomday` |
| `player_message.broadcast_enabled` | `true` |
| `player_message.startup_delay_ms` | `30000` |
| `player_message.join_check_interval_ms` | `15000` |
| `player_message.send_daily_joke_after_join` | `true` |
| `player_message.daily_joke_delay_seconds` | `10` |
| `player_message.criticality_join` | `2` |
| `player_message.criticality_joke` | `0` |
| `player_message.max_line_chars` | `42` |
| `player_message.max_join_lines` | `4` |
| `player_message.max_warning_lines` | `3` |
| `player_message.max_note_lines` | `3` |

メッセージ長の検証によりソース制限がチェックされます。すべてのクライアント解像度でのビジュアル テストに代わるものではありません。

タイミング値は、`daily_joke_delay_seconds` がすでに含まれている場合にのみ有効になります。メッセージまたはブロードキャスト設定を無効にすると、サンドボックスの準備を変更せずにクライアント通知が抑制されます。コンソール コマンドは、設定と UE4SS ハンドラーの両方が使用可能な場合にのみ登録されます。名前付きクライアント テストで別の値が証明されない限り、重要度の値を出荷時のトランスポート レベルに維持します。

`max_line_chars` は、トランスレータによって 8 ～ 64 文字に制限されます。 3 つの行数設定により、それぞれ結合、警告、およびメモの出力が制限されます。出荷時の値は、使用可能なソース行の数と一致します。クライアント レイアウト テストでより狭い設定であることが証明されない限り、これら 4 つの制限はデフォルトのままにしておきます。

メッセージが無効になっている例:

```lua
player_message = {
    enabled = false,
    log_on_startup = true,
    register_console_command = false,
    console_command = "randomday",
    broadcast_enabled = false,
    startup_delay_ms = 30000,
    join_check_interval_ms = 15000,
    send_daily_joke_after_join = false,
    daily_joke_delay_seconds = 10,
    criticality_join = 2,
    criticality_joke = 0,
    max_line_chars = 42,
    max_join_lines = 4,
    max_warning_lines = 3,
    max_note_lines = 3,
}
```

<a id="profiles-and-sandbox-values"></a>
## プロファイルとサンドボックス値

`RandomDay/Scripts/ax_profiles/families/`の下のファミリー ソース ファイルは、ファミリーあたり 17 日を完全に定義します。 `docs/profiles/`の下に生成されたドキュメントはリファレンス出力であり、カスタマイズ ソースではありません。

使用する [サンドボックス キー リファレンス](%E3%83%97%E3%83%AD%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB/%E3%82%B5%E3%83%B3%E3%83%89%E3%83%9C%E3%83%83%E3%82%AF%E3%82%B9%E8%A8%AD%E5%AE%9A%E3%82%AD%E3%83%BC.md)がすでに含まれている場合にのみ有効になります。プロファイル ソースを編集した後、289 個の組み合わせすべてを再生成して検証します。変更不可能な Abiotic Factor ルールではなく、生成された Markdown または JSON レコードに手動でパッチを適用しないでください。

<a id="customize-the-shipped-profile-defaults"></a>
### 出荷されたプロファイルのデフォルトをカスタマイズする

開く:

```text
RandomDay/Scripts/ax_config/server.lua
```

このブロックは`sandbox`:

```lua
profile_overrides = {
    HardcoreMode = false,
    AllowIronMode = false,
    StructuralSupportLimit = 0,
    BridgeSupports = 0,
}
```

これらは RandomDay's 開始選択にパッチを適用しないでください。いずれかのモードを `true` または `false` に設定します。各サポート値を `0`から`1000` の整数に設定します。ファイルを編集する前にゲームまたは専用サーバーを停止し、保存してから再度開始すると、Lua が新しい設定をロードします。

RandomDay に設定すると、ファミリ内の 17 個のプロファイルを構築するたびにこのブロックが読み取られます。したがって、選択した値は、ローテーション後に準備されたプロファイルや、その後のサーバーの起動後に再構築されたプロファイルを含め、すべての家族と日に適用されます。 289 プロファイル ファイルを編集したり、プロファイル参照を再生成したりする必要はありません。

ライブのみの変更 `SandboxSettings.ini`は、次に準備されるプロファイルが `server.lua` から生成されるため、一時的なものです。無効なタイプ、不明なキー、またはサポート値が`0..1000`以外の場合、サイレントにデフォルトに戻るのではなく、名前付き設定エラーでプロファイルの構築が停止します。

生成されたプロファイル参照には、引き続き出荷時のデフォルトが表示されます。これはリリースのリファレンスであり、1 つのサーバーのプライベート構成のコピーではありません。
