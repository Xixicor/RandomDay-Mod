# ランタイム ファイルとステータスを特定します。

> **正規の英語ソース:** [RUNTIME_FILES.md](../../RUNTIME_FILES.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


これは、オペレータとソースのトレーサビリティによって使用される正規のパス インベントリです。ファイルがどこにあるのか、誰が書き込んだのか、いつ変更されたのか、どのくらいの期間残っているのか、どのような回復の役割を果たしているのかを答えます。 [ランタイム出力リファレンス](%E3%83%A9%E3%83%B3%E3%82%BF%E3%82%A4%E3%83%A0%E5%87%BA%E5%8A%9B.md) は、スキーマ、フィールドの意味、空の状態、およびマシン値の解釈を所有します。

このガイドのすべてのパスは、特に明記されていない限り、インストールされている `RandomDay/` フォルダーを基準としています。ランタイム出力はインストール後に作成されます。これらはリリース ZIP から除外されます。

<a id="recognize-empty-and-failed-file-states"></a>
### 空のファイルと失敗したファイルの状態を認識する

- 欠落しているプラ​​イマリ ターゲットまたはミラー ターゲットが作成される可能性があります。無効なプロファイル、保留中の書き込み、プロモーション、または運用リードバックの失敗の準備ができていません。ミラー障害が発生しても、受け入れられた主な結果は変更されません。
- `runtime/singleplayer_manual/SandboxSettings.ini` は、最初の手動実行時に作成される場合があります。生成エラーはステータスとログ出力に表示されたままになります。
- 判読不能`rotation_state.txt` は、前回正常な状態またはマーカーベースのブートストラップにフォールバックできます。失敗した状態のコミットにより生成される `degraded_state_persistence`.
- `runtime/last_good/` は、最初に検証されたターゲットの前に存在しない可能性があります。ペアになったマニフェストの更新が失敗した場合、RandomDay 以前に受け入れられたペアを復元します。
- `runtime/backups/mirror_<operation>/` は、ミラー固有のバックアップの場所です。トランザクション前にターゲットが存在しなかった場合、プライマリ バックアップ ファイルまたはミラー バックアップ ファイルは存在しません。
- バックアップの作成またはリードバックが失敗した場合、アダプターの変更は開始されません。
- ランタイム ステータスの出力が利用できないか不完全な場合、現在のステータス、辞書、またはプレビュー ファイルが存在しない可能性があります。
- アン `export_failed` 結果には古いものが残る場合があります `today.json` が所定の位置にあります。サンドボックスの障害に関する最新情報 JSON ただし、新たな障害は発生しません HTML ページ;タイムスタンプを `UE4SS.log`.
- 古い保留中のサイドカーは、新しい試行の前に削除されます。クリーンアップに失敗するとトランザクションが停止します。本番ターゲットとロールバック サイドカーの両方が存在する場合、RandomDay は、レビュー用にリカバリ バイトを保存します。
- いいえ `[RandomDay]` 開始行 `UE4SS.log` は、MOD の読み込みが証明されていないことを意味します。

<a id="transaction-sidecars"></a>
## トランザクション サイドカー

トランザクション ライターは、ターゲットの横に兄弟ファイルを作成する場合があります。

| パターン | 状態 | オペレータのアクション |
|---|---|---|
| `<target>.randomday.pending` | 昇格前のバイト候補。 | 通常はプロモーションによって削除されます。障害によって保留中のクリーンアップまたはリードバックの問題が報告された場合は、このファイルを保存してください。 |
| `<target>.randomday.rollback` | 置換中に保持された元のバイト。 | 通常、失敗時に復元されるか、成功が確認された後に削除されます。ターゲットも存在する場合は削除しないでください。その組み合わせには確認が必要です。 |
| `<target>.randomday.restore.pending` | アダプターの復元中の候補バイト。 | 復元が失敗した場合はアダプターのバックアップとともに保存します。 |
| `<target>.randomday.restore.rollback` | アダプターの復元中に保持される回復バイト。 | クリーンアップまたは復元が検証されない場合は、影響を受けるサービスを保存および停止します。 |

これらのファイルは存在する可能性があります。専用のサンドボックスまたは個別にインストールされたアダプター ターゲットの横にあります。それらの存在はトランザクションの状態であり、新しいプロファイルがアクティブになったことを示すものではありません。

<a id="interpret-file-contents"></a>
## ファイルの内容を解釈する

使用する [実行時の状態と出力リファレンス](%E3%83%A9%E3%83%B3%E3%82%BF%E3%82%A4%E3%83%A0%E5%87%BA%E5%8A%9B.md) 完全版 `rotation_state.txt`, `randomday_status.json` と `today.json` スキーマ。この参照は、空の状態、失敗の意味、辞書の出力、および準備された状態がアクティブな状態ではないというルールも所有します。 [ステータスとエラーのリファレンス](%E3%82%B9%E3%83%86%E3%83%BC%E3%82%BF%E3%82%B9%E3%81%A8%E3%82%A8%E3%83%A9%E3%83%BC%E3%81%AE%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9.md)正確なマシン値にオペレータのアクションが必要な場合。

<a id="retain-recovery-evidence"></a>
## 回復証拠の保持

RandomDay は、現在の状態、現在のステータス、前回正常な状態、および Web ビューを上書きします。独自の操作バックアップ ディレクトリを作成し、古いディレクトリは削除しません。実行中のプロセスの外で保持ポリシーを選択しますが、書き込み、読み取り、状態、またはロールバックの問題が未解決である間は、最新の回復証拠を決して削除しないでください。
