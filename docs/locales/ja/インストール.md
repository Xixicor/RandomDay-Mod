# インストール、更新、または削除 RandomDay

> **正規の英語ソース:** [INSTALL.md](../../../INSTALL.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


RandomDay には 2 つの完全なダウンロードがあります。設定しているワールドに合わせて 1 つ選択してください:

- 専用サーバーには**専用サーバーZIP**を使用します。これには、不定期のセッションに対してのみ開かれるサーバーも含まれます。
- 専用サーバーには**singleplayer/LAN ZIP**設定を手動でコピーするローカル ワールドの場合は、別のダウンロードではなく、

パッケージを結合しないでください。永続的または一時的な専用サーバーは RandomDay's設定を使用します。

<a id="before-you-begin"></a>
## 始める前に

以下の復元可能なコピーを作成します。

- 変更する世界、
- 現在の`SandboxSettings.ini`;
- 既存の`RandomDay` フォルダー (インストールされている場合)。

インストール UE4SS 前 RandomDay以下の手順では、**Mods フォルダー**は、`ue4ss/Mods/`ディレクトリを意味します。

<a id="dedicated-server"></a>
## 専用サーバー

<a id="new-installation"></a>
### 新規インストール

1. サーバーを停止します。
2. そのファイルを開きますUE4SS `Mods` フォルダー。
3. 専用サーバーを抽出します ZIP。結果は 1 になるはずです。`ue4ss/Mods/RandomDay/` フォルダ。別のフォルダ内のフォルダではありません。`RandomDay` フォルダー。
4. そのフォルダを開いて、`RandomDay/Scripts/main.lua` が存在します。見つからない場合は、ZIP は間違ったレベルに抽出されました。
5. インストールされた MOD フォルダで UE4SS `mods.txt`次の行を有効にします。

   ```text
   RandomDay : 1
   ```

6. サーバーを通常どおり起動します。
7. インストールされた MOD フォルダで RandomDay's読み取り可能なステータス ページを意味し、アクティブなプロファイルと次回の起動用に準備されたプロファイルの両方の名前が指定されていることを確認します。

最初の起動では、そのセッションによってすでにロードされているルールは置き換えられません。次のプロファイルを準備します。準備したプロファイルを実際にアクティブにする必要がある場合にのみ、サーバーを再起動します。

[最初のサイクルを確認する](%E3%81%93%E3%81%93%E3%81%8B%E3%82%89%E9%96%8B%E5%A7%8B.md)

<a id="choose-always-on-or-temporary-behavior"></a>
### 常時オンまたは一時的な動作を選択します。

専用サーバー パッケージは両方のスタイルをサポートします。

- **永続的な専用**通常の再起動で保存されたローテーションを再開します。
- **一時専用**は、新しい一時実行が開始されるときに、設定された開始点またはランダムな開始点から開始できます。

[構成](%E6%A7%8B%E6%88%90.md)で動作を選択します。この設定を変更するために 2 番目のパッケージをインストールしないでください。

<a id="update-an-existing-installation"></a>
### 既存のインストールを更新します。

1. サーバーを停止して、
2. 古い `RandomDay` フォルダ全体を UE4SS `Mods` フォルダーから移動します。更新が 1 回正常に完了するまで保持します。
3. 新しい専用サーバーを抽出します ZIP を `Mods` フォルダー。
4. 意図的に変更した設定のうち、新しい[設定ガイド](%E6%A7%8B%E6%88%90.md).
5. 文書化された回転状態ファイルは、リリース ノートに形式に互換性があると記載されている場合にのみ保管してください。古い一時出力ファイルや書き込み失敗ファイルを新しいインストールにコピーしないでください。
6. 確認 `RandomDay : 1` はまだ有効になっています。サーバーを一度起動し、アクティブなプロファイル名と準備されたプロファイル名を確認します。

<a id="updating-from-v0315-alpha"></a>
### v0.3.15-alpha

`RandomDay_v0.3.15-alpha.zip` からの更新は古い基本パッケージでした。 `RandomDay_v0.3.15-alpha_singleplayer_patch.zip` はオーバーレイであり、スタンドアロン ダウンロードではありませんでした。

現在の `v0.3.16-alpha` は、従来のベースとオーバーレイの配置を 2 つの完全なパッケージに置き換えます。どちらのパッケージにも古いパッチを置かないでください。現在のマーカーは `.randomday_mode=dedicated_server` と `.randomday_mode=singleplayer_manual`.

<a id="singleplayer-or-lan"></a>
## シングルプレイヤーまたは LAN

singleplayer/LAN パッケージは設定ファイルを作成します。個人セーブを単独で検索したり変更したりすることはありません。

1. ゲームを閉じます。
2. ワールドとその現在の`SandboxSettings.ini`.
3. バックアップを作成します。 singleplayer/LAN ZIP ゲームのUE4SS `Mods` フォルダに解凍します。`Mods/RandomDay/` フォルダーが存在します。
4. UE4SS で `RandomDay : 1` 内 UE4SS `mods.txt`.
5. 一度ゲームを開始し、しばらく待ちますRandomDay を終了してゲームを完全に閉じます。
6. RandomDay で生成された `SandboxSettings.ini` 内 RandomDay's `runtime/singleplayer_manual/` フォルダー。
7. 生成された概要を読み、選択した 1 つのワールドにファイルをコピーします。
8. そのワールドを開始し、予想されるサンドボックスの動作がアクティブであることを確認します。

LAN は、ホストがローカル ワールドを所有しているため、同じ手動プロセスを使用します。 MOD はワールドを選択したり、ワールドを自動的に上書きしたりしません。

[シングルプレイヤーとLANガイド](%E3%82%B7%E3%83%B3%E3%82%B0%E3%83%AB%E3%83%97%E3%83%AC%E3%82%A4%E3%83%A4%E3%83%BC_LAN.md)

<a id="remove-or-disable-randomday"></a>
## 削除または無効にする RandomDay

1. ゲームまたはサーバーを停止します。
2. ワールドとその現在のサンドボックス設定をバックアップします。RandomDay'sの状態にまだ存在する設定のみを再適用してください。
3. `RandomDay : 0` 内 UE4SS `mods.txt`を次のように設定します。 MOD を無効にするか、`RandomDay` フォルダ全体を `Mods` フォルダから移動して削除します。
4. 次回の起動時にどの `SandboxSettings.ini` は次回の起動時にロードされる必要があります。現在準備されているものが不要な場合は、プレインストール コピーを復元してください。 RandomDay プロフィール。
5. ワールドを起動して、バックアップを削除する前にルールを確認してください。

無効にする RandomDay 今後のプロファイルの準備が停止されます。すでにディスク上で待機しているサンドボックス ファイルは書き換えられません。

<a id="recover-from-an-unsuccessful-update"></a>
## 失敗した更新から回復する

最初の明確な失敗後に再起動を繰り返すと、どのプロファイルがアクティブでどれが待機していたのかがわかりにくくなる可能性があります。

1. ゲームまたはサーバーを停止します。
2. 失敗したインストールは削除せずに脇に移動します。
3. 完全な復元RandomDay アップデート前に作成されたフォルダーとサンドボックスのバックアップ。
4. 一度開始して、復元されたアクティブなプロファイル名と準備されたプロファイル名を確認します。
5. 使用する [トラブルシューティング](%E3%83%88%E3%83%A9%E3%83%96%E3%83%AB%E3%82%B7%E3%83%A5%E3%83%BC%E3%83%86%E3%82%A3%E3%83%B3%E3%82%B0.md)最初の欠落または失敗した手順については、別のアップデートを試行してください。
