# トラブルシューティング

> **正規の英語ソース:** [TROUBLESHOOTING.md](../../TROUBLESHOOTING.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


最初に失敗したチェックで停止します。現在のサンドボックスを保持します。`runtime/`, `web_export/` および関連する `UE4SS.log` リカバリを試みる前に。

<a id="try-these-common-fixes-first"></a>
## まずこれらの一般的な修正を試してください

1. **RandomDay決して表示されません:**確認してください。`RandomDay` フォルダは `ue4ss/Mods`、有効にする `RandomDay : 1` 内 `mods.txt`一度開始してください。
2. **現在のセッションは古いルールを保持しています:**これは正常です。 RandomDay は次のプロファイルを準備します。ゲームは後の起動時にそれをロードします。
3. **同じプロファイルが返され続けます:** サーバー パネルが置き換えられている可能性があります。`SandboxSettings.ini`。 1 つの信頼できるサンドボックス ファイルを使用し、`web_export/today.html`.
4. **オプションの MOD がプロファイルに従っていませんでした:** 開きます [サポートされているオプションの MOD](%E3%82%B5%E3%83%9D%E3%83%BC%E3%83%88%E3%81%95%E3%82%8C%E3%81%A6%E3%81%84%E3%82%8B%E3%82%A2%E3%83%80%E3%83%97%E3%82%BF.md)。欠落している、無効になっている、または認識されないオプションの MOD は変更されません。
5. **RandomDay は書き込みまたは復元の失敗を報告します:** もう一度再起動する前に停止し、`runtime/backups/` をクリックし、以下の指定された回復セクションに従ってください。

これら 5 つのチェックで問題が特定されない場合は、詳細なデシジョン ツリーに進みます。

<a id="follow-the-safe-diagnostic-order"></a>
### 次の手順に従ってください。安全な診断順序

1. ファイルを変更する前に現在の証拠を保存します。
2. 次のことを証明するRandomDay がロードされました。
3. 文書化された結果に達しなかった最初のステージを見つけます。
4. ランタイム出力から正確なステータスまたはエラー値をコピーします。
5. 以下の一致するテーブル行を使用します。 1 つの安全な応答のために。
6. 別の開始前にターゲットと回転の状態をリードバックします。

一致する行がない場合は、[実行時の状態と出力を使用します。構成を変更する前にプロデューサーとフィールドの意味を特定するための参照](%E3%83%A9%E3%83%B3%E3%82%BF%E3%82%A4%E3%83%A0%E5%87%BA%E5%8A%9B.md)。

<a id="restore-a-missing-randomday-start"></a>
## 失われたものを復元する RandomDay 開始

**最も考えられる限定的な原因:** 間違った抽出レイアウト、無効になった MOD、間違ったパッケージ モード、または UE4SS は Lua エントリ ポイントをロードしませんでした。

**正確なチェック:**確認`RandomDay/enabled.txt`, `.randomday_mode`, `.randomday_version` と `RandomDay/Scripts/main.lua`; `RandomDay : 1` 内 `mods.txt`を確認します。 `UE4SS.log` を`[RandomDay]`.

**期待される結果:** 開始行の 1 行にリリース ID とパッケージ モードの名前が含まれています。

**安全な次のアクション:** 停止中にレイアウトまたは有効化を修正し、一度開始します。

**推測しないでください:** いいえRandomDay 行はゲームまたはプロファイルのバグを証明するものではありません。

<a id="confirm-the-restart-boundary"></a>
## 再起動の境界を確認する

**最も考えられる限定的な原因:**通常の次回再起動動作。

**正確なチェック:**アクティブなプロファイルと準備済みのプロファイルを比較します。family/day 内 `web_export/today.json` または `today.html`.

**期待される結果:**準備されたプロファイルはアクティブなプロファイルと異なるか、明示的に分離されています。

**安全な次のアクション:**アクティブ化する準備ができた場合にのみ再起動し、確認します。アクティブなマーカー。

**推測しないでください:** 準備されたプロファイルは、再起動後のリードバックの前にはアクティブではありません。

<a id="stop-repeated-preparation"></a>
## 繰り返しの準備を停止します

**最も考えられる限定的な原因:** アクティブな RandomDay サーバー パネルまたは別のツールが書き換えたため、マーカーが見つかりません `SandboxSettings.ini`を書き換えたため、アクティブな RandomDay マーカーが見つかりません。

**正確なチェック:** サンドボックス ファイルとそのRandomDay 起動直前、パネル起動後、および起動後のマーカー RandomDay ファイルを準備します。

**期待される結果:** 次回の起動時に存在するファイルは、準備されたマーカーを保持します。

**安全な次のアクション:** 1 つの信頼できるサンドボックス ソースを構成し、競合するパネルの書き換えを無効にします。

**推測しないでください:** 繰り返します。 1 日目は、ファミリー セレクターが正しくランダム化されていないことを証明しません。

<a id="recover-from-failed-preparation"></a>
## 失敗した準備から回復する

**最も考えられる限定的な原因:** 保留中の書き込み、バックアップ、プロモーション、本番リードバック、検証、またはロールバックが失敗しました。

**正確なチェック:** 最初の読み取り `[RandomDay] [ERROR]` 行を削除し、名前付き操作のバックアップを保存します。検査する`runtime/last_good/manifest.lua` サンドボックス ファイルを使用する前に。

**期待される結果:** 以前のファイルが復元されたことが検証されるか、結果が復元を明確に報告するかのいずれかです。

**安全な次のアクション:** サーバーを停止したままにして、[手動リカバリ](%E6%93%8D%E4%BD%9C.md#manual-recovery).

**推測しないでください:** バックアップ ファイルが存在するだけでは、それが意図したアクティブな状態と一致することを証明できません。

<a id="diagnose-a-skipped-adapter"></a>
## スキップされたアダプターを診断する

**最も考えられる限定的な原因:** MOD が存在しないか、ファイルがサポートされている署名と一致しません。

**正確なチェック:** アダプターの結果を読み取り、インストールされているバージョンとレイアウトを比較します。[サポートされている Mod アダプター](%E3%82%B5%E3%83%9D%E3%83%BC%E3%83%88%E3%81%95%E3%82%8C%E3%81%A6%E3%81%84%E3%82%8B%E3%82%A2%E3%83%80%E3%83%97%E3%82%BF.md).

**期待される結果:** `not_installed` ターゲットが存在しない場合、または `skipped_incompatible` 認識されないターゲットの場合。

**安全な次のアクション:** ファイルを変更せずにそのままにするか、そのアダプターを無効にするか、元の作成者から正確にサポートされているバージョンをインストールします。

**推測しないでください:** 類似したファイル名または新しいバージョンは互換性の証拠ではありません。

<a id="recover-an-adapter-rollback-failure"></a>
## アダプターのロールバックの失敗を回復する

**最も考えられる限定的な原因:** 試行された書き込みと自動復元の両方を確認できませんでした。

**正確なチェック:** ターゲット、兄弟を保持します。 pending/rollback ファイル、アダプターのステータス、`runtime/backups/`.

**期待される結果:** 結果は `rollback_failed`、 ない`applied`.

**安全な次のアクション:** 影響を受けるものを停止します。 mod/server 再度起動する前に、検証済みのバックアップを手動で復元します。

**推測しないでください:** RandomDay's プライマリ サンドボックスの結果は、別のアダプター ターゲットが正常であることを証明しません。

<a id="generate-a-missing-singleplayerlan-file"></a>
## 欠落しているものを生成する singleplayer/LAN ファイル

**最も考えられる限定的な原因:** 専用パッケージがインストールされ、モードマーカーが無効であるか、RandomDay が読み込まれませんでした。

**正確なチェック:** `.randomday_mode` には `singleplayer_manual`; RandomDay 開始行と検査 `runtime/singleplayer_manual/SandboxSettings.ini`.

**期待される結果:** ファイルが RandomDay フォルダーのみ。

**安全な次のアクション:** 内に存在します。正しいパッケージを正しくインストールして、一度開始してください。

**推測しないでください:** RandomDay は、お客様に代わってターゲット ワールドを検索したり書き込んだりすることはありません。

<a id="diagnose-a-message-problem"></a>
## メッセージの問題を診断する

**最も考えられる限定的な原因:** スケジュールされたパスで有効なプレイヤー キャラクターが使用できなかったか、警告トランスポートが使用できなかったか、またはクライアント ディスプレイのテキストの折り返しが異なっていました。

**正確なチェック:** `[RandomDay]` メッセージ ログを検査し、ソース メッセージを文書化された長さと比較します。

**期待される結果:**ランタイムはメッセージ パスが実行されたかどうかを報告します。ソース検証では最大長が報告されます。

**安全な次のアクション:** 意図されたクライアント解像度を確認してください。ゲームプレイとプロファイルの検証をメッセージの結果とは別にしてください。

**推測しないでください:**表示されるメッセージはサンドボックス プロファイルが適用されたことを証明するものではなく、メッセージが表示されないことは準備が失敗したことを証明するものではありません。
<a id="four-profile-wide-choices-returned-to-the-shipped-values"></a>
## 出荷時の値に返されるプロファイル全体の 4 つの選択肢

**最も考えられる限定的な原因:**生成されたメッセージのみ `SandboxSettings.ini` が編集されたか、同じ Lua プロセスの実行中に `server.lua` が変更されました。

**正確なチェック:**ゲームまたは専用サーバーを停止し、次回起動後に `RandomDay/Scripts/ax_config/server.lua` を開き、保存された `sandbox.profile_overrides` ブロックに目的の 4 つの値が含まれていることを確認してください。

**期待される結果:** を開き、新しく準備されたメッセージが表示されるたびに family/dayプロファイルには、選択した値が含まれます。その後のプロファイルのローテーションとサーバーの起動では、同じブロックが引き続き使用されます。

**安全な次のアクション:** ブロックを修正し、一度開始して、準備されたプロファイルを検査します。生成されたサンドボックス ファイルのみにパッチを適用しないでください。後の準備によって置き換えられるためです。

<a id="look-up-an-exact-status"></a>
## 正確なステータスを確認する

デシジョン ツリーで失敗したステージが特定されたら、ランタイム エクスポートから正確な`status`, `transaction_status`, `rollback_status`、または `error` ランタイム エクスポートの値。 [ステータスとエラーのリファレンス](%E3%82%B9%E3%83%86%E3%83%BC%E3%82%BF%E3%82%B9%E3%81%A8%E3%82%A8%E3%83%A9%E3%83%BC%E3%81%AE%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9.md) を使用して、その意味とオペレータの安全な応答を確認してください。パネルまたはコンソール内の同様の文言は、エクスポートされた値の代わりにはなりません。

投稿者限定のテスト環境の失敗は、[リリース検証](%E3%83%AA%E3%83%AA%E3%83%BC%E3%82%B9%E3%81%AE%E6%A4%9C%E8%A8%BC.md#avoid-validation-environment-pitfalls)、オペレーターの回復パスにはありません。
