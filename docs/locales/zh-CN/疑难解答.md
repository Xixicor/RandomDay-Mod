# 疑难解答

> **规范的英文来源:** [TROUBLESHOOTING.md](../../TROUBLESHOOTING.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


在第一次失败的检查处停止。在尝试恢复之前，请保留当前沙箱、`runtime/`, `web_export/` 和相关的 `UE4SS.log`。

<a id="try-these-common-fixes-first"></a>
## 首先尝试这些常见修复

1. **RandomDay永远不会出现：**确认`RandomDay` 文件夹直接位于`ue4ss/Mods` 内，启用`RandomDay : 1` 在 `mods.txt` 中，并启动一次。
2. **当前会话保留其旧规则：**这是正常的。 RandomDay 准备下一个配置文件；游戏在稍后启动时加载它。
3. **相同的配置文件不断返回：**服务器面板可能正在替换`SandboxSettings.ini`。使用一个权威沙箱文件并比较 `web_export/today.html`.
4. **可选模组未遵循配置文件：**打开[支持的可选模组](%E6%94%AF%E6%8C%81%E7%9A%84%E9%80%82%E9%85%8D%E5%99%A8.md)。丢失、禁用或无法识别的可选模块保持不变。
5. **RandomDay报告写入或恢复失败：**在再次重新启动之前停止，保留`runtime/backups/`，并按照下面指定的恢复部分进行操作。

如果这五项检查无法识别问题，请继续使用详细的决策树。

<a id="choose-the-first-failed-stage"></a>
## 选择第一个失败的阶段

使用与您实际可以证明的内容相匹配的第一行。不要从最严重的解释开始，也不要将不相关的输出故障合并到一个诊断中。

| 您可以观察到什么 | 首先检查 | 继续 | 预期结果 |
|---|---|---|---|
| 否 `[RandomDay]`起始行存在于`UE4SS.log`. | 安装根目录、软件包标记、`mods.txt` 和 UE4SSLua启动。 | [恢复丢失的RandomDay开始](#restore-a-missing-randomday-start) | 一个启动行命名了版本和打包模式，否则失败必然会加载。 |
| RandomDay已加载，但没有准备好配置文件。 | 第一个启动、配置、目标、事务或状态错误。 | [从失败的准备中恢复](#recover-from-failed-preparation)，然后[状态和错误参考](%E7%8A%B6%E6%80%81%E5%92%8C%E9%94%99%E8%AF%AF%E5%8F%82%E8%80%83.md) | 一个确切的代码标识安全的下一步操作。 |
| 存在准备好的配置文件，但运行规则未更改。 | 活动和准备好的 ID `today.json` 或 `today.html`. | [确认重启边界](#confirm-the-restart-boundary) | 当前会话保持活动状态；准备好的配置文件等待稍后启动。 |
| 重启后重复第一天或另一天。 | 面板启动前、面板启动后和启动后的沙盒标记 | [停止重复准备](#stop-repeated-preparation) | 识别出权威写入点或覆盖点。 |
| 沙箱运行正常，但可选模组被跳过或失败。 | 各个适配器结果和兼容性证据。 | [诊断跳过的适配器](#diagnose-a-skipped-adapter) 或 [恢复适配器回滚失败](#recover-an-adapter-rollback-failure) | 适配器运行状况独立于沙箱决定health。 |
| 手动singleplayer/LAN文件不存在。 | 打包模式和有界输出文件夹。 | [生成缺失的singleplayer/LAN 文件](#generate-a-missing-singleplayerlan-file) | 文件在RandomDay内部生成，但未发现个人保存。 |
| 只有面向玩家的消息丢失或换行不良。 | 消息传递日志、源预览和记录的限制。 | [诊断消息问题](#diagnose-a-message-problem) | 演示文稿经过测试，未被视为配置文件证明。 |

<a id="follow-the-safe-diagnostic-order"></a>
### 遵循安全诊断顺序

1. 在更改文件之前保留当前证据。
2. 证明是否已加载RandomDay。
3. 查找未达到其记录结果的第一个阶段。
4. 从运行时输出复制确切的状态或错误值。
5. 使用下面的匹配表行进行安全响应。
6. 在另一次开始之前读回目标和旋转状态。

如果没有行匹配，则使用[运行时状态和输出更改配置之前，请参考](%E8%BF%90%E8%A1%8C%E6%97%B6%E8%BE%93%E5%87%BA.md)识别生产者和字段含义。

<a id="restore-a-missing-randomday-start"></a>
## 恢复丢失的RandomDay开始

**最可能的有限原因：**错误的提取布局、禁用的 mod、错误的包模式或UE4SS未加载Lua入口点。

**精确检查：**确认`RandomDay/enabled.txt`, `.randomday_mode`, `.randomday_version` 和 `RandomDay/Scripts/main.lua`；确认`RandomDay : 1` 在 `mods.txt`;搜索 `UE4SS.log` `[RandomDay]`.

**预期结果：**一个起始行命名发布标识和包模式。

**安全的下一步操作：**在停止时更正布局或启用，然后启动一次。

**不要推断：**否RandomDay行不能证明游戏或配置文件错误。

<a id="confirm-the-restart-boundary"></a>
## 确认重启边界

**最可能的有限原因：**正常的下次重新启动行为。

**精确检查：**比较活动的和准备的family/day 在 `web_export/today.json` 或 `today.html`.

**预期结果：**准备的配置文件与活动的配置文件不同或明确分开。

**安全的下一步操作：**仅在您准备好激活它时重新启动，然后验证活动标记。

**不要推断：**准备的配置文件在重启后不会处于活动状态回读。

<a id="stop-repeated-preparation"></a>
## 停止重复准备

**最可能的有限原因：**活动RandomDay 标记丢失，因为服务器面板或其他工具重写了 `SandboxSettings.ini` 启动期间。

**精确检查：**比较沙箱文件及其RandomDay 标记。RandomDay 准备文件后立即比较沙盒文件及其

**预期结果：**下次启动时出现的文件保留准备好的标记。

**安全的下一步操作：**配置一个权威沙箱源并禁用冲突的面板重写。

**不要推断：**重复的第一天并不能证明该系列选择器随机化不正确。

<a id="recover-from-failed-preparation"></a>
## 从失败的准备中恢复

**最可能的有限原因：**挂起的写入、备份、升级、生产读回、验证或回滚失败。

**精确检查：**读取第一个`[RandomDay] [ERROR]` 并保留命名操作备份。在使用其沙箱文件之前检查`runtime/last_good/manifest.lua`。

**预期结果：**之前的文件被验证为已恢复，或者结果明确报告恢复失败。

**安全的下一步操作：**保持服务器停止并遵循[手动恢复](%E6%93%8D%E4%BD%9C.md#manual-recovery).

**不要推断：**仅备份文件的存在并不能证明它与预期的活动世界状态匹配。

<a id="diagnose-a-skipped-adapter"></a>
## 诊断跳过的适配器

**最可能的有限原因：**模组不存在或文件与支持的签名不匹配。

**精确检查：**读取适配器结果并将安装的版本和布局与[支持的 Mod 适配器](%E6%94%AF%E6%8C%81%E7%9A%84%E9%80%82%E9%85%8D%E5%99%A8.md).

**预期结果：** `not_installed` 对于不存在的目标或 `skipped_incompatible` 对于无法识别的目标。

**安全的下一步操作：** 保持文件不变，禁用该适配器，或安装原作者提供的完全受支持的版本。

**不要推断：** 类似的文件名或更新版本并不能证明兼容性。

<a id="recover-an-adapter-rollback-failure"></a>
## 恢复适配器回滚失败

**最可能的有限原因：** 无法验证尝试的写入和自动恢复。

**精确检查：** 保留目标同级pending/rollback文件、适配器状态和最新适配器备份`runtime/backups/`.

**预期结果：** 结果是`rollback_failed`，而不是`applied`.

**安全的下一步操作：**停止受影响的mod/server并在下次启动之前手动恢复已验证的备份。

**不要推断：** RandomDay's主沙箱结果不能证明单独的适配器目标是健康的。

<a id="generate-a-missing-singleplayerlan-file"></a>
## 生成缺失的singleplayer/LAN 文件

**最可能的有限原因：**安装了专用软件包、模式标记无效，或者RandomDay未加载。

**精确检查：** `.randomday_mode` 必须包含 `singleplayer_manual`；然后确认 RandomDay 起始行并检查 `runtime/singleplayer_manual/SandboxSettings.ini`.

**预期结果：**文件存在于RandomDay 文件夹中。

**安全的下一步操作：**干净地安装正确的软件包并启动一次。

**不要推断：** RandomDay 不会代表您搜索或写入目标世界。

<a id="diagnose-a-message-problem"></a>
## 诊断消息问题

**最可能的有限原因：**在计划的传递中没有有效的玩家角色，警告传输不可用，或者客户端显示以不同的方式包装文本。

**精确检查：**检查`[RandomDay]`消息日志并将源消息与记录的长度限制进行比较。

**预期结果：**运行时报告是否运行了消息传递；源验证报告最大长度。

**安全的下一步操作：**验证预期的客户端分辨率。将游戏玩法和配置文件验证与消息结果分开。

**不要推断：**可见的消息并不能证明沙盒配置文件已应用，丢失的消息也不能证明准备失败。
<a id="four-profile-wide-choices-returned-to-the-shipped-values"></a>
## 返回到交付值的四个配置文件范围选择

**最可能的有限原因：**仅生成`SandboxSettings.ini`已编辑，或`server.lua`在同一 Lua 进程仍在运行时被更改。

**精确检查：**停止游戏或专用服务器，下次启动后打开`RandomDay/Scripts/ax_config/server.lua`，并确认保存的`sandbox.profile_overrides`块包含预期的四个值。

**预期结果：**，每次新准备的family/day 配置文件都包含所选值。稍后的配置文件轮换和服务器启动继续使用相同的块。

**安全的下一步操作：** 更正块，启动一次，然后检查准备好的配置文件。不要仅修补生成的沙箱文件，因为稍后的准备工作将替换它。

<a id="look-up-an-exact-status"></a>
## 查找确切的状态

决策树识别出失败的阶段后，从运行时导出复制确切的`status`, `transaction_status`, `rollback_status`，或 `error` 来自运行时导出的值。使用 [状态和错误参考](%E7%8A%B6%E6%80%81%E5%92%8C%E9%94%99%E8%AF%AF%E5%8F%82%E8%80%83.md) 了解其含义和一个安全的操作员响应。面板或控制台中的类似措辞不能替代导出的值。

仅限贡献者的测试环境故障属于[发布验证](%E5%8F%91%E5%B8%83%E9%AA%8C%E8%AF%81.md#avoid-validation-environment-pitfalls)，而不是操作员恢复路径。
