# 解释运行时状态和输出架构

> **规范的英文来源:** [RUNTIME_OUTPUTS.md](../../RUNTIME_OUTPUTS.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


这是规范的字段完整架构指南。它回答了每个字段、状态、空值和机器结果的含义。使用[运行时文件映射](%E8%BF%90%E8%A1%8C%E6%97%B6%E6%96%87%E4%BB%B6.md)作为生产者、路径、写入时间、保留、事务 sidecar 和恢复位置。

除非另有说明，本指南中的所有路径均相对于已安装的`RandomDay/` 文件夹，除非在安装后生成了一行明确命名的已配置沙箱或可选适配器目标，并且这些输出不是任一版本ZIP.

<a id="choose-the-authoritative-view"></a>
## 选择权威视图

| 需要 | 权威来源 |
|---|---|
| 当前进程加载的规则 | RandomDay 标记的成员。 `SandboxSettings.ini`启动时读取 |
| 准备好的队列簿记 | `runtime/rotation_state.txt`，架构`1` |
| 详细的本地状态 | `runtime/current/randomday_status.json`, `randomday_runtime_status_v2` |
| 公共机器可读状态 | `web_export/today.json`，架构`2` 和 `randomday_public_status_v2` |
| 人类可读状态 | `web_export/today.html`，源自相同的公共状态过渡 |
| 翻译词汇 | `runtime/current/randomday_dictionary.json`, `randomday_runtime_dictionary_v2` |
| 精确限制玩家注意 | `runtime/current/player_message_preview.txt` |

HTML 视图、预览和翻译摘要是派生视图，它们不会覆盖沙箱标记、事务结果或原始配置文件值、操作备份、sidecar、镜像、适配器目标和`UE4SS.log` 在 [ 运行时文件](%E8%BF%90%E8%A1%8C%E6%97%B6%E6%96%87%E4%BB%B6.md).

<a id="rotation-state-schema"></a>
## 旋转状态架构

`runtime/rotation_state.txt`使用架构`1`并且每个包含一对`key=value`中查找最后一次正确的文件、操作备份、sidecar、镜像、适配器目标和

| 字段 | 含义 |
|---|---|
| `schema_version` | 必须是`1`. |
| `mod_version` | 读取自的包标识`.randomday_version`. |
| `rotation_id` | 合格家族集中当前轮次的标识符。 |
| `mode` | `selected_run`, `non_repeating_random_run`，或 `rotation_run`. |
| `available_families` | 配置过滤后以逗号分隔的合格家族 ID。 |
| `remaining_families` | 当前非重复轮次中尚未选择的合格家族。 |
| `completed_families` | 当前轮次中已完成完整持久 17 位订单的家族。 |
| `active_family`, `active_day` | 提交选择时记录的活动标记信息。沙盒标记在下次启动时具有权威性。 |
| `prepared_family`, `prepared_day` | 为下次重新启动保留的配置文件。 |
| `active_run_id` | 与准备好的选择关联的家庭运行标识符。 |
| `last_status` | 生成此文件的日历选择状态。 |
| `session_mode` | 已解决持久专用、临时专用或singleplayer/LAN生命周期。 |
| `start_day_mode` | 新运行的配置或一次性随机开始选择。 |
| `day_progression_mode` | 包装顺序或非重复随机进程。 |
| `day_order` | 按照准备的确切顺序以逗号分隔的持久日 ID。 |
| `day_position` | 已准备日的位置`day_order`. |
| `updated_at` | 用于运算符比较的本地写入时间。 |

仅当模式标记、准备族和准备日正确读回时才接受状态写入。无法读取的当前文件可能会回退到 `rotation_state.last_good.txt`；所选沙箱标记仍决定游戏为当前进程加载的内容。

<a id="runtime-status-json"></a>
## 运行时状态JSON

`runtime/current/randomday_status.json` 使用`status_schema=randomday_runtime_status_v2`。其主要字段组是：

| 组 | 字段和解释 |
|---|---|
| 身份 | `mod`, `version`, `package_mode`, `mode`, `session_mode`, `profile_system`, `status_schema`, `dictionary_version` |
| 选择 | `reason`, `selection_status`, `active_profile_detection`, `rotation_id`, `run_id`, `cycle_length_days` |
| 活动 | `active_cycle_day`, `active_profile_id`, `active_display_name`, `active_family`, `active_family_label`, `active_profile_translation` |
| 准备 | `prepared_next_cycle_day`, `prepared_next_profile_id`, `prepared_next_display_name`, `prepared_next_family`, `prepared_next_family_label`, `prepared_profile_translation` |
| 人工摘要 | `profile_intensity`, `player_summary`, `prepared_profile_intensity`, `prepared_player_summary`, `admin_summary`, `message_preview` |
| 写入证明 | `write_status`, `backup_status`, `last_known_good_status`, `sandbox_transaction_status`, `sandbox_rollback_status`, `prepared_ready`, `state_commit_ok`, `state_commit_error_code` |
| 适配器证明 | `adapter_status`, `adapter_results`；每个适配器记录都包含兼容性证据、transaction/rollback状态、更改文件计数和编辑的目标引用 |
| 边界 | `restart_required_for_prepared_profile`, `sandbox_target`, `manual_copy_required`, `mirrors_written`, `world_scope`, `dictionary_path` |
| 诊断 | `hash`, `replacement_method`, `pending_readback_verified`, `target_readback_verified`, `updated_at` |

未知的活动值意味着当前沙箱不包含可读的RandomDay 标记。它们不能被替换为准备好的值。外部适配器路径`runtime/` 之外的适配器路径将简化为基本名称引用，并且诊断字符串会编辑检测到的绝对路径。

<a id="public-status-json"></a>
## 公开状态JSON

`web_export/today.json` 使用`schema_version=2` 和 `status_schema=randomday_public_status_v2`。它重复操作员所需的身份、active/prepared、选择、事务、适配器和重新启动边界事实。它还包括：

- `session_mode`, `start_day_mode`, `configured_start_day`, `day_progression_mode`, `day_order` 和 `prepared_day_position`;
- `family_selection_mode`、旧版`family_locked_until_day_17` 和 `family_locked_until_cycle_complete`;
- `remaining_families`, `completed_families`及其计数；
- 准备好的遭遇概况、层级、主题和混合遭遇机会；
- 世界范围启用、开放世界设置、未知世界策略以及仅配置的排除世界模式的计数；
- 准备好的消息和组合消息预览；
- `selected_at`, `sandbox_target`, `manual_copy_required`，以及准备好的哈希。

`profile_status`是其中之一`prepared_for_next_reboot`, `next_reboot_already_prepared`, `degraded_state_persistence`，或 `write_failed_or_rollback`. `prepared_ready=true`仍然不意味着活跃；需要稍后的启动标记。

<a id="dictionary-and-translation-output"></a>
## 词典和翻译输出

`runtime/current/randomday_dictionary.json` 使用`schema=randomday_runtime_dictionary_v2`并标识词典版本`randomday_dictionary_v2`。它描述了包模式、选择状态、压力域、设置标签、原始值和简单语言含义。未知值保持明确，而不是转换为可信的描述。

`player_message_preview.txt`, `today.json`, `today.html` 和游戏内通知是源自同一翻译模块的视图。底层配置文件和原始`SandboxSettings.ini` 值仍然是事实的来源。

<a id="failure-and-recovery-rules"></a>
## 失败和恢复规则

1. 失败的挂起写入或验证永远不会成为生产目标。
2. 升级或生产回读失败会触发保留的原始文件的恢复；操作备份是恢复失败时的后备措施。
3. 保留的回滚文件或`rollback_failed`状态需要在游戏或服务器停止时手动审核。
4. 成功的沙箱写入加上失败的轮换状态提交已降级，未就绪；适配器和准备好的配置文件消息传递将被跳过。
5. 导出失败不会更改沙箱结果，但会删除便利性证明源。使用事务日志、状态和文件回读。
6. 运行时输出是本地操作数据。不要将它们添加到版本中ZIP 或将它们作为示例发布，无需单独的隐私审查。
