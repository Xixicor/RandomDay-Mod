# 查找运行时文件和状态

> **规范的英文来源:** [RUNTIME_FILES.md](../../RUNTIME_FILES.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


这是操作员和源头可追溯性使用的规范路径清单。它回答文件在哪里、谁写入、何时更改、保留多长时间以及它充当哪个恢复角色。 [运行时输出参考](%E8%BF%90%E8%A1%8C%E6%97%B6%E8%BE%93%E5%87%BA.md) 拥有架构、字段含义、空状态和机器值解释。

除非另有说明，本指南中的所有路径均相对于已安装的`RandomDay/`文件夹。安装后创建运行时输出；它们被排除在发布 ZIP 之外。

<a id="operator-file-map"></a>
## 操作员文件映射

| 路径 | 生产者和触发器 | 更新和保留 | 含义和恢复 |
|---|---|---|---|
| 配置的主要`SandboxSettings.ini` | `ax_sandbox/writer.lua` 在专用模式下进行配置文件序列化和验证后。 | 以事务方式替换；目标是操作员配置的或安装派生的。 | 完成下次启动的配置文件。正在运行的会话保留其已加载的规则。 |
| 配置的镜像`SandboxSettings.ini` | 当显式镜像符合条件时，在一次成功的主要结果后沙箱编写器。 | 尽力事务替换。 | 仅限次要副本；镜像不会替换正确的主路径配置。 |
| 完成布局签名匹配后可识别的适配器目标 | `ax_external/bridge.lua`。 | 现有分配通过唯一备份以事务方式更改。 | 单独安装的 mod 配置；独立于主沙箱检查六状态适配器结果。 |
| `runtime/rotation_state.txt` | `ax_cycle/calendar.lua`成功沙箱事务后。 | 在每次接受的准备工作后以事务方式替换。 | 队列簿记。如果不可读，RandomDay尝试last-good状态。 |
| `runtime/rotation_state.last_good.txt` | 日历事务备份。 | 当前状态更新时替换。 | 以前的可读状态；在诊断和更新期间保留它。 |
| `runtime/current/randomday_status.json` | `ax_runtime/status.lua`在成功、持久性降级或写入失败后。 | 在每个状态传递上以事务方式替换。 | 规范结构化active/prepared、事务、转换和适配器摘要。 |
| `runtime/current/randomday_dictionary.json` | `ax_runtime/status.lua`旁边状态。 | 以事务方式替换。 | 架构`randomday_runtime_dictionary_v2`：术语、设置翻译、域、包模式和选择状态。 |
| `runtime/current/player_message_preview.txt` | `ax_runtime/status.lua`旁边状态。 | 以事务方式替换。 | 用于操作员审核的精确有界消息预览；它不证明客户端渲染。 |
| `runtime/last_good/SandboxSettings.ini` | `ax_backup/manager.lua`在验证主沙箱结果之后。 | 以事务方式替换。 | 最后一个沙箱被接受为已知良好。仅与其清单一起使用。 |
| `runtime/last_good/manifest.lua` | `ax_backup/manager.lua`在沙箱快照成功后。 | 以事务方式与沙箱快照成对替换。 | 版本、配置文件 ID、名称、日期、内容哈希以及最后一次正确文件的写入时间。 |
| `runtime/backups/<operation>/SandboxSettings.ini` | 突变前的主要或镜像编写器。 | 唯一的操作目录； RandomDay 不会修剪它。 | 验证预写字节。审核后运营商拥有保留权。 |
| `runtime/backups/external_<operation>/...` | 任何适配器突变之前的适配器桥接。 | 独特的操作目录；没有自动修剪。 | 每个计划的适配器目标的一个经过验证的副本。 |
| `runtime/pending/` | 由运行时目录设置创建。 | 保留；当前的主要事务使用同级 sidecar。 | 不要将空目录视为准备证明。 |
| `runtime/singleplayer_manual/SandboxSettings.ini` | 沙箱编写器处于 `singleplayer_manual` 模式。 | 在手动包运行时以事务方式替换。 | 供操作员检查并手动复制到的完整文件一个停止的世界。 |
| `web_export/today.json` | `ax_web/export.lua`在每个准备结果之后。 | 以事务方式替换。 | 紧凑的机器可读active/prepared 和 writer/adapter结果。 |
| `web_export/today.html` | `ax_web/export.lua`在成功导出之后。 | 以事务方式替换。 | 从同一转换导出的人类视图；不是独立证明。 |
| `UE4SS.log` | UE4SS 和 `ax_core/log.lua`. | 管理者UE4SS，而不是RandomDay. | 启动、选定的配置文件、写入、适配器、消息、状态和故障行，前缀为 `[RandomDay]`. |

<a id="recognize-empty-and-failed-file-states"></a>
### 识别空文件和失败文件状态

- 可能会创建丢失的主目标或镜像目标。无效的配置文件、挂起的写入、升级或生产读回失败未准备好。镜像失败不会更改已接受的主要结果。
- `runtime/singleplayer_manual/SandboxSettings.ini`可能会在第一次手动运行时创建。生成失败在状态和日志输出中仍然可见。
- 不可读的`rotation_state.txt`可以回退到最后的良好状态或基于标记的引导程序。失败的状态提交产生的​​`degraded_state_persistence`.
- `runtime/last_good/` 在第一个经过验证的目标之前可能不存在。如果配对清单更新失败，RandomDay将恢复之前接受的配对。
- `runtime/backups/mirror_<operation>/` 是特定于镜像的备份位置。如果目标在事务之前不存在，则不存在主或镜像备份文件。
- 当备份创建或读回失败时，适配器突变不会开始。
- 当运行时状态输出不可用或不完整时，当前状态、字典或预览文件可能不存在。
- `export_failed`结果可能会留下较旧的`today.json`就位。沙箱故障会更新JSON，但不会创建新的故障HTML页面；将时间戳与 `UE4SS.log`.
- 在新尝试之前删除陈旧的待处理 sidecar 进行比较；清理失败会停止事务。如果生产目标和回滚 sidecar 都存在，RandomDay 会保留恢复字节以供审核。
- 否 `[RandomDay]` `UE4SS.log` 中的起始行表示 mod 加载未经验证。

<a id="transaction-sidecars"></a>
## 事务 sidecar

事务编写器可能会在目标：

| 模式 | 状态 | 操作员操作 |
|---|---|---|
| `<target>.randomday.pending` | 升级前的候选字节。 | 通常通过升级删除。如果故障报告挂起的清理或读回问题，请保留它。 |
| `<target>.randomday.rollback` | 替换期间保留的原始字节。 | 通常在失败时恢复或在验证成功后删除。当目标也存在时不要删除它；该组合需要审查。 |
| `<target>.randomday.restore.pending` | 适配器恢复期间的候选字节。 | 如果恢复失败，则保留适配器备份。 |
| `<target>.randomday.restore.rollback` | 适配器恢复期间保留的恢复字节。 | 如果清理或恢复未经验证，则保留并停止受影响的服务。 |

这些文件可以存在于专用文件旁边沙箱或单独安装的适配器目标。它们的存在是一种事务状态，而不是新配置文件已激活的证据。

<a id="retain-recovery-evidence"></a>
## 保留恢复证据

RandomDay覆盖当前状态、当前状态、它会创建唯一的操作备份目录，并且不会在运行进程之外选择保留策略，但在写入、读回、状态或回滚问题未解决时切勿删除最新的恢复证据。
