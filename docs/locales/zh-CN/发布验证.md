<a id="release-validation"></a>
# 发布验证

> **规范的英文来源:** [RELEASE_VALIDATION.md](../../RELEASE_VALIDATION.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


此页面供贡献者和版本维护者使用。安装该模组的玩家不需要运行这些命令。

<a id="ordinary-user-proof"></a>
## 普通用户证明

当新读者可以选择两个软件包之一、安装它、识别活动配置文件和准备好的配置文件，并按照链接的指南从丢失的结果中恢复时，发布是可以理解的。这些读者任务一定不需要 Git，PowerShell、Python 或校验和知识。

<a id="contributor-checks"></a>
## 贡献者检查

从存储库根运行：

```powershell
python -B tools/validate_repo.py
python -B -m unittest discover tests
```

何时 `luac` 可用，对每个已发布的 Lua 文件进行语法检查：

```powershell
Get-ChildItem RandomDay -Recurse -Filter *.lua | ForEach-Object { luac -p $_.FullName }
```

Lua 运行时测试需要 `lupa`。缺少 Lua 解释器或 `lupa`安装是不可用的测试能力，不是通过的结果。

<a id="release-checks"></a>
## 发布检查

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

发布检查验证这些条件：

- `VERSION` 和 `RandomDay/.randomday_version` 匹配。
- 仅当前版本存在于`releases/`.
- 专用和singleplayer/LAN ZIP 是完整的替代方案。
- 两个档案都包含规范`RandomDay/Scripts/main.lua` 路径并且没有大小写冲突的加载程序。
- 包模式标记为 `dedicated_server` 和 `singleplayer_manual`.
- ZIP字节是确定性的并且匹配`CHECKSUMS.sha256`.
- 没有打包运行时数据、私有配置、凭据、缓存或测试输出。
- 所有本地文档链接和 27 个区域设置条目页面均经过验证。

<a id="avoid-validation-environment-pitfalls"></a>
## 避免验证环境陷阱

- 连续运行存储库写入检查，以便两个进程不会同时替换同一个临时文件。
- 在 Windows 上，检查ZIP成员名称，而不是使用不区分大小写的文件查找来确定小写加载程序是否存在。
- 确认`mods.txt` 和 `enabled.txt` 仅在已安装服务器测试中；它们不能证明源测试已运行。
- 将命令超时记录为不完整。如果没有命令的有界输出，请勿将其转换为通过或失败。
- 将临时文件保留在存储库中被忽略的`.tmp/` 目录。

<a id="known-limits"></a>
## 已知限制

本地验证证明源、包、文档和固定装置合同。它不证明特定服务器面板的启动顺序、实时客户端的消息布局或特定于主机的文件系统路径。在测试时将它们记录为单独的集成结果。
