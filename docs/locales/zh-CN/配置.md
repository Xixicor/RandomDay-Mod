<a id="configuration"></a>
# 配置

> **规范的英文来源:** [CONFIGURATION.md](../../CONFIGURATION.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


主要操作员配置是：

```text
RandomDay/Scripts/ax_config/server.lua
```

备份文件并一次更改一个部分。 Lua 布尔值是小写的 `true` 和 `false`；字符串需要引号；列表条目需要逗号。下次启动后，请在进行另一次更改之前阅读状态页。从源代码工作的贡献者可以在打包修改后的版本之前使用单独的[发布验证](%E5%8F%91%E5%B8%83%E9%AA%8C%E8%AF%81.md)检查。

不要手动编辑`.randomday_mode`, `.randomday_version`，生成的配置文件引用，`runtime/`，或 `web_export/`。包构建者拥有包模式和版本标记，并检查它们是否与发布元数据一致。

下面的每个设置都在 `RandomDay/Scripts/ax_config/server.lua`。表将可编辑设置与版本拥有的标识和保留的兼容性字段区分开来。 Lua 中存在的字段并不意味着更改它是受支持的行为。

<a id="choose-an-experience"></a>
## 选择体验

RandomDay有两个软件包：一个用于每个专用服务器，另一个用于singleplayer/LAN 手动复制。专用包有两种工作模式；这些模式是设置，而不是单独的下载。

| 你的世界 | 安装 | 选择此行为 |
| --- | --- | --- |
| 一台专用服务器，可让一个广告活动在例行重启期间继续进行 | 专用服务器包 | `persistent_dedicated`恢复保存的家庭和个人资料订单。 |
| 仅为个人游戏会话开放的专用服务器 | 相同的专用服务器包 | `temporary_dedicated` 在训练之间保留安全准备的下一个配置文件，而新的家庭跑步可能会使用配置的或随机的开始。 |
| 单人游戏或LAN世界 | Singleplayer/LAN 包 | `auto` 选择手动复制行为；在复制生成的文件之前停止世界。 |

如果您不确定，请使用 `auto`。该包为其安装类型选择正常行为。在[家庭轮换](%E5%AE%B6%E5%BA%AD%E8%BD%AE%E6%8D%A2.md)中选择广泛的游戏风格。当您需要精确的游戏玩法和沙盒值时，请使用[生成的系列索引](%E5%89%96%E9%9D%A2/%E9%85%8D%E7%BD%AE%E6%96%87%E4%BB%B6%E6%96%87%E6%A1%A3.md)。然后选择第一天和进度：

- `start_day_mode="configured"` 开始于 `start_day`.
- `start_day_mode="random"` 在新的家庭运行开始时选择一个有效的第一天并保留该选择。
- `day_progression_mode="sequential"` 包含所有 17 个位置。
- `day_progression_mode="non_repeating_random"` 存储一个包含每天一次的随机订单。

使用[旋转](#rotation)中的完整预设。全新安装仍然需要启动一次来准备所选的第一个配置文件，然后启动来激活它。

<a id="release-identity-and-logging"></a>
## 发布身份和日志记录

| 设置 | 类型和发货价值 | 支持的用途 | 失败或交互 |
|---|---|---|---|
| `version` | 字符串读取自 `.randomday_version` | 只读。 | 缺失或空白标记变为 `unversioned`;最终包验证拒绝身份漂移。 |
| `package_mode` | 字符串读取自 `.randomday_mode` | 只读：`dedicated_server` 或 `singleplayer_manual`. | 任何其他值都会在目标写入之前停止启动。 |
| `plan_basis` | 字符串：`RandomDay - Seventeen Suns Rotation + Open World Scope` | 仅限诊断标签；不要将其用作功能切换。 | 当前运行时不会在此字段上分支。 |
| `logging.level` | 字符串：`info` | `debug`, `info`, `warn`，或 `error`. | 未知值不会添加日志记录目标；保留`info`除非诊断配置文件生成行为。 |

示例：

```lua
logging = { level = "debug" }
```

暂时使用`debug`，保留相关`UE4SS.log`，然后返回`info`。日志可以包含低级故障的本地路径；在分享之前先查看它们。

<a id="experience-mode"></a>
## 体验模式

`experience.mode`命名此安装的操作方式。它不会削弱下次启动的安全边界：Abiotic Factor会在UE4SS 加载 RandomDay之前读取沙箱设置，因此任何模式都无法替换已经运行的进程的规则。

| 设置 | 运送值 | 支持的值 | 效果 |
|---|---:|---|---|
| `experience.mode` | `auto` | `auto`, `persistent_dedicated`, `temporary_dedicated`, `singleplayer_lan` | `auto`从包中解析。专用包可以使用任一专用模式。手动复制包仅接受`auto` 或 `singleplayer_lan`. |

- `persistent_dedicated`在正常的长期服务器重新启动期间保留一个存储的family/day订单。
- `temporary_dedicated`描述了为有界游戏会话启动的服务器。它仍然保留准备好的顺序，因此停止主机不会默默地重新滚动下一个会话。
- `singleplayer_lan`仅生成有限的手动复制输出。它永远不会发现或编辑个人保存文件夹。

不兼容的package/experience组合在沙箱写入之前停止。

<a id="rotation"></a>
## 旋转

| 设置 | 运送值 | 支持的值 | 效果 |
|---|---:|---|---|
| `cycle.application_mode` | `next_reboot_queue` | `next_reboot_queue` | 将所有沙箱更改保留在重新启动边界。 |
| `cycle.cycle_length_days` | `17` | `17`适用于标准配置文件集 | 匹配每个家庭包和生成的参考。 |
| `cycle.start_day_mode` | `configured` | `configured`, `random` | 使用`cycle.start_day`或在家庭跑步开始时选择一个有效的开始日期。 |
| `cycle.start_day` | `1` | 整数`1`到`17` | 第一天`start_day_mode=configured`. |
| `cycle.day_progression_mode` | `sequential` | `sequential`, `non_repeating_random` | 构建包含每天一次的打包顺序订单或随机订单。 |
| `cycle.bootstrap_day` | `1` | 整数`1`到`17` | 仅当 `cycle.start_day` 不存在时才使用兼容性回退。新配置应使用`cycle.start_day`. |
| `cycle.check_interval_ms` | `0` | `0`或有界正区间 | `0`在启动时准备一次；当 UE4SS 提供 `LoopAsync`. |
| `profile_family.mode` | `non_repeating_random_run` | `selected_run`, `non_repeating_random_run`, `rotation_run` | 选择如何开始新的 17 天家庭运行。 |
| `profile_family.selected_family` | `action` | `allowed_families` | 家庭使用的一个 ID `selected_run`并作为后备。 |
| `profile_family.default_family` | `action` | 一个注册的家庭 ID | 当所选 ID 丢失或无效时回退。 |
| `profile_family.allowed_families` | 所有 17 个公共家庭 ID | 注册 ID 的任何非空子集 | 限制有资格参加新运行的家庭。 |
| `profile_family.preserve_family_until_day_17` | 布尔值：`true` | 保留兼容性字段； keep `true`. | 当前日历始终将系列保留在持续 17 天顺序中的每个位置，并且不会将此字段读取为切换。 |
| `profile_family.reroll_only_after_day_17` | 布尔值：`true` | 保留兼容性字段； keep `true`. | 当前日历仅在每天 ID 完成后更改系列，无论存储顺序中的最后一天是哪一天。 |
| `profile_family.prevent_repeats_until_rotation_complete` | 布尔值：`true` | 保留兼容性字段； keep `true`. | 当前的非重复池逻辑已修复，不会将此值读取为切换 |

为新的家庭运行创建一次日订单并写入`runtime/rotation_state.txt`。恢复和稍后的重新启动会重复使用这些确切位置。配置编辑不会重新滚动正在进行的订单。只有在所有 17 个职位都完成后，家族才会发生变化。

<a id="recommended-presets"></a>
### 推荐预设

永久专用服务器：

```lua
experience = { mode = "persistent_dedicated" }
cycle = {
    application_mode = "next_reboot_queue",
    cycle_length_days = 17,
    start_day_mode = "configured",
    start_day = 1,
    day_progression_mode = "sequential",
    bootstrap_day = 1,
    check_interval_ms = 0,
}
```

每个新系列运行具有不同非重复顺序的临时专用会话：

```lua
experience = { mode = "temporary_dedicated" }
cycle.start_day_mode = "random"
cycle.day_progression_mode = "non_repeating_random"
```

Singleplayer/LAN手动复制使用单人游戏包，通常会离开`experience.mode="auto"`。在生成下一个文件之前，您可以选择相同的开始和进度控件。如果您希望运行时状态和世界加载的配置文件保持一致，请在另一代运行之前将生成的文件复制到所选的停止世界中。

在全新安装中，第一个进程只能准备所选的开始日期。稍后的过程将激活它。随机或配置启动不会绕过该引擎加载顺序。

固定构建器运行的示例：

```lua
profile_family = {
    mode = "selected_run",
    selected_family = "builder",
    default_family = "action",
    allowed_families = { "builder" },
    preserve_family_until_day_17 = true,
    reroll_only_after_day_17 = true,
    prevent_repeats_until_rotation_complete = true,
}
```

空的或未知的合格集回退到已注册的系列，而不是创建不完整的配置文件。

<a id="primary-sandbox-path"></a>
## 主沙箱路径

| 设置 | 类型和发货价值 | 支持的用途 | 失败或交互 |
|---|---|---|---|
| `paths.runtime_dir` | 字符串：`ue4ss/Mods/RandomDay/runtime` | 在源配置中只读。 | `init.lua`替换它与已解析的 mod-root `runtime/` 路径一起使用。 |
| `paths.web_export_dir` | 字符串：`ue4ss/Mods/RandomDay/web_export` | 在源配置中只读。 | `init.lua`替换它与已解析的 mod-root `web_export/` 路径一起使用。 |
| `paths.sandbox_path_override` | 字符串或 `nil`: `nil` | 非标准专用布局的一个文字 `SandboxSettings.ini` 路径。 | 不安全或不可用的目标会导致写入失败；单人游戏模式清除覆盖。 |
| `paths.sandbox_candidates` | 字符串列表：七个通用候选项 | 有序的专用服务器后备候选项。 | `init.lua`前置安装派生的候选项；第一个现有路径获胜。 |
| `paths.write_sandbox_mirrors` | 布尔值：`true` | 允许故意配置镜像。 | 当镜像列表为空且`world_name=nil`时不会写入镜像；单人游戏模式强制`false`. |
| `paths.sandbox_mirror_required` | 布尔值：`false` | 保留兼容性字段； keep `false`. | 当前编写者将镜像视为可选，并且不会将此字段读取为必需的门。 |
| `paths.world_name` | 字符串或 `nil`: `nil` | 一个用于派生通用镜像候选者的安全世界文件夹组件。 | 字母、数字、空格之外的任何内容`_`，或 `-`将停止启动；单人游戏模式会忽略它。 |
| `paths.sandbox_mirror_candidates` | 字符串列表：空 | 精确的可选镜像文件。 | 每个符合条件的镜像都使用自己的事务；镜像失败不会改变主要成功。 |

`paths.sandbox_path_override`默认为`nil` 时，正值启用定期监督。如果没有覆盖，RandomDay首先检查锚定到检测到的WindowsServer候选，然后检查任何配置的候选。如果不存在，它将使用第一个安装锚定的通用候选者，该候选者解析为服务器安装的：RandomDay安装的通用

```text
AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini
```

此后备不会从进程的当前工作目录解析。仅当您的安装使用不同的文字文件时才设置 `sandbox_path_override`。将其指向一个 `SandboxSettings.ini`，而不是目录。使用前请停止服务器并确认文件位于预期安装中。

<a id="optional-mirrors"></a>
### 可选镜像

`paths.write_sandbox_mirrors`以`true`形式发货，但镜像路径列表为空，`paths.world_name`为`nil`。因此，出厂默认设置不写入额外的镜像。当安装必须始终只写入已解析的主要目标时，请将其设置为 `false`。在没有配置镜像候选者或世界名称的情况下，任一值仍然只写入主沙箱文件。

仅当您故意向`paths.sandbox_mirror_candidates`或设置`paths.world_name`有意添加精确条目时，镜像才符合资格。镜像是读取第二个世界特定沙箱路径的安装的尽力而为的副本。它们不能替代配置正确的主路径。

启用镜像之前：

1. 停止服务器；
2. 确定服务器读取的确切文件；
3. 确认目标位于预期安装内；
4. 备份它；
5. 仅添加该路径；
6. 准备后验证镜像结果。

不使用镜像的覆盖示例：

```lua
paths = {
    runtime_dir = "ue4ss/Mods/RandomDay/runtime",
    web_export_dir = "ue4ss/Mods/RandomDay/web_export",
    sandbox_path_override = "<server-root>/AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini",
    sandbox_candidates = {},
    write_sandbox_mirrors = false,
    sandbox_mirror_required = false,
    world_name = nil,
    sandbox_mirror_candidates = {},
}
```

`<server-root>`是占位符。本地替换；不要发布特定于计算机的路径。

<a id="non-disableable-safety-locks"></a>
## 不可禁用的安全锁

| 设置 | 所需值 | 含义 |
|---|---:|---|
| `sandbox.backup_before_write` | `true` | 在替换现有主文件之前保留经过验证的副本。 |
| `sandbox.restore_last_good_on_failure` | `true` | 在替换或读回失败后尝试自动恢复。 |
| `external_mods.patch_only_existing_keys` | `true` | 拒绝在另一个 mod 的文件中创建未知设置。 |
| `external_mods.backup_before_write` | `true` | 在受支持的事务适配器编辑之前保留目标字节。 |

RandomDay如果这四个值中的任何一个不是，则拒绝启动`true`，RandomDay 将拒绝启动。它们是安全锁，不支持操作员开关。不要禁用它们，包括在开发或故障排除过程中，因为这样做会更改编写器和适配器测试证明的失败关闭边界。

`sandbox.force_rewrite_every_supervision_tick` 仍然是正常设置并以 `false` 形式提供，这会保持已匹配的沙箱文件不变。它接受一个布尔值。将其设置为 `true` 会强制再次通过写入器使用相同的进程拥有的准备好的字节；它不会推进 family/day。仅将其用于有限恢复测试，因为重复写入会创建更多操作备份。

<a id="optional-mod-adapters"></a>
## 可选 Mod 适配器

| 设置 | 运送值 | 含义 |
|---|---:|---|
| `external_mods.enabled` | `true` | 允许配置的适配器检查单独安装的目标。 |
| `external_mods.optional_by_default` | `true` | 缺少或不兼容的可选模块不会阻止RandomDay. |
| `external_mods.patch_only_existing_keys` | `true` | 必需的安全锁；如果更改，启动将失败。 |
| `external_mods.backup_before_write` | `true` | 必需的安全锁；如果更改，启动将失败。 |
| `external_mods.adapters` | 四个公共适配器 ID | 限制RandomDay-owned适配器可以运行。 |

从列表中删除适配器 ID，以保留该集成，而无需禁用或卸载第三方 mod。 singleplayer/LAN 软件包会禁用每个适配器，无论此列表如何。

`external_mods.optional_by_default=false` 使配置的适配器结果不同于 `applied` 或 `already_current` 聚合适配器结果失败。它不会使主沙箱事务回滚。保留已发货`true`除非运营商有经过测试的理由需要集成。

请参阅[支持的 Mod 适配器](%E6%94%AF%E6%8C%81%E7%9A%84%E9%80%82%E9%85%8D%E5%99%A8.md)用于识别的布局和六种可能的结果。

<a id="optional-chaotic-spawn-engine-scope-fields"></a>
### 可选的混沌生成引擎范围字段

`world_scope`仅当已识别的混沌生成引擎RandomDay扩展设置`DynamicSpawns/SharedData.lua` 布局已包含这些字段。这不是一个单独的模组或下载：

| 设置 | 运送值 | 适配器效果 |
|---|---:|---|
| `world_scope.enabled` | `true` | 在已识别的混沌生成引擎内请求可选的RandomDay世界范围门时，才提供五个可选的DynamicSpawns 布局。 |
| `world_scope.affect_open_worlds` | `true` | 包括开放世界，除非目标模组应用了受保护世界规则。 |
| `world_scope.unknown_world_policy` | `allow` | 请求`allow` 或 `block` 当目标 mod 无法对世界进行分类时。 |
| `world_scope.log_scope_decisions` | `true` | 请求 target-mod 记录其范围决策。 |
| `world_scope.protected_worlds` | 空列表 | 向目标布局提供逗号分隔的受保护世界模式。 |

这些值是适配器输入，而不是由 RandomDay's沙箱编写器。仅当单独安装的 Chaotic Spawn Engine 布局已包含完整的可选RandomDay字段集和报告`applied` 或 `already_current`。 Chaotic Spawn Engine 仍然负责在运行时使用这些字段。没有扩展字段的普通安装保持不变。

所有五个值都是适配器输入。 `unknown_world_policy` 仅接受记录的目标值 `allow` 或 `block`;跳过无法识别的目标布局。保留`protected_worlds` 文档示例中为空。如果操作员使用本地模式，则它们不得包含在屏幕截图、问题或发布工件中。

<a id="player-messages"></a>
## 玩家消息

附带的专用服务器配置可实现紧凑的加入通知和较短的每日线路。它在第一次通过之前等待 30 秒，每 15 秒检查一次新加入的玩家，并在每日线路之前的加入通知后等待 10 秒。

| 设置 | 运送值 |
|---|---:|
| `player_message.enabled` | `true` |
| `player_message.log_on_startup` | `true` |
| `player_message.register_console_command` | `false` |
| `player_message.console_command` | `randomday` |
| `player_message.broadcast_enabled` | `true` |
| `player_message.startup_delay_ms` | `30000` |
| `player_message.join_check_interval_ms` | `15000` |
| `player_message.send_daily_joke_after_join` | `true` |
| `player_message.daily_joke_delay_seconds` | `10` |
| `player_message.criticality_join` | `2` |
| `player_message.criticality_joke` | `0` |
| `player_message.max_line_chars` | `42` |
| `player_message.max_join_lines` | `4` |
| `player_message.max_warning_lines` | `3` |
| `player_message.max_note_lines` | `3` |

消息长度验证检查源限制。它不会取代对每个客户端分辨率的视觉测试。

计时值是解释为毫秒的非负数，`daily_joke_delay_seconds`时，它们才会生效。禁用的消息或广播设置会抑制客户端通知，而无需更改沙箱准备工作。仅当设置和 UE4SS 处理程序都可用时，才会注册控制台命令。将关键性值保留在已发布的传输级别，除非指定的客户端测试证明了另一个值。

`max_line_chars` 被翻译器限制为 8 到 64 个字符。三种行数设置分别限制连接、警告和注释输出；提供的值与可用源代码行的数量相匹配。将这四个限制保留为默认值，除非客户端布局测试证明设置更窄。

禁用消息的示例：

```lua
player_message = {
    enabled = false,
    log_on_startup = true,
    register_console_command = false,
    console_command = "randomday",
    broadcast_enabled = false,
    startup_delay_ms = 30000,
    join_check_interval_ms = 15000,
    send_daily_joke_after_join = false,
    daily_joke_delay_seconds = 10,
    criticality_join = 2,
    criticality_joke = 0,
    max_line_chars = 42,
    max_join_lines = 4,
    max_warning_lines = 3,
    max_note_lines = 3,
}
```

<a id="profiles-and-sandbox-values"></a>
## 配置文件和沙箱值

`RandomDay/Scripts/ax_profiles/families/`下的家庭源文件定义每个家庭 17 个完整天。 `docs/profiles/` 下生成的文档是参考输出，而不是自定义源。

暂时使用[沙箱密钥引用](%E5%89%96%E9%9D%A2/%E6%B2%99%E7%AE%B1%E8%AE%BE%E7%BD%AE%E9%94%AE.md)（用于类型、范围、附带的配置文件默认值和剩余不变值）时，它们才会生效。编辑配置文件源后，重新生成并验证所有 289 种组合；不要修补生成的 Markdown 或 JSON 记录。

<a id="customize-the-shipped-profile-defaults"></a>
### 自定义已发布的配置文件默认值

打开：

```text
RandomDay/Scripts/ax_config/server.lua
```

在 `sandbox`:

```lua
profile_overrides = {
    HardcoreMode = false,
    AllowIronMode = false,
    StructuralSupportLimit = 0,
    BridgeSupports = 0,
}
```

这些是 RandomDay's 起始选项，而不是不可更改的 Abiotic Factor 规则。将任一模式设置为`true` 或 `false`。将每个支持值设置为 `0`到`1000` 中的整数。在编辑文件之前停止游戏或专用服务器，保存它，然后重新启动，以便 Lua 加载新配置。

RandomDay 每当在一个系列中构建 17 个配置文件时都会读取此块。因此，所选值适用于每个家庭和每一天，包括轮换后准备的配置文件以及稍后服务器启动后重建的配置文件。您无需编辑 289 个配置文件或重新生成配置文件引用。

仅更改实时`SandboxSettings.ini`是暂时的，因为下一个准备好的配置文件是从`server.lua`生成的。无效类型、未知键或外部支持值`0..1000`会因指定配置错误而停止配置文件构建，而不是默默地恢复为默认值。

生成的配置文件引用继续显示已发布的默认值。它是一个版本参考，而不是一台服务器私有配置的副本。
