# 支持的可选模组

> **规范的英文来源:** [SUPPORTED_ADAPTERS.md](../../SUPPORTED_ADAPTERS.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


RandomDay可以使单独安装的模组遵循活动的RandomDay配置文件。此功能仅在专用服务器包中可用。 singleplayer/LAN 软件包永远不会编辑其他模组。

RandomDay 不包含或重新分发此处列出的任何模组。从其自己的 Nexus 页面安装并启用每个可选模组，并首先遵循其作者的说明。 RandomDay 仅更改已安装文件中已存在的已识别设置。它不会向另一个模组添加功能，并且可以在不卸载该模组的情况下禁用适配器。专用服务器包从`external_mods.enabled = true`.

<a id="what-randomday-changes"></a>
## 更改内容RandomDay开始

| 可选集成 | 从活动配置文件中选择的设置 |
| --- | --- |
| 混沌生成引擎/DynamicSpawns | 困难模式，player/area 冷却行为、风暴和热区活动、Boss 和爆发生成、生成周期计时、小和大冷却范围、生成距离，global/local/mod 上限、传送门风暴、违反秩序和 Boss 机会，以及每个区域的最小生成次数。 |
| 可选的混沌生成引擎扩展字段 | 安装时`SharedData.lua`已经包含RandomDay扩展字段，适配器可以提供遭遇配置文件、等级、主题、组限制、特殊事件和混合遭遇值、预算、冷却时间和世界范围控制。这不是另一个需要下载的模组。 |
| 致命激光 | Mod 激活加上伤害并启用对可部署发射器、环境发射器、反射器和棱镜的控制。 |
| ANTE向上 | 重生频率乘数、前变频率和现有development/debug 开关。 RandomDay关闭所有已识别的开发和调试开关。 |

配置文件库为每个受支持的日期提供准备好的值集。安静的一天可以减轻压力，危险的一天可以增加压力，恢复的一天可以急剧减少压力。 RandomDay 启动时不计算任意值；它应用由活动配置文件命名的审核值集。

<a id="how-recognition-protects-another-mod"></a>
## 识别如何保护另一个模组

仅找到熟悉的文件名是不够的。RandomDay会检查目标文件中是否存在该适配器所需的所有设置；它不会创建缺失的设置。

对于已识别的布局，RandomDay会执行一个有界事务：

1. 计算活动配置文件的每个预期值；
2. 创建并字节检查每个目标文件的备份；
3. 通过同级挂起文件写入；
4. 提升挂起的文件并读回保存的字节；
5. 确认每个预期值；
6. 如果任何步骤失败，请使用经过验证的备份自动恢复。

DynamicSpawns 可以在一次事务中包含其设置和已识别的玩家消息文件。 RandomDay除非整个事务完成，否则不会报告多文件更新成功。

<a id="read-an-adapter-result"></a>
## 读取适配器结果

| 结果 | 含义 |
| --- | --- |
| `applied` | 已识别的设置已更改并通过回读。 |
| `already_current` | 已识别的设置已与活动配置文件匹配。 |
| `not_installed` | 未找到可选模组。 RandomDay没有它继续。 |
| `skipped_incompatible` | 已找到文件，但无法识别其完整设置布局。没有任何改变。 |
| `partial` | 主要DynamicSpawns设置已应用，但可选的翻译消息文件未完成。查看记录的适配器结果。 |
| `failed_rolled_back` | 事务失败，之前的字节保持不变或已恢复并验证。 |
| `rollback_failed` | RandomDay无法验证更改或恢复。让受影响的模组保持停止状态并手动恢复其记录的备份。 |

丢失和不兼容的可选模组不会停止RandomDay's在交付的配置下进行沙箱轮换。

<a id="enable-or-disable-integrations"></a>
## 启用或禁用集成

控件位于：

```text
RandomDay/Scripts/ax_config/server.lua
```

专用服务器包附带：

```lua
external_mods = {
    enabled = true,
    optional_by_default = true,
    patch_only_existing_keys = true,
    backup_before_write = true,
    adapters = {
        "lethal_lasers",
        "dynamic_spawns",
        "encounter_director",
        "ante_up"
    }
}
```

- 设置 `enabled = false`阻止RandomDay检查或更改每个可选模组。
- 删除一个适配器 ID 以保留该模组，同时保持其他集成处于活动状态。
- 保留 `patch_only_existing_keys` 和 `backup_before_write` 设置为 `true`。它们是写入安全边界。
- 保留 `optional_by_default = true`除非每个列出的可选模块都是服务器的必需部分。将其设置为 `false` 会使丢失、不兼容或安全回滚的适配器影响聚合结果。

您不必卸载或更改当您禁用可选模组时，该模组也会被禁用。RandomDay 适配器。

<a id="backups-and-manual-recovery"></a>
## 备份和手动恢复

验证的预写副本保留在：

```text
RandomDay/runtime/backups/external_<transaction>_<adapter>/
```

如果`rollback_failed`出现：

1. 停止游戏或服务器；
2. 设置`external_mods.enabled = false`，或删除受影响的适配器 ID；
3. 保留当前目标文件及其同级pending/rollback文件；
4. 将编号的备份文件与适配器结果中记录的目标路径进行匹配；
5. 在服务停止时恢复已验证的字节；
6. 在重新启用其之前自行启动可选模组RandomDay 适配器。

不要通过重命名设置或添加缺失的键来强制兼容。在扩展支持声明之前，使用可识别的布局、禁用适配器或添加新版本固定装置和事务测试。
