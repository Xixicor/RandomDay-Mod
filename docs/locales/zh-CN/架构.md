<a id="architecture-and-data-flow"></a>
# 架构和数据。 Flow

> **规范的英文来源:** [ARCHITECTURE.md](../../ARCHITECTURE.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


RandomDay 拥有一项有界作业：为将来的启动准备完整的沙箱配置文件，而无需将该配置文件描述为在当前进程中处于活动状态。活动配置文件来自 Abiotic Factor 之前加载的沙箱文件中的标记UE4SS开始RandomDay。准备好的配置文件是一个单独的、经过验证的文件状态，供下次重新启动使用。

<a id="package-modes"></a>
## 打包模式

发布构建器从相同的源白名单中生成两个 ZIP，并在每个 ZIP 中进行不同的设置`RandomDay/.randomday_mode`。

| 模式 | 主要输出 | 自动外部写入 |
|---|---|---|
| `dedicated_server` | 已解决专用服务器`SandboxSettings.ini` | 主沙箱、特意配置的镜像以及可识别的可选适配器。 |
| `singleplayer_manual` | `RandomDay/runtime/singleplayer_manual/SandboxSettings.ini` | 没有任何外部 RandomDay 文件夹；镜子和适配器被禁用。 |

`RandomDay/.randomday_version` 和 `RandomDay/.randomday_mode` 是生成的包标记。 `RandomDay/Scripts/ax_core/version.lua` 读取它们；安装后操作员不得编辑它们。

<a id="session-modes"></a>
## 会话模式

打包模式控制位置RandomDay 可以写入。 `experience.mode`单独描述了预期的生命周期：

| 会话模式 | 套餐 | 生命周期合同 |
|---|---|---|
| `persistent_dedicated` | 专用 | 长期恢复持久的系列和 17 位置日订单重新启动。 |
| `temporary_dedicated` | 专用 | 将每次启动视为有界游戏会话，同时保留启动之间的排队顺序。 |
| `singleplayer_lan` | 单人游戏手册 | 为操作员选择的世界生成 mod-local 文件；没有保存发现或自动复制。 |

`auto`解析为专用包中的`persistent_dedicated`并且`singleplayer_lan` 在手册包中。会话模式不会改变引擎边界：当前进程之前已经加载了其沙箱RandomDay 执行。

<a id="startup-path"></a>
## 启动路径

1. UE4SS 加载 `RandomDay/Scripts/main.lua`.
2. 入口点解析一个`RandomDay/`根目录并加载`Scripts/ax_core/init.lua`.
3. `init.lua`加载配置、配置文件、日历、编写器、适配器、状态、网络导出和玩家消息模块。它拒绝无效的包模式或禁用的事务安全锁。它还验证包兼容的会话模式、开始日模式、配置的开始日和日进度模式。
4. 每个系列构建都会验证`sandbox.profile_overrides`从`Scripts/ax_config/server.lua`。四个配置文件范围的选择在 family/day 值之后和其余不变规则之前应用，因此每个准备好的配置文件都使用相同的配置选择。
5. 运行时和 Web 输出根锚定到已解析的 mod 文件夹。单人游戏模式在选择之前会减少为一个 mod-local 输出。
6. `ax_cycle/calendar.lua`读取沙盒标记和可恢复的旋转状态，然后为此游戏过程创建一个active/prepared决策。
7. `ax_sandbox/writer.lua`序列化并验证准备好的配置文件，然后对选定的目标使用事务替换。
8. 只有在以下情况下才会提交旋转状态沙盒交易成功。状态提交失败会降级：适配器和准备好的播放器消息传递会被跳过，因为沙箱和队列状态不一致。
9. 在专用模式下，`ax_external/bridge.lua`根据活动配置文件评估可选适配器。在第一次引导期间，不存在活动标记，因此准备好的 configured/random 开始日配置文件是唯一可用的适配器映射。
10. 运行时 JSON/text 状态和 HTML/JSON Web 视图根据同一决策重写。播放器通知最后安装。

默认`cycle.check_interval_ms=0` 在启动时运行此序列一次。如果运算符提供正区间并且 UE4SS 公开 `LoopAsync`，稍后的回调重用进程拥有的选择。他们可以修复或重新导出该选择，但不要在同一过程中选择另一天。

<a id="rotation-state-machine"></a>
## 轮换状态机

| 选择状态 | 输入条件 | 准备好的结果 | 安全恢复 |
|---|---|---|---|
| `bootstrap_prepare_first_family_start_day` | 没有活动标记，也没有可恢复的准备状态。 | 在新持久的日订单中配置或随机选择第一个位置。 | 保持现有会话运行； `prepared_ready=true`. |
| `active_marker_found_family_locked_prepare_next_day` | 活跃日不是存储顺序中的最后一个位置。 | 同一系列中的下一个存储位置。 | 如果持久性失败，请保持服务器停止并协调沙箱和轮换状态。 |
| `active_marker_found_completed_run_prepare_next_unused_family` | 活跃日是存储顺序中的最后一个位置。 | 下一次符合条件的家庭运行中新订单的第一个位置。 | 在重新启动之前确认新的family/day/order。 |
| `state_recovery_rewrite_prepared_profile_no_reroll` | 没有活动标记，但轮换状态会命名准备好的配置文件。 | 重建相同的排队配置文件。 | 保留状态文件；不要删除它们来强制重新滚动。 |
| `supervision_reconfirm_prepared_profile_no_advance` | 稍后的回调在同一进程中运行。 | 相同的准备好的配置文件。 | 诊断第一个失败阶段；重复回调不是新选择。 |

`selected_run`始终使用`selected_family`. `rotation_run`消耗配置的合格订单。 `non_repeating_random_run` 从剩余的符合条件的家庭中进行选择，并在所有家庭完成后启动一个新的池。每种模式都会保留一个家庭，直到完成 `day_order` 中的所有 17 个唯一日期 ID。当配置的开始不是第 1 天时，顺序模式会在第 17 天后回绕；非重复随机模式存储一种排列，并且在恢复期间不会重新滚动它。

<a id="sandbox-transaction"></a>
## 沙箱事务

写入器按规范顺序呈现所有密钥，并在写入之前验证类型、范围、固定规则、标记值和配置文件身份。然后替换遵循以下顺序：

1. 仅在安全时才删除过时的待处理文件；
2. 保留或停止预先存在的恢复 sidecar；
3. 写入待处理字节；
4. 读回待处理文件并验证它；
5. 创建经过验证的文件当目标存在时进行操作备份；
6. 保留原始文件作为事务回滚文件；
7. 提升待处理文件；
8. 读取并验证生产文件；
9. 如果提升或生产验证失败，则恢复保留的原始文件；
10. 保留恢复数据，如果清理无法完成则报告失败进行验证。

首次写入使用相同的pending/readback/validation路径。如果没有原始目标，则无法恢复任何内容，因此首次写入失败不得报告为原始文件恢复。

<a id="adapter-boundary"></a>
## 适配器边界

适配器是 RandomDay-owned单独安装的 mod 的修补程序定义。该桥首先需要一个可识别的目标路径和完整的密钥签名。它仅修补现有分配，创建操作备份，将每个计划文件作为一个事务应用，并在任何步骤失败时回滚所有受影响的目标。缺失和不兼容的目标是正常的可选结果。

RandomDay 不会将第三方代码加载到其包中。夹具支持的布局证明了RandomDay's解析器和事务行为，而不是第三方版本在游戏进程中加载​​或使用这些值。

<a id="output-boundary"></a>
## 输出边界

运行时文件在下面生成`RandomDay/runtime/` 和 `RandomDay/web_export/`;没有一个是发布ZIP 输入。状态编写器从公共中删除计算机本地适配器路径JSON诊断。完整的路径、架构、节奏和保留图位于[运行时文件和状态](%E8%BF%90%E8%A1%8C%E6%97%B6%E6%96%87%E4%BB%B6.md).

<a id="failure-ownership"></a>
## 失败所有权

| 阶段失败 | 所有者可见的后果 |
|---|---|
| 个人资料或 INI验证 | 未尝试进行生产写入。 |
| 待处理 write/readback | 现有的生产字节保持不变。 |
| 操作备份 | 在移动原始数据之前替换停止。 |
| 促销或生产验证 | 尝试自动恢复并报告其结果。 |
| 旋转状态持久性 | 准备好的沙箱字节可能存在，但转换已降级并且adapters/messages 被跳过。 |
| 适配器兼容性 | 目标保持不变 `not_installed` 或 `skipped_incompatible`. |
| 适配器write/readback | 尽可能恢复所有更改的适配器目标。 |
| 状态或 Web 导出 | 沙箱结果保持权威；输出失败会被记录下来，并且不能被视为成功的报告。 |

按照[操作](%E6%93%8D%E4%BD%9C.md)进行恢复，[疑难解答](%E7%96%91%E9%9A%BE%E8%A7%A3%E7%AD%94.md)进行症状优先检查。

<a id="evidence-limit"></a>
## 证据限制

本地 Lua 固定套件可以证明源行为、生成的配置文件不变量、事务分支、输出形状和包边界。它并不能证明当前的非生物因子构建，当前的UE4SS 版本、特定服务器面板、每种显示尺寸或未经测试的第三方 mod 版本。这些主张仍然`not tested`，直到记录指定的兼容性运行。
