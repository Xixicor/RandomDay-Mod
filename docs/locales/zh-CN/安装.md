# 安装、更新或删除RandomDay

> **规范的英文来源:** [INSTALL.md](../../../INSTALL.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


RandomDay 有两个完整的下载。为您正在设置的世界选择一个：

- 使用**专用服务器ZIP**适用于任何专用服务器，包括仅针对偶尔会话打开的服务器；
- 使用**singleplayer/LAN ZIP**适用于您将手动复制其设置的本地世界。

不要合并软件包。持久或临时专用服务器是一个选择 RandomDay's设置，而不是不同的下载。

<a id="before-you-begin"></a>
## 开始之前

制作以下内容的可恢复副本：

- 您正在改变的世界；
- 其当前`SandboxSettings.ini`;
- 现有`RandomDay` 文件夹（如果已安装）。

安装UE4SS 之前 RandomDay。在下面的说明中，**Mods 文件夹**表示`ue4ss/Mods/`目录。

<a id="dedicated-server"></a>
## 专用服务器

<a id="new-installation"></a>
### 新安装

1. 停止服务器。
2. 打开它UE4SS `Mods` 文件夹。
3. 提取专用服务器ZIP。结果应该是一个 `ue4ss/Mods/RandomDay/` 文件夹，而不是另一个文件夹内的文件夹`RandomDay` 文件夹。
4. 打开该文件夹并确认`RandomDay/Scripts/main.lua` 存在。如果缺少，则ZIP 被提取到错误的级别。
5. 在已安装的 mod 文件夹中打开 UE4SS `mods.txt` 并启用此行：

   ```text
   RandomDay : 1
   ```

6. 正常启动服务器。
7. 在已安装的 mod 文件夹中打开 RandomDay's可读状态页面，并确认其命名了活动配置文件和为下次启动准备的配置文件。

首次启动不会替换该会话已加载的规则。它准备下一个配置文件。仅当您确实希望准备好的配置文件处于活动状态时才再次启动服务器。

[检查第一个周期](%E4%BB%8E%E8%BF%99%E9%87%8C%E5%BC%80%E5%A7%8B.md)

<a id="choose-always-on-or-temporary-behavior"></a>
### 选择始终开启或临时行为

专用服务器包支持两种样式：

- **持久专用**恢复正常重启期间保存的轮换；
- **临时专用**可以在新的临时运行开始时从配置的或随机的起点开始。

在[配置](%E9%85%8D%E7%BD%AE.md)中选择行为。请勿安装第二个软件包来更改此设置。

<a id="update-an-existing-installation"></a>
### 更新现有安装

1. 停止服务器并进行设置。上面列出的备份。
2. 将旧的 `RandomDay` 文件夹移出 UE4SS `Mods` 文件夹。保留该文件夹直至更新成功完成一个周期。
3. 提取新的专用服务器ZIP 进入 `Mods` 文件夹。
4. 仅重新应用您有意更改且仍存在于新版[配置指南](%E9%85%8D%E7%BD%AE.md).
5. 仅当发行说明表明其格式兼容时才保留记录的旋转状态文件。请勿将旧的临时输出或写入失败的文件复制到新安装中。
6. 确认`RandomDay : 1` 仍处于启用状态，然后启动服务器一次并检查活动的和准备好的配置文件名称。

<a id="updating-from-v0315-alpha"></a>
### 更新自 v0.3.15-alpha

`RandomDay_v0.3.15-alpha.zip` 是旧的基础包。 `RandomDay_v0.3.15-alpha_singleplayer_patch.zip` 是一个叠加层，不是独立下载。

当前`v0.3.16-alpha` 用两个完整的包替换了历史上的基础和覆盖安排。不要将旧补丁放在任何一个包上。当前标记为 `.randomday_mode=dedicated_server` 和 `.randomday_mode=singleplayer_manual`.

<a id="singleplayer-or-lan"></a>
## 单人游戏或 LAN

singleplayer/LAN 包创建一个设置文件；它本身不会搜索或更改个人保存。

1. 关闭游戏。
2. 备份世界及其当前`SandboxSettings.ini`.
3. 提取singleplayer/LAN ZIP进入游戏UE4SS `Mods` 文件夹如此一个 `Mods/RandomDay/` 文件夹存在。
4. 启用`RandomDay : 1` 在 UE4SS `mods.txt`.
5. 启动游戏一次，等待RandomDay 完成，并完全关闭游戏。
6. 查找生成的`SandboxSettings.ini` 在 RandomDay's `runtime/singleplayer_manual/` 文件夹。
7. 阅读生成的摘要，然后将文件复制到您选择的世界中。
8. 启动该世界并检查预期的沙箱行为是否处于活动状态。

LAN 使用相同的手动过程，因为主机拥有本地世界。该模组不会自动选择世界或覆盖世界。

[单人游戏和 LAN指南](%E5%8D%95%E4%BA%BA%E5%B1%80%E5%9F%9F%E7%BD%91.md)

<a id="remove-or-disable-randomday"></a>
## 删除或禁用RandomDay

1. 停止游戏或服务器。
2. 备份世界及其当前沙箱设置，以及RandomDay's状态的设置。
3. 设置 `RandomDay : 0` 在 UE4SS `mods.txt` 以禁用该模组，或将整个 `RandomDay` 文件夹移出 `Mods` 文件夹以将其删除。
4. 决定下次启动时应加载哪个 `SandboxSettings.ini` 应在下次启动时加载。如果您不需要当前准备的副本，请恢复您的预安装副本RandomDay个人资料。
5. 在删除任何内容之前启动世界并确认其规则。备份。

禁用RandomDay 停止将来的配置文件准备。它不会重写已经在磁盘上等待的沙箱文件。

<a id="recover-from-an-unsuccessful-update"></a>
## 从不成功的更新中恢复

在第一次明确失败后停止。重复重新启动可能会导致更难查看哪个配置文件处于活动状态以及哪个配置文件正在等待。

1. 停止游戏或服务器。
2. 移动将不成功的安装放在一边，而不删除它。
3. 恢复完整RandomDay更新前制作的文件夹和沙箱备份。
4. 启动一次并确认恢复的活动和准备的配置文件名称。
5. 暂时使用[疑难解答](%E7%96%91%E9%9A%BE%E8%A7%A3%E7%AD%94.md)尝试其他更新之前先执行第一个缺失或失败的步骤。
