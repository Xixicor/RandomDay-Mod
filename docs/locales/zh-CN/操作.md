# 操作活动、准备和恢复状态

> **规范的英文来源:** [OPERATIONS.md](../../OPERATIONS.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


RandomDay更改将来启动的沙箱文件。

此页面拥有操作员决策和恢复过程。使用 [词汇表](%E8%AF%8D%E6%B1%87%E8%A1%A8.md) 获取规范术语，使用 [ 运行时文件](%E8%BF%90%E8%A1%8C%E6%97%B6%E6%96%87%E4%BB%B6.md) 获取路径所有权，使用 [运行时输出](%E8%BF%90%E8%A1%8C%E6%97%B6%E8%BE%93%E5%87%BA.md) 获取确切的架构和字段含义。

<a id="distinguish-active-and-prepared-state"></a>
## 区分活动状态和准备状态

准备好的配置文件直到稍后的启动读取其标记才处于活动状态。不要使用准备好的 family/day 来描述当前会话。

暂时使用`web_export/today.html` 获取可读的摘要，`web_export/today.json` 获取准确的状态。在决定重新启动之前，请确认活动标记、准备好的身份、`prepared_ready`, `profile_status`、事务结果、回滚结果和状态提交结果。

<a id="follow-the-normal-dedicated-server-sequence"></a>
## 遵循正常的专用服务器顺序

| 之前 | 行动 | 之后 |
|---|---|---|
| 否 RandomDay标记 | 从启用RandomDay开始。 | 当前会话保留其现有规则；RandomDay 创建并保留每日订单，然后准备第一个 configured/random 仓位。 |
| 第一个位置已准备好 | 重新启动。 | 该日生效；同族中的下一个存储位置已准备好。 |
| 中间位置有效 | 查看准备好的配置文件后重新启动。 | 已准备的日期变为活动状态，并已准备好以下存储的位置。 |
| 最终头寸有效 | 查看下一个系列后重新启动。 | 另一个符合条件的家庭订单的第一个位置变为有效。 |

`selected_run` 保留配置的系列。 `non_repeating_random_run` 在所有 17 天的职位中保留随机选择的系列，并避免重复使用某个系列，直到符合条件的列表用完为止。 `rotation_run` 遵循配置的系列顺序。 `cycle.day_progression_mode` 独立于家庭选择控制日顺序。

全新安装始终需要一个过程来准备，并需要一个后续过程来激活。对于持久服务器、临时服务器和手动服务器都是如此singleplayer/LAN一代。

<a id="read-the-right-evidence"></a>
## 阅读正确的证据

使用[运行时文件映射](%E8%BF%90%E8%A1%8C%E6%97%B6%E6%96%87%E4%BB%B6.md) 定位旋转状态、当前状态、最后已知状态每个字段组、架构、空状态、失败含义和保留规则的文件、操作备份、导出和`UE4SS.log`中选择广泛的游戏风格。当您需要精确的游戏玩法和沙盒值时，请使用[运行时输出参考](%E8%BF%90%E8%A1%8C%E6%97%B6%E8%BE%93%E5%87%BA.md)。规范六状态结果表和下一步操作的HTML 和 JSON 导出汇总源状态；它们不能证明配置文件已被实时游戏客户端使用。

如果`prepared_ready`为`false` 或 `profile_status`为`degraded_state_persistence`，保持服务器停止，直到沙箱和旋转状态一致。具有失败状态持久性的有效沙箱写入不是一个健康的准备好的转换。

<a id="respond-to-writer-outcomes"></a>
## 回应作者的成果

RandomDay在同级文件中准备新字节，读回它们，验证完整的沙箱，保留原始文件（如果存在），升级新文件，然后再次读回。仅在生产回读同意后才报告就绪。

如果升级或生产验证失败，RandomDay将尝试恢复该操作持有的文件。恢复失败是硬停止：保持服务器停止并手动恢复，而不是反复重新启动。

<a id="respond-to-adapter-outcomes"></a>
## 响应适配器结果

暂时使用[支持的适配器](%E6%94%AF%E6%8C%81%E7%9A%84%E9%80%82%E9%85%8D%E5%99%A8.md#read-an-adapter-result)。对待`rollback_failed` 视为硬停止；单独记录的适配器备份是恢复源。

适配器仅影响单独安装的 mod。他们从不激活准备好的 RandomDay 沙箱配置文件。

在正常启动时，将从活动配置文件中选择适配器值，因为单独安装的 mod 可能稍后会在同一 UE4SS 启动中加载。在第一次引导期间，当不存在活动的 RandomDay 标记时，准备好的开始日配置文件是唯一可用的映射。此计时规则与下次重新启动沙箱边界无关，并且仍然取决于其他 mod 自身的加载行为。

<a id="manual-recovery"></a>
## 手动恢复

1. 停止游戏或服务器。请勿恢复打开的文件。
2. 将当前的 `SandboxSettings.ini`, `runtime/` 和 `web_export/` 复制到单独的诊断备份。
3. 检查 `runtime/last_good/manifest.lua` 以及 `runtime/backups/` 下的最新相关条目。选择一个文件，其family/day和哈希值与您要恢复的状态匹配。
4. 将选定的已验证文件复制到配置的主沙箱路径。
5. 在开始之前读回并确认其已完成。
6. 启动一次并检查活动标记和准备状态。不要仅仅因为没有错误消息就认为恢复成功。

如果不存在经过验证的备份，请恢复安装前创建的操作员备份。 RandomDay无法重建无法读取的文件。

<a id="account-for-control-panel-writes"></a>
## 控制面板写入的帐户

某些服务器面板会生成`SandboxSettings.ini`在启动期间。 RandomDay 如果在验证写入后另一个工具覆盖了准备好的配置文件，则无法保留该配置文件。配置一个权威沙箱源，并在诊断重复的第 1 天或丢失转换时在重新启动之前和之后立即检查文件标记。
