# இயக்க நேர கோப்புகள் மற்றும் நிலையைக் கண்டறிக

> **நியாய ஆங்கில மூல:** [RUNTIME_FILES.md](../../RUNTIME_FILES.md). இந்த உள்ளூர்மயமாக்கப்பட்ட ஆவணம் சரியான கட்டளைகள், பாதைகள், விசைகள், நிலை மதிப்புகள், ஹாஷ்கள் மற்றும் கோப்பு பெயர்களைப் பாதுகாக்கிறது. தொழில்நுட்ப வார்த்தைகள் வேறுபட்டால், ஆங்கில மூலத்தைப் பயன்படுத்தவும்.


இது ஆபரேட்டர்கள் மற்றும் மூல கண்டுபிடிப்புகளால் பயன்படுத்தப்படும் கேனானிகல் பாதை இருப்பு ஆகும். ஒரு கோப்பு எங்கே உள்ளது, யார் அதை எழுதுகிறார்கள், அது எப்போது மாறுகிறது, அது எவ்வளவு காலம் இருக்கும், எந்த மீட்புப் பாத்திரத்தை வழங்குகிறது. தி [இயக்க நேர வெளியீட்டு குறிப்பு](%E0%AE%87%E0%AE%AF%E0%AE%95%E0%AF%8D%E0%AE%95_%E0%AE%A8%E0%AF%87%E0%AE%B0_%E0%AE%B5%E0%AF%86%E0%AE%B3%E0%AE%BF%E0%AE%AF%E0%AF%80%E0%AE%9F%E0%AF%81%E0%AE%95%E0%AE%B3%E0%AF%8D.md) ஸ்கீமாக்கள், புல அர்த்தங்கள், வெற்று நிலைகள் மற்றும் இயந்திர மதிப்பு விளக்கம் ஆகியவற்றைக் கொண்டுள்ளது.

இந்த வழிகாட்டியில் உள்ள அனைத்து பாதைகளும் நிறுவப்பட்டவற்றுடன் தொடர்புடையவை `RandomDay/` கோப்புறை. நிறுவிய பின் இயக்க நேர வெளியீடுகள் உருவாக்கப்படுகின்றன; அவை ரிலீஸ் ஜிப்களில் இருந்து விலக்கப்பட்டுள்ளன.

### வெற்று மற்றும் தோல்வியடைந்த கோப்பு நிலைகளை அங்கீகரிக்கவும்

- விடுபட்ட முதன்மை அல்லது கண்ணாடி இலக்கு உருவாக்கப்படலாம். தவறான சுயவிவரம், நிலுவையில் உள்ள எழுதுதல், பதவி உயர்வு அல்லது தயாரிப்பை மீண்டும் பெறுவதில் தோல்வி தயாராக இல்லை. ஒரு கண்ணாடி தோல்வி ஏற்றுக்கொள்ளப்பட்ட முதன்மை முடிவை மாற்றாது.
- `runtime/singleplayer_manual/SandboxSettings.ini` உருவாக்கப்படலாம். நிலை மற்றும் பதிவு வெளியீட்டில் ஒரு தலைமுறை தோல்வி தெரியும்.
- படிக்க முடியாதது `rotation_state.txt` கடைசி-நல்ல நிலை அல்லது மார்க்கர் அடிப்படையிலான பூட்ஸ்ட்ராப்புக்கு திரும்பலாம். ஒரு தோல்வியுற்ற நிலை `degraded_state_persistence`.
- `runtime/last_good/` இல்லாமல் இருக்கலாம். இணைக்கப்பட்ட மேனிஃபெஸ்ட் புதுப்பிப்பு தோல்வியுற்றால், RandomDay முந்தைய ஏற்றுக்கொள்ளப்பட்ட ஜோடியை மீட்டமைக்கிறது.
- `runtime/backups/mirror_<operation>/` என்பது கண்ணாடி-குறிப்பிட்ட காப்புப்பிரதி இடம். பரிவர்த்தனைக்கு முன் அந்த இலக்கு இல்லாதபோது முதன்மை அல்லது பிரதிபலிப்பு காப்பு கோப்பு எதுவும் இல்லை.
- அடாப்டர் பிறழ்வு அதன் காப்பு உருவாக்கம் அல்லது ரீட்பேக் தோல்வியடையும் போது தொடங்காது.
- இயக்க நேர நிலை வெளியீடு கிடைக்காதபோது அல்லது முழுமையடையாமல் இருக்கும் போது தற்போதைய நிலை, அகராதி அல்லது மாதிரிக்காட்சி கோப்புகள் இல்லாமல் இருக்கலாம்.
- ஒரு `export_failed` முடிவு பழையதாக இருக்கலாம் `today.json` இடத்தில். சாண்ட்பாக்ஸ் தோல்வி புதுப்பிப்புகள் JSON ஆனால் புதிய தோல்வியை உருவாக்காது HTML பக்கம்; நேர முத்திரைகளை `UE4SS.log`.
- புதிய முயற்சிக்கு முன், நிலுவையில் உள்ள பழைய பக்க கார் அகற்றப்பட்டது; துப்புரவு தோல்வி பரிவர்த்தனையை நிறுத்துகிறது. உற்பத்தி இலக்கு மற்றும் ரோல்பேக் சைட்கார் இரண்டும் இருந்தால், RandomDay மீட்டெடுப்பு பைட்டுகளை மதிப்பாய்வுக்காகப் பாதுகாக்கிறது.
- இல்லை `[RandomDay]` தொடக்க வரி `UE4SS.log` என்றால் மோட் ஏற்றுதல் நிரூபிக்கப்படவில்லை.

<a id="transaction-sidecars"></a>
## பரிவர்த்தனை பக்க கார்கள்

பரிவர்த்தனை எழுத்தாளர் இலக்குக்கு அருகில் உடன்பிறப்பு கோப்புகளை உருவாக்கலாம்:

| முறை | நிலை | ஆப்பரேட்டர் செயல் |
|---|---|---|
| `<target>.randomday.pending` | பதவி உயர்வுக்கு முன் வேட்பாளர் பைட்டுகள். | பொதுவாக பதவி உயர்வு மூலம் அகற்றப்படும். ஒரு தோல்வி நிலுவையில் உள்ள துப்புரவு அல்லது ரீட்பேக் சிக்கலைப் புகாரளித்தால் அதைப் பாதுகாக்கவும். |
| `<target>.randomday.rollback` | மாற்றத்தின் போது வைத்திருக்கும் அசல் பைட்டுகள். | பொதுவாக தோல்வியில் மீட்டெடுக்கப்படும் அல்லது சரிபார்க்கப்பட்ட வெற்றிக்குப் பிறகு அகற்றப்படும். இலக்கு இருக்கும் போது அதை நீக்க வேண்டாம்; அந்த கலவைக்கு மதிப்பாய்வு தேவை. |
| `<target>.randomday.restore.pending` | அடாப்டர் மீட்டமைப்பின் போது கேண்டிடேட் பைட்டுகள். | மீட்டெடுப்பு தோல்வியுற்றால், அடாப்டர் காப்புப்பிரதியுடன் சேமிக்கவும். |
| `<target>.randomday.restore.rollback` | அடாப்டர் மீட்டமைப்பின் போது மீட்டெடுக்கும் பைட்டுகள். | சுத்தப்படுத்துதல் அல்லது மீட்டமைக்கப்படாவிட்டால், பாதிக்கப்பட்ட சேவையைப் பாதுகாத்து நிறுத்தவும். |

இந்த கோப்புகள் பிரத்யேக சாண்ட்பாக்ஸ் அல்லது தனித்தனியாக நிறுவப்பட்ட அடாப்டர் இலக்குக்கு அருகில் இருக்கலாம். அவர்களின் இருப்பு ஒரு பரிவர்த்தனை நிலை, புதிய சுயவிவரம் செயலில் உள்ளது என்பதற்கான ஆதாரம் அல்ல.

## மீட்பு ஆதாரத்தை வைத்திருங்கள்

RandomDay தற்போதைய நிலை, தற்போதைய நிலை, கடைசி-நல்ல நிலை மற்றும் இணையப் பார்வைகளை மேலெழுதுகிறது. இது தனித்துவமான செயல்பாட்டு காப்பு கோப்பகங்களை உருவாக்குகிறது மற்றும் பழையவற்றை நீக்காது. இயங்கும் செயல்முறைக்கு வெளியே தக்கவைப்புக் கொள்கையைத் தேர்வுசெய்யவும், ஆனால் எழுதுதல், மறுபரிசீலனை செய்தல், நிலை அல்லது திரும்பப்பெறுதல் சிக்கல் தீர்க்கப்படாத நிலையில், புதிய மீட்புச் சான்றுகளை ஒருபோதும் நீக்க வேண்டாம்.
