# კონფიგურაცია

> **კანონიკური ინგლისური წყარო:** [CONFIGURATION.md](../../CONFIGURATION.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


მთავარი ოპერატორის კონფიგურაციაა:

```text
RandomDay/Scripts/ax_config/server.lua
```

დააკეთეთ ფაილის სარეზერვო ასლი და შეცვალეთ ერთი სექცია ერთდროულად. ლუა ლოგინები მცირეა `true` და `false`; სტრინგებს სჭირდება ბრჭყალები; სიის ჩანაწერებს მძიმეები სჭირდება. შემდეგი დაწყების შემდეგ წაიკითხეთ სტატუსის გვერდი სხვა ცვლილების შეტანამდე. წყაროდან მომუშავე კონტრიბუტორებს შეუძლიათ გამოიყენონ ცალკე [გამოშვების ვალიდაცია](%E1%B2%92%E1%B2%90%E1%B2%9B%E1%B2%9D%E1%B2%A8%E1%B2%95%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%95%E1%B2%90%E1%B2%9A%E1%B2%98%E1%B2%93%E1%B2%90%E1%B2%AA%E1%B2%98%E1%B2%90.md) ამოწმებს შეცვლილი კონსტრუქციის შეფუთვამდე.

არ დაარედაქტირო ხელით `.randomday_mode`, `.randomday_version`, გენერირებული პროფილის მითითებები, `runtime/` ან `web_export/`. პაკეტის შემქმნელი ფლობს პაკეტის რეჟიმისა და ვერსიის მარკერებს და ამოწმებს, რომ ისინი ეთანხმებიან გამოშვების მეტამონაცემებს.

ქვემოთ ყველა პარამეტრი განსაზღვრულია `RandomDay/Scripts/ax_config/server.lua`. ცხრილები განასხვავებენ რედაქტირებადი პარამეტრებს გამოშვების საკუთრებაში არსებული იდენტურობისა და რეზერვირებული თავსებადობის ველებისგან. ველის არსებობა ლუაში არ ნიშნავს რომ მისი შეცვლა მხარდაჭერილი ქცევაა.

<a id="choose-an-experience"></a>
## აირჩიეთ გამოცდილება

RandomDay აქვს ორი პაკეტი: ერთი ყველა გამოყოფილი სერვერისთვის და ერთი singleplayer/LAN ხელით ასლი. სპეციალურ პაკეტს აქვს ორი ოპერაციული რეჟიმი; ეს რეჟიმები არის პარამეტრები და არა ცალკე ჩამოტვირთვები.

| თქვენი სამყარო | ინსტალაცია | აირჩიეთ ეს ქცევა |
| --- | --- | --- |
| გამოყოფილი სერვერი, რომელიც აგრძელებს ერთი კამპანიის მოძრაობას რუტინული გადატვირთვის დროს | გამოყოფილი სერვერის პაკეტი | `persistent_dedicated` განაახლებს შენახულ საოჯახო და პროფილის შეკვეთას. |
| გამოყოფილი სერვერი გახსნილია მხოლოდ ინდივიდუალური სათამაშო სესიებისთვის | იგივე გამოყოფილი სერვერის პაკეტი | `temporary_dedicated` ინახავს უსაფრთხოდ მომზადებულ შემდეგ პროფილს სესიებს შორის, მაშინ როცა ახალი ოჯახური გაშვება შეიძლება გამოიყენოს კონფიგურირებული ან შემთხვევითი დაწყება. |
| ერთი მოთამაშე ან LAN სამყარო | Singleplayer/LAN პაკეტი | `auto` ირჩევს ხელით ასლის ქცევას; შეაჩერე სამყარო გენერირებული ფაილის კოპირებამდე. |

თუ არ ხართ დარწმუნებული, გამოიყენეთ `auto`. პაკეტი ირჩევს ნორმალურ ქცევას მისი ინსტალაციის ტიპისთვის. აირჩიეთ ფართო თამაშის სტილი [ოჯახის როტაცია](%E1%B2%9D%E1%B2%AF%E1%B2%90%E1%B2%AE%E1%B2%98%E1%B2%A1_%E1%B2%A0%E1%B2%9D%E1%B2%A2%E1%B2%90%E1%B2%AA%E1%B2%98%E1%B2%90.md). გამოიყენეთ [გენერირებული ოჯახის ინდექსი](%E1%B2%9E%E1%B2%A0%E1%B2%9D%E1%B2%A4%E1%B2%98%E1%B2%9A%E1%B2%94%E1%B2%91%E1%B2%98/%E1%B2%9E%E1%B2%A0%E1%B2%9D%E1%B2%A4%E1%B2%98%E1%B2%9A%E1%B2%98%E1%B2%A1_%E1%B2%93%E1%B2%9D%E1%B2%99%E1%B2%A3%E1%B2%9B%E1%B2%94%E1%B2%9C%E1%B2%A2%E1%B2%90%E1%B2%AA%E1%B2%98%E1%B2%90.md) როდესაც გსურთ თამაშის ზუსტი მნიშვნელობები და sandbox. შემდეგ აირჩიეთ პირველი დღე და პროგრესი:

- `start_day_mode="configured"` იწყება `start_day`.
- `start_day_mode="random"` ირჩევს ერთ მოქმედ პირველ დღეს ახალი ოჯახური გაშვების დაწყებისას და აგრძელებს ამ არჩევანს.
- `day_progression_mode="sequential"` ახვევს 17-ვე პოზიციას.
- `day_progression_mode="non_repeating_random"` ინახავს ერთ შერეულ შეკვეთას, რომელიც შეიცავს ყოველ დღე ზუსტად ერთხელ.

გამოიყენეთ სრული წინასწარ პარამეტრები [როტაცია](#rotation). ახალ ინსტალაციას ჯერ კიდევ სჭირდება ერთი დაწყება არჩეული პირველი პროფილის მოსამზადებლად და მოგვიანებით მისი გააქტიურებისთვის.

<a id="release-identity-and-logging"></a>
## გაათავისუფლეთ ვინაობა და ჟურნალი

| პარამეტრები | ტიპი და გაგზავნილი მნიშვნელობა | მხარდაჭერილი გამოყენება | მარცხი ან ურთიერთქმედება |
|---|---|---|---|
| `version` | სტრიქონი წაკითხული `.randomday_version` | მხოლოდ წაკითხვა. | გამოტოვებული ან ცარიელი მარკერი ხდება `unversioned`; საბოლოო პაკეტის ვალიდაცია უარყოფს პირადობის დრიფტს. |
| `package_mode` | სტრიქონი წაკითხული `.randomday_mode` | მხოლოდ წაკითხვა: `dedicated_server` ან `singleplayer_manual`. | ნებისმიერი სხვა მნიშვნელობა აჩერებს გაშვებას სამიზნის ჩაწერამდე. |
| `plan_basis` | სტრიქონი: `RandomDay - Seventeen Suns Rotation + Open World Scope` | მხოლოდ დიაგნოსტიკური ეტიკეტი; არ გამოიყენოთ იგი როგორც ფუნქციის გადართვა. | მიმდინარე გაშვების დრო არ განშტოდება ამ ველზე. |
| `logging.level` | სტრიქონი: `info` | `debug`, `info`, `warn` ან `error`. | უცნობი მნიშვნელობები არ ამატებს შესვლის მიზნებს; შეინახე `info` თუ პროფილის თაობის ქცევის დიაგნოსტიკა. |

მაგალითი:

```lua
logging = { level = "debug" }
```

გამოიყენეთ `debug` დროებით, შეინახეთ შესაბამისი `UE4SS.log`, შემდეგ დაბრუნდით `info`. ჟურნალები შეიძლება შეიცავდეს ლოკალურ ბილიკებს დაბალი დონის წარუმატებლობისგან; გადახედეთ მათ გაზიარებამდე.

<a id="experience-mode"></a>
## გამოცდილების რეჟიმი

`experience.mode` ასახელებს ამ ინსტალაციის ოპერირებას. ის არ ასუსტებს შემდეგი დაწყების უსაფრთხოების საზღვრებს: Abiotic Factor კითხულობს ქვიშის ყუთის პარამეტრებს მანამდე UE4SS იტვირთება RandomDay, ასე რომ, არცერთი რეჟიმი არ შეუძლია ჩაანაცვლოს უკვე გაშვებული პროცესის წესებს.

| პარამეტრები | გაგზავნილი მნიშვნელობა | მხარდაჭერილი მნიშვნელობები | ეფექტი |
|---|---:|---|---|
| `experience.mode` | `auto` | `auto`, `persistent_dedicated`, `temporary_dedicated`, `singleplayer_lan` | `auto` წყდება პაკეტიდან. გამოყოფილ პაკეტებს შეუძლიათ გამოიყენონ რომელიმე გამოყოფილი რეჟიმი. ხელით ასლის პაკეტი იღებს მხოლოდ `auto` ან `singleplayer_lan`. |

- `persistent_dedicated` ინახავს ერთს family/day შეუკვეთეთ ნორმალური გრძელვადიანი სერვერის გადატვირთვა.
- `temporary_dedicated` აღწერს სერვერს, რომელიც გაშვებულია შეზღუდული თამაშის სესიებისთვის. ის კვლავ აგრძელებს მომზადებულ შეკვეთას, ამიტომ მასპინძლის შეჩერება ჩუმად არ განაახლებს მომდევნო სესიას.
- `singleplayer_lan` წარმოქმნის მხოლოდ შეზღუდულ ხელით ასლის გამომავალს. ის არასოდეს აღმოაჩენს ან არედაქტირებს პირადი შენახვის საქაღალდეს.

არათავსებადი package/experience კომბინაცია ჩერდება სავარჯიშოში ჩაწერამდე.

<a id="rotation"></a>
## როტაცია

| პარამეტრები | გაგზავნილი მნიშვნელობა | მხარდაჭერილი მნიშვნელობები | ეფექტი |
|---|---:|---|---|
| `cycle.application_mode` | `next_reboot_queue` | `next_reboot_queue` | ინახავს სავარჯიშო ყუთის ყველა ცვლილებას გადატვირთვის საზღვრებზე. |
| `cycle.cycle_length_days` | `17` | `17` სტანდარტული პროფილის ნაკრებისთვის | ემთხვევა ყველა საოჯახო პაკეტს და გენერირებულ მითითებას. |
| `cycle.start_day_mode` | `configured` | `configured`, `random` | იყენებს `cycle.start_day` ან ირჩევს ერთ მოქმედ დაწყების დღეს ერთხელ ოჯახის გაშვების დასაწყისში. |
| `cycle.start_day` | `1` | მთელი ნომერი `1` `17` | პირველი დღე, როდესაც `start_day_mode=configured`. |
| `cycle.day_progression_mode` | `sequential` | `sequential`, `non_repeating_random` | აქმნის შეფუთულ თანმიმდევრულ წესრიგს ან ერთ შერეულ შეკვეთას, რომელიც შეიცავს ყოველ დღე ზუსტად ერთხელ. |
| `cycle.bootstrap_day` | `1` | მთელი ნომერი `1` `17` | თავსებადობის სარეზერვო გამოყენება გამოიყენება მხოლოდ მაშინ, როდესაც `cycle.start_day` არ არის. ახალმა კონფიგურაციამ უნდა გამოიყენოს `cycle.start_day`. |
| `cycle.check_interval_ms` | `0` | `0` ან შემოსაზღვრული დადებითი ინტერვალი | `0` მზადდება ერთხელ გაშვებისას; დადებითი მნიშვნელობა იძლევა პერიოდულ ზედამხედველობას, როდესაც UE4SS უზრუნველყოფს `LoopAsync`. |
| `profile_family.mode` | `non_repeating_random_run` | `selected_run`, `non_repeating_random_run`, `rotation_run` | ირჩევს, როგორ დაიწყოს ახალი 17-დღიანი ოჯახური რბოლა. |
| `profile_family.selected_family` | `action` | ერთი ID `allowed_families` | ოჯახის მიერ გამოყენებული `selected_run` და როგორც სარეზერვო. |
| `profile_family.default_family` | `action` | ერთი რეგისტრირებული ოჯახის ID | გამობრუნება, როდესაც არჩეული ID აკლია ან არასწორია. |
| `profile_family.allowed_families` | 17-ვე საჯარო ოჯახის ID | რეგისტრირებული ID-ების ნებისმიერი არა ცარიელი ქვეჯგუფი | შეზღუდავს ოჯახებს, რომლებსაც შეუძლიათ ახალი გაშვებები. |
| `profile_family.preserve_family_until_day_17` | ლოგიკური: `true` | დაჯავშნილი თავსებადობის ველი; შეინახე `true`. | მიმდინარე კალენდარი ყოველთვის ინახავს ოჯახს ყველა თანამდებობაზე მუდმივი 17-დღიანი თანმიმდევრობით და არ კითხულობს ამ ველს გადამრთველად. |

დღის შეკვეთა იქმნება ერთხელ ახალი ოჯახური გაშვებისთვის და იწერება `runtime/rotation_state.txt`. აღდგენა და მოგვიანებით გადატვირთვა ხელახლა გამოიყენეთ ზუსტად ეს პოზიციები. კონფიგურაციის შესწორება არ აბრუნებს მიმდინარე შეკვეთას. ოჯახი იცვლება მხოლოდ 17-ვე პოზიციის დასრულების შემდეგ.

### რეკომენდებული წინასწარ პარამეტრები

მუდმივი გამოყოფილი სერვერი:

```lua
experience = { mode = "persistent_dedicated" }
cycle = {
    application_mode = "next_reboot_queue",
    cycle_length_days = 17,
    start_day_mode = "configured",
    start_day = 1,
    day_progression_mode = "sequential",
    bootstrap_day = 1,
    check_interval_ms = 0,
}
```

დროებითი გამოყოფილი სესიები განსხვავებული არაგანმეორებადი თანმიმდევრობით ყოველ ახალ ოჯახურ გაშვებაზე:

```lua
experience = { mode = "temporary_dedicated" }
cycle.start_day_mode = "random"
cycle.day_progression_mode = "non_repeating_random"
```

Singleplayer/LAN ხელით ასლი იყენებს singleplayer პაკეტს და ჩვეულებრივ ტოვებს `experience.mode="auto"`. შემდეგი ფაილის გენერირებამდე შეგიძლიათ აირჩიოთ დაწყებისა და პროგრესის იგივე კონტროლი. დააკოპირეთ გენერირებული ფაილი არჩეულ შეჩერებულ სამყაროში სხვა თაობის გაშვებამდე, თუ გსურთ მუშაობის დროის მდგომარეობა და მსოფლიოს დატვირთული პროფილი დარჩეს გასწორებული.

ახალი ინსტალაციისას, პირველ პროცესს შეუძლია მოამზადოს მხოლოდ შერჩეული დაწყების დღე. მოგვიანებით პროცესი ააქტიურებს მას. შემთხვევითი ან კონფიგურირებული დაწყება არ გვერდს უვლის ძრავის ჩატვირთვის ბრძანებას.

მაგალითი ფიქსირებული Builder გაშვებისთვის:

```lua
profile_family = {
    mode = "selected_run",
    selected_family = "builder",
    default_family = "action",
    allowed_families = { "builder" },
    preserve_family_until_day_17 = true,
    reroll_only_after_day_17 = true,
    prevent_repeats_until_rotation_complete = true,
}
```

ცარიელი ან უცნობი დასაშვები ნაკრები არასრული პროფილის შექმნის ნაცვლად უბრუნდება რეგისტრირებულ ოჯახს.

`paths.sandbox_path_override` ნაგულისხმევად არის `nil`. უგულებელყოფის გარეშე, RandomDay ჯერ ამოწმებს ზოგად WindowsServer კანდიდატები მიმაგრებულია აღმოჩენილ RandomDay ინსტალაცია, შემდეგ ამოწმებს ნებისმიერ კონფიგურირებულ კანდიდატს. თუ არცერთი არ არსებობს, ის იყენებს პირველ ინსტალაციაზე დამაგრებულ ზოგად კანდიდატს, რომელიც გადაწყვეტს სერვერის ინსტალაციას:

```text
AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini
```

ეს სარეზერვო არ არის გადაწყვეტილი პროცესის მიმდინარე სამუშაო დირექტორიადან. დააყენეთ `sandbox_path_override` მხოლოდ მაშინ, როდესაც თქვენი ინსტალაცია იყენებს სხვა ლიტერატურულ ფაილს. მიუთითეთ ის ერთზე `SandboxSettings.ini` და არა დირექტორია. შეაჩერეთ სერვერი და დაადასტურეთ, რომ ფაილი განზრახ ინსტალაციაშია გამოყენებამდე.

<a id="optional-mirrors"></a>
### სურვილისამებრ სარკეები

`paths.write_sandbox_mirrors` იგზავნება როგორც `true`, მაგრამ სარკის ბილიკების სია ცარიელია და `paths.world_name` არის `nil`. ამიტომ გაგზავნილი ნაგულისხმევი არ წერს დამატებით სარკეს. დააყენეთ `false` როდესაც ინსტალაცია ყოველთვის უნდა წერდეს მხოლოდ გადაწყვეტილ პირველად სამიზნეს. კონფიგურირებული სარკის კანდიდატის ან მსოფლიო სახელის გარეშე, ორივე მნიშვნელობა მაინც წერს მხოლოდ პირველადი sandbox ფაილს.

სარკე ნებადართული ხდება მხოლოდ მაშინ, როდესაც შეგნებულად დაამატებთ ზუსტ ჩანაწერს `paths.sandbox_mirror_candidates` ან დააყენეთ `paths.world_name`. სარკეები საუკეთესო ძალისხმევის ასლებია იმ ინსტალაციებისთვის, რომლებიც კითხულობენ მეორე მსოფლიოსთვის სპეციფიკურ სავარჯიშო ბილიკს. ისინი არ ანაცვლებენ სწორი პირველადი გზის კონფიგურაციას.

სარკის ჩართვამდე:

1. შეაჩერე სერვერი;
2. ზუსტი ფაილის იდენტიფიცირება, რომელსაც სერვერი კითხულობს;
3. დაადასტურეთ, რომ სამიზნე ინსტალაციაშია;
4. სარეზერვო ასლი;
5. დაამატეთ მხოლოდ ეს გზა;
6. დაადასტურეთ სარკის შედეგი მომზადების შემდეგ.

მაგალითი უარყო სარკის გარეშე:

```lua
paths = {
    runtime_dir = "ue4ss/Mods/RandomDay/runtime",
    web_export_dir = "ue4ss/Mods/RandomDay/web_export",
    sandbox_path_override = "<server-root>/AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini",
    sandbox_candidates = {},
    write_sandbox_mirrors = false,
    sandbox_mirror_required = false,
    world_name = nil,
    sandbox_mirror_candidates = {},
}
```

`<server-root>` არის ჩანაცვლების ადგილი. შეცვალეთ იგი ადგილობრივად; არ გამოაქვეყნოთ მანქანის სპეციფიკური გზა.

<a id="non-disableable-safety-locks"></a>
## უსაფრთხოების ბლოკირების გამორთვის გარეშე

| პარამეტრები | საჭირო მნიშვნელობა | მნიშვნელობა |
|---|---:|---|
| `sandbox.backup_before_write` | `true` | შეინახე დამოწმებული ასლი არსებული ძირითადი ფაილის ჩანაცვლებამდე. |
| `sandbox.restore_last_good_on_failure` | `true` | სცადეთ ავტომატური აღდგენა წარუმატებელი ჩანაცვლების ან წაკითხვის შემდეგ. |
| `external_mods.patch_only_existing_keys` | `true` | უარი თქვით უცნობი პარამეტრის გამოგონებაზე სხვა მოდიფიკაციის ფაილში. |
| `external_mods.backup_before_write` | `true` | შეინახეთ სამიზნე ბაიტები მხარდაჭერილი ტრანზაქციის ადაპტერის რედაქტირებამდე. |

RandomDay უარს ამბობს გაშვებაზე, თუ ამ ოთხი მნიშვნელობიდან რომელიმე არ არის `true`. ეს არის უსაფრთხოების საკეტები, არ არის მხარდაჭერილი ოპერატორის გადამრთველები. არ გამორთოთ ისინი, მათ შორის შემუშავების ან პრობლემების აღმოფხვრისას, რადგან ამით ცვლის ჩავარდნის გამო დახურულ ზღვარს, რასაც დამწერისა და ადაპტერის ტესტები ადასტურებს.

`sandbox.force_rewrite_every_supervision_tick` რჩება ნორმალურ პარამეტრად და იგზავნება როგორც `false`, რომელიც ხელშეუხებელ ტოვებს უკვე შესატყვის სავარჯიშო ფაილს. იგი იღებს ლოგიკურს. დააყენეთ `true` აიძულებს იგივე პროცესის კუთვნილ მომზადებულ ბაიტებს ხელახლა ჩაწერის მეშვეობით; ის არ აგრძელებს family/day. გამოიყენეთ იგი მხოლოდ შეზღუდული აღდგენის ტესტისთვის, რადგან განმეორებითი ჩაწერა ქმნის უფრო მეტ ოპერაციულ სარეზერვო ასლებს.

## სურვილისამებრ მოდიფიკაციის ადაპტერები

| პარამეტრები | გაგზავნილი მნიშვნელობა | მნიშვნელობა |
|---|---:|---|
| `external_mods.enabled` | `true` | ნება მიეცით კონფიგურირებულ გადამყვანებს, შეამოწმონ ცალკე დაყენებული სამიზნეები. |
| `external_mods.optional_by_default` | `true` | გამოტოვებული ან შეუთავსებელი არჩევითი რეჟიმი არ იბლოკება RandomDay. |
| `external_mods.patch_only_existing_keys` | `true` | საჭირო უსაფრთხოების დაბლოკვა; გაშვება ვერ ხერხდება, თუ შეიცვალა. |
| `external_mods.backup_before_write` | `true` | საჭირო უსაფრთხოების დაბლოკვა; გაშვება ვერ ხერხდება, თუ შეიცვალა. |
| `external_mods.adapters` | ოთხი საჯარო ადაპტერის ID | შეზღუდავს RandomDay-owned ადაპტერები შეიძლება მუშაობდეს. |

ამოშალეთ ადაპტერის ID სიიდან, რათა დატოვოთ ეს ინტეგრაცია მესამე მხარის რეჟიმის გამორთვის ან დეინსტალაციის გარეშე. singleplayer/LAN პაკეტი გამორთავს ყველა ადაპტერს ამ სიის მიუხედავად.

`external_mods.optional_by_default=false` ქმნის კონფიგურირებულ ადაპტერის შედეგს, გარდა `applied` ან `already_current` ვერ მიიღება ადაპტერის მთლიანი შედეგი. ეს არ აიძულებს პირველადი სავარჯიშო ტრანზაქციის დაბრუნებას. შეინახეთ გაგზავნილი `true` გარდა იმ შემთხვევისა, როდესაც ოპერატორს არ აქვს გამოცდილი მიზეზი, რომ მოითხოვოს ინტეგრაცია.

იხილეთ [მოდიფიკაციის მხარდაჭერილი ადაპტერები](%E1%B2%9B%E1%B2%AE%E1%B2%90%E1%B2%A0%E1%B2%93%E1%B2%90%E1%B2%AD%E1%B2%94%E1%B2%A0%E1%B2%98%E1%B2%9A%E1%B2%98_%E1%B2%90%E1%B2%93%E1%B2%90%E1%B2%9E%E1%B2%A2%E1%B2%94%E1%B2%A0%E1%B2%94%E1%B2%91%E1%B2%98.md) აღიარებული განლაგებისთვის და ექვსი შესაძლო შედეგისთვის.

<a id="optional-chaotic-spawn-engine-scope-fields"></a>
### სურვილისამებრ Chaotic Spawn Engine ველები

`world_scope` აწვდის ხუთ არჩევით RandomDay გაფართოების პარამეტრები მხოლოდ მაშინ, როდესაც აღიარებულია Chaotic Spawn Engine `DynamicSpawns/SharedData.lua` განლაგება უკვე შეიცავს ამ ველებს. ეს არ არის ცალკე რეჟიმი ან ჩამოტვირთვა:

| პარამეტრები | გაგზავნილი მნიშვნელობა | ადაპტერის ეფექტი |
|---|---:|---|
| `world_scope.enabled` | `true` | ითხოვს არასავალდებულო RandomDay მსოფლიო მასშტაბის კარიბჭე ამოცნობილ DynamicSpawns განლაგება. |
| `world_scope.affect_open_worlds` | `true` | მოიცავს ღია სამყაროებს, თუ სამიზნე მოდიფიკაცია არ გამოიყენებს დაცული სამყაროს წესს. |
| `world_scope.unknown_world_policy` | `allow` | მოთხოვნები `allow` ან `block` როდესაც სამიზნე მოდიფიკაციას არ შეუძლია სამყაროს კლასიფიკაცია. |
| `world_scope.log_scope_decisions` | `true` | ითხოვს სამიზნე-მოდის აღრიცხვას მისი ფარგლების გადაწყვეტილების მისაღებად. |
| `world_scope.protected_worlds` | ცარიელი სია | მიწოდებს მძიმით გამოყოფილი დაცული სამყაროს შაბლონებს სამიზნე განლაგებას. |

ეს მნიშვნელობები არის ადაპტერის შეყვანა და არა მსოფლიო ფილტრი, რომელიც დანერგილია RandomDay's sandbox ჩამწერი. ისინი მოქმედებს მხოლოდ მაშინ, როდესაც ცალკე დაინსტალირებული Chaotic Spawn Engine განლაგება უკვე შეიცავს სრულ არჩევით RandomDay ველების კომპლექტს და ანგარიშებს `applied` ან `already_current`. Chaotic Spawn Engine პასუხისმგებელია ამ ველების გამოყენებაზე მუშაობის დროს. ჩვეულებრივი ინსტალაცია გაფართოების ველების გარეშე რჩება უცვლელი.

ხუთივე მნიშვნელობა არის ადაპტერის შეყვანა. `unknown_world_policy` იღებს მხოლოდ დოკუმენტირებულ სამიზნე მნიშვნელობებს `allow` ან `block`; ამოუცნობი სამიზნე განლაგება გამოტოვებულია. შეინახეთ `protected_worlds` ცარიელია დოკუმენტაციის მაგალითებში. თუ ოპერატორი იყენებს ლოკალურ შაბლონებს, ისინი არ უნდა იყოს ჩართული ეკრანის სურათებში, პრობლემებში ან გამოშვების არტეფაქტებში.

## მოთამაშის შეტყობინებები

გაგზავნილი გამოყოფილი სერვერის კონფიგურაცია საშუალებას იძლევა კომპაქტური შეერთების შეტყობინებები და მოკლე ყოველდღიური ხაზი. ის ელოდება 30 წამს პირველ პასამდე, ამოწმებს ახლად შეერთებულ მოთამაშეებს ყოველ 15 წამში და ელოდება 10 წამს შეერთების შეტყობინების შემდეგ ყოველდღიური ხაზის წინ.

| პარამეტრები | გაგზავნილი მნიშვნელობა |
|---|---:|
| `player_message.enabled` | `true` |
| `player_message.log_on_startup` | `true` |
| `player_message.register_console_command` | `false` |
| `player_message.console_command` | `randomday` |
| `player_message.broadcast_enabled` | `true` |
| `player_message.startup_delay_ms` | `30000` |
| `player_message.join_check_interval_ms` | `15000` |
| `player_message.send_daily_joke_after_join` | `true` |
| `player_message.daily_joke_delay_seconds` | `10` |
| `player_message.criticality_join` | `2` |
| `player_message.criticality_joke` | `0` |

| `player_message.max_warning_lines` | `3` |
| `player_message.max_note_lines` | `3` |

შეტყობინებების სიგრძის ვალიდაცია ამოწმებს წყაროს ლიმიტებს. ის არ ცვლის ვიზუალურ ტესტს ყველა კლიენტის გარჩევადობაზე.

დროის მნიშვნელობები არის არაუარყოფითი რიცხვები, რომლებიც ინტერპრეტირებულია როგორც მილიწამები, გარდა `daily_joke_delay_seconds`. გათიშული შეტყობინება ან მაუწყებლობის პარამეტრი ახშობს კლიენტის შეტყობინებებს სავარჯიშო ყუთის მომზადების შეცვლის გარეშე. კონსოლის ბრძანება რეგისტრირებულია მხოლოდ მაშინ, როდესაც ორივე პარამეტრი და UE4SS ხელმისაწვდომია. შეინახეთ კრიტიკულობის მნიშვნელობები გაგზავნილ სატრანსპორტო დონეზე, თუ დასახელებული კლიენტის ტესტი არ დაადასტურებს სხვა მნიშვნელობას.

`max_line_chars` მთარგმნელის მიერ დამაგრებულია 8-დან 64 სიმბოლომდე. სამი ხაზის დათვლის პარამეტრების ლიმიტი შეერთების, გაფრთხილებისა და შენიშვნის გამომავალი, შესაბამისად; გაგზავნილი მნიშვნელობები ემთხვევა ხელმისაწვდომი წყაროს ხაზების რაოდენობას. შეინახეთ ეს ოთხი ლიმიტი ნაგულისხმევად, თუ კლიენტის განლაგების ტესტი არ დაადასტურებს უფრო ვიწრო პარამეტრს.

<a id="customize-the-shipped-profile-defaults"></a>
### გაგზავნილი პროფილის ნაგულისხმევი პარამეტრების მორგება

გახსნა:

```text
RandomDay/Scripts/ax_config/server.lua
```

იპოვეთ ეს ბლოკი `sandbox`:

```lua
profile_overrides = {
    HardcoreMode = false,
    AllowIronMode = false,
    StructuralSupportLimit = 0,
    BridgeSupports = 0,
}
```

ეს არის RandomDay's საწყისი არჩევანი, არა უცვლელი აბიოტური ფაქტორის წესები. დააყენეთ რომელიმე რეჟიმი `true` ან `false`. დააყენეთ თითოეული მხარდაჭერის მნიშვნელობა მთელ რიცხვზე `0` `1000`. შეაჩერეთ თამაში ან გამოყოფილი სერვერი ფაილის რედაქტირებამდე, შეინახეთ იგი და შემდეგ ისევ დაიწყეთ, რათა ლუამ ჩატვირთოს ახალი კონფიგურაცია.

RandomDay წაიკითხავს ამ ბლოკს, როდესაც ის აყალიბებს 17 პროფილს ოჯახში. ამიტომ, არჩეული მნიშვნელობები გამოიყენება ყველა ოჯახსა და დღეს, მათ შორის პროფილები, რომლებიც მომზადებულია როტაციის შემდეგ და პროფილები, რომლებიც აღდგენილია მოგვიანებით სერვერის გაშვების შემდეგ. თქვენ არ გჭირდებათ 289 პროფილის ფაილის რედაქტირება ან პროფილის მითითების რეგენერაცია.

Changing only a live `SandboxSettings.ini` is temporary because the next prepared profile is generated from `server.lua`. Invalid types, unknown keys, or support values outside `0..1000` stop profile construction with a named configuration error instead of silently reverting to defaults.

The generated profile reference continues to show the shipped defaults. It is a release reference, not a copy of one server's private configuration.
