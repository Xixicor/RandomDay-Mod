# გაშვების დროის მდგომარეობისა და გამომავალი სქემების ინტერპრეტაცია

> **კანონიკური ინგლისური წყარო:** [RUNTIME_OUTPUTS.md](../../RUNTIME_OUTPUTS.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს არის კანონიკური ველის სრული სქემის სახელმძღვანელო. ის პასუხობს რას ნიშნავს თითოეული ველი, მდგომარეობა, ცარიელი მნიშვნელობა და მანქანის შედეგი. გამოიყენეთ [გაშვების ფაილის რუკა](%E1%B2%92%E1%B2%90%E1%B2%A8%E1%B2%95%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%A4%E1%B2%90%E1%B2%98%E1%B2%9A%E1%B2%94%E1%B2%91%E1%B2%98.md) მწარმოებლებისთვის, ბილიკები, ჩაწერის დრო, შეკავება, ტრანზაქციის გვერდითი კარები და აღდგენის მდებარეობები.

ამ სახელმძღვანელოში ყველა ბილიკი შეესაბამება დაინსტალირებულს `RandomDay/` საქაღალდე, თუ მწკრივი ცალსახად არ ასახელებს კონფიგურირებულ სავარჯიშოს ან არასავალდებულო ადაპტერის სამიზნეს. Runtime-ის შედეგები გენერირდება ინსტალაციის შემდეგ და არ არის არც ერთი გამოშვების წევრი ZIP.

|---|---|

| მანქანით წაკითხული საჯარო სტატუსი | `web_export/today.json`, სქემა `2` და `randomday_public_status_v2` |
| ადამიანის წაკითხვის სტატუსი | `web_export/today.html`, მიღებული იგივე საჯარო სტატუსის გადასვლიდან |

| მოთამაშის ზუსტი შეზღუდვის შეტყობინება | `runtime/current/player_message_preview.txt` |

HTML ხედი, გადახედვა და თარგმნილი რეზიუმეები მიღებული ხედებია. ისინი არ უგულებელყოფენ sandbox მარკერს, ტრანზაქციის შედეგებს ან პროფილის ნედლეულ მნიშვნელობებს. იპოვნეთ ბოლო ცნობილი-კარგი ფაილები, ოპერაციების სარეზერვო ასლები, გვერდითი კარები, სარკეები, ადაპტერის სამიზნეები და `UE4SS.log` [გაშვების ფაილები](%E1%B2%92%E1%B2%90%E1%B2%A8%E1%B2%95%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%A4%E1%B2%90%E1%B2%98%E1%B2%9A%E1%B2%94%E1%B2%91%E1%B2%98.md).

<a id="rotation-state-schema"></a>
## როტაციის მდგომარეობის სქემა

`runtime/rotation_state.txt` იყენებს სქემას `1` და შეიცავს ერთს `key=value` წყვილი თითო სტრიქონზე:

| ველი | მნიშვნელობა |
|---|---|
| `schema_version` | უნდა იყოს `1`. |
| `mod_version` | პაკეტის იდენტიფიკაცია წაკითხული `.randomday_version`. |
| `rotation_id` | იდენტიფიკატორი მიმდინარე გადასასვლელისთვის შესაფერის საოჯახო ნაკრებში. |
| `mode` | `selected_run`, `non_repeating_random_run` ან `rotation_run`. |
| `available_families` | მძიმით გამოყოფილი ოჯახის ID-ები კონფიგურაციის ფილტრაციის შემდეგ. |
| `remaining_families` | შესაბამისი ოჯახები ჯერ არ არის შერჩეული მიმდინარე განმეორებით საშვალედ. |
| `completed_families` | ოჯახები, რომელთა 17 პოზიციის სრული შეკვეთა შესრულებულია მიმდინარე საშვით. |
| `active_family`, `active_day` | აქტიური მარკერის ინფორმაცია ჩაწერილია შერჩევის შესრულებისას. Sandbox მარკერი ავტორიტეტულია შემდეგ ჩატვირთვაზე. |
| `prepared_family`, `prepared_day` | პროფილი შენახულია შემდეგი გადატვირთვისთვის. |
| `active_run_id` | ოჯახის გაშვების იდენტიფიკატორი, რომელიც დაკავშირებულია მომზადებულ შერჩევასთან. |
| `last_status` | კალენდრის შერჩეული მდგომარეობა, რომელმაც შექმნა ეს ფაილი. |
| `session_mode` | გადაწყვეტილი მუდმივი გამოყოფილი, დროებითი გამოყოფილი ან singleplayer/LAN სიცოცხლის ციკლი. |
| `start_day_mode` | კონფიგურირებული ან ერთჯერადი შემთხვევითი დაწყების არჩევანი ახალი გაშვებისთვის. |
| `day_progression_mode` | შეფუთული თანმიმდევრული ან არაგანმეორებადი შემთხვევითი პროგრესირება. |
| `day_order` | მძიმით გამოყოფილი დღეების ID-ები ზუსტად იმ თანმიმდევრობით, როგორიც ისინი მომზადდება. |
| `day_position` | მომზადებული დღის პოზიცია `day_order`. |
| `updated_at` | ოპერატორის შედარებისთვის ადგილობრივი ჩაწერის დრო. |

სახელმწიფო ჩაწერა მიიღება მხოლოდ მაშინ, როდესაც სქემის მარკერი, მომზადებული ოჯახი და მომზადებული დღე სწორად წაიკითხება. წაუკითხავი მიმდინარე ფაილი შეიძლება დაუბრუნდეს `rotation_state.last_good.txt`; შერჩეული სავარჯიშო მარკერი მაინც განსაზღვრავს, რა ჩაიტვირთა თამაში მიმდინარე პროცესისთვის.

<a id="runtime-status-json"></a>
## გაშვების სტატუსი JSON

`runtime/current/randomday_status.json` იყენებს `status_schema=randomday_runtime_status_v2`. მისი ძირითადი ველების ჯგუფებია:

| ჯგუფი | ველები და ინტერპრეტაცია |
|---|---|
| იდენტიფიკაცია | `mod`, `version`, `package_mode`, `mode`, `session_mode`, `profile_system`, `status_schema`, `dictionary_version` |
| არჩევა | `reason`, `selection_status`, `active_profile_detection`, `rotation_id`, `run_id`, `cycle_length_days` |
| აქტიური | `active_cycle_day`, `active_profile_id`, `active_display_name`, `active_family`, `active_family_label`, `active_profile_translation` |
| მომზადებულია | `prepared_next_cycle_day`, `prepared_next_profile_id`, `prepared_next_display_name`, `prepared_next_family`, `prepared_next_family_label`, `prepared_profile_translation` |
| ადამიანის შეჯამებები | `profile_intensity`, `player_summary`, `prepared_profile_intensity`, `prepared_player_summary`, `admin_summary`, `message_preview` |
| დაწერე მტკიცებულება | `write_status`, `backup_status`, `last_known_good_status`, `sandbox_transaction_status`, `sandbox_rollback_status`, `prepared_ready`, `state_commit_ok`, `state_commit_error_code` |
| ადაპტერის მტკიცებულება | `adapter_status`, `adapter_results`; თითოეული ადაპტერის ჩანაწერი შეიცავს თავსებადობის მტკიცებულებებს, transaction/rollback მდგომარეობა, შეცვლილი ფაილების რაოდენობა და რედაქტირებული სამიზნე მიმართვები |
| საზღვრები | `restart_required_for_prepared_profile`, `sandbox_target`, `manual_copy_required`, `mirrors_written`, `world_scope`, `dictionary_path` |
| დიაგნოსტიკა | `hash`, `replacement_method`, `pending_readback_verified`, `target_readback_verified`, `updated_at` |

უცნობი აქტიური მნიშვნელობები ნიშნავს, რომ მიმდინარე სავარჯიშო ყუთი არ შეიცავდა წასაკითხად RandomDay მარკერი. ისინი არ უნდა შეიცვალოს მომზადებული მნიშვნელობებით. ადაპტერის ბილიკები გარეთ `runtime/` დაყვანილია საბაზისო სახელის მითითებამდე და დიაგნოსტიკური სტრიქონები ასწორებენ აღმოჩენილ აბსოლუტურ ბილიკებს.

<a id="public-status-json"></a>
## საჯარო სტატუსი JSON

`web_export/today.json` იყენებს `schema_version=2` და `status_schema=randomday_public_status_v2`. ის იმეორებს პირადობას, active/prepared, შერჩევის, ტრანზაქციის, ადაპტერისა და გადატვირთვის საზღვრის ფაქტები, რომლებიც საჭიროა ოპერატორისთვის. იგი ასევე მოიცავს:

- `session_mode`, `start_day_mode`, `configured_start_day`, `day_progression_mode`, `day_order` და `prepared_day_position`;
- `family_selection_mode`, მემკვიდრეობითი `family_locked_until_day_17` და `family_locked_until_cycle_complete`;
- `remaining_families`, `completed_families` და მათი რაოდენობა;
- მომზადებული შეხვედრის პროფილი, დონე, თემა და შერეული შეხვედრის შანსი;
- world-scope ჩართვა, open-world პარამეტრი, უცნობი სამყაროს პოლიტიკა და მხოლოდ კონფიგურირებული გამორიცხული სამყაროს შაბლონების რაოდენობა;
- მომზადებული შეტყობინებისა და შეტყობინებების კომბინირებული გადახედვები;
- `selected_at`, `sandbox_target`, `manual_copy_required` და მოამზადა ჰეში.

`profile_status` არის ერთ-ერთი `prepared_for_next_reboot`, `next_reboot_already_prepared`, `degraded_state_persistence` ან `write_failed_or_rollback`. `prepared_ready=true` მაინც არ ნიშნავს აქტიურს; საჭიროა მოგვიანებით გაშვების მარკერი.

<a id="dictionary-and-translation-output"></a>
## ლექსიკონი და თარგმანი

`runtime/current/randomday_dictionary.json` იყენებს `schema=randomday_runtime_dictionary_v2` და განსაზღვრავს ლექსიკონის ვერსიას `randomday_dictionary_v2`. იგი აღწერს პაკეტის რეჟიმებს, შერჩევის მდგომარეობებს, წნევის დომენებს, დაყენების ეტიკეტებს, ნედლეულ მნიშვნელობებს და უბრალო ენობრივ მნიშვნელობებს. უცნობი მნიშვნელობები რჩება აშკარა, იმის ნაცვლად, რომ გარდაიქმნას თავდაჯერებულ აღწერაში.

`player_message_preview.txt`, `today.json`, `today.html` და თამაშში შეტყობინებები არის ნახვები, რომლებიც მიღებულია იმავე თარგმანის მოდულიდან. ძირითადი პროფილი და ნედლეული `SandboxSettings.ini` მნიშვნელობები რჩება სიმართლის წყაროდ.

<a id="failure-and-recovery-rules"></a>
## შეცდომის და აღდგენის წესები

1. წარუმატებელი მომლოდინე ჩაწერა ან დადასტურება არასოდეს ხდება წარმოების სამიზნე.
2. წარუმატებელი პრომოცია ან პროდუქციის წაკითხვა იწვევს შენახული ორიგინალის აღდგენას; ოპერაციის სარეზერვო არის სარეზერვო საშუალება, როდესაც აღდგენა ვერ ხერხდება.
3. შენახული დაბრუნების ფაილი ან `rollback_failed` სტატუსი მოითხოვს ხელით განხილვას, სანამ თამაში ან სერვერი შეჩერებულია.
4. Sandbox-ის წარმატებული ჩაწერა პლუს ვერ მოხერხდა rotation-state commit დეგრადირებულია, არ არის მზად; ადაპტერები და მომზადებული პროფილის შეტყობინებები გამოტოვებულია.
5. ექსპორტის წარუმატებლობა არ ცვლის სავარჯიშოში შედეგს, მაგრამ წაშლის მოხერხებულობის დამადასტურებელ წყაროს. გამოიყენეთ ტრანზაქციის ჟურნალები, მდგომარეობა და ფაილების წაკითხვა.
6. გაშვების დროის გამომავალი არის ადგილობრივი ოპერატიული მონაცემები. არ დაამატოთ ისინი გამოშვებაში ZIP ან გამოაქვეყნეთ ისინი მაგალითებად ცალკე კონფიდენციალურობის განხილვის გარეშე.
