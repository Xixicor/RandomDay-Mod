# მოქმედი, მომზადებული და აღდგენის მდგომარეობა

> **კანონიკური ინგლისური წყარო:** [OPERATIONS.md](../../OPERATIONS.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


RandomDay ცვლის sandbox ფაილს მომავალი ჩატვირთვისთვის. ის არ ცვლის უკვე ჩატვირთულ წესებს გაშვებულ Abiotic Factor სესიაში.

ეს გვერდი ფლობს ოპერატორის გადაწყვეტილებებს და აღდგენის პროცედურებს. გამოიყენეთ [ტერმინი](%E1%B2%A2%E1%B2%94%E1%B2%A0%E1%B2%9B%E1%B2%98%E1%B2%9C%E1%B2%98.md) კანონიკური ტერმინებისთვის, [გაშვების ფაილები](%E1%B2%92%E1%B2%90%E1%B2%A8%E1%B2%95%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%A4%E1%B2%90%E1%B2%98%E1%B2%9A%E1%B2%94%E1%B2%91%E1%B2%98.md) ბილიკის მფლობელობისთვის და [გაშვების დროის გამომავალი](%E1%B2%92%E1%B2%90%E1%B2%A8%E1%B2%95%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%93%E1%B2%A0%E1%B2%9D%E1%B2%98%E1%B2%A1_%E1%B2%A8%E1%B2%94%E1%B2%93%E1%B2%94%E1%B2%92%E1%B2%94%E1%B2%91%E1%B2%98.md) ზუსტი სქემებისა და ველის მნიშვნელობებისთვის.

<a id="distinguish-active-and-prepared-state"></a>
## განასხვავეთ აქტიური და მომზადებული მდგომარეობა

მომზადებული პროფილი არ არის აქტიური, სანამ მოგვიანებით გაშვება არ წაიკითხავს მის მარკერს. არ გამოიყენოთ მომზადებული family/day მიმდინარე სესიის აღსაწერად.

გამოიყენეთ `web_export/today.html` წასაკითხი შეჯამებისთვის და `web_export/today.json` ზუსტი მდგომარეობისთვის. დაადასტურეთ აქტიური მარკერი, მომზადებული იდენტურობა, `prepared_ready`, `profile_status`, ტრანზაქციის შედეგი, უკან დაბრუნების შედეგი და სტაჟირების შედეგი გადატვირთვის გადაწყვეტილებამდე.

<a id="follow-the-normal-dedicated-server-sequence"></a>
## მიჰყევით ჩვეულებრივ გამოყოფილი სერვერის თანმიმდევრობას

| ადრე | მოქმედება | შემდეგ |
|---|---|---|
| არა RandomDay მარკერი | დაიწყეთ RandomDay ჩართულია. | მიმდინარე სესია ინარჩუნებს არსებულ წესებს; RandomDay ქმნის და აგრძელებს დღის შეკვეთას, შემდეგ ამზადებს მის პირველ configured/random პოზიცია. |
| მომზადებულია პირველი პოზიცია | გადატვირთეთ. | ის დღე აქტიური ხდება; მომზადებულია შემდეგი შენახული პოზიცია იმავე ოჯახში. |
| შუა პოზიცია აქტიურია | გადატვირთეთ მომზადებული პროფილის გადახედვის შემდეგ. | მომზადებული დღე აქტიურდება და შემდეგი შენახული პოზიცია მზადდება. |
| საბოლოო პოზიცია აქტიურია | გადატვირთეთ შემდეგი ოჯახის გადახედვის შემდეგ. | სხვა დასაშვები საოჯახო შეკვეთის პირველი პოზიცია აქტიური ხდება. |

`selected_run` ინახავს კონფიგურირებულ ოჯახს. `non_repeating_random_run` ინახავს შემთხვევით არჩეულ ოჯახს ყველა 17 დღის განმავლობაში და თავს არიდებს ოჯახის ხელახლა გამოყენებას უფლებათა სიის ამოწურვამდე. `rotation_run` მიჰყვება კონფიგურირებულ ოჯახის წესრიგს. `cycle.day_progression_mode` აკონტროლებს დღის წესრიგს ოჯახის არჩევისგან დამოუკიდებლად.

ახალ ინსტალაციას ყოველთვის სჭირდება ერთი პროცესი მოსამზადებლად და მოგვიანებით პროცესი გასააქტიურებლად. ეს ეხება მუდმივ სერვერებს, დროებით სერვერებს და სახელმძღვანელოს singleplayer/LAN გენერაცია.

<a id="read-the-right-evidence"></a>
## წაიკითხეთ სწორი მტკიცებულება

გამოიყენეთ [გაშვების ფაილის რუკა](%E1%B2%92%E1%B2%90%E1%B2%A8%E1%B2%95%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%A4%E1%B2%90%E1%B2%98%E1%B2%9A%E1%B2%94%E1%B2%91%E1%B2%98.md) ბრუნვის მდგომარეობის, მიმდინარე სტატუსის, ბოლო ცნობილი-კარგი ფაილების, ოპერაციის სარეზერვო ასლების, ექსპორტის და `UE4SS.log`. გამოიყენეთ [გაშვების დროის გამომავალი მითითება](%E1%B2%92%E1%B2%90%E1%B2%A8%E1%B2%95%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%93%E1%B2%A0%E1%B2%9D%E1%B2%98%E1%B2%A1_%E1%B2%A8%E1%B2%94%E1%B2%93%E1%B2%94%E1%B2%92%E1%B2%94%E1%B2%91%E1%B2%98.md) ყველა ველის ჯგუფისთვის, სქემა, ცარიელი მდგომარეობა, წარუმატებლობის მნიშვნელობა და შეკავების წესი. HTML და JSON ექსპორტი აჯამებს წყაროს მდგომარეობას; ისინი არ ამტკიცებენ, რომ პროფილი გამოიყენებოდა თამაშის პირდაპირი კლიენტის მიერ.

თუ `prepared_ready` არის `false` ან `profile_status` არის `degraded_state_persistence`, შეინახეთ სერვერი გაჩერებული მანამ, სანამ ქვიშის ყუთი და როტაციის მდგომარეობა არ შეთანხმებული იქნება. სწორი სავარჯიშოში ჩაწერა წარუმატებელი მდგომარეობის მდგრადობით არ არის ჯანსაღი მომზადებული გადასვლა.

<a id="respond-to-writer-outcomes"></a>
## უპასუხეთ მწერლის შედეგებს

RandomDay ამზადებს ახალ ბაიტებს და-ძმის ფაილში, კითხულობს მათ უკან, ამოწმებს სრულ სავარჯიშო ყუთს, ინახავს ორიგინალს, როდესაც ის არსებობს, ხელს უწყობს ახალ ფაილს და ხელახლა კითხულობს მას. ის მზადაა მხოლოდ მას შემდეგ, რაც პროდუქციის წაკითხვა დაეთანხმება.

თუ პრომოცია ან წარმოების ვალიდაცია ვერ მოხერხდა, RandomDay ცდილობს აღადგინოს ამ ოპერაციის მიერ დაცული ფაილი. აღდგენის წარუმატებლობა რთული გაჩერებაა: შეაჩერეთ სერვერი და აღადგინეთ ხელით, ვიდრე განმეორებით გადატვირთოთ.

<a id="respond-to-adapter-outcomes"></a>
## უპასუხეთ ადაპტერის შედეგებს

გამოიყენეთ [მხარდაჭერილი გადამყვანები](%E1%B2%9B%E1%B2%AE%E1%B2%90%E1%B2%A0%E1%B2%93%E1%B2%90%E1%B2%AD%E1%B2%94%E1%B2%A0%E1%B2%98%E1%B2%9A%E1%B2%98_%E1%B2%90%E1%B2%93%E1%B2%90%E1%B2%9E%E1%B2%A2%E1%B2%94%E1%B2%A0%E1%B2%94%E1%B2%91%E1%B2%98.md#read-an-adapter-result) კანონიკური ექვსი მდგომარეობის შედეგების ცხრილისთვის და შემდეგი მოქმედებისთვის. მკურნალობა `rollback_failed` როგორც მყარი გაჩერება; ცალკე ჩაწერილი ადაპტერის სარეზერვო ასლი არის აღდგენის წყარო.

ადაპტერები გავლენას ახდენენ მხოლოდ ცალკე დაყენებულ მოდიფიკაციებზე. ისინი არასოდეს ააქტიურებენ მომზადებულ RandomDay sandbox პროფილს.

ჩვეულ ჩატვირთვისას, ადაპტერის მნიშვნელობები არჩეულია აქტიური პროფილიდან, რადგან ცალკე დაინსტალირებული მოდი შეიძლება მოგვიანებით ჩაიტვირთოს იმავე UE4SS გაშვებისას. პირველი ჩატვირთვის დროს, როდესაც არ არსებობს აქტიური RandomDay მარკერი, მომზადებული საწყისი დღის პროფილი ერთადერთი ხელმისაწვდომია. დროის ეს წესი განცალკევებულია შემდეგი გადატვირთვის sandbox-ის საზღვრებისგან და მაინც დამოკიდებულია სხვა მოდიფიკაციის საკუთარ დატვირთვაზე.

<a id="manual-recovery"></a>
## ხელით აღდგენა

1. გააჩერეთ თამაში ან სერვერი. არ აღადგინოთ ფაილი, სანამ ის ღიაა.
2. დააკოპირეთ მიმდინარე `SandboxSettings.ini`, `runtime/` და `web_export/` ცალკე დიაგნოსტიკური სარეზერვო ასლისთვის.
3. შეამოწმეთ `runtime/last_good/manifest.lua` და უახლესი შესაბამისი ჩანაწერი ქვეშ `runtime/backups/`. აირჩიეთ ფაილი, რომლის family/day და ჰეში ემთხვევა იმ მდგომარეობას, რომლის აღდგენასაც აპირებთ.
4. დააკოპირეთ არჩეული დადასტურებული ფაილი კონფიგურირებულ პირველად სავარჯიშო ბილიკზე.
5. ხელახლა წაიკითხეთ და დაადასტურეთ, რომ დასრულებულია დაწყებამდე.
6. დაიწყეთ ერთხელ და შეამოწმეთ აქტიური მარკერი და მომზადებული მდგომარეობა. არ იფიქროთ, რომ აღდგენა წარმატებით დასრულდა მხოლოდ შეცდომის შეტყობინების არარსებობის გამო.

თუ დადასტურებული სარეზერვო ასლი არ არსებობს, აღადგინეთ ინსტალაციამდე შექმნილი ოპერატორის სარეზერვო ასლი. RandomDay ვერ აღადგენს ფაილს, რომელიც არასოდეს იკითხება.

<a id="account-for-control-panel-writes"></a>
## ანგარიში საკონტროლო პანელზე იწერება

ზოგიერთი სერვერის პანელი ქმნის `SandboxSettings.ini` გაშვებისას. RandomDay ვერ შეინარჩუნებს მომზადებულ პროფილს, თუ სხვა ხელსაწყო გადაწერს მას ჩაწერის გადამოწმების შემდეგ. დააკონფიგურირეთ ერთი ავტორიტეტული სავარჯიშო წყარო და შეამოწმეთ ფაილის მარკერი გადატვირთვამდე და გადატვირთვის შემდეგ, როდესაც დიაგნოზირებულია განმეორებითი 1 დღის ან დაკარგული გადასვლის დროს.
