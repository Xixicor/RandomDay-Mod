# დააინსტალირეთ, განაახლეთ ან წაშალეთ RandomDay

> **კანონიკური ინგლისური წყარო:** [INSTALL.md](../../../INSTALL.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


RandomDay აქვს ორი სრული ჩამოტვირთვა. აირჩიეთ ერთი იმ სამყაროსთვის, რომელსაც თქვენ ქმნით:

- გამოიყენეთ **გამოყოფილი სერვერი ZIP** ნებისმიერი გამოყოფილი სერვერისთვის, სერვერის ჩათვლით, რომელიც იხსნება მხოლოდ შემთხვევითი სესიებისთვის;
- გამოიყენეთ **singleplayer/LAN ZIP** ადგილობრივი სამყაროსთვის, რომლის პარამეტრებს ხელით დააკოპირებთ.

არ დააკავშიროთ პაკეტები. მუდმივი ან დროებითი გამოყოფილი სერვერი არის არჩევანი RandomDay's პარამეტრები და არა სხვა ჩამოტვირთვა.

<a id="before-you-begin"></a>
## სანამ დაიწყებთ

გადაიღეთ აღდგენითი ასლი:

- სამყარო, რომელსაც ცვლით;
- მისი მიმდინარე `SandboxSettings.ini`;
- არსებული `RandomDay` საქაღალდე, თუ დაინსტალირებულია.

ინსტალაცია UE4SS RandomDay. ქვემოთ მოცემულ ინსტრუქციებში **Mods საქაღალდე** ნიშნავს `ue4ss/Mods/` დირექტორია თამაშის შიგნით ან გამოყოფილი სერვერის ინსტალაცია.

<a id="dedicated-server"></a>
## გამოყოფილი სერვერი

<a id="new-installation"></a>
### ახალი ინსტალაცია

1. გააჩერეთ სერვერი.
2. გახსენით მისი UE4SS `Mods` საქაღალდე.
3. გამოყავით გამოყოფილი სერვერი ZIP. შედეგი უნდა იყოს ერთი `ue4ss/Mods/RandomDay/` საქაღალდე და არა საქაღალდე სხვაში `RandomDay` საქაღალდე.
4. გახსენით ეს საქაღალდე და დაადასტურეთ `RandomDay/Scripts/main.lua` არის. თუ ის აკლია, ZIP ამოღებული იქნა არასწორ დონეზე.
5. გახსენით UE4SS `mods.txt` და ჩართეთ ეს ხაზი:

   ```text
   RandomDay : 1
   ```

6. ჩართეთ სერვერი ნორმალურად.
7. გახსენით RandomDay's წაკითხვადი სტატუსის გვერდი და დაადასტურეთ, რომ ის ასახელებს როგორც აქტიურ პროფილს, ასევე შემდგომ დასაწყებად მომზადებულ პროფილს.

პირველი დაწყება არ ცვლის ამ სესიის მიერ უკვე ჩატვირთულ წესებს. ის ამზადებს შემდეგ პროფილს. ხელახლა გაუშვით სერვერი მხოლოდ მაშინ, როცა ნამდვილად გსურთ, რომ მომზადებული პროფილი გააქტიურდეს.

[შეამოწმეთ პირველი ციკლი](%E1%B2%93%E1%B2%90%E1%B2%98%E1%B2%AC%E1%B2%A7%E1%B2%94%E1%B2%97_%E1%B2%90%E1%B2%A5.md)

<a id="choose-always-on-or-temporary-behavior"></a>
### აირჩიეთ მუდამ ჩართული ან დროებითი ქცევა

გამოყოფილი სერვერის პაკეტი მხარს უჭერს ორივე სტილს:

- **მუდმივი გამოყოფილი** განაახლებს შენახულ ბრუნვას ნორმალური გადატვირთვის დროს;
- **დროებითი გამოყოფილი** შეიძლება დაიწყოს კონფიგურირებული ან შემთხვევითი საწყისი წერტილიდან, როდესაც იწყება ახალი დროებითი გაშვება.

აირჩიეთ ქცევა [კონფიგურაცია](%E1%B2%99%E1%B2%9D%E1%B2%9C%E1%B2%A4%E1%B2%98%E1%B2%92%E1%B2%A3%E1%B2%A0%E1%B2%90%E1%B2%AA%E1%B2%98%E1%B2%90.md). არ დააინსტალიროთ მეორე პაკეტი ამ პარამეტრის შესაცვლელად.

<a id="update-an-existing-installation"></a>
### განაახლეთ არსებული ინსტალაცია

1. გააჩერეთ სერვერი და გააკეთეთ ზემოთ ჩამოთვლილი სარეზერვო ასლები.
2. გადაიტანეთ ძველი `RandomDay` საქაღალდე UE4SS `Mods` საქაღალდე. შეინახეთ მანამ, სანამ განახლება არ დაასრულებს ერთ წარმატებულ ციკლს.
3. ამოიღეთ ახალი გამოყოფილი სერვერი ZIP `Mods` საქაღალდე.
4. ხელახლა გამოიყენეთ მხოლოდ ის პარამეტრები, რომლებიც განზრახ შეცვალეთ და რომლებიც ჯერ კიდევ არსებობს ახალში [კონფიგურაციის სახელმძღვანელო](%E1%B2%99%E1%B2%9D%E1%B2%9C%E1%B2%A4%E1%B2%98%E1%B2%92%E1%B2%A3%E1%B2%A0%E1%B2%90%E1%B2%AA%E1%B2%98%E1%B2%90.md).
5.  შეინახეთ დოკუმენტირებული როტაციის მდგომარეობის ფაილები მხოლოდ მაშინ, როდესაც გამოშვების ჩანაწერებში ნათქვამია, რომ მათი ფორმატი თავსებადია. არ დააკოპიროთ ძველი დროებითი გამომავალი ან წარუმატებელი ფაილები ახალ ინსტალაციაში.
6. დაადასტურეთ `RandomDay : 1` ჯერ კიდევ ჩართულია, შემდეგ ერთხელ გაუშვით სერვერი და შეამოწმეთ აქტიური და მომზადებული პროფილის სახელები.

<a id="updating-from-v0315-alpha"></a>
### განახლება v0.3.15-alpha

`RandomDay_v0.3.15-alpha.zip` იყო ძველი საბაზისო პაკეტი. `RandomDay_v0.3.15-alpha_singleplayer_patch.zip` იყო გადაფარვა და არ იყო დამოუკიდებელი ჩამოტვირთვა.

მიმდინარე `v0.3.16-alpha` ცვლის ისტორიული ბაზის და გადაფარვის მოწყობას ორი სრული პაკეტით. არ მოათავსოთ ძველი პატჩი არცერთ შეფუთვაზე. მიმდინარე მარკერები არის `.randomday_mode=dedicated_server` და `.randomday_mode=singleplayer_manual`.

<a id="singleplayer-or-lan"></a>
## ერთი მოთამაშე ან LAN

singleplayer/LAN პაკეტი ქმნის პარამეტრების ფაილს; ის თავისთავად არ ეძებს და არ ცვლის პირად შენახვას.

1. დახურეთ თამაში.
2. სამყაროს და მის ამჟამინდელ სარეზერვო ასლის შექმნა `SandboxSettings.ini`.
3. ამოიღეთ singleplayer/LAN ZIP თამაშის UE4SS `Mods` საქაღალდე ასე ერთი `Mods/RandomDay/` საქაღალდე არსებობს.
4. ჩართეთ `RandomDay : 1` UE4SS `mods.txt`.
5. დაიწყეთ თამაში ერთხელ, დაელოდეთ RandomDay დასასრულებლად და სრულად დახურეთ თამაში.
6. იპოვეთ გენერირებული `SandboxSettings.ini` RandomDay's `runtime/singleplayer_manual/` საქაღალდე.
7. წაიკითხეთ გენერირებული რეზიუმე, შემდეგ დააკოპირეთ ფაილი თქვენს მიერ არჩეულ სამყაროში.
8. დააწყეთ ეს სამყარო და შეამოწმეთ, რომ მოსალოდნელი საცდელი ქცევა აქტიურია.

LAN იყენებს იგივე მექანიკურ პროცესს, რადგან მასპინძელი ფლობს ლოკალურ სამყაროს. მოდიფიკაცია არ ირჩევს სამყაროს და არ გადაწერს მას ავტომატურად.

[ერთი მოთამაშე და LAN სახელმძღვანელო](SINGLEPLAYER_LAN.md)

<a id="remove-or-disable-randomday"></a>
## წაშალეთ ან გამორთეთ RandomDay

1. შეაჩერეთ თამაში ან სერვერი.
2. შექმენით სარეზერვო ასლები მსოფლიოს, მისი ამჟამინდელი სავარჯიშო პარამეტრების და RandomDay's მდგომარეობა.
3. დაყენება `RandomDay : 0` UE4SS `mods.txt` გამორთეთ mod, ან გადაიტანოთ სრული `RandomDay` საქაღალდე `Mods` საქაღალდე წასაშლელად.
4. გადაწყვიტეთ რომელი `SandboxSettings.ini` უნდა ჩაიტვირთოს მომდევნო დაწყებაზე. აღადგინეთ თქვენი წინასწარი ინსტალაციის ასლი, თუ არ გსურთ ამჟამად მომზადებული RandomDay პროფილი.
5. დააწყეთ სამყარო და დაადასტურეთ მისი წესები ნებისმიერი სარეზერვო ასლის წაშლამდე.

გამორთვა RandomDay აჩერებს მომავალი პროფილის მომზადებას. ის არ იწერს დისკზე მოლოდინში არსებულ sandbox ფაილს.

<a id="recover-from-an-unsuccessful-update"></a>
## აღდგენა წარუმატებელი განახლებიდან

შეჩერება პირველი ავარიის შემდეგ. განმეორებით გადატვირთვამ შეიძლება გაართულოს იმის დანახვა, თუ რომელი პროფილი იყო აქტიური და რომელი ელოდა.

1. შეაჩერეთ თამაში ან სერვერი.
2. გადაიტანეთ წარუმატებელი ინსტალაცია წაშლის გარეშე.
3. აღადგინეთ სრული RandomDay საქაღალდისა და sandbox-ის სარეზერვო ასლი გაკეთდა განახლებამდე.
4. დაიწყეთ ერთხელ და დაადასტურეთ აღდგენილი აქტიური და მომზადებული პროფილის სახელები.
5. გამოიყენეთ [პრობლემების აღმოფხვრა](%E1%B2%9E%E1%B2%A0%E1%B2%9D%E1%B2%91%E1%B2%9A%E1%B2%94%E1%B2%9B%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%90%E1%B2%A6%E1%B2%9B%E1%B2%9D%E1%B2%A4%E1%B2%AE%E1%B2%95%E1%B2%A0%E1%B2%90.md) პირველი დაკარგული ან წარუმატებელი ნაბიჯისთვის სხვა განახლების ცდამდე.
