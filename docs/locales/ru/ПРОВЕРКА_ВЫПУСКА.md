# Проверка выпуска

> **Канонический английский источник:** [RELEASE_VALIDATION.md](../../RELEASE_VALIDATION.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


Эта страница предназначена для участников и сопровождающих выпусков. Игрокам, устанавливающим мод, не нужно запускать эти команды.

<a id="ordinary-user-proof"></a>
## Обычная проверка пользователя

Выпуск понятен, когда новый читатель может выбрать один из двух пакетов, установить его, идентифицировать активный профиль и подготовленный профиль и восстановить отсутствующий результат, следуя связанному руководству. Эти задачи чтения не должны требовать Git, PowerShell, Python или знание контрольной суммы.

<a id="contributor-checks"></a>
## Проверки участников

Запуск из корня репозитория:

```powershell
python -B tools/validate_repo.py
python -B -m unittest discover tests
```

Когда `luac` доступен, проверяйте синтаксис каждого отправленного файла Lua:

```powershell
Get-ChildItem RandomDay -Recurse -Filter *.lua | ForEach-Object { luac -p $_.FullName }
```

Тесты времени выполнения Lua требуют `lupa`. Отсутствие интерпретатора Lua или `lupa` является недоступной возможностью тестирования, а не пройденным результатом.

<a id="release-checks"></a>
## Проверки выпуска

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

Проверка выпуска проверяет эти условия:

- `VERSION` и `RandomDay/.randomday_version` соответствие.
- Только текущая версия существует в `releases/`.
- Выделенный и singleplayer/LAN ZIP-архивы являются полной альтернативой.
- Оба архива содержат канонический `RandomDay/Scripts/main.lua` путь и не имеют регистрозависимого загрузчика.
- Маркерами режима пакета являются `dedicated_server` и `singleplayer_manual`.
- ZIP байты детерминированы и соответствуют `CHECKSUMS.sha256`.
- Никакие данные времени выполнения, частная конфигурация, учетные данные, кэши или результаты тестирования не упаковываются.
- Все локальные ссылки на документацию и 27 страниц ввода локали проверяются.

<a id="avoid-validation-environment-pitfalls"></a>
## Избегайте ошибок среды проверки

- Запускайте проверки записи репозитория последовательно, чтобы два процесса не заменяли один и тот же временный файл одновременно.
- В Windows проверьте ZIP имена членов вместо использования поиска файлов без учета регистра, чтобы определить, существует ли загрузчик в нижнем регистре.
- Подтвердить `mods.txt` и `enabled.txt` только в тесте на установленном сервере; они не являются доказательством того, что исходные тесты были выполнены.
- Запишите время ожидания команды как неполное. Не преобразуйте его для прохождения или сбоя без ограниченного вывода команды.
- Храните временные файлы внутри репозитория, игнорируя `.tmp/`.

<a id="known-limits"></a>
## Известные ограничения

Локальная проверка подтверждает контракты на исходный код, пакет, документацию и приспособления. Он не подтверждает порядок запуска конкретной панели сервера, структуру сообщений активного клиента или путь к файловой системе, специфичный для хоста. Запишите их как отдельные результаты интеграции при их тестировании.
