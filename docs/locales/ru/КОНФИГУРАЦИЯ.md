<a id="configuration"></a>
# Конфигурация

> **Канонический английский источник:** [CONFIGURATION.md](../../CONFIGURATION.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


Основная конфигурация оператора:

```text
RandomDay/Scripts/ax_config/server.lua
```

Создавайте резервную копию файла и изменяйте по одному разделу за раз. Логические значения Lua записываются строчными буквами `true` и `false`; строки нуждаются в кавычках; записи списка должны быть запятыми. После следующего запуска прочтите страницу состояния, прежде чем вносить еще одно изменение. Участники, работающие с исходным кодом, могут использовать отдельные проверки [проверки выпуска](%D0%9F%D0%A0%D0%9E%D0%92%D0%95%D0%A0%D0%9A%D0%90_%D0%92%D0%AB%D0%9F%D0%A3%D0%A1%D0%9A%D0%90.md) перед упаковкой измененной сборки.

Не редактируйте вручную `.randomday_mode`, `.randomday_version`, созданные ссылки на профили, `runtime/` или `web_export/`. Сборщик пакетов владеет маркерами режима и версии пакета и проверяет их соответствие метаданным выпуска.

Каждый параметр, указанный ниже, определен в `RandomDay/Scripts/ax_config/server.lua`. В таблицах различаются редактируемые параметры, поля идентификации, принадлежащие выпуску, и зарезервированные поля совместимости. Наличие поля в Lua не означает, что его изменение является поддерживаемым поведением.

<a id="choose-an-experience"></a>
## Выберите вариант

RandomDay имеется два пакета: один для каждого выделенного сервера и один для singleplayer/LAN копирования вручную. Специальный пакет имеет два режима работы; эти режимы являются настройками, а не отдельными загрузками.

| Ваш мир | Установить | Выберите это поведение |
| --- | --- | --- |
| Выделенный сервер, поддерживающий перемещение одной кампании при регулярных перезапусках | Пакет выделенного сервера | `persistent_dedicated` возобновляет сохраненный порядок семейств и профилей. |
| Выделенный сервер, открытый только для отдельных игровых сеансов. | Тот же пакет выделенного сервера | `temporary_dedicated` сохраняет безопасно подготовленный следующий профиль между сеансами, в то время как новый семейный запуск может использовать настроенный или случайный запуск. |
| одиночной игры или LAN мира | Singleplayer/LAN | `auto` выбирает режим копирования вручную; остановите мир перед копированием сгенерированного файла. |

Если вы не уверены, используйте `auto`. Пакет выбирает обычное поведение для своего типа установки. Выберите общий стиль игры в [Семейной ротации](%D0%A0%D0%9E%D0%A2%D0%90%D0%A6%D0%98%D0%AF_%D0%A1%D0%95%D0%9C%D0%95%D0%99%D0%A1%D0%A2%D0%92.md). Используйте [сгенерированный индекс семейства](%D0%9F%D0%A0%D0%9E%D0%A4%D0%98%D0%9B%D0%98/%D0%94%D0%9E%D0%9A%D0%A3%D0%9C%D0%95%D0%9D%D0%A2%D0%90%D0%A6%D0%98%D0%AF_%D0%9F%D0%9E_%D0%9F%D0%A0%D0%9E%D0%A4%D0%98%D0%9B%D0%AE.md), если вам нужны точные значения игрового процесса и песочницы. Затем выберите первый день и прогресс:

- `start_day_mode="configured"` начинается с `start_day`.
- `start_day_mode="random"` выбирает один действительный первый день в начале нового семейного пробега и сохраняет этот выбор.
- `day_progression_mode="sequential"` проходит через все 17 позиций.
- `day_progression_mode="non_repeating_random"` сохраняет один перетасованный порядок, который содержит каждый день ровно один раз.

Используйте полные настройки в [Поворот](#rotation). Для новой установки по-прежнему требуется один запуск для подготовки выбранного первого профиля и последующий запуск для его активации.

<a id="release-identity-and-logging"></a>
## Освободить идентификацию и ведение журнала

| Настройка | Тип и отправленное значение | Поддерживаемое использование | Сбой или взаимодействие |
|---|---|---|---|
| `version` | Строка, прочитанная из `.randomday_version` | Только чтение. | Отсутствующий или пустой маркер становится `unversioned`; окончательная проверка пакета отклоняет изменение идентичности. |
| `package_mode` | Строка, прочитанная из `.randomday_mode` | Только чтение: `dedicated_server` или `singleplayer_manual`. | Любое другое значение останавливает запуск до записи цели. |
| `plan_basis` | Строка: `RandomDay - Seventeen Suns Rotation + Open World Scope` | Только диагностическая метка; не используйте его в качестве переключателя функций. | Текущая среда выполнения не выполняет ветвление в этом поле. |
| `logging.level` | Строка: `info` | `debug`, `info`, `warn` или `error`. | Неизвестные значения не добавляют места назначения для журналирования; держи `info`, если не проводится диагностика поведения при создании профиля. |

Пример:

```lua
logging = { level = "debug" }
```

Временно используйте `debug`, сохраните соответствующий `UE4SS.log`, затем вернитесь к `info`. Журналы могут содержать локальные пути от сбоев низкого уровня; просмотрите их перед отправкой.

<a id="experience-mode"></a>
## Режим опыта

`experience.mode`, описывающий способ работы этой установки. Это не ослабляет границу безопасности при следующем запуске: Abiotic Factor считывает настройки песочницы до UE4SS загружает RandomDay, поэтому ни один режим не может заменить правила уже запущенного процесса.

| Настройка | Поставляемое значение | Поддерживаемые значения | Эффект |
|---|---:|---|---|
| `experience.mode` | `auto` | `auto`, `persistent_dedicated`, `temporary_dedicated`, `singleplayer_lan` | `auto` разрешается из пакета. Выделенные пакеты могут использовать любой выделенный режим. Пакет ручного копирования принимает только `auto` или `singleplayer_lan`. |

- `persistent_dedicated` сохраняет один сохраненный family/day порядок при обычных долгосрочных перезапусках сервера.
- `temporary_dedicated` описывает сервер, который запускается для ограниченных игровых сеансов. Он по-прежнему сохраняет подготовленный порядок, поэтому остановка хоста не приводит к автоматическому перезапуску следующего сеанса.
- `singleplayer_lan` генерирует только ограниченный вывод для копирования вручную. Он никогда не обнаруживает и не редактирует личную папку сохранения.

Несовместимая package/experience комбинация останавливается перед записью в песочницу.

<a id="rotation"></a>
## Поворот

| Настройка | Поставляемое значение | Поддерживаемые значения | Эффект |
|---|---:|---|---|
| `cycle.application_mode` | `next_reboot_queue` | `next_reboot_queue` | Сохраняет все изменения в песочнице на границе перезапуска. |
| `cycle.cycle_length_days` | `17` | `17` для стандартного набора профилей | Соответствует каждому семейному пакету и сгенерированному номеру. |
| `cycle.start_day_mode` | `configured` | `configured`, `random` | Использует `cycle.start_day` или выбирает один допустимый день начала один раз в начале семейного пробега. |
| `cycle.start_day` | `1` | Целое число `1` до `17` | Первый день, когда `start_day_mode=configured`. |
| `cycle.day_progression_mode` | `sequential` | `sequential`, `non_repeating_random` | Создает завернутый последовательный порядок или один перетасованный порядок, содержащий каждый день ровно один раз. |
| `cycle.bootstrap_day` | `1` | Целое число `1` до `17` | Откат совместимости используется только тогда, когда `cycle.start_day` отсутствует. В новой конфигурации следует использовать `cycle.start_day`. |
| `cycle.check_interval_ms` | `0` | `0` или ограниченный положительный интервал. | `0` готовится один раз при запуске; положительное значение включает периодический контроль, когда UE4SS предоставляет `LoopAsync`. |
| `profile_family.mode` | `non_repeating_random_run` | `selected_run`, `non_repeating_random_run`, `rotation_run` | Выбирает, как начинается новый 17-дневный семейный пробег. |
| `profile_family.selected_family` | `action` | Один идентификатор в `allowed_families` | Семье, используемый `selected_run` и в качестве резерва. |
| `profile_family.default_family` | `action` | Один зарегистрированный семейный идентификатор | Резервный вариант, когда выбранный идентификатор отсутствует или недействителен. |
| `profile_family.allowed_families` | Все 17 общедоступных идентификаторов семей | Любое непустое подмножество зарегистрированных идентификаторов | Ограничивает семьи, имеющие право на новые запуски. |
| `profile_family.preserve_family_until_day_17` | Логическое значение: `true` | Зарезервированное поле совместимости; Keep `true`. | Текущий календарь всегда сохраняет семейство в каждой позиции в сохраненном 17-дневном порядке и не считывает это поле как переключатель. |
| `profile_family.reroll_only_after_day_17` | Логическое значение: `true` | Зарезервированное поле совместимости; Keep `true`. | Текущий календарь меняет семейство только после завершения идентификатора каждого дня, независимо от того, какой день является последним в сохраненном порядке. |
| `profile_family.prevent_repeats_until_rotation_complete` | Логическое значение: `true` | Зарезервированное поле совместимости; Keep `true`. | Текущая неповторяющаяся логика пула фиксирована и не считывает это значение как переключатель. |

Распорядок дня создается один раз для нового семейного пробега и записывается в `runtime/rotation_state.txt`. Восстановление и последующие перезапуски повторно используют именно эти позиции. Изменение конфигурации не меняет выполняющийся заказ. Семья меняется только после того, как будут заполнены все 17 позиций.

<a id="recommended-presets"></a>
### Рекомендуемые настройки

Постоянный выделенный сервер:

```lua
experience = { mode = "persistent_dedicated" }
cycle = {
    application_mode = "next_reboot_queue",
    cycle_length_days = 17,
    start_day_mode = "configured",
    start_day = 1,
    day_progression_mode = "sequential",
    bootstrap_day = 1,
    check_interval_ms = 0,
}
```

Временные выделенные сеансы с другим неповторяющимся порядком для каждого нового семейства:

```lua
experience = { mode = "temporary_dedicated" }
cycle.start_day_mode = "random"
cycle.day_progression_mode = "non_repeating_random"
```

Singleplayer/LAN при копировании вручную используется пакет однопользовательской игры и обычно удаляется `experience.mode="auto"`. Вы можете выбрать те же элементы управления началом и прогрессом перед созданием следующего файла. Скопируйте сгенерированный файл в выбранный остановленный мир перед запуском следующего поколения, если вы хотите, чтобы состояние времени выполнения и загруженный профиль мира оставались согласованными.

При новой установке первый процесс может подготовить только выбранный день запуска. Более поздний процесс активирует его. Случайный или настроенный запуск не обходит этот порядок загрузки механизма.

Пример фиксированного запуска Builder:

```lua
profile_family = {
    mode = "selected_run",
    selected_family = "builder",
    default_family = "action",
    allowed_families = { "builder" },
    preserve_family_until_day_17 = true,
    reroll_only_after_day_17 = true,
    prevent_repeats_until_rotation_complete = true,
}
```

Пустой или неизвестный подходящий набор возвращается в зарегистрированное семейство вместо создания неполного профиля.

<a id="primary-sandbox-path"></a>
## Основной путь к песочнице

| Настройка | Тип и отправленное значение | Поддерживаемое использование | Сбой или взаимодействие |
|---|---|---|---|
| `paths.runtime_dir` | Строка: `ue4ss/Mods/RandomDay/runtime` | Только чтение в исходной конфигурации. | `init.lua` заменяет его разрешенным корневым модом `runtime/` путем. |
| `paths.web_export_dir` | Строка: `ue4ss/Mods/RandomDay/web_export` | Только чтение в исходной конфигурации. | `init.lua` заменяет его разрешенным корневым модом `web_export/` путем. |
| `paths.sandbox_path_override` | Строка или `nil`: `nil` | Один литеральный `SandboxSettings.ini` путь для нестандартного выделенного макета. | Небезопасные или недоступные цели не позволяют выполнить запись; в однопользовательском режиме переопределение отменяется. |
| `paths.sandbox_candidates` | Список строк: семь общих кандидатов | Упорядоченные резервные кандидаты для выделенных серверов. | `init.lua` добавляет кандидаты, полученные из установки; побеждает первый существующий путь. |
| `paths.write_sandbox_mirrors` | Логическое значение: `true` | Разрешает намеренно настроенные зеркала. | Зеркало не записывается, пока список зеркал пуст и `world_name=nil`; режим одиночной игры `false`. |
| `paths.sandbox_mirror_required` | Логическое значение: `false` | Зарезервированное поле совместимости; Keep `false`. | Текущий модуль записи рассматривает зеркала как необязательные и не читает это поле как обязательный шлюз. |
| `paths.world_name` | Строка или `nil`: `nil` | Один безопасный компонент мировой папки, используемый для получения общих кандидатов на зеркало. | Все, что находится за пределами букв, цифр и пробелов, `_` или `-` останавливает запуск; в однопользовательском режиме это игнорируется. |
| `paths.sandbox_mirror_candidates` | Список строк: пусто | Точные необязательные файлы зеркала. | Каждое подходящее зеркало использует свою собственную транзакцию; сбой зеркала не влияет на основной успех. |

`paths.sandbox_path_override` по умолчанию имеет значение `nil`. Без переопределения RandomDay сначала проверяет общие WindowsServer кандидаты, привязанные к обнаруженной RandomDay установке, а затем проверяет всех настроенных кандидатов. Если таковой не существует, используется первый универсальный кандидат, привязанный к установке, который соответствует установке сервера:

```text
AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini
```

Этот резервный вариант не разрешается из текущего рабочего каталога процесса. Устанавливайте `sandbox_path_override` только в том случае, если ваша установка использует другой литеральный файл. Укажите его на один `SandboxSettings.ini`, а не на каталог. Перед использованием остановите сервер и убедитесь, что файл находится внутри предполагаемой установки.

<a id="optional-mirrors"></a>
### Дополнительные зеркала

`paths.write_sandbox_mirrors` поставляются как `true`, но список путей к зеркалу пуст, а `paths.world_name` — `nil`. Поэтому поставляемые по умолчанию настройки не содержат дополнительного зеркала. Установите значение `false`, если установка всегда должна записывать только разрешенную основную цель. Без настроенного кандидата на зеркало или мирового имени любое значение по-прежнему записывает только основной файл песочницы.

Зеркало становится подходящим только тогда, когда вы намеренно добавляете точную запись в `paths.sandbox_mirror_candidates` или устанавливаете `paths.world_name`. Зеркала — это лучшие копии для установок, которые считывают второй путь песочницы для конкретного мира. Они не заменяют настройку правильного основного пути.

Перед включением зеркала:

1. остановите сервер;
2. определите точный файл, который читает сервер;
3. убедитесь, что целевой объект находится внутри предполагаемой установки;
4. сохраните его резервную копию;
5. добавьте только этот путь;
6. проверьте результат зеркалирования после подготовки.

Пример переопределения без зеркала:

```lua
paths = {
    runtime_dir = "ue4ss/Mods/RandomDay/runtime",
    web_export_dir = "ue4ss/Mods/RandomDay/web_export",
    sandbox_path_override = "<server-root>/AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini",
    sandbox_candidates = {},
    write_sandbox_mirrors = false,
    sandbox_mirror_required = false,
    world_name = nil,
    sandbox_mirror_candidates = {},
}
```

`<server-root>` — это заполнитель. Замените его локально; не публикуйте путь, специфичный для компьютера.

<a id="non-disableable-safety-locks"></a>
## Неотключаемые блокировки безопасности

| Настройка | Требуемое значение | Значение |
|---|---:|---|
| `sandbox.backup_before_write` | `true` | Сохранять проверенную копию перед заменой существующего основного файла. |
| `sandbox.restore_last_good_on_failure` | `true` | Попытка автоматического восстановления после неудачной замены или повторного чтения. |
| `external_mods.patch_only_existing_keys` | `true` | Отказаться от создания неизвестного параметра в файле другого мода. |
| `external_mods.backup_before_write` | `true` | Сохранять целевые байты перед редактированием поддерживаемого транзакционного адаптера. |

RandomDay отказывает в запуске, если какое-либо из этих четырех значений не соответствует `true`. Это предохранительные замки, а не поддерживаемые переключатели оператора. Не отключайте их, в том числе при разработке или устранении неполадок, поскольку это изменяет границу отказоустойчивости, которую подтверждают тесты средства записи и адаптера.

`sandbox.force_rewrite_every_supervision_tick` остается обычной настройкой и поставляется как `false`, что оставляет уже соответствующий файл песочницы нетронутым. Он принимает логическое значение. Установка значения `true` заставляет те же подготовленные байты, принадлежащие процессу, снова пройти через средство записи; он не продвигает family/day. Используйте его только для ограниченного теста восстановления, поскольку повторные записи создают больше резервных копий операций.

## Дополнительные адаптеры модов

| Настройка | Поставляемое значение | Значение |
|---|---:|---|
| `external_mods.enabled` | `true` | Разрешить настроенным адаптерам проверять отдельно установленные цели. |
| `external_mods.optional_by_default` | `true` | Отсутствующие или несовместимые дополнительные моды не блокируют RandomDay. |
| `external_mods.patch_only_existing_keys` | `true` | Требуется блокировка безопасности; при изменении произойдет сбой. |
| `external_mods.backup_before_write` | `true` | Требуется блокировка безопасности; при изменении произойдет сбой. |
| `external_mods.adapters` | Четыре общедоступных идентификатора адаптера | Ограничения, которые могут RandomDay-owned могут работать адаптеры. |

Удалите идентификатор адаптера из списка, чтобы оставить эту интеграцию без отключения или удаления стороннего мода. singleplayer/LAN отключает каждый адаптер независимо от этого списка.

`external_mods.optional_by_default=false` приводит к тому, что настроенный результат адаптера, отличный от `applied` или `already_current`, не соответствует агрегированному результату адаптера. Это не приводит к откату основной транзакции песочницы. Сохраняйте отправленный `true`, если у оператора нет проверенной причины требовать интеграции.

См. [Поддерживаемые адаптеры мод](%D0%9F%D0%9E%D0%94%D0%94%D0%95%D0%A0%D0%96%D0%98%D0%92%D0%90%D0%95%D0%9C%D0%AB%D0%95_%D0%90%D0%94%D0%90%D0%9F%D0%A2%D0%95%D0%A0%D0%AB.md) для распознаваемых макетов и шести возможных результатов.

<a id="optional-chaotic-spawn-engine-scope-fields"></a>
### Необязательные поля области действия Chaotic Spawn Engine

`world_scope` предоставляет пять дополнительных RandomDay настроек расширения только в том случае, если распознанный механизм Chaotic Spawn Engine `DynamicSpawns/SharedData.lua` уже содержит эти поля. Это не отдельный мод или загрузка:

| Настройка | Поставляемое значение | Эффект адаптера |
|---|---:|---|
| `world_scope.enabled` | `true` | запрашивает необязательные RandomDay ворота мировой области внутри распознанного DynamicSpawns. |
| `world_scope.affect_open_worlds` | `true` | Включает открытые миры, если целевой мод не применяет правило защищенного мира. |
| `world_scope.unknown_world_policy` | `allow` | Запросы `allow` или `block` когда целевой мод не может классифицировать мир. |
| `world_scope.log_scope_decisions` | `true` | Запрашивает регистрацию целевого мода для принятия решения об области действия. |
| `world_scope.protected_worlds` | Пустой список | Поставляет разделенные запятыми шаблоны защищенного мира в целевой макет. |

Эти значения являются входными данными адаптера, а не мировым фильтром, реализованным модулем записи песочницы RandomDay's писатель песочницы. Они вступают в силу только в том случае, если отдельно установленный макет Chaotic Spawn Engine уже содержит полную необязательную RandomDay полей и отчетов `applied` или `already_current`. Chaotic Spawn Engine продолжает отвечать за использование этих полей во время выполнения. Обычная установка без полей расширения остается без изменений.

Все пять значений являются входными данными адаптера. `unknown_world_policy` принимает только документированные целевые значения `allow` или `block`; нераспознанный целевой макет пропускается. В примерах документации оставляйте `protected_worlds` пустым. Если оператор использует локальные шаблоны, их нельзя включать в скриншоты, задачи или артефакты выпуска.

<a id="player-messages"></a>
## Сообщения игрока

Поставляемая конфигурация выделенного сервера обеспечивает компактные уведомления о присоединении и короткую ежедневную очередь. Он ожидает 30 секунд перед первым проходом, проверяет наличие вновь присоединившихся игроков каждые 15 секунд и ожидает 10 секунд после уведомления о присоединении перед ежедневной строкой.

| Настройка | Поставляемое значение |
|---|---:|
| `player_message.enabled` | `true` |
| `player_message.log_on_startup` | `true` |
| `player_message.register_console_command` | `false` |
| `player_message.console_command` | `randomday` |
| `player_message.broadcast_enabled` | `true` |
| `player_message.startup_delay_ms` | `30000` |
| `player_message.join_check_interval_ms` | `15000` |
| `player_message.send_daily_joke_after_join` | `true` |
| `player_message.daily_joke_delay_seconds` | `10` |
| `player_message.criticality_join` | `2` |
| `player_message.criticality_joke` | `0` |
| `player_message.max_line_chars` | `42` |
| `player_message.max_join_lines` | `4` |
| `player_message.max_warning_lines` | `3` |
| `player_message.max_note_lines` | `3` |

Проверка длины сообщения проверяет ограничения источника. Он не заменяет визуальный тест для каждого разрешения клиента.

Значения времени представляют собой неотрицательные числа, интерпретируемые как миллисекунды, за исключением `daily_joke_delay_seconds`. Отключенное сообщение или настройка широковещательной рассылки подавляют уведомления клиента без изменения подготовки песочницы. Консольная команда регистрируется только тогда, когда доступны и настройка, и обработчик UE4SS. Сохраняйте значения критичности на уровне отправленного транспорта, если тест именованного клиента не подтвердит другое значение.

`max_line_chars` переводчик ограничивает длину от 8 до 64 символов. Три настройки количества строк ограничивают вывод соединения, предупреждения и примечания соответственно; отправленные значения соответствуют количеству доступных исходных строк. Сохраняйте для этих четырех ограничений значения по умолчанию, если тест макета клиента не подтвердит более узкие настройки.

Пример с отключенными сообщениями:

```lua
player_message = {
    enabled = false,
    log_on_startup = true,
    register_console_command = false,
    console_command = "randomday",
    broadcast_enabled = false,
    startup_delay_ms = 30000,
    join_check_interval_ms = 15000,
    send_daily_joke_after_join = false,
    daily_joke_delay_seconds = 10,
    criticality_join = 2,
    criticality_joke = 0,
    max_line_chars = 42,
    max_join_lines = 4,
    max_warning_lines = 3,
    max_note_lines = 3,
}
```

<a id="profiles-and-sandbox-values"></a>
## Профили и значения песочницы

Исходные файлы семейства в разделе `RandomDay/Scripts/ax_profiles/families/` определяют 17 полных дней на семью. Созданная документация в разделе `docs/profiles/` является справочным результатом, а не источником настройки.

Временно используйте [ссылку на ключи песочницы](%D0%9F%D0%A0%D0%9E%D0%A4%D0%98%D0%9B%D0%98/%D0%9A%D0%9B%D0%AE%D0%A7%D0%98_%D0%9D%D0%90%D0%A1%D0%A2%D0%A0%D0%9E%D0%95%D0%9A_%D0%9F%D0%95%D0%A1%D0%9E%D0%A7%D0%9D%D0%98%D0%A6%D0%AB.md) для типов, диапазонов, поставляемых значений профиля по умолчанию и остальных инвариантных значений. После редактирования источника профиля заново сгенерируйте и проверьте все 289 комбинаций; не исправляйте ни один сгенерированный Markdown или JSON.

<a id="customize-the-shipped-profile-defaults"></a>
### Настройте поставляемые параметры профиля по умолчанию

Открыть:

```text
RandomDay/Scripts/ax_config/server.lua
```

Найдите этот блок в разделе `sandbox`:

```lua
profile_overrides = {
    HardcoreMode = false,
    AllowIronMode = false,
    StructuralSupportLimit = 0,
    BridgeSupports = 0,
}
```

Это начальный выбор RandomDay's стартовый выбор, а не неизменяемые правила абиотического фактора. Установите любой режим: `true` или `false`. Установите для каждого значения поддержки целое число из `0` до `1000`. Остановите игру или выделенный сервер перед редактированием файла, сохраните его, а затем запустите снова, чтобы Lua загрузил новую конфигурацию.

RandomDay, этот блок будет считываться всякий раз, когда он создает 17 профилей в семействе. Таким образом, выбранные значения применяются к каждой семье и дню, включая профили, подготовленные после ротации, и профили, перестроенные после более позднего запуска сервера. Вам не нужно редактировать 289 файлов профиля или повторно создавать ссылку на профиль.

Изменение только действующего `SandboxSettings.ini` является временным, поскольку следующий подготовленный профиль создается из `server.lua`. Неверные типы, неизвестные ключи или поддерживаемые значения за пределами `0..1000` останавливают создание профиля с именованной ошибкой конфигурации вместо автоматического возврата к значениям по умолчанию.

Сгенерированная ссылка на профиль продолжает отображать отправленные значения по умолчанию. Это ссылка на выпуск, а не копия частной конфигурации одного сервера.
