# रनटाइम स्थिति और आउटपुट स्कीमा की व्याख्या करें

> **कैनोनिकल अंग्रेजी स्रोत:** [RUNTIME_OUTPUTS.md](../../RUNTIME_OUTPUTS.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


यह विहित फ़ील्ड-पूर्ण स्कीमा मार्गदर्शिका है। यह उत्तर देता है कि प्रत्येक फ़ील्ड, स्थिति, खाली मान और मशीन परिणाम का क्या अर्थ है। [रनटाइम फ़ाइल मैप](%E0%A4%B0%E0%A4%A8%E0%A4%9F%E0%A4%BE%E0%A4%87%E0%A4%AE_%E0%A4%AB%E0%A4%BC%E0%A4%BE%E0%A4%87%E0%A4%B2%E0%A5%87%E0%A4%82.md) उत्पादकों, पथों, लिखने का समय, अवधारण, लेन-देन साइडकार और पुनर्प्राप्ति स्थानों के लिए।

इस गाइड के सभी पथ स्थापित `RandomDay/` फ़ोल्डर जब तक कि कोई पंक्ति स्पष्ट रूप से कॉन्फ़िगर किए गए सैंडबॉक्स या वैकल्पिक एडाप्टर लक्ष्य का नाम न दे। रनटाइम आउटपुट इंस्टॉलेशन के बाद उत्पन्न होते हैं और किसी भी रिलीज़ के सदस्य नहीं होते हैं ZIP.

<a id="rotation-state-schema"></a>
## रोटेशन स्थिति स्कीमा

`runtime/rotation_state.txt` स्कीमा का उपयोग करता है `1` और इसमें एक `key=value` जोड़ी प्रति पंक्ति:

| फ़ील्ड | मतलब |
|---|---|
| `schema_version` | होना चाहिए `1`. |
| `mod_version` | पैकेज पहचान `.randomday_version`. |
| `rotation_id` | पात्र परिवार सेट के माध्यम से वर्तमान पास के लिए पहचानकर्ता। |
| `mode` | `selected_run`, `non_repeating_random_run`, या `rotation_run`. |
| `available_families` | कॉन्फ़िगरेशन फ़िल्टरिंग के बाद अल्पविराम से अलग किए गए पात्र परिवार आईडी। |
| `remaining_families` | वर्तमान नॉन-रिपीटिंग पास में पात्र परिवारों का अभी तक चयन नहीं किया गया है। |
| `completed_families` | वे परिवार जिनका पूरा 17-पोजीशन ऑर्डर वर्तमान पास में पूरा हो चुका है। |
| `active_family`, `active_day` | चयन किए जाने पर सक्रिय मार्कर जानकारी रिकॉर्ड की गई। सैंडबॉक्स मार्कर अगले बूट पर आधिकारिक है। |
| `prepared_family`, `prepared_day` | प्रोफ़ाइल को अगले पुनरारंभ के लिए रखा गया है। |
| `active_run_id` | तैयार चयन से संबद्ध परिवार-संचालित पहचानकर्ता। |
| `last_status` | कैलेंडर चयन स्थिति जिसने इस फ़ाइल को तैयार किया। |
| `session_mode` | निरंतर समर्पित, अस्थायी समर्पित, या singleplayer/LAN जीवनचक्र। |
| `start_day_mode` | नए रन के लिए कॉन्फ़िगर या एक बार यादृच्छिक प्रारंभ विकल्प। |
| `day_progression_mode` | लिपटे अनुक्रमिक या गैर-दोहराई-यादृच्छिक प्रगति। |
| `day_order` | अल्पविराम से अलग किए गए निरंतर दिन आईडी ठीक उसी क्रम में जिस क्रम में वे तैयार किए जाएंगे। |
| `day_position` | `day_order`. |
| `updated_at` | ऑपरेटर तुलना के लिए स्थानीय लेखन समय। |

स्टेट राइट तभी स्वीकार किया जाता है जब स्कीमा मार्कर, तैयार परिवार और तैयार दिन सही ढंग से पढ़ा जाता है। एक अपठनीय वर्तमान फ़ाइल `rotation_state.last_good.txt`; चयनित सैंडबॉक्स मार्कर अभी भी यह निर्धारित करता है कि गेम ने वर्तमान प्रक्रिया के लिए क्या लोड किया है।

<a id="runtime-status-json"></a>
## रनटाइम स्थिति JSON

`runtime/current/randomday_status.json` `status_schema=randomday_runtime_status_v2`. इसके मुख्य क्षेत्र समूह हैं:

| समूह | फ़ील्ड और व्याख्या |
|---|---|
| पहचान | `mod`, `version`, `package_mode`, `mode`, `session_mode`, `profile_system`, `status_schema`, `dictionary_version` |
| चयन | `reason`, `selection_status`, `active_profile_detection`, `rotation_id`, `run_id`, `cycle_length_days` |
| सक्रिय | `active_cycle_day`, `active_profile_id`, `active_display_name`, `active_family`, `active_family_label`, `active_profile_translation` |
| तैयार | `prepared_next_cycle_day`, `prepared_next_profile_id`, `prepared_next_display_name`, `prepared_next_family`, `prepared_next_family_label`, `prepared_profile_translation` |
| मानव सारांश | `profile_intensity`, `player_summary`, `prepared_profile_intensity`, `prepared_player_summary`, `admin_summary`, `message_preview` |
| प्रमाण लिखें | `write_status`, `backup_status`, `last_known_good_status`, `sandbox_transaction_status`, `sandbox_rollback_status`, `prepared_ready`, `state_commit_ok`, `state_commit_error_code` |
| एडेप्टर प्रमाण | `adapter_status`, `adapter_results`; प्रत्येक एडॉप्टर रिकॉर्ड में संगतता प्रमाण होता है, transaction/rollback स्थिति, परिवर्तित-फ़ाइल गणना, और संशोधित लक्ष्य संदर्भ |
| सीमाएँ | `restart_required_for_prepared_profile`, `sandbox_target`, `manual_copy_required`, `mirrors_written`, `world_scope`, `dictionary_path` |
| डायग्नोस्टिक्स | `hash`, `replacement_method`, `pending_readback_verified`, `target_readback_verified`, `updated_at` |

अज्ञात सक्रिय मानों का मतलब है कि वर्तमान सैंडबॉक्स में पढ़ने योग्य सामग्री नहीं है RandomDay मार्कर। उन्हें तैयार मूल्यों से प्रतिस्थापित नहीं किया जाना चाहिए। एडाप्टर पथ बाहर `runtime/` को बेसनेम संदर्भ में घटा दिया गया है, और डायग्नोस्टिक स्ट्रिंग्स ने निरपेक्ष पथों का पता लगाया है।

<a id="public-status-json"></a>
## सार्वजनिक स्थिति JSON

`web_export/today.json` `schema_version=2` और `status_schema=randomday_public_status_v2`. यह पहचान को दोहराता है, active/prepared, चयन, लेन-देन, एडॉप्टर, और पुनरारंभ-सीमा तथ्य एक ऑपरेटर के लिए आवश्यक हैं। इसमें यह भी शामिल है:

- `session_mode`, `start_day_mode`, `configured_start_day`, `day_progression_mode`, `day_order`, और `prepared_day_position`;
- `family_selection_mode`, विरासत `family_locked_until_day_17`, और `family_locked_until_cycle_complete`;
- `remaining_families`, `completed_families`, और उनकी गिनती;
- तैयार मुठभेड़ प्रोफ़ाइल, स्तर, थीम और मिश्रित-मुठभेड़ का मौका;
- विश्व-स्कोप सक्षमता, खुली-विश्व सेटिंग, अज्ञात-विश्व नीति, और केवल कॉन्फ़िगर किए गए बहिष्कृत-विश्व पैटर्न की गिनती;
- तैयार संदेश और संयुक्त संदेश पूर्वावलोकन;
- `selected_at`, `sandbox_target`, `manual_copy_required`, और तैयार हैश।

`profile_status` `prepared_for_next_reboot`, `next_reboot_already_prepared`, `degraded_state_persistence`, या `write_failed_or_rollback`. `prepared_ready=true` का अभी भी मतलब सक्रिय नहीं है; बाद वाला स्टार्टअप मार्कर आवश्यक है.

<a id="dictionary-and-translation-output"></a>
## शब्दकोश और अनुवाद आउटपुट

`runtime/current/randomday_dictionary.json` `schema=randomday_runtime_dictionary_v2` और शब्दकोश संस्करण की पहचान करता है `randomday_dictionary_v2`. यह पैकेज मोड, चयन स्थिति, दबाव डोमेन, सेटिंग लेबल, कच्चे मान और सादे-भाषा अर्थ का वर्णन करता है। अज्ञात मान विश्वसनीय विवरण में परिवर्तित होने के बजाय स्पष्ट रहते हैं।

`player_message_preview.txt`, `today.json`, `today.html`, और इन-गेम नोटिस एक ही अनुवाद मॉड्यूल से प्राप्त दृश्य हैं। अंतर्निहित प्रोफ़ाइल और कच्चा `SandboxSettings.ini` मान सत्य का स्रोत बने रहते हैं।

<a id="failure-and-recovery-rules"></a>
## विफलता और पुनर्प्राप्ति नियम

1. एक असफल लंबित लेखन या सत्यापन कभी भी उत्पादन लक्ष्य नहीं बनता है।
2. एक असफल प्रचार या उत्पादन रीडबैक रोके गए मूल को पुनर्स्थापित करने का कारण बनता है; जब वह पुनर्स्थापना विफल हो जाती है तो ऑपरेशन बैकअप फ़ॉलबैक होता है।
3. एक बरकरार रखी गई रोलबैक फ़ाइल या `rollback_failed` गेम या सर्वर बंद होने पर स्थिति की मैन्युअल समीक्षा की आवश्यकता होती है।
4. एक सफल सैंडबॉक्स राइट प्लस विफल रोटेशन-स्टेट कमिट ख़राब है, तैयार नहीं है; एडाप्टर और तैयार-प्रोफ़ाइल संदेश को छोड़ दिया गया है।
5. निर्यात विफलता सैंडबॉक्स परिणाम को नहीं बदलती है, लेकिन यह एक सुविधा प्रमाण स्रोत को हटा देती है। लेन-देन लॉग, स्थिति और फ़ाइल रीडबैक का उपयोग करें।
6. रनटाइम आउटपुट स्थानीय परिचालन डेटा हैं। उन्हें किसी रिलीज़ में न जोड़ें ZIP या अलग गोपनीयता समीक्षा के बिना उन्हें उदाहरण के रूप में प्रकाशित करें।
