# सत्यापन जारी करें

> **कैनोनिकल अंग्रेजी स्रोत:** [RELEASE_VALIDATION.md](../../RELEASE_VALIDATION.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


यह पृष्ठ योगदानकर्ताओं और रिलीज़ अनुरक्षकों के लिए है। मॉड इंस्टॉल करने वाले खिलाड़ियों को इन कमांड को चलाने की आवश्यकता नहीं है।

<a id="ordinary-user-proof"></a>
## साधारण उपयोगकर्ता प्रमाण

एक रिलीज़ तब समझ में आती है जब एक नया पाठक दो पैकेजों में से एक को चुन सकता है, इसे इंस्टॉल कर सकता है, सक्रिय प्रोफ़ाइल और तैयार प्रोफ़ाइल की पहचान कर सकता है, और लिंक किए गए गाइड का पालन करके लापता परिणाम से पुनर्प्राप्त कर सकता है। उन पाठक कार्यों के लिए Git की आवश्यकता नहीं होनी चाहिए, PowerShell, पायथन, या चेकसम ज्ञान।

<a id="contributor-checks"></a>
## योगदानकर्ता जाँच

रिपॉजिटरी रूट से चलाएँ:

```powershell
python -B tools/validate_repo.py
python -B -m unittest discover tests
```

कब `luac` उपलब्ध है, प्रत्येक भेजी गई Lua फ़ाइल का सिंटैक्स-जाँच करें:

```powershell
Get-ChildItem RandomDay -Recurse -Filter *.lua | ForEach-Object { luac -p $_.FullName }
```

Lua रनटाइम परीक्षणों के लिए `lupa`. एक लापता लुआ दुभाषिया या `lupa` इंस्टॉलेशन एक अनुपलब्ध परीक्षण क्षमता है, उत्तीर्ण परिणाम नहीं।

<a id="release-checks"></a>
## रिलीज़ चेक

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

रिलीज़ चेक इन शर्तों की पुष्टि करता है:

- `VERSION` और `RandomDay/.randomday_version` मिलान।
- केवल वर्तमान संस्करण `releases/`.
- समर्पित और singleplayer/LAN ज़िप पूर्ण विकल्प हैं।
- दोनों अभिलेखों में विहित `RandomDay/Scripts/main.lua` पथ और कोई केस-कोलाइडिंग लोडर नहीं।
- पैकेज मोड मार्कर `dedicated_server` और `singleplayer_manual`.
- ZIP बाइट्स नियतात्मक हैं और `CHECKSUMS.sha256`.
- कोई रनटाइम डेटा, निजी कॉन्फ़िगरेशन, क्रेडेंशियल, कैश या परीक्षण आउटपुट पैक नहीं किया गया है।
- सभी स्थानीय दस्तावेज़ लिंक और 27 स्थानीय प्रविष्टि पृष्ठ मान्य हैं।

<a id="avoid-validation-environment-pitfalls"></a>
## सत्यापन पर्यावरण संबंधी कठिनाइयों से बचें

- रिपॉजिटरी-राइटिंग चेक को क्रमिक रूप से चलाएँ ताकि दो प्रक्रियाएँ एक ही अस्थायी फ़ाइल को एक साथ प्रतिस्थापित न करें।
- Windows पर, ZIP लोअरकेस लोडर मौजूद है या नहीं यह तय करने के लिए केस-असंवेदनशील फ़ाइल लुकअप का उपयोग करने के बजाय सदस्य नाम।
- पुष्टि करें `mods.txt` और `enabled.txt` केवल इंस्टॉल-सर्वर परीक्षण में; वे इस बात का प्रमाण नहीं हैं कि स्रोत परीक्षण चलाए गए।
- कमांड टाइमआउट को अपूर्ण के रूप में रिकॉर्ड करें। कमांड के बाउंडेड आउटपुट के बिना इसे पास या फेल में न बदलें।
- अस्थायी फ़ाइलों को रिपॉजिटरी के अंदर अनदेखा रखें `.tmp/` निर्देशिका।

<a id="known-limits"></a>
## ज्ञात सीमाएँ

स्थानीय सत्यापन स्रोत, पैकेज, दस्तावेज़ीकरण और फिक्सचर अनुबंधों को साबित करता है। यह किसी विशेष सर्वर पैनल के स्टार्टअप ऑर्डर, लाइव क्लाइंट के संदेश लेआउट या होस्ट-विशिष्ट फ़ाइल सिस्टम पथ को साबित नहीं करता है। जब उनका परीक्षण किया जाए तो उन्हें अलग-अलग एकीकरण परिणामों के रूप में रिकॉर्ड करें।
