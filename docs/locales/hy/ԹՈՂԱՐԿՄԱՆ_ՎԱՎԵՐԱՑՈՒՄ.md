# Թողարկման վավերացում

> **Կանոնական անգլերեն աղբյուր:** [RELEASE_VALIDATION.md](../../RELEASE_VALIDATION.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


Այս էջը ներդրողների և թողարկումների սպասարկողների համար է: Mod-ը տեղադրող խաղացողները կարիք չունեն գործարկել այս հրամանները:

<a id="ordinary-user-proof"></a>
## Սովորական օգտատիրոջ ապացույց

Թողարկումը հասկանալի է, երբ նոր ընթերցողը կարող է ընտրել երկու փաթեթներից մեկը, տեղադրել այն, բաց թողնել պատրաստած պրոֆիլը և վերականգնել ակտիվ պրոֆիլը հետևյալ հղումով: Ընթերցողի այդ առաջադրանքները չպետք է պահանջեն Git, PowerShell, Python կամ ստուգիչ գումարի իմացություն:

<a id="contributor-checks"></a>
## Աջակցողի ստուգումներ

Գործարկեք պահեստի արմատից.

```powershell
python -B tools/validate_repo.py
python -B -m unittest discover tests
```

Երբ `luac` հասանելի է, շարահյուսական ստուգեք յուրաքանչյուր առաքված Lua ֆայլ.

```powershell
Get-ChildItem RandomDay -Recurse -Filter *.lua | ForEach-Object { luac -p $_.FullName }
```

Lua-ի գործարկման ժամանակի թեստերը պահանջում են `lupa`: Բացակայում է Լուա թարգմանիչը կամ `lupa` տեղադրումը անհասանելի փորձարկման հնարավորություն է, ոչ թե անցողիկ արդյունք:

<a id="release-checks"></a>
## Թողարկեք չեկերը

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

Թողարկման ստուգումը հաստատում է հետևյալ պայմանները.

- `VERSION` և `RandomDay/.randomday_version` համընկնում:
- `releases/`.
- Նվիրված և singleplayer/LAN ZIP-ները ամբողջական այլընտրանք են:
- Երկու արխիվներն էլ պարունակում են կանոնական `RandomDay/Scripts/main.lua` ճանապարհ և առանց դեպքերի բախվող բեռնիչ:
- Փաթեթի ռեժիմի նշիչներն են `dedicated_server` և `singleplayer_manual`.
- ZIP բայթերը որոշիչ են և համընկնում են `CHECKSUMS.sha256`.
- Աշխատաժամանակի տվյալներ, անձնական կազմաձևեր, հավատարմագրեր, քեշեր կամ փորձնական ելք փաթեթավորված չեն:
- Տեղական փաստաթղթերի բոլոր հղումները և 27 տեղային մուտքի էջերը վավերացվում են:

<a id="avoid-validation-environment-pitfalls"></a>
## Խուսափեք վավերացման միջավայրի որոգայթներից

- Հերթականորեն կատարեք պահեստի գրման ստուգումները, որպեսզի երկու գործընթացները միանգամից չփոխարինեն նույն ժամանակավոր ֆայլը:
- Windows-ում ստուգեք ZIP անդամների անունները, այլ ոչ թե մեծատառերով բեռնվող ֆայլի որոնում օգտագործելու փոխարեն, որոշելու համար, թե արդյոք գոյություն ունի փոքրատառ բեռնիչ:
- Հաստատեք `mods.txt` և `enabled.txt` միայն տեղադրված սերվերի թեստում; դրանք ապացույց չեն, որ սկզբնաղբյուրի թեստերն անցել են:
- Գրանցեք հրամանի ժամկետի ավարտը որպես թերի: Մի փոխարկեք այն անցնելու կամ ձախողման առանց հրամանի սահմանափակ ելքի:
- Անտեսված պահեք պահոցի ներսում գտնվող ժամանակավոր ֆայլերը `.tmp/` գրացուցակ:

<a id="known-limits"></a>
## Հայտնի սահմաններ

Տեղական վավերացումը ապացուցում է աղբյուրի, փաթեթի, փաստաթղթերի և հարմարանքների պայմանագրերը: Այն չի ապացուցում որոշակի սերվերի վահանակի գործարկման կարգը, կենդանի հաճախորդի հաղորդագրությունների դասավորությունը կամ հոսթին հատուկ ֆայլային համակարգի ուղին: Գրանցեք դրանք որպես առանձին ինտեգրման արդյունքներ, երբ դրանք փորձարկվեն:
