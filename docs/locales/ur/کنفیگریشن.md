# کنفیگریشن

> **کیننیکل انگریزی ماخذ:** [CONFIGURATION.md](../../CONFIGURATION.md). یہ مقامی دستاویزات درست کمانڈز، پاتھز، کیز، اسٹیٹس ویلیوز، ہیشز اور فائل کے ناموں کو محفوظ رکھتی ہیں۔ اگر تکنیکی الفاظ میں فرق ہے تو انگریزی ماخذ استعمال کریں۔


مین آپریٹر کنفیگریشن ہے:

```text
RandomDay/Scripts/ax_config/server.lua
```

فائل کا بیک اپ لیں اور ایک وقت میں ایک سیکشن تبدیل کریں۔ Lua بولین چھوٹے ہیں `true` اور `false`؛ تاروں کو اقتباسات کی ضرورت ہے۔ فہرست اندراجات کو کوما کی ضرورت ہے۔ اگلی شروعات کے بعد، دوسری تبدیلی کرنے سے پہلے اسٹیٹس کا صفحہ پڑھیں۔ ماخذ سے کام کرنے والے شراکت دار علیحدہ [ریلیز کی توثیق](%D8%B1%DB%8C%D9%84%DB%8C%D8%B2_%DA%A9%DB%8C_%D8%AA%D9%88%D8%AB%DB%8C%D9%82.md) ترمیم شدہ تعمیر کو پیک کرنے سے پہلے چیک کرتا ہے۔

ہاتھ سے ترمیم نہ کریں `.randomday_mode`, `.randomday_version`، تیار کردہ پروفائل حوالہ جات، `runtime/`، یا `web_export/`۔ پیکیج بنانے والا پیکیج موڈ اور ورژن مارکر کا مالک ہے اور یہ چیک کرتا ہے کہ وہ ریلیز میٹا ڈیٹا سے متفق ہیں۔

نیچے ہر ترتیب کی وضاحت `RandomDay/Scripts/ax_config/server.lua`۔ جدولیں قابل تدوین ترتیبات کو ریلیز کی ملکیت والی شناخت اور محفوظ مطابقت والے فیلڈز سے ممتاز کرتی ہیں۔ Lua میں موجود فیلڈ کا مطلب یہ نہیں ہے کہ اسے تبدیل کرنا ایک معاون رویہ ہے۔

<a id="choose-an-experience"></a>
## ایک تجربہ منتخب کریں

RandomDay کے دو پیکیج ہیں: ایک ہر سرشار سرور کے لیے اور ایک کے لیے singleplayer/LAN دستی کاپی۔ وقف شدہ پیکیج میں دو آپریٹنگ موڈز ہیں۔ وہ موڈز سیٹنگز ہیں، علیحدہ ڈاؤن لوڈز نہیں۔

| آپ کی دنیا | انسٹال کریں | اس طرز عمل کا انتخاب کریں |
| --- | --- | --- |
| ایک سرشار سرور جو ایک مہم کو روٹین ری اسٹارٹ پر چلتا رکھتا ہے | سرشار سرور پیکیج | `persistent_dedicated` محفوظ کردہ فیملی اور پروفائل آرڈر کو دوبارہ شروع کرتا ہے۔ |
| صرف انفرادی پلے سیشنز کے لیے کھولا گیا ایک وقف سرور | وہی سرشار سرور پیکیج | `temporary_dedicated` سیشنز کے درمیان محفوظ طریقے سے تیار کردہ اگلی پروفائل رکھتا ہے، جب کہ ایک نیا فیملی رن کنفیگرڈ یا بے ترتیب آغاز کا استعمال کر سکتا ہے۔ |
| ایک واحد کھلاڑی یا LAN دنیا | Singleplayer/LAN پیکیج | `auto` مینوئل کاپی رویے کو منتخب کرتا ہے؛ تیار کردہ فائل کو کاپی کرنے سے پہلے دنیا کو روکیں۔ |

اگر آپ کو یقین نہیں ہے تو `auto`۔ پیکج اپنی تنصیب کی قسم کے لیے عام طرز عمل کا انتخاب کرتا ہے۔ [خاندانی گردش](%D8%AE%D8%A7%D9%86%D8%AF%D8%A7%D9%86%DB%8C_%DA%AF%D8%B1%D8%AF%D8%B4.md)۔ استعمال کریں [جنریٹڈ فیملی انڈیکس](%D9%BE%D8%B1%D9%88%D9%81%D8%A7%D8%A6%D9%84%D8%B2/%D9%BE%D8%B1%D9%88%D9%81%D8%A7%D8%A6%D9%84_%D8%AF%D8%B3%D8%AA%D8%A7%D9%88%DB%8C%D8%B2%D8%A7%D8%AA.md) جب آپ گیم پلے اور سینڈ باکس کی درست اقدار چاہتے ہیں۔ پھر پہلا دن اور ترقی کا انتخاب کریں:

- `start_day_mode="configured"` سے شروع ہوتا ہے `start_day`.
- `start_day_mode="random"` نئے خاندان کے آغاز پر ایک درست پہلے دن کا انتخاب کرتا ہے اور اس انتخاب کو برقرار رکھتا ہے۔
- `day_progression_mode="sequential"` تمام 17 پوزیشنز کو لپیٹتا ہے۔
- `day_progression_mode="non_repeating_random"` ایک شفل شدہ آرڈر کو اسٹور کرتا ہے جس میں ہر دن بالکل ایک بار ہوتا ہے۔

میں مکمل پیش سیٹ استعمال کریں [گھومنا](#rotation)۔ ایک تازہ تنصیب کے لیے اب بھی منتخب کردہ پہلے پروفائل کو تیار کرنے کے لیے ایک آغاز اور اسے فعال کرنے کے لیے بعد میں شروع کرنے کی ضرورت ہے۔

<a id="release-identity-and-logging"></a>
## ریلیز شناخت اور لاگنگ

| ترتیب | قسم اور بھیجی گئی قدر | تعاون یافتہ استعمال | ناکامی یا تعامل |
|---|---|---|---|
| `version` | اسٹرنگ سے پڑھا گیا `.randomday_version` | صرف پڑھنے کے لیے۔ | گمشدہ یا خالی مارکر بن جاتا ہے `unversioned`؛ حتمی پیکج کی توثیق شناختی بہاؤ کو مسترد کرتی ہے۔ |
| `package_mode` | اسٹرنگ سے پڑھا گیا `.randomday_mode` | صرف پڑھنے کے لیے: `dedicated_server` یا `singleplayer_manual`. | ٹارگٹ لکھنے سے پہلے کوئی بھی دوسری قدر اسٹارٹ اپ کو روک دیتی ہے۔ |
| `plan_basis` | سٹرنگ: `RandomDay - Seventeen Suns Rotation + Open World Scope` | صرف تشخیصی لیبل؛ اسے فیچر ٹوگل کے طور پر استعمال نہ کریں۔ | موجودہ رن ٹائم اس فیلڈ پر برانچ نہیں کرتا۔ |
| `logging.level` | سٹرنگ: `info` | `debug`, `info`, `warn`، یا `error`. | نامعلوم قدریں لاگنگ کی منزلیں شامل نہیں کرتی ہیں۔ رکھیں `info` جب تک کہ پروفائل جنریشن رویے کی تشخیص نہ ہو۔ |

مثال:

```lua
logging = { level = "debug" }
```

استعمال کریں `debug` عارضی طور پر، متعلقہ کو محفوظ رکھیں `UE4SS.log`، پھر `info`۔ نوشتہ جات میں کم سطح کی ناکامیوں کے مقامی راستے شامل ہو سکتے ہیں۔ اشتراک کرنے سے پہلے ان کا جائزہ لیں۔

<a id="experience-mode"></a>
## تجربہ کا موڈ

`experience.mode` اس انسٹالیشن کو چلانے کے طریقے کا نام دیتا ہے۔ یہ اگلی شروعات کی حفاظتی حد کو کمزور نہیں کرتا: ابیوٹک فیکٹر اس سے پہلے سینڈ باکس کی ترتیبات کو پڑھتا ہے UE4SS لوڈز RandomDay، اس لیے کوئی موڈ پہلے سے چل رہے عمل کے قواعد کو تبدیل نہیں کر سکتا۔

| ترتیب | بھیجائی گئی قدر | تعاون شدہ اقدار | اثر |
|---|---:|---|---|
| `experience.mode` | `auto` | `auto`, `persistent_dedicated`, `temporary_dedicated`, `singleplayer_lan` | `auto` پیکیج سے حل ہوتا ہے۔ وقف شدہ پیکجز یا تو سرشار موڈ استعمال کر سکتے ہیں۔ دستی کاپی پیکج صرف `auto` یا `singleplayer_lan`. |

- `persistent_dedicated` ایک کو ذخیرہ کرتا ہے family/day عام طویل مدتی سرور پر آرڈر دوبارہ شروع ہوتا ہے۔
- `temporary_dedicated` ایک سرور کی وضاحت کرتا ہے جو باؤنڈڈ پلے سیشنز کے لیے شروع کیا جاتا ہے۔ یہ اب بھی تیار کردہ ترتیب کو برقرار رکھتا ہے لہذا میزبان کو روکنے سے اگلے سیشن کو خاموشی سے دوبارہ نہیں چلایا جاتا ہے۔
- `singleplayer_lan` صرف باؤنڈڈ مینوئل کاپی آؤٹ پٹ تیار کرتا ہے۔ یہ کبھی بھی ذاتی محفوظ فولڈر کو دریافت یا ترمیم نہیں کرتا ہے۔

ایک غیر موافق package/experience سینڈ باکس لکھنے سے پہلے مجموعہ رک جاتا ہے۔

<a id="rotation"></a>
## گھومنا

| ترتیب | بھیجائی گئی قدر | تعاون شدہ اقدار | اثر |
|---|---:|---|---|
| `cycle.application_mode` | `next_reboot_queue` | `next_reboot_queue` | سینڈ باکس کی تمام تبدیلیوں کو ری اسٹارٹ باؤنڈری پر رکھتا ہے۔ |
| `cycle.cycle_length_days` | `17` | `17` معیاری پروفائل سیٹ کے لیے | ہر فیملی پیک اور تیار کردہ حوالہ سے میل کھاتا ہے۔ |
| `cycle.start_day_mode` | `configured` | `configured`, `random` | استعمال کرتا ہے `cycle.start_day` یا فیملی رن کے آغاز میں ایک بار ایک درست شروعاتی دن کا انتخاب کرتا ہے۔ |
| `cycle.start_day` | `1` | پورا نمبر `1` کے ذریعے `17` | پہلا دن جب `start_day_mode=configured`. |
| `cycle.day_progression_mode` | `sequential` | `sequential`, `non_repeating_random` | ایک لپیٹے ہوئے ترتیب وار آرڈر یا ایک شفل شدہ آرڈر بناتا ہے جس میں ہر دن بالکل ایک بار ہوتا ہے۔ |
| `cycle.bootstrap_day` | `1` | پورا نمبر `1` کے ذریعے `17` | مطابقت فال بیک کا استعمال صرف اس وقت ہوتا ہے جب `cycle.start_day` غیر حاضر ہے۔ نئی ترتیب کو `cycle.start_day`. |
| `cycle.check_interval_ms` | `0` | `0` یا ایک پابند مثبت وقفہ | `0` آغاز پر ایک بار تیار کرتا ہے؛ ایک مثبت قدر متواتر نگرانی کو قابل بناتی ہے جب UE4SS فراہم کرتا ہے `LoopAsync`. |
| `profile_family.mode` | `non_repeating_random_run` | `selected_run`, `non_repeating_random_run`, `rotation_run` | منتخب کرتا ہے کہ 17 دن کا نیا خاندانی دوڑ کیسے شروع ہوتا ہے۔ |
| `profile_family.selected_family` | `action` | میں ایک ID `allowed_families` | خاندان استعمال کرتا ہے `selected_run` اور بطور فال بیک۔ |
| `profile_family.default_family` | `action` | ایک رجسٹرڈ فیملی ID | منتخب ID غائب یا غلط ہونے پر فال بیک۔ |
| `profile_family.allowed_families` | تمام 17 عوامی فیملی IDs | رجسٹرڈ IDs کا کوئی بھی غیر خالی ذیلی سیٹ | نئے رنز کے اہل خاندانوں کو محدود کرتا ہے۔ |
| `profile_family.preserve_family_until_day_17` | بولین: `true` | محفوظ مطابقت والا فیلڈ؛ رکھیں `true`. | موجودہ کیلنڈر ہمیشہ خاندان کو 17 دن کے مسلسل ترتیب میں ہر پوزیشن پر رکھتا ہے اور اس فیلڈ کو ٹوگل کے طور پر نہیں پڑھتا ہے۔ |
| `profile_family.reroll_only_after_day_17` | بولین: `true` | محفوظ مطابقت والا فیلڈ؛ رکھیں `true`. | موجودہ کیلنڈر ہر دن کی ID کے مکمل ہونے کے بعد ہی خاندان کو تبدیل کرتا ہے، اس سے قطع نظر کہ ذخیرہ شدہ ترتیب میں کون سا دن آخری ہے۔ |
| `profile_family.prevent_repeats_until_rotation_complete` | بولین: `true` | محفوظ مطابقت والا فیلڈ؛ رکھیں `true`. | موجودہ غیر دہرائی جانے والی پول منطق فکسڈ ہے اور اس قدر کو ٹوگل کے طور پر نہیں پڑھتی ہے۔ |

دن کا آرڈر ایک بار نئے خاندان کے چلانے کے لیے بنایا جاتا ہے اور `runtime/rotation_state.txt`۔ بازیابی اور بعد میں دوبارہ شروع ہونے پر ان عین پوزیشنوں کو دوبارہ استعمال کریں۔ کنفیگریشن میں ترمیم جاری آرڈر کو دوبارہ رول نہیں کرتی ہے۔ تمام 17 عہدے مکمل ہونے کے بعد ہی خاندان تبدیل ہوتا ہے۔

<a id="recommended-presets"></a>
### تجویز کردہ پیش سیٹ

مسلسل سرشار سرور:

```lua
experience = { mode = "persistent_dedicated" }
cycle = {
    application_mode = "next_reboot_queue",
    cycle_length_days = 17,
    start_day_mode = "configured",
    start_day = 1,
    day_progression_mode = "sequential",
    bootstrap_day = 1,
    check_interval_ms = 0,
}
```

نئے فیملی رن کے مطابق مختلف غیر دہرائے جانے والے آرڈر کے ساتھ عارضی وقف سیشنز:

```lua
experience = { mode = "temporary_dedicated" }
cycle.start_day_mode = "random"
cycle.day_progression_mode = "non_repeating_random"
```

Singleplayer/LAN دستی کاپی سنگل پلیئر پیکیج کا استعمال کرتی ہے اور عام طور پر چھوڑ دیتی ہے `experience.mode="auto"`۔ اگلی فائل بنانے سے پہلے آپ وہی آغاز اور ترقی کے کنٹرول کا انتخاب کر سکتے ہیں۔ اگر آپ چاہتے ہیں کہ رن ٹائم سٹیٹ اور دنیا کی بھری ہوئی پروفائل سیدھ میں رہے تو تخلیق شدہ فائل کو دوسری جنریشن کے چلنے سے پہلے منتخب بند دنیا میں کاپی کریں۔

ایک تازہ تنصیب پر، پہلا عمل صرف منتخب آغاز کے دن کو تیار کر سکتا ہے۔ بعد کا عمل اسے چالو کرتا ہے۔ بے ترتیب یا کنفیگرڈ اسٹارٹ انجن لوڈنگ آرڈر کو نظرانداز نہیں کرتا۔

ایک فکسڈ بلڈر رن کی مثال:

```lua
profile_family = {
    mode = "selected_run",
    selected_family = "builder",
    default_family = "action",
    allowed_families = { "builder" },
    preserve_family_until_day_17 = true,
    reroll_only_after_day_17 = true,
    prevent_repeats_until_rotation_complete = true,
}
```

ایک خالی یا نامعلوم اہل سیٹ ایک نامکمل پروفائل بنانے کے بجائے ایک رجسٹرڈ فیملی کو واپس آتا ہے۔

<a id="primary-sandbox-path"></a>
## بنیادی سینڈ باکس کا راستہ

| ترتیب | قسم اور بھیجی گئی قدر | تعاون یافتہ استعمال | ناکامی یا تعامل |
|---|---|---|---|
| `paths.runtime_dir` | سٹرنگ: `ue4ss/Mods/RandomDay/runtime` | صرف سورس کنفیگریشن میں پڑھیں۔ | `init.lua` اسے حل شدہ mod-root `runtime/` راستہ۔ |
| `paths.web_export_dir` | سٹرنگ: `ue4ss/Mods/RandomDay/web_export` | صرف سورس کنفیگریشن میں پڑھیں۔ | `init.lua` اسے حل شدہ mod-root `web_export/` راستہ۔ |
| `paths.sandbox_path_override` | سٹرنگ یا `nil`: `nil` | ایک لفظی `SandboxSettings.ini` غیر معیاری وقف لے آؤٹ کے لیے راستہ۔ | غیر محفوظ یا غیر دستیاب اہداف لکھنے میں ناکام ہوجاتے ہیں۔ سنگل پلیئر موڈ اوور رائیڈ کو صاف کرتا ہے۔ |
| `paths.sandbox_candidates` | سٹرنگز کی فہرست: سات عام امیدوار | آرڈر کردہ سرشار سرور فال بیک امیدوار۔ | `init.lua` انسٹالیشن سے ماخوذ امیدواروں کو پیش کرتا ہے۔ پہلا موجودہ راستہ جیت جاتا ہے۔ |
| `paths.write_sandbox_mirrors` | بولین: `true` | جان بوجھ کر کنفیگر کردہ آئینے کی اجازت دیتا ہے۔ | آئینے کی فہرست خالی ہونے کے دوران کوئی آئینہ نہیں لکھا جاتا اور `world_name=nil`؛ سنگل پلیئر موڈ فورسز `false`. |
| `paths.sandbox_mirror_required` | بولین: `false` | محفوظ مطابقت والا فیلڈ؛ رکھیں `false`. | موجودہ مصنف آئینے کو اختیاری سمجھتا ہے اور اس فیلڈ کو مطلوبہ گیٹ کے طور پر نہیں پڑھتا۔ |
| `paths.world_name` | سٹرنگ یا `nil`: `nil` | ایک محفوظ عالمی فولڈر جزو جو عام آئینہ کے امیدواروں کو حاصل کرنے کے لیے استعمال ہوتا ہے۔ | حروف، اعداد، خالی جگہوں، `_`، یا `-` اسٹارٹ اپ روکتا ہے؛ سنگل پلیئر موڈ اسے نظر انداز کرتا ہے۔ |
| `paths.sandbox_mirror_candidates` | سٹرنگز کی فہرست: خالی | بالکل اختیاری آئینہ فائلز۔ | ہر اہل آئینہ اپنا اپنا لین دین استعمال کرتا ہے۔ آئینے کی ناکامی بنیادی کامیابی کو تبدیل نہیں کرتی۔ |

`paths.sandbox_path_override` پہلے سے طے شدہ `nil`۔ بغیر کسی اوور رائیڈ کے، RandomDay پہلے عام چیک کرتا ہے WindowsServer امیدواروں کا پتہ لگایا گیا RandomDay انسٹالیشن، پھر کسی بھی کنفیگر کردہ امیدواروں کو چیک کرتا ہے۔ اگر کوئی بھی موجود نہیں ہے، تو یہ پہلے انسٹالیشن اینکرڈ عام امیدوار کا استعمال کرتا ہے، جو سرور کی تنصیب کو حل کرتا ہے:

```text
AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini
```

یہ فال بیک عمل کی موجودہ ورکنگ ڈائرکٹری سے حل نہیں ہوا ہے۔ سیٹ کریں `sandbox_path_override` صرف اس وقت جب آپ کی انسٹالیشن ایک مختلف لٹریل فائل استعمال کرتی ہے۔ اسے ایک کی طرف اشارہ کریں `SandboxSettings.ini`، ڈائرکٹری نہیں۔ سرور کو روکیں اور استعمال کرنے سے پہلے تصدیق کریں کہ فائل مطلوبہ تنصیب کے اندر ہے۔

<a id="optional-mirrors"></a>
### اختیاری آئینہ

`paths.write_sandbox_mirrors` بھیجتا ہے بطور `true`، لیکن آئینہ کے راستے کی فہرست خالی ہے اور `paths.world_name` ہے `nil`۔ لہذا بھیجے گئے ڈیفالٹس کوئی اضافی آئینہ نہیں لکھتے ہیں۔ اسے `false` جب انسٹالیشن کو ہمیشہ صرف حل شدہ بنیادی ہدف لکھنا چاہیے۔ بغیر کسی کنفیگر شدہ آئینے کے امیدوار یا عالمی نام کے، یا تو قدر اب بھی صرف بنیادی سینڈ باکس فائل لکھتی ہے۔

ایک آئینہ صرف اس وقت قابل بنتا ہے جب آپ جان بوجھ کر اس میں ایک درست اندراج شامل کرتے ہیں `paths.sandbox_mirror_candidates` یا سیٹ کریں `paths.world_name`۔ آئینے ان تنصیبات کے لیے بہترین کوشش کی کاپیاں ہیں جو دنیا کے لیے مخصوص سینڈ باکس کا دوسرا راستہ پڑھتی ہیں۔ وہ صحیح بنیادی راستے کو ترتیب دینے کا متبادل نہیں ہیں۔

آئینے کو فعال کرنے سے پہلے:

1. سرور کو روکیں؛
2. سرور کی طرف سے پڑھی جانے والی درست فائل کی شناخت کریں؛
3. تصدیق کریں کہ ہدف مطلوبہ تنصیب کے اندر ہے؛
4. اس کا بیک اپ لیں؛
5. صرف وہ راستہ شامل کریں؛
6. تیار کرنے کے بعد عکس کے نتیجے کی تصدیق کریں۔

آئینے کے بغیر اوور رائڈ کی مثال:

```lua
paths = {
    runtime_dir = "ue4ss/Mods/RandomDay/runtime",
    web_export_dir = "ue4ss/Mods/RandomDay/web_export",
    sandbox_path_override = "<server-root>/AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini",
    sandbox_candidates = {},
    write_sandbox_mirrors = false,
    sandbox_mirror_required = false,
    world_name = nil,
    sandbox_mirror_candidates = {},
}
```

`<server-root>` ایک پلیس ہولڈر ہے۔ اسے مقامی طور پر تبدیل کریں؛ مشین کے لیے مخصوص راستہ شائع نہ کریں۔

<a id="non-disableable-safety-locks"></a>
## غیر قابل عمل حفاظتی تالے

| ترتیب | مطلوبہ قدر | مطلب |
|---|---:|---|
| `sandbox.backup_before_write` | `true` | موجودہ بنیادی فائل کو تبدیل کرنے سے پہلے ایک تصدیق شدہ کاپی محفوظ کریں۔ |
| `sandbox.restore_last_good_on_failure` | `true` | ایک ناکام تبدیلی یا ریڈ بیک کے بعد خودکار بحالی کی کوشش کریں۔ |
| `external_mods.patch_only_existing_keys` | `true` | کسی دوسرے موڈ کی فائل میں نامعلوم ترتیب ایجاد کرنے سے انکار کریں۔ |
| `external_mods.backup_before_write` | `true` | تعاون یافتہ ٹرانزیکشنل اڈاپٹر ترمیم سے پہلے ٹارگٹ بائٹس کو محفوظ کریں۔ |

RandomDay اسٹارٹ اپ سے انکار کرتا ہے اگر ان چاروں میں سے کوئی بھی قدر نہیں ہے `true`۔ وہ حفاظتی تالے ہیں، تعاون یافتہ آپریٹر ٹوگل نہیں ہیں۔ ان کو غیر فعال نہ کریں، بشمول ڈیولپمنٹ یا ٹربل شوٹنگ، کیونکہ ایسا کرنے سے فیل بند حد تبدیل ہو جاتی ہے جسے مصنف اور اڈاپٹر ٹیسٹ ثابت کرتے ہیں۔

`sandbox.force_rewrite_every_supervision_tick` ایک عام ترتیب بنی ہوئی ہے اور `false`، جو پہلے سے مماثل سینڈ باکس فائل کو اچھوتا چھوڑ دیتا ہے۔ یہ بولین کو قبول کرتا ہے۔ اسے `true` دوبارہ مصنف کے ذریعے اسی عمل کی ملکیت والے تیار کردہ بائٹس کو مجبور کرتا ہے۔ یہ family/day۔ اسے صرف باؤنڈڈ ریکوری ٹیسٹ کے لیے استعمال کریں کیونکہ بار بار لکھنے سے مزید آپریشن بیک اپ بنتا ہے۔

<a id="optional-mod-adapters"></a>
## اختیاری موڈ اڈاپٹر

| ترتیب | بھیجائی گئی قدر | مطلب |
|---|---:|---|
| `external_mods.enabled` | `true` | کنفیگر کردہ اڈاپٹرز کو الگ سے انسٹال کردہ اہداف کا معائنہ کرنے کی اجازت دیں۔ |
| `external_mods.optional_by_default` | `true` | گمشدہ یا غیر موازن اختیاری موڈز مسدود نہیں ہوتے ہیں RandomDay. |
| `external_mods.patch_only_existing_keys` | `true` | ضروری حفاظتی تالا؛ اگر تبدیل کیا گیا تو آغاز ناکام ہو جاتا ہے۔ |
| `external_mods.backup_before_write` | `true` | ضروری حفاظتی تالا؛ اگر تبدیل کیا گیا تو آغاز ناکام ہو جاتا ہے۔ |
| `external_mods.adapters` | چار عوامی اڈاپٹر IDs | وہ حد جو RandomDay-owned اڈاپٹر چل سکتے ہیں۔ |

 تیسرے فریق موڈ کو غیر فعال یا ان انسٹال کیے بغیر اس انضمام کو تنہا چھوڑنے کے لیے فہرست سے ایک اڈاپٹر ID کو ہٹا دیں۔ singleplayer/LAN پیکیج اس فہرست سے قطع نظر ہر اڈاپٹر کو غیر فعال کرتا ہے۔

`external_mods.optional_by_default=false` `applied` یا `already_current` مجموعی اڈاپٹر کا نتیجہ ناکام ہو جاتا ہے۔ یہ بنیادی سینڈ باکس ٹرانزیکشن کو رول بیک نہیں کرتا ہے۔ بھیجے گئے `true` جب تک کہ آپریٹر کے پاس انضمام کی ضرورت کی کوئی آزمائشی وجہ نہ ہو۔

دیکھیں [تعاون یافتہ Mod Adapters](%D8%AA%D8%B9%D8%A7%D9%88%D9%86_%DB%8C%D8%A7%D9%81%D8%AA%DB%81_%D8%A7%DA%88%D8%A7%D9%BE%D9%B9%D8%B1.md) تسلیم شدہ لے آؤٹس اور چھ ممکنہ نتائج کے لیے۔

<a id="optional-chaotic-spawn-engine-scope-fields"></a>
### اختیاری Chaotic Spawn Engine اسکوپ فیلڈز

`world_scope` پانچ اختیاری RandomDay توسیع کی ترتیبات صرف اس صورت میں جب ایک تسلیم شدہ Chaotic Spawn Engine `DynamicSpawns/SharedData.lua` لے آؤٹ پہلے سے ہی ان فیلڈز پر مشتمل ہے۔ یہ کوئی الگ موڈ یا ڈاؤن لوڈ نہیں ہے:

| ترتیب | بھیجائی گئی قدر | اڈاپٹر اثر |
|---|---:|---|
| `world_scope.enabled` | `true` | اختیاری کی درخواست کرتا ہے RandomDay ایک تسلیم شدہ DynamicSpawns لے آؤٹ۔ |
| `world_scope.affect_open_worlds` | `true` | اس میں کھلی دنیا شامل ہوتی ہے جب تک کہ ٹارگٹ موڈ ایک محفوظ دنیا کے اصول کا اطلاق نہ کرے۔ |
| `world_scope.unknown_world_policy` | `allow` | درخواستیں `allow` یا `block` جب ٹارگٹ موڈ دنیا کی درجہ بندی نہیں کرسکتا۔ |
| `world_scope.log_scope_decisions` | `true` | اپنے دائرہ کار کے فیصلے کے لیے ٹارگٹ موڈ لاگنگ کی درخواست کرتا ہے۔ |
| `world_scope.protected_worlds` | خالی فہرست | ٹارگٹ لے آؤٹ کو کوما سے الگ کردہ محفوظ دنیا کے پیٹرن فراہم کرتا ہے۔ |

یہ اقدار اڈاپٹر ان پٹ ہیں، RandomDay's سینڈ باکس رائٹر۔ وہ صرف اس وقت اثر انداز ہوتے ہیں جب الگ سے نصب شدہ Chaotic Spawn Engine لے آؤٹ پہلے سے مکمل اختیاری پر مشتمل ہو RandomDay فیلڈ سیٹ اور رپورٹس `applied` یا `already_current`۔ Chaotic Spawn Engine رن ٹائم پر ان فیلڈز کو استعمال کرنے کا ذمہ دار رہتا ہے۔ ایکسٹینشن فیلڈز کے بغیر ایک عام انسٹالیشن میں کوئی تبدیلی نہیں کی جاتی ہے۔

تمام پانچ اقدار اڈاپٹر ان پٹ ہیں۔ `unknown_world_policy` صرف دستاویزی ہدف کی اقدار کو قبول کرتا ہے `allow` یا `block`؛ ایک غیر تسلیم شدہ ہدف لے ​​آؤٹ کو چھوڑ دیا گیا ہے۔ رکھیں `protected_worlds` دستاویزات کی مثالوں میں خالی۔ اگر کوئی آپریٹر مقامی نمونوں کا استعمال کرتا ہے، تو انہیں اسکرین شاٹس، ایشوز، یا ریلیز آرٹفیکٹس میں شامل نہیں کرنا چاہیے۔

<a id="player-messages"></a>
## پلیئر کے پیغامات

بھیج دیا گیا سرشار سرور کنفیگریشن کومپیکٹ شمولیت کے نوٹس اور ایک مختصر روزانہ لائن کو قابل بناتا ہے۔ یہ پہلے پاس سے پہلے 30 سیکنڈ انتظار کرتا ہے، ہر 15 سیکنڈ میں نئے شامل ہونے والے کھلاڑیوں کو چیک کرتا ہے، اور روزانہ لائن سے پہلے شمولیت کے نوٹس کے بعد 10 سیکنڈ انتظار کرتا ہے۔

| ترتیب | بھیجائی گئی قدر |
|---|---:|
| `player_message.enabled` | `true` |
| `player_message.log_on_startup` | `true` |
| `player_message.register_console_command` | `false` |
| `player_message.console_command` | `randomday` |
| `player_message.broadcast_enabled` | `true` |
| `player_message.startup_delay_ms` | `30000` |
| `player_message.join_check_interval_ms` | `15000` |
| `player_message.send_daily_joke_after_join` | `true` |
| `player_message.daily_joke_delay_seconds` | `10` |
| `player_message.criticality_join` | `2` |
| `player_message.criticality_joke` | `0` |
| `player_message.max_line_chars` | `42` |
| `player_message.max_join_lines` | `4` |
| `player_message.max_warning_lines` | `3` |
| `player_message.max_note_lines` | `3` |

پیغام کی لمبائی کی توثیق ماخذ کی حدود کو چیک کرتی ہے۔ یہ ہر کلائنٹ ریزولوشن پر بصری ٹیسٹ کی جگہ نہیں لیتا۔

وقت کی قدریں غیر منفی اعداد ہیں جنہیں ملی سیکنڈز سے تعبیر کیا جاتا ہے سوائے `daily_joke_delay_seconds`۔ ایک غیر فعال پیغام یا نشریاتی ترتیب سینڈ باکس کی تیاری کو تبدیل کیے بغیر کلائنٹ کے نوٹس کو دبا دیتی ہے۔ کنسول کمانڈ صرف اس وقت رجسٹرڈ ہوتی ہے جب سیٹنگ اور UE4SS ہینڈلر دستیاب ہیں۔ بھیجے گئے ٹرانسپورٹ کی سطحوں پر تنقیدی اقدار کو برقرار رکھیں جب تک کہ ایک نامزد کلائنٹ ٹیسٹ کوئی اور قدر ثابت نہ کرے۔

`max_line_chars` مترجم کے ذریعہ 8 سے 64 حروف تک بند کیا گیا ہے۔ تین لائن گنتی کی ترتیبات کی حد بالترتیب شمولیت، وارننگ، اور نوٹ آؤٹ پٹ؛ بھیجی گئی قدریں دستیاب سورس لائنوں کی تعداد سے ملتی ہیں۔ ان چار حدود کو ان کے ڈیفالٹ پر رکھیں جب تک کہ کلائنٹ لے آؤٹ ٹیسٹ ایک تنگ ترتیب کو ثابت نہ کرے۔

غیر فعال پیغامات کے ساتھ مثال:

```lua
player_message = {
    enabled = false,
    log_on_startup = true,
    register_console_command = false,
    console_command = "randomday",
    broadcast_enabled = false,
    startup_delay_ms = 30000,
    join_check_interval_ms = 15000,
    send_daily_joke_after_join = false,
    daily_joke_delay_seconds = 10,
    criticality_join = 2,
    criticality_joke = 0,
    max_line_chars = 42,
    max_join_lines = 4,
    max_warning_lines = 3,
    max_note_lines = 3,
}
```

<a id="customize-the-shipped-profile-defaults"></a>
### بھیجے گئے پروفائل ڈیفالٹس کو حسب ضرورت بنائیں

کھولیں:

```text
RandomDay/Scripts/ax_config/server.lua
```

اس بلاک کو `sandbox`:

```lua
profile_overrides = {
    HardcoreMode = false,
    AllowIronMode = false,
    StructuralSupportLimit = 0,
    BridgeSupports = 0,
}
```

RandomDay جب بھی یہ کسی خاندان میں 17 پروفائلز بناتا ہے تو اس بلاک کو پڑھتا ہے۔ اس لیے منتخب کردہ اقدار کا اطلاق ہر خاندان اور دن پر ہوتا ہے، بشمول ایک گردش کے بعد تیار کردہ پروفائلز اور بعد میں سرور کے آغاز کے بعد دوبارہ بنائے گئے پروفائلز۔ آپ کو 289 پروفائل فائلوں میں ترمیم کرنے یا پروفائل ریفرنس کو دوبارہ تخلیق کرنے کی ضرورت نہیں ہے۔
