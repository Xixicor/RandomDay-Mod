# 런타임 파일 및 상태 찾기

> **표준 영어 소스:** [RUNTIME_FILES.md](../../RUNTIME_FILES.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이것은 운영자 및 소스 추적성이 사용하는 표준 경로 목록입니다. 파일이 어디에 있는지, 누가 기록하는지, 언제 변경되는지, 얼마나 오래 남아 있는지, 어떤 복구 역할을 하는지에 대한 답을 제공합니다. [런타임 출력 참조](%EB%9F%B0%ED%83%80%EC%9E%84_%EC%B6%9C%EB%A0%A5.md) 스키마, 필드 의미, 빈 상태 및 기계 값 해석을 소유합니다.

이 가이드의 모든 경로는 달리 명시되지 않는 한 설치된 `RandomDay/` 폴더를 기준으로 합니다. 런타임 출력은 설치 후에 생성됩니다. 릴리스 ZIP에서 제외됩니다.

## 연산자 파일 맵

| 경로 | 생산자 및 트리거 | 업데이트 및 보관 | 의미 및 복구 |
|---|---|---|---|
| 구성된 기본 `SandboxSettings.ini` | `ax_sandbox/writer.lua`전용 모드에서 프로필 직렬화 및 유효성 검사 후. | 트랜잭션적으로 대체됩니다. 대상은 운영자가 구성하거나 설치에서 파생됩니다. | 다음 시작을 위한 프로필을 완료하세요. 실행 중인 세션은 이미 로드된 규칙을 유지합니다. |
| 구성된 미러 `SandboxSettings.ini` | 명시적 미러가 적합한 경우 성공적인 기본 결과 후 샌드박스 작성기. | 최선의 트랜잭션 교체. | 2차 사본만 해당; 미러는 올바른 기본 경로 구성을 대체하지 않습니다. |
| 인식된 어댑터 대상 | `ax_external/bridge.lua` 레이아웃 서명 일치가 완료된 후. | 기존 할당은 고유한 백업으로 트랜잭션 방식으로 변경됩니다. | 별도로 설치된 모드 구성, 기본 샌드박스와 독립적으로 6상태 어댑터 결과를 검사합니다. |
| `runtime/rotation_state.txt` | `ax_cycle/calendar.lua`샌드박스 트랜잭션이 성공한 후. | 승인된 각 준비 후에 트랜잭션별로 교체됩니다. | 큐 기록. 읽을 수 없는 경우 RandomDay 마지막으로 양호한 상태를 시도합니다. |
| `runtime/rotation_state.last_good.txt` | 캘린더 트랜잭션 백업. | 현재 상태가 업데이트되면 교체됩니다. | 이전 읽기 가능 상태. 진단 및 업데이트 중에 보존합니다. |
| `runtime/current/randomday_status.json` | `ax_runtime/status.lua`성공 후, 지속성 저하 또는 쓰기 실패 후. | 각 상태 전달에서 트랜잭션 방식으로 교체됩니다. | 표준 구조화 active/prepared, 트랜잭션, 변환 및 어댑터 요약. |
| `runtime/current/randomday_dictionary.json` | `ax_runtime/status.lua`상태 옆. | 트랜잭션 방식으로 대체되었습니다. | 스키마 `randomday_runtime_dictionary_v2`: 용어, 번역 설정, 도메인, 패키지 모드 및 선택 상태. |
| `runtime/current/player_message_preview.txt` | `ax_runtime/status.lua`상태 옆. | 트랜잭션 방식으로 대체되었습니다. | 운영자 검토를 위한 정확한 제한된 메시지 미리보기, 클라이언트 렌더링을 증명하지는 않습니다. |
| `runtime/last_good/SandboxSettings.ini` | `ax_backup/manager.lua` 검증된 기본 샌드박스 결과 이후. | 트랜잭션 방식으로 대체되었습니다. | 마지막 샌드박스는 알려진 양호한 것으로 승인되었습니다. 매니페스트와 함께만 사용하세요. |
| `runtime/last_good/manifest.lua` | `ax_backup/manager.lua`샌드박스 스냅샷이 성공한 후. | 샌드박스 스냅샷과 쌍으로 트랜잭션 방식으로 대체됩니다. | 버전, 프로필 ID, 이름, 날짜, 콘텐츠 해시 및 마지막으로 좋은 파일에 대한 쓰기 시간. |
| `runtime/backups/<operation>/SandboxSettings.ini` | 변이 전의 기본 또는 미러 작성자. | 고유한 작업 디렉터리입니다. RandomDay는 이를 정리하지 않습니다. | 확인된 사전 쓰기 바이트입니다. 운영자는 검토 후 보존을 소유합니다. |
| `runtime/backups/external_<operation>/...` | 어댑터 변형 전 어댑터 브리지. | 고유한 작업 디렉터리. 자동 정리는 없습니다. | 계획된 모든 어댑터 대상의 확인된 사본 하나. |
| `runtime/pending/` | 런타임 디렉토리 설정에 의해 생성됩니다. | 예약됨; 현재 기본 트랜잭션은 형제 사이드카를 대신 사용합니다. | 빈 디렉터리를 준비 증명으로 취급하지 마세요. |
| `runtime/singleplayer_manual/SandboxSettings.ini` | `singleplayer_manual` 모드의 샌드박스 작성기 | 수동 패키지가 실행될 때 트랜잭션 방식으로 교체됩니다. | 운영자가 검사하고 복사할 수 있는 전체 파일 수동으로 하나의 정지된 세계로 들어갑니다. |
| `web_export/today.json` | `ax_web/export.lua`각 준비 결과 후. | 트랜잭션 방식으로 대체되었습니다. | 기계가 읽을 수 있는 컴팩트한 active/prepared 및 writer/adapter결과. |
| `web_export/today.html` | `ax_web/export.lua`성공적인 내보내기 통과 후. | 트랜잭션 방식으로 대체되었습니다. | 동일한 전환에서 파생된 인간 시점. 독립적인 증명이 아닙니다. |
| `UE4SS.log` | UE4SS 및 `ax_core/log.lua`. | Managed by UE4SS, 아님 RandomDay. | 시작, 선택한 프로필, 쓰기, 어댑터, 메시지, 상태 및 `[RandomDay]`. |

<a id="recognize-empty-and-failed-file-states"></a>
### 빈 파일 상태 및 실패한 파일 상태 인식

- 누락된 기본 또는 미러 대상이 생성될 수 있습니다. 잘못된 프로필, 보류 중인 쓰기, 승격 또는 프로덕션 다시 읽기 실패가 준비되지 않았습니다. 미러 실패는 허용된 기본 결과를 변경하지 않습니다.
- `runtime/singleplayer_manual/SandboxSettings.ini` 첫 번째 수동 실행 시 생성될 수 있습니다. 생성 실패는 상태 및 로그 출력에 계속 표시됩니다.
- 읽을 수 없는 `rotation_state.txt`는 마지막 양호한 상태나 마커 기반 부트스트랩으로 돌아갈 수 있습니다. 실패한 상태 커밋으로 인해 `degraded_state_persistence`.
- `runtime/last_good/`는 처음으로 확인된 대상 이전에 없을 수 있습니다. 페어링된 매니페스트 업데이트가 실패하면 RandomDay 이전에 허용된 쌍을 복원합니다.
- `runtime/backups/mirror_<operation>/`는 미러별 백업 위치입니다. 트랜잭션 이전에 해당 대상이 존재하지 않았다면 기본 또는 미러 백업 파일이 존재하지 않습니다.
- 백업 생성 또는 다시 읽기에 실패하면 어댑터 변형이 시작되지 않습니다.
- 런타임 상태 출력을 사용할 수 없거나 불완전하면 현재 상태, 사전 또는 미리보기 파일이 없을 수 있습니다.
- `export_failed` 결과로 인해 이전 파일이 남을 수 있습니다. `today.json`. 샌드박스 실패는 JSON 업데이트되지만 새로운 실패를 생성하지는 않습니다 HTML 페이지; 타임스탬프를 `UE4SS.log`.
- 비활성 보류 중인 사이드카는 새로운 시도 전에 제거됩니다. 정리 실패로 인해 트랜잭션이 중지됩니다. 프로덕션 대상과 롤백 사이드카가 모두 존재하는 경우 RandomDay 검토를 위해 복구 바이트를 보존합니다.
- 아니요 `[RandomDay]` `UE4SS.log`의 시작 줄은 모드 로딩이 입증되지 않았음을 의미합니다.

<a id="transaction-sidecars"></a>
## 트랜잭션 사이드카

트랜잭션 작성자는 옆에 형제 파일을 생성할 수 있습니다. 대상:

| 패턴 | 상태 | 운영자 작업 |
|---|---|---|
| `<target>.randomday.pending` | 승격 전 후보 바이트. | 일반적으로 승격에 의해 제거됩니다. 오류가 보류 중인 정리 또는 다시 읽기 문제를 보고하는 경우 이를 보존하세요. |
| `<target>.randomday.rollback` | 교체 중에 원래 바이트가 유지됩니다. | 일반적으로 실패 시 복원되거나 성공 확인 후 제거됩니다. 대상도 있으면 삭제하지 마십시오. 해당 조합은 검토가 필요합니다. |
| `<target>.randomday.restore.pending` | 어댑터 복원 중 후보 바이트. | 복원이 실패할 경우 어댑터 백업과 함께 보존합니다. |
| `<target>.randomday.restore.rollback` | 어댑터 복원 중 유지되는 복구 바이트. | 정리 또는 복원이 확인되지 않은 경우 영향을 받는 서비스를 보존하고 중지합니다. |

이러한 파일은 옆에 존재할 수 있습니다. 전용 샌드박스 또는 별도로 설치된 어댑터 대상. 해당 존재는 트랜잭션 상태이지 새 프로필이 활성화되었다는 증거가 아닙니다.

## 복구 증거 유지

RandomDay가 현재 상태, 현재 상태를 덮어씁니다. 고유한 작업 백업 디렉토리를 생성하고 이전 디렉토리를 삭제하지 않습니다. 그러나 쓰기, 다시 읽기, 상태 또는 롤백 문제가 해결되지 않은 동안에는 최신 복구 증거를 삭제하지 마십시오.
