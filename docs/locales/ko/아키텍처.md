#  Flow

> **표준 영어 소스:** [ARCHITECTURE.md](../../ARCHITECTURE.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


RandomDay한 가지 제한된 작업을 소유합니다. 즉, 현재 프로세스 중에 해당 프로필을 활성 상태로 설명하지 않고 향후 시작을 위해 완전한 샌드박스 프로필을 준비합니다. 활성 프로필은 UE4SS 시작 RandomDay 전에 Abiotic Factor가 로드한 샌드박스 파일의 마커에서 나옵니다. 준비된 프로필은 다음 다시 시작을 위해 별도의 검증된 파일 상태입니다.

<a id="package-modes"></a>
## 패키지 모드

릴리스 빌더는 동일한 소스 허용 목록에서 2개의 ZIP을 생성하고 `RandomDay/.randomday_mode` 각각 다르게 설정합니다.

| 모드 | 기본 출력 | 자동 외부 쓰기 |
|---|---|---|
| `dedicated_server` | 해결된 전용 서버 `SandboxSettings.ini` | 기본 샌드박스, 의도적으로 구성된 미러 및 인식된 선택적 어댑터. |
| `singleplayer_manual` | `RandomDay/runtime/singleplayer_manual/SandboxSettings.ini` | RandomDay 폴더 외부에는 없습니다. 미러와 어댑터는 비활성화됩니다. |

`RandomDay/.randomday_version` 및 `RandomDay/.randomday_mode`는 생성된 패키지 마커입니다. `RandomDay/Scripts/ax_core/version.lua` 이를 읽습니다. 운영자는 설치 후에 편집하면 안 됩니다.

<a id="session-modes"></a>
## 세션 모드

RandomDay가 쓸 수 있는 패키지 모드 제어. `experience.mode` 의도한 수명 주기를 별도로 설명합니다.

| 세션 모드 | 패키지 | 수명 주기 계약 |
|---|---|---|
| `persistent_dedicated` | 전용 | 장기적으로 지속적인 가족 및 17위치 일 순서 재개 재시작합니다. |
| `temporary_dedicated` | 전용 | 실행 사이에 대기 순서를 유지하면서 각 실행을 제한된 플레이 세션으로 처리합니다. |
| `singleplayer_lan` | 싱글 플레이어 수동 | 운영자가 선택한 세계에 대한 모드 로컬 파일을 생성합니다. 저장 검색이나 자동 복사가 없습니다. |

`auto`는 전용 패키지에서 `persistent_dedicated`로 확인되며 `singleplayer_lan` 수동 패키지에 있습니다. 세션 모드는 엔진 경계를 변경하지 않습니다. 현재 프로세스는 RandomDay가 실행되기 전에 이미 샌드박스를 로드했습니다.

<a id="startup-path"></a>
## 시작 경로

1. UE4SS는 `RandomDay/Scripts/main.lua`.
2. 진입 지점은 하나의 루트를 확인하고 `RandomDay/` 로드하고 `Scripts/ax_core/init.lua`.
3. `init.lua` 구성, 프로필, 달력, 작성자, 어댑터를 로드합니다. 상태, 웹 내보내기 및 플레이어 메시지 모듈. 유효하지 않은 패키지 모드 또는 비활성화된 트랜잭션 안전 잠금을 거부합니다. 또한 패키지 호환 세션 모드, 시작일 모드, 구성된 시작일 및 일일 진행 모드를 검증합니다.
4. 모든 제품군 빌드는 `sandbox.profile_overrides` `Scripts/ax_config/server.lua`에서 유효성을 검사합니다. 네 가지 프로필 전체 선택 사항은 family/day 값 뒤, 나머지 고정 규칙 앞에 적용되므로 준비된 모든 프로필은 동일한 구성된 선택 사항을 사용합니다.
5. 런타임 및 웹 출력 루트는 확인된 mod 폴더에 고정됩니다. 싱글 플레이어 모드는 선택 전 하나의 모드-로컬 출력으로 축소됩니다.
6. `ax_cycle/calendar.lua`샌드박스 마커와 복구 가능한 회전 상태를 읽은 다음 이 게임 프로세스에 대해 하나의 active/prepared 결정을 만듭니다.
7. `ax_sandbox/writer.lua` 준비된 프로필을 직렬화하고 검증한 다음 선택한 대상에 대해 트랜잭션 대체를 사용합니다.
8. 회전 상태는 다음 후에만 커밋됩니다. 샌드박스 트랜잭션이 성공합니다. 상태 커밋 실패의 성능이 저하됩니다. 샌드박스와 대기열 상태가 일치하지 않기 때문에 어댑터와 준비된 플레이어 메시징을 건너뜁니다.
9. 전용 모드에서 `ax_external/bridge.lua`는 활성 프로필에 대해 선택적 어댑터를 평가합니다. 첫 번째 부트스트랩 중에는 활성 마커가 존재하지 않으므로 준비된 configured/random 시작일 프로필이 유일하게 사용 가능한 어댑터 매핑입니다.
10. 런타임 JSON/text 상태와 HTML/JSON 웹 보기는 동일한 결정으로 다시 작성됩니다. 플레이어 알림은 마지막에 설치됩니다.

기본값 `cycle.check_interval_ms=0`는 시작 시 이 시퀀스를 한 번 실행합니다. 운영자가 양의 간격을 제공하고 UE4SS 노출하는 경우 `LoopAsync`, 이후 콜백은 프로세스 소유 선택을 재사용합니다. 해당 선택 항목을 복구하거나 다시 내보낼 수 있지만 동일한 프로세스 중에 다른 날짜를 선택하지 마십시오.

<a id="rotation-state-machine"></a>
## 회전 상태 머신

| 선택 상태 | 입력 조건 | 준비된 결과 | 안전한 복구 |
|---|---|---|---|
| `bootstrap_prepare_first_family_start_day` | 활성 마커 및 없음 복구 가능한 준비 상태. | 새로 지속되는 날짜 순서에서 첫 번째 위치를 구성하거나 무작위로 선택합니다. | 기존 세션을 계속 실행합니다. `prepared_ready=true`. |
| `active_marker_found_family_locked_prepare_next_day` | 활성 날짜는 저장된 순서의 마지막 위치가 아닙니다. | 동일 계열의 다음 저장 위치. | 지속성에 실패하면 서버를 중지한 상태로 유지하고 샌드박스와 회전 상태를 조정하세요. |
| `active_marker_found_completed_run_prepare_next_unused_family` | 활성 날짜는 저장된 순서의 마지막 위치입니다. | 다음 적격 가족 실행에서 새 주문의 첫 번째 위치. | 다시 시작하기 전에 새 family/day/order를 확인하세요. |
| `state_recovery_rewrite_prepared_profile_no_reroll` | 활성 마커는 없지만 회전 상태는 준비된 프로필의 이름을 지정합니다. | 동일한 대기 프로필이 재구축됩니다. | 보존 상태 파일; 강제로 다시 롤백하기 위해 삭제하지 마세요. |
| `supervision_reconfirm_prepared_profile_no_advance` | 나중 콜백은 동일한 프로세스에서 실행됩니다. | 동일하게 준비된 프로필. | 첫 번째 실패 단계를 진단하세요. 반복되는 콜백은 새로운 선택이 아닙니다. |

`selected_run` 항상 `selected_family`. `rotation_run` 구성된 적격 주문을 사용합니다. `non_repeating_random_run` 나머지 적격 가족 중에서 선택하고 모두 완료한 후 새 풀을 시작합니다. 모든 모드는 `day_order`의 17개 고유 요일 ID가 모두 완료될 때까지 하나의 가족을 유지합니다. 순차 모드는 구성된 시작이 1일차가 아닌 경우 17일 이후에 종료됩니다. 비반복 무작위 모드는 하나의 순열을 저장하고 복구 중에 이를 다시 롤링하지 않습니다.

<a id="sandbox-transaction"></a>
## 샌드박스 트랜잭션

작성기는 쓰기 전에 모든 키를 표준 순서로 렌더링하고 유형, 범위, 고정 규칙, 마커 값 및 프로필 ID를 검증합니다. 그런 다음 교체는 다음 순서를 따릅니다.

1. 안전한 경우에만 오래된 보류 파일을 제거합니다.
2. 기존 복구 사이드카를 보존하거나 중지합니다.
3. 보류 바이트를 씁니다.
4. 보류 파일을 다시 읽고 유효성을 검사합니다.
5. 확인된 파일을 만듭니다. 대상이 존재할 때 작업 백업,
6. 원본을 트랜잭션 롤백 파일로 보관,
7. 보류 중인 파일 승격,
8. 프로덕션 파일 읽기 및 유효성 검사,
9. 프로모션 또는 프로덕션 검증이 실패할 경우 보관된 원본 복원,
10. 복구 데이터를 유지하고 정리할 수 없는 경우 실패 보고 확인하세요.

첫 번째 쓰기는 동일한 pending/readback/validation 경로를 사용합니다. 원래 대상이 없으면 복원할 것이 없으므로 실패한 첫 번째 쓰기가 원본 파일 복구로 보고되어서는 안 됩니다.

<a id="adapter-boundary"></a>
## 어댑터 경계

어댑터는 별도로 설치된 모드에 대한 RandomDay-owned 별도로 설치된 모드에 대한 패치 정의. 브리지에는 먼저 인식된 대상 경로와 완전한 키 서명이 필요합니다. 기존 할당만 패치하고, 작업 백업을 생성하고, 계획된 모든 파일을 하나의 트랜잭션으로 적용하고, 단계가 실패하면 영향을 받는 모든 대상을 롤백합니다. 누락되거나 호환되지 않는 타겟은 일반적인 선택적 결과입니다.

RandomDay 타사 코드를 패키지에 로드하지 않습니다. 픽스처 지원 레이아웃은 RandomDay's 파서 및 트랜잭션 동작. 제3자 릴리스가 게임 프로세스에서 값을 로드하거나 사용한 것은 아닙니다.

<a id="output-boundary"></a>
## 출력 경계

런타임 파일은 아래에서 생성됩니다. `RandomDay/runtime/` 및 `RandomDay/web_export/`; none은 릴리스 ZIP 입력입니다. 상태 기록기는 공개 JSON 진단. 전체 경로, 스키마, 흐름 및 유지 맵은 [런타임 파일 및 상태](%EB%9F%B0%ED%83%80%EC%9E%84_%ED%8C%8C%EC%9D%BC.md).

<a id="failure-ownership"></a>
## 실패 소유권

| 실패한 단계 | 소유자가 볼 수 있는 결과 |
|---|---|
| 프로필 또는 INI 유효성 검사 | 프로덕션 쓰기가 시도되지 않습니다. |
| 보류 중write/readback | 기존 프로덕션 바이트는 그대로 유지됩니다. |
| 작업 백업 | 원본을 이동하기 전에 교체가 중지됩니다. |
| 프로모션 또는 제작 검증 | 자동 복원이 시도되고 결과가 보고됩니다. |
| 회전 상태 지속성 | 준비된 샌드박스 바이트가 존재할 수 있지만 전환 성능이 저하되고 adapters/messages 건너뛰었습니다. |
| 어댑터 호환성 | 대상은 `not_installed` 또는 `skipped_incompatible`. |
| 어댑터 write/readback | 가능한 경우 변경된 모든 어댑터 대상이 복원됩니다. |
| 상태 또는 웹 내보내기 | 샌드박스 결과는 여전히 신뢰할 수 있습니다. 출력 실패가 기록되며 성공적인 보고서로 처리되어서는 안 됩니다. |

<a id="evidence-limit"></a>
## 증거 제한

로컬 Lua 픽스처 제품군은 소스 동작, 생성된 프로필 불변성, 트랜잭션 분기, 출력 형태 및 패키지 경계를 증명할 수 있습니다. 현재 Abiotic Factor 빌드, 현재 UE4SS 릴리스, 특정 서버 패널, 모든 디스플레이 크기 또는 테스트되지 않은 타사 모드 버전. 이러한 주장은 여전히 ​​`not tested` 유지됩니다.
