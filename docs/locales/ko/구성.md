<a id="configuration"></a>
# 구성

> **표준 영어 소스:** [CONFIGURATION.md](../../CONFIGURATION.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


주요 운영자 구성은 다음과 같습니다.

```text
RandomDay/Scripts/ax_config/server.lua
```

파일을 백업하고 한 번에 한 섹션씩 변경합니다. Lua 부울은 소문자입니다 `true` 및 `false`; 문자열에는 따옴표가 필요합니다. 목록 항목에는 쉼표가 필요합니다. 다음에 시작한 후 다른 변경을 하기 전에 상태 페이지를 읽으십시오. 소스에서 작업하는 기여자는 수정된 빌드를 패키징하기 전에 별도의 [릴리스 유효성 검사](%EB%A6%B4%EB%A6%AC%EC%8A%A4_%EC%9C%A0%ED%9A%A8%EC%84%B1_%EA%B2%80%EC%82%AC.md) 검사를 사용할 수 있습니다.

직접 편집하지 마세요 `.randomday_mode`, `.randomday_version`, 생성된 프로필 참조, `runtime/` 또는 `web_export/`. 패키지 빌더는 패키지 모드 및 버전 표시를 소유하고 릴리스 메타데이터와 일치하는지 확인합니다.

아래의 모든 설정은 `RandomDay/Scripts/ax_config/server.lua`. 테이블은 편집 가능한 설정을 릴리스 소유 ID 및 예약된 호환성 필드와 구별합니다. Lua에 필드가 존재한다고 해서 변경이 지원되는 동작이라는 의미는 아닙니다.

<a id="choose-an-experience"></a>
## 경험 선택

RandomDay에는 두 개의 패키지가 있습니다. 하나는 모든 전용 서버용이고 다른 하나는 singleplayer/LAN 수동 복사. 전용 패키지에는 두 가지 작동 모드가 있습니다. 이러한 모드는 설정이지 별도의 다운로드가 아닙니다.

| 당신의 세계 | 설치 | 이 동작을 선택하세요 |
| --- | --- | --- |
| 일상적인 재시작 후에도 하나의 캠페인을 계속 이동시키는 전용 서버 | 전용 서버 패키지 | `persistent_dedicated` 저장된 가족 및 프로필 주문을 재개합니다. |
| 개별 플레이 세션만을 위한 전용 서버 오픈 | 동일한 전용 서버 패키지 | `temporary_dedicated` 세션 사이에 안전하게 준비된 다음 프로필을 유지하는 반면, 새로운 가족 운영은 구성된 시작 또는 무작위 시작을 사용할 수 있습니다. |
| 싱글 플레이어 또는 LAN world | Singleplayer/LAN 패키지 | `auto` 수동 복사 동작을 선택합니다. 생성된 파일을 복사하기 전에 세상을 멈추세요. |

확실하지 않은 경우 `auto`. 패키지는 설치 유형에 따라 정상적인 동작을 선택합니다. [가족 순환](%EA%B0%80%EC%A1%B1_%EC%88%9C%ED%99%98.md)에서 다양한 플레이 스타일을 선택하세요. 정확한 게임플레이 및 샌드박스 값을 원할 때 [생성된 패밀리 색인](%ED%94%84%EB%A1%9C%ED%95%84/%ED%94%84%EB%A1%9C%ED%95%84_%EB%AC%B8%EC%84%9C.md)을 사용하세요. 그런 다음 첫 번째 날과 진행 상황을 선택하세요.

- `start_day_mode="configured"` 시작 `start_day`.
- `start_day_mode="random"` 새로운 가족 운영이 시작될 때 하나의 유효한 첫 번째 날을 선택하고 그 선택을 유지합니다.
- `day_progression_mode="sequential"` 17개 위치를 모두 순환합니다.
- `day_progression_mode="non_repeating_random"` 매일 정확히 한 번씩 포함되는 하나의 섞인 순서를 저장합니다.

[회전](#rotation)의 전체 사전 설정을 사용하세요. 새로 설치하려면 선택한 첫 번째 프로필을 준비하고 나중에 활성화하기 위해 한 번 시작해야 합니다.

<a id="release-identity-and-logging"></a>
## 신원 및 로깅 릴리스

| 설정 | 유형 및 배송된 값 | 지원되는 사용 | 실패 또는 상호 작용 |
|---|---|---|---|
| `version` | `.randomday_version` | 읽기 전용. | 누락되거나 빈 마커는 `unversioned`에서 읽은 문자열입니다. 최종 패키지 검증은 ID 드리프트를 거부합니다. |
| `package_mode` | `.randomday_mode` | 읽기 전용: `dedicated_server` 또는 `singleplayer_manual`. | 다른 값은 대상 쓰기 전에 시작을 중지합니다. |
| `plan_basis` | 문자열: `RandomDay - Seventeen Suns Rotation + Open World Scope` | 진단 레이블만; 기능 전환으로 사용하지 마십시오. | 현재 런타임은 이 필드에서 분기되지 않습니다. |
| `logging.level` | 문자열: `info` | `debug`, `info`, `warn` 또는 `error`. | 알 수 없는 값은 로깅 대상을 추가하지 않습니다. 유지 `info` 프로필 생성 동작을 진단하지 않는 한. |

예:

```lua
logging = { level = "debug" }
```

`debug`를 일시적으로 사용하고 관련 `UE4SS.log`를 보존한 다음 `info`로 돌아갑니다. 로그에는 낮은 수준 오류의 로컬 경로가 포함될 수 있습니다. 공유하기 전에 검토하세요.

<a id="experience-mode"></a>
## 체험 모드

`experience.mode`용으로 이 설치가 작동하는 방식을 지정합니다. 다음 시작 안전 경계를 약화시키지 않습니다. Abiotic Factor는 UE4SS는 RandomDay 전에 샌드박스 설정을 읽으므로 어떤 모드도 이미 실행 중인 프로세스의 규칙을 대체할 수 없습니다.

| 설정 | Shipped value | 지원되는 값 | 효과 |
|---|---:|---|---|
| `experience.mode` | `auto` | `auto`, `persistent_dedicated`, `temporary_dedicated`, `singleplayer_lan` | `auto`는 패키지에서 확인됩니다. 전용 패키지는 전용 모드를 사용할 수 있습니다. 수동 복사 패키지는 일반적인 장기 서버 재시작 시 `auto` 또는 `singleplayer_lan`. |

- `persistent_dedicated` 저장된 순서만 family/day 유지합니다.
- `temporary_dedicated` 제한된 플레이 세션을 위해 시작되는 서버를 설명합니다. 준비된 순서를 계속 유지하므로 호스트를 중지해도 다음 세션이 자동으로 다시 시작되지 않습니다.
- `singleplayer_lan` 제한된 수동 복사 출력만 생성합니다. 개인 저장 폴더를 검색하거나 편집하지 않습니다.

호환되지 않는 package/experience 조합이 샌드박스 쓰기 전에 중지됩니다.

<a id="rotation"></a>
## 회전

| 설정 | Shipped value | 지원되는 값 | 효과 |
|---|---:|---|---|
| `cycle.application_mode` | `next_reboot_queue` | `next_reboot_queue` | 모든 샌드박스 변경 사항을 다시 시작 경계에서 유지합니다. |
| `cycle.cycle_length_days` | `17` | `17`표준 프로필 세트의 경우 | 모든 가족 팩 및 생성된 참조와 일치합니다. |
| `cycle.start_day_mode` | `configured` | `configured`, `random` | `cycle.start_day`를 사용하거나 가족 운영 시작 시 유효한 시작일을 한 번 선택합니다. |
| `cycle.start_day` | `1` | 정수 `1`부터 `17` | 첫 번째 날 `start_day_mode=configured`. |
| `cycle.day_progression_mode` | `sequential` | `sequential`, `non_repeating_random` | 매일 정확히 한 번씩 포함하는 래핑된 순차 순서 또는 섞인 순서 하나를 만듭니다. |
| `cycle.bootstrap_day` | `1` | 정수 `1`부터 `17` | 호환성 대체는 `cycle.start_day`가 없는 경우에만 사용됩니다. 새로운 구성은 `cycle.start_day`. |
| `cycle.check_interval_ms` | `0` | `0` 또는 제한된 양의 간격 | `0` 시작 시 한 번 준비합니다. 양수 값은 UE4SS가 `LoopAsync`. |
| `profile_family.mode` | `non_repeating_random_run` | `selected_run`, `non_repeating_random_run`, `rotation_run` | 새로운 17일 가족 달리기 시작 방법을 선택하는 경우 주기적인 감독을 가능하게 합니다. |
| `profile_family.selected_family` | `action` | `allowed_families` | 가족이 `selected_run`에서 대체 수단으로 사용하는 ID 1개. |
| `profile_family.default_family` | `action` | 등록된 가족 ID 1개 | 선택한 ID가 없거나 유효하지 않은 경우 대체. |
| `profile_family.allowed_families` | 공개 가족 ID 17개 모두 | 등록된 ID의 비어 있지 않은 하위 집합 | 새 실행에 적합한 가족을 제한합니다. |
| `profile_family.preserve_family_until_day_17` | 부울: `true` | 예약된 호환성 필드; keep `true`. | 현재 달력은 항상 지속되는 17일 순서의 모든 위치에서 가족을 유지하며 이 필드를 토글로 읽지 않습니다. |
| `profile_family.reroll_only_after_day_17` | 부울: `true` | 예약된 호환성 필드; keep `true`. | 현재 달력은 저장된 순서의 마지막 날짜에 관계없이 매일 ID가 완료된 후에만 가족을 변경합니다. |
| `profile_family.prevent_repeats_until_rotation_complete` | 부울: `true` | 예약된 호환성 필드; keep `true`. | 현재 비반복 풀 논리는 고정되어 있으며 이 값을 토글. |

일 순서는 새로운 가족 실행에 대해 한 번 생성되어 `runtime/rotation_state.txt`에 기록됩니다. 복구 및 나중에 다시 시작하면 정확한 위치를 재사용합니다. 구성 편집은 진행 중인 주문을 다시 롤링하지 않습니다. 가족은 17개의 직위가 모두 완료된 후에야 변경됩니다.

<a id="recommended-presets"></a>
### 권장 사전 설정

영구 전용 서버:

```lua
experience = { mode = "persistent_dedicated" }
cycle = {
    application_mode = "next_reboot_queue",
    cycle_length_days = 17,
    start_day_mode = "configured",
    start_day = 1,
    day_progression_mode = "sequential",
    bootstrap_day = 1,
    check_interval_ms = 0,
}
```

새로운 가족 운영마다 반복되지 않는 순서가 다른 임시 전용 세션:

```lua
experience = { mode = "temporary_dedicated" }
cycle.start_day_mode = "random"
cycle.day_progression_mode = "non_repeating_random"
```

Singleplayer/LAN 수동 복사는 싱글 플레이어 패키지를 사용하며 일반적으로 `experience.mode="auto"`를 떠납니다. 다음 파일을 생성하기 전에 동일한 시작 및 진행 컨트롤을 선택할 수 있습니다. 런타임 상태와 월드의 로드된 프로필이 정렬된 상태로 유지되도록 하려면 다른 생성이 실행되기 전에 생성된 파일을 선택한 중지된 월드에 복사하세요.

새로 설치하는 경우 첫 번째 프로세스는 선택한 시작 날짜만 준비할 수 있습니다. 이후 프로세스에서 이를 활성화합니다. 무작위 또는 구성된 시작은 해당 엔진 로드 순서를 우회하지 않습니다.

고정 Builder 실행의 예:

```lua
profile_family = {
    mode = "selected_run",
    selected_family = "builder",
    default_family = "action",
    allowed_families = { "builder" },
    preserve_family_until_day_17 = true,
    reroll_only_after_day_17 = true,
    prevent_repeats_until_rotation_complete = true,
}
```

비어 있거나 알 수 없는 적격 세트는 불완전한 프로필을 생성하는 대신 등록된 제품군으로 대체됩니다.

<a id="primary-sandbox-path"></a>
## 기본 샌드박스 경로

| 설정 | 유형 및 배송된 값 | 지원되는 사용 | 실패 또는 상호 작용 |
|---|---|---|---|
| `paths.runtime_dir` | 문자열: `ue4ss/Mods/RandomDay/runtime` | 소스 구성에서만 읽기. | `init.lua`가 이를 대체합니다. 해결된 mod-root `runtime/` 경로. |
| `paths.web_export_dir` | 문자열: `ue4ss/Mods/RandomDay/web_export` | 소스 구성에서만 읽기. | `init.lua`가 이를 대체합니다. 해결된 mod-root `web_export/` 경로. |
| `paths.sandbox_path_override` | 문자열 또는 `nil`: `nil` | 비표준 전용 레이아웃에 대한 1 리터럴 `SandboxSettings.ini` 경로. | 안전하지 않거나 사용할 수 없는 대상은 쓰기에 실패합니다. 싱글 플레이어 모드에서는 재정의가 삭제됩니다. |
| `paths.sandbox_candidates` | 문자열 목록: 7개의 일반 후보 | 순서가 지정된 전용 서버 대체 후보. | `init.lua` 설치 파생 후보 앞에 추가됩니다. 첫 번째 기존 경로가 우선합니다. |
| `paths.write_sandbox_mirrors` | 부울: `true` | 의도적으로 구성된 미러를 허용합니다. | 미러 목록이 비어 있고 `world_name=nil`인 동안에는 미러가 작성되지 않습니다. 싱글 플레이어 모드 강제 `false`. |
| `paths.sandbox_mirror_required` | 부울: `false` | 예약된 호환성 필드; keep `false`. | 현재 작성자는 미러를 선택 사항으로 취급하고 이 필드를 필수 게이트로 읽지 않습니다. |
| `paths.world_name` | 문자열 또는 `nil`: `nil` | 일반 미러 후보를 파생하는 데 사용되는 하나의 안전한 월드 폴더 구성 요소입니다. | 문자, 숫자, 공백 이외의 항목이 있으면 `_` 또는 `-` 시작이 중지됩니다. 싱글 플레이어 모드에서는 이를 무시합니다. |
| `paths.sandbox_mirror_candidates` | 문자열 목록: 비어 있음 | 정확한 선택적 미러 파일. | 각 적격 미러는 자체 트랜잭션을 사용합니다. 미러 실패는 기본 성공을 변경하지 않습니다. |

`paths.sandbox_path_override` 기본값은 `nil`를 제공할 때 주기적인 감독을 가능하게 합니다. 재정의하지 않으면 RandomDay 먼저 감지된 WindowsServer 후보를 확인한 다음 구성된 후보를 확인합니다. 아무 것도 없으면 첫 번째 설치 고정 일반 후보를 사용하여 서버 설치를 확인합니다.RandomDay 설치에 고정된 일반

```text
AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini
```

이 폴백은 프로세스의 현재 작업 디렉터리에서 확인되지 않습니다. 설치에서 다른 리터럴 파일을 사용하는 경우에만 `sandbox_path_override`를 설정하세요. 디렉터리가 아닌 하나의 `SandboxSettings.ini`를 가리킵니다. 사용하기 전에 서버를 중지하고 파일이 의도한 설치 내에 있는지 확인하세요.

<a id="optional-mirrors"></a>
### 선택적 미러

`paths.write_sandbox_mirrors`는 `true`로 제공되지만 미러 경로 목록은 비어 있고 `paths.world_name`는 `nil`입니다. 따라서 제공된 기본값은 추가 미러를 작성하지 않습니다. 설치 시 항상 확인된 기본 대상만 작성해야 하는 경우 `false`로 설정하십시오. 구성된 미러 후보 또는 세계 이름이 없어도 두 값 중 하나는 여전히 기본 샌드박스 파일에만 기록됩니다.

미러는 `paths.sandbox_mirror_candidates`에 정확한 항목을 의도적으로 추가하거나 `paths.world_name`를 설정하는 경우에만 적합해집니다. 미러는 두 번째 세계별 샌드박스 경로를 읽는 설치를 위한 최선의 복사본입니다. 이는 올바른 기본 경로 구성을 대신할 수 없습니다.

미러를 활성화하기 전에:

1. 서버를 중지하고,
2. 서버가 읽는 정확한 파일을 식별하고,
3. 대상이 의도한 설치 내에 있는지 확인하고,
4. 백업하고,
5. 해당 경로만 추가하세요.
6. 준비 후 미러 결과를 확인하세요.

미러가 없는 재정의 예:

```lua
paths = {
    runtime_dir = "ue4ss/Mods/RandomDay/runtime",
    web_export_dir = "ue4ss/Mods/RandomDay/web_export",
    sandbox_path_override = "<server-root>/AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini",
    sandbox_candidates = {},
    write_sandbox_mirrors = false,
    sandbox_mirror_required = false,
    world_name = nil,
    sandbox_mirror_candidates = {},
}
```

`<server-root>`는 자리 표시자입니다. 로컬로 교체하세요. 시스템별 경로를 게시하지 마십시오.

<a id="non-disableable-safety-locks"></a>
## 비활성화할 수 없는 안전 잠금

| 설정 | 필수 값 | 의미 |
|---|---:|---|
| `sandbox.backup_before_write` | `true` | 기존 기본 파일을 교체하기 전에 확인된 사본을 보존하십시오. |
| `sandbox.restore_last_good_on_failure` | `true` | 실패한 교체 또는 다시 읽기 후 자동 복구를 시도하십시오. |
| `external_mods.patch_only_existing_keys` | `true` | 다른 모드의 파일에서 알 수 없는 설정을 고안하는 것을 거부하세요. |
| `external_mods.backup_before_write` | `true` | 지원되는 트랜잭션 어댑터 편집 전에 대상 바이트를 보존하세요. |

RandomDay 이 네 가지 값 중 하나라도 없으면 시작을 거부합니다. `true`가 아니면 시작을 거부합니다. 이는 안전 잠금 장치이며 지원되는 운전자 토글이 아닙니다. 개발이나 문제 해결 시에는 비활성화하지 마십시오. 비활성화하면 작성자 및 어댑터 테스트에서 입증된 페일클로즈 경계가 변경됩니다.

`sandbox.force_rewrite_every_supervision_tick` 일반 설정으로 유지되며 `false`로 배송되어 이미 일치하는 샌드박스 파일은 그대로 유지됩니다. 부울을 허용합니다. `true`로 설정하면 동일한 프로세스 소유의 준비된 바이트가 기록기를 다시 통과하게 됩니다. family/day을 진행하지 않습니다. 쓰기를 반복하면 더 많은 작업 백업이 생성되므로 제한된 복구 테스트에만 사용하세요.

현재 인식되는 정확한 레이아웃은 [지원되는 Mod 어댑터](%EC%A7%80%EC%9B%90%EB%90%98%EB%8A%94_%EC%96%B4%EB%8C%91%ED%84%B0.md) 인식된 레이아웃과 6가지 가능한 결과.

<a id="optional-chaotic-spawn-engine-scope-fields"></a>
### 선택적 Chaotic Spawn 엔진 범위 필드

`world_scope` 5개의 선택적인 RandomDay 확장 설정은 인식된 Chaotic Spawn Engine이 있는 경우에만 제공됩니다. `DynamicSpawns/SharedData.lua` 레이아웃에는 이미 해당 필드가 포함되어 있습니다. 이것은 별도의 모드 또는 다운로드가 아닙니다.

| 설정 | Shipped value | 어댑터 효과 |
|---|---:|---|
| `world_scope.enabled` | `true` | 인식된 RandomDay 세계 범위 게이트를 요청합니다. DynamicSpawns 레이아웃. |
| `world_scope.affect_open_worlds` | `true` | 대상 모드가 보호 세계 규칙을 적용하지 않는 한 오픈 월드를 포함합니다. |
| `world_scope.unknown_world_policy` | `allow` | 요청 `allow` 또는 `block` 대상 모드가 세계를 분류할 수 없는 경우. |
| `world_scope.log_scope_decisions` | `true` | 범위 결정을 위해 대상 모드 로깅을 요청합니다. |
| `world_scope.protected_worlds` | 빈 목록 | 쉼표로 구분된 보호 세계 패턴을 대상 레이아웃에 제공합니다. |

이 값은 어댑터 입력이며 RandomDay's 샌드박스 작성기. 이는 별도로 설치된 Chaotic Spawn Engine 레이아웃에 유형, 범위, 배송된 프로필 기본값 및 나머지 불변 값에 대한 완전한 선택적 RandomDay 필드 세트 및 보고서 `applied` 또는 `already_current`가 포함되어 있는 경우에만 적용됩니다. Chaotic Spawn Engine은 런타임 시 해당 필드 사용을 담당합니다. 확장 필드가 없는 일반 설치는 변경되지 않습니다.

5개 값은 모두 어댑터 입력입니다. `unknown_world_policy` 문서화된 목표 값만 허용합니다 `allow` 또는 `block`; 인식할 수 없는 대상 레이아웃은 건너뜁니다. 문서 예제에서는 `protected_worlds`를 비워 두세요. 운영자가 로컬 패턴을 사용하는 경우 스크린샷, 이슈 또는 릴리스 아티팩트에 포함되어서는 안 됩니다.

<a id="player-messages"></a>
## 플레이어 메시지

제공된 전용 서버 구성을 통해 간단한 가입 알림과 짧은 일일 회선이 가능합니다. 첫 번째 패스 전 30초를 기다리고, 15초마다 새로 합류한 플레이어를 확인하고, 일일 라인 전에 합류 알림 후 10초를 기다립니다.

| 설정 | Shipped value |
|---|---:|
| `player_message.enabled` | `true` |
| `player_message.log_on_startup` | `true` |
| `player_message.register_console_command` | `false` |
| `player_message.console_command` | `randomday` |
| `player_message.broadcast_enabled` | `true` |
| `player_message.startup_delay_ms` | `30000` |
| `player_message.join_check_interval_ms` | `15000` |
| `player_message.send_daily_joke_after_join` | `true` |
| `player_message.daily_joke_delay_seconds` | `10` |
| `player_message.criticality_join` | `2` |
| `player_message.criticality_joke` | `0` |
| `player_message.max_line_chars` | `42` |
| `player_message.max_join_lines` | `4` |
| `player_message.max_warning_lines` | `3` |
| `player_message.max_note_lines` | `3` |

메시지 길이 유효성 검사는 소스 제한을 확인합니다. 모든 클라이언트 해상도에 대한 시각적 테스트를 대체하지는 않습니다.

타이밍 값은 `daily_joke_delay_seconds`가 이미 포함되어 있는 경우에만 적용됩니다. 비활성화된 메시지 또는 브로드캐스트 설정은 샌드박스 준비를 변경하지 않고 클라이언트 알림을 억제합니다. 콘솔 명령은 설정과 UE4SS 핸들러를 모두 사용할 수 있는 경우에만 등록됩니다. 명명된 클라이언트 테스트에서 다른 값을 증명하지 않는 한 배송된 전송 수준에서 중요도 값을 유지하세요.

`max_line_chars`는 변환기에 의해 8~64자로 고정됩니다. 세 가지 라인 수 설정은 각각 결합, 경고 및 메모 출력을 제한합니다. 제공된 값은 사용 가능한 소스 줄 수와 일치합니다. 클라이언트 레이아웃 테스트에서 더 좁은 설정이 입증되지 않는 한 이 네 가지 제한을 기본값으로 유지하십시오.

메시지가 비활성화된 예:

```lua
player_message = {
    enabled = false,
    log_on_startup = true,
    register_console_command = false,
    console_command = "randomday",
    broadcast_enabled = false,
    startup_delay_ms = 30000,
    join_check_interval_ms = 15000,
    send_daily_joke_after_join = false,
    daily_joke_delay_seconds = 10,
    criticality_join = 2,
    criticality_joke = 0,
    max_line_chars = 42,
    max_join_lines = 4,
    max_warning_lines = 3,
    max_note_lines = 3,
}
```

<a id="profiles-and-sandbox-values"></a>
## 프로필 및 샌드박스 값

`RandomDay/Scripts/ax_profiles/families/` 아래의 가족 소스 파일은 가족당 17일을 정의합니다. `docs/profiles/`에 생성된 문서는 사용자 정의 소스가 아닌 참조 출력입니다.

[샌드박스 키 참조](%ED%94%84%EB%A1%9C%ED%95%84/%EC%83%8C%EB%93%9C%EB%B0%95%EC%8A%A4_%EC%84%A4%EC%A0%95_%ED%82%A4.md)가 이미 포함되어 있는 경우에만 적용됩니다. 프로필 소스를 편집한 후 289개 조합을 모두 재생성하고 검증합니다. 생성된 마크다운 또는 JSON 직접 기록하지 마세요.

<a id="customize-the-shipped-profile-defaults"></a>
### 배송된 프로필 기본값을 사용자 정의하세요.

열기:

```text
RandomDay/Scripts/ax_config/server.lua
```

`sandbox`:

```lua
profile_overrides = {
    HardcoreMode = false,
    AllowIronMode = false,
    StructuralSupportLimit = 0,
    BridgeSupports = 0,
}
```

이것은 RandomDay's 시작 선택 사항을 패치하지 마십시오. 변경할 수 없는 비생물적 요소 규칙이 아닙니다. 하나의 가족을 열려면 `true` 또는 `false`로 설정하세요. 각 지원 값을 `0`부터 `1000`의 정수로 설정하세요. 파일을 편집하기 전에 게임이나 전용 서버를 중지하고 저장한 다음 Lua가 새 구성을 로드하도록 다시 시작하세요.

RandomDay로 설정하면 패밀리에 17개의 프로필을 구축할 때마다 이 블록을 읽습니다. 따라서 선택한 값은 순환 후 준비된 프로필과 나중에 서버 시작 후 다시 작성된 프로필을 포함하여 모든 가족과 날짜에 적용됩니다. 289개의 프로필 파일을 편집하거나 프로필 참조를 다시 생성할 필요가 없습니다.

라이브만 변경하는 것은 `SandboxSettings.ini` 준비된 다음 프로필이 `server.lua`에서 생성되기 때문에 일시적입니다. 잘못된 유형, 알 수 없는 키 또는 외부 값 지원 `0..1000` 자동으로 기본값으로 되돌리는 대신 명명된 구성 오류로 프로필 생성을 중지합니다.

생성된 프로필 참조는 계속해서 제공된 기본값을 표시합니다. 이는 한 서버의 비공개 구성 복사본이 아니라 릴리스 참조입니다.
