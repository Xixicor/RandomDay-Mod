# 활성, 준비 및 복구 상태 운영

> **표준 영어 소스:** [OPERATIONS.md](../../OPERATIONS.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


RandomDay는 향후 부팅을 위해 샌드박스 파일을 변경합니다. 실행 중인 Abiotic Factor 세션에 이미 로드된 규칙은 변경되지 않습니다.

이 페이지는 운영자 결정 및 복구 절차를 소유합니다. 표준 용어는 [용어집](%EC%9A%A9%EC%96%B4%EC%A7%91.md), 경로 소유권은 [런타임 파일](%EB%9F%B0%ED%83%80%EC%9E%84_%ED%8C%8C%EC%9D%BC.md), 정확한 스키마 및 필드 의미는 [런타임 출력](%EB%9F%B0%ED%83%80%EC%9E%84_%EC%B6%9C%EB%A0%A5.md)를 사용하세요.

<a id="distinguish-active-and-prepared-state"></a>
## 활성 상태와 준비된 상태를 구별하세요

준비된 프로필 나중에 시작하여 해당 마커를 읽을 때까지 활성화되지 않습니다. 현재 세션을 설명하기 위해 준비된 family/day를 사용하지 마세요.

`web_export/today.html`는 읽기 쉬운 요약을 위해, `web_export/today.json`는 정확한 상태를 위해 사용하세요. 재시작을 결정하기 전에 활성 마커, 준비된 ID, `prepared_ready`, `profile_status`, 트랜잭션 결과, 롤백 결과 및 상태 커밋 결과를 확인하세요.

## 일반적인 전용 서버 순서를 따르세요

| 전 | 액션 | 후 |
|---|---|---|
| 아니요 RandomDay 마커 | 다음으로 시작RandomDay 활성화되었습니다. | 현재 세션은 기존 규칙을 유지합니다. RandomDay 일일 주문을 생성 및 유지한 후 첫 번째 주문을 준비합니다 configured/random 위치를 준비합니다. |
| 첫 번째 포지션 준비 | 다시 시작하세요. | 그 날이 활성화됩니다. 동일한 계열의 다음 저장 위치가 준비됩니다. |
| 중간 위치 활성 | 준비된 프로필을 검토한 후 다시 시작하세요. | 준비된 요일이 활성화되고 다음 저장위치가 준비됩니다. |
| 최종 위치 활성화 | 다음 계열을 검토한 후 다시 시작하세요. | 적격한 다른 가족 주문의 첫 번째 위치가 활성화됩니다. |

`selected_run` 구성된 제품군을 유지합니다. `non_repeating_random_run` 17일 동안 무작위로 선택된 제품군을 유지하고 적격 목록이 소진될 때까지 제품군 재사용을 방지합니다. `rotation_run` 구성된 계열 순서를 따릅니다. `cycle.day_progression_mode` 가족 선택과 별도로 요일 순서를 제어합니다.

새로 설치하려면 항상 하나의 프로세스를 준비하고 이후 프로세스를 활성화해야 합니다. 이는 영구 서버, 임시 서버 및 수동 서버에 해당됩니다. singleplayer/LAN 세대.

<a id="read-the-right-evidence"></a>
## 올바른 증거 읽기

사용[런타임 파일 맵](%EB%9F%B0%ED%83%80%EC%9E%84_%ED%8C%8C%EC%9D%BC.md)을 사용하여 회전 상태, 현재 상태, 마지막으로 알려진 양호함을 찾을 수 있습니다. 모든 필드 그룹, 스키마, 빈 상태, 실패 의미 및 보관 규칙에 대한 파일, 작업 백업, 내보내기 및 `UE4SS.log`에서 다양한 플레이 스타일을 선택하세요. 정확한 게임플레이 및 샌드박스 값을 원할 때 [런타임 출력 참조](%EB%9F%B0%ED%83%80%EC%9E%84_%EC%B6%9C%EB%A0%A5.md). 표준 6개 상태 결과 테이블 및 다음 작업에 대한 HTML 및 JSON 내보내기는 소스 상태를 요약합니다. 이는 라이브 게임 클라이언트에서 프로필이 사용되었음을 증명하지 않습니다.

만약 `prepared_ready`는 `false` 또는 `profile_status`는 `degraded_state_persistence`, 샌드박스와 회전 상태가 일치할 때까지 서버를 중지된 상태로 유지하세요. 실패한 상태 지속성을 갖춘 유효한 샌드박스 쓰기는 정상적으로 준비된 전환이 아닙니다.

<a id="respond-to-writer-outcomes"></a>
## 작가 결과에 응답

RandomDay 형제 파일의 새 바이트를 준비하고 다시 읽고 전체 샌드박스의 유효성을 검사하고 원본이 있으면 원본을 보존하고 새 파일을 승격하고 다시 읽습니다. 프로덕션 리드백이 동의한 후에만 준비가 완료되었음을 보고합니다.

프로모션 또는 프로덕션 검증이 실패하면 RandomDay 해당 작업에 의해 보관된 파일을 복원하려고 시도합니다. 복원 실패는 강제 종료입니다. 서버를 정지 상태로 유지하고 반복적으로 다시 시작하는 대신 수동으로 복구하세요.

<a id="respond-to-adapter-outcomes"></a>
## 어댑터 결과에 응답

[지원되는 어댑터](%EC%A7%80%EC%9B%90%EB%90%98%EB%8A%94_%EC%96%B4%EB%8C%91%ED%84%B0.md#read-an-adapter-result) 처리 `rollback_failed`를 강제 종료로 간주하세요. 별도로 기록된 어댑터 백업이 복구 소스입니다.

어댑터는 별도로 설치된 모드에만 영향을 미칩니다. 그들은 준비된 RandomDay 샌드박스 프로필을 활성화하지 않습니다.

일반 부팅 시 별도로 설치된 모드가 나중에 동일한 시작 시 로드될 수 있기 때문에 어댑터 값은 활성 프로필에서 선택됩니다. UE4SS 첫 번째 부트스트랩 동안 활성 RandomDay 마커가 없으면 준비된 시작일 프로필이 유일하게 사용 가능한 매핑입니다. 이 타이밍 규칙은 다음 재시작 샌드박스 경계와 별개이며 여전히 다른 모드의 자체 로드 동작에 따라 달라집니다.

<a id="manual-recovery"></a>
## 수동 복구

1. 게임이나 서버를 중지하세요. 파일이 열려 있는 동안에는 파일을 복구하지 마십시오.
2. 현재 `SandboxSettings.ini`, `runtime/` 및 `web_export/`를 별도의 진단 백업에 복사하세요.
3. 검사 `runtime/last_good/manifest.lua` 및 `runtime/backups/`에서 최신 관련 항목을 검사하세요. family/day 및 해시가 복원하려는 상태와 일치하는 파일을 선택하세요.
4. 선택한 확인된 파일을 구성된 기본 샌드박스 경로에 복사하세요.
5. 시작하기 전에 다시 읽고 완료되었는지 확인하세요.
6. 한 번 시작하여 활성 마커와 준비된 상태를 검사하세요. 오류 메시지가 없다고 해서 복구가 성공했다고 가정하지 마세요.

확인된 백업이 없으면 설치 전에 생성된 운영자 백업을 복원하세요. RandomDay 읽을 수 없는 파일은 재구성할 수 없습니다.

<a id="account-for-control-panel-writes"></a>
## 제어판 쓰기용 계정

일부 서버 패널에서는 `SandboxSettings.ini` 시작하는 동안. RandomDay 쓰기가 확인된 후 다른 도구가 프로필을 덮어쓰는 경우 준비된 프로필을 보존할 수 없습니다. 하나의 신뢰할 수 있는 샌드박스 소스를 구성하고 반복되는 1일 차 또는 누락된 전환을 진단할 때 다시 시작하기 직전과 직후에 파일 마커를 확인하십시오.
