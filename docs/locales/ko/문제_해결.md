## 먼저 다음과 같은 일반적인 수정 사항을 시도해 보세요

1. **RandomDay 절대 나타나지 않습니다:** 확인 `RandomDay` 폴더는 바로 안에 있습니다 `ue4ss/Mods`, 활성화 `RandomDay : 1` `mods.txt`한 번만 시작하세요.
2. **현재 세션이 이전 규칙을 유지했습니다:** 이는 정상입니다. RandomDay은 다음 프로필을 준비합니다. 나중에 시작할 때 게임이 로드됩니다.
3. **동일한 프로필이 계속 표시됩니다.** 서버 패널이 교체될 수 있습니다. `SandboxSettings.ini`. 하나의 신뢰할 수 있는 샌드박스 파일을 사용하고 `web_export/today.html`.
4. **선택적 모드가 프로필을 따르지 않았습니다.** 엽니다 [지원되는 선택적 모드](%EC%A7%80%EC%9B%90%EB%90%98%EB%8A%94_%EC%96%B4%EB%8C%91%ED%84%B0.md). 누락, 비활성화 또는 인식되지 않은 선택적 모드는 변경되지 않은 채로 남아 있습니다.
5. **RandomDay 쓰기 또는 복원 실패를 보고합니다.** 다시 시작하기 전에 중지하고 `runtime/backups/`아래의 복구 섹션을 따르세요.

5가지 검사를 통해 문제를 식별할 수 없는 경우 자세한 진단 트리를 계속 진행하세요.

<a id="follow-the-safe-diagnostic-order"></a>
### 안전한 진단 순서를 따르세요

1. 파일을 변경하기 전에 현재 증거를 보존하세요.
2. 로드되었는지 여부를 RandomDay 확인하십시오.
3. 문서화된 결과에 도달하지 못한 첫 번째 단계를 찾으세요.
4. 런타임 출력에서 정확한 상태 또는 오류 값을 복사하세요.
5. 한 번의 안전한 응답을 위해 아래 일치하는 표 행을 사용하세요.
6. 다음 시작 전에 대상 및 회전 상태를 다시 읽어보세요.

일치하는 행이 없으면 [런타임 상태 및 출력을 사용하세요. 구성을 변경하기 전에 ](%EB%9F%B0%ED%83%80%EC%9E%84_%EC%B6%9C%EB%A0%A5.md) 생산자와 필드 의미를 식별하려면 참조하세요.

<a id="restore-a-missing-randomday-start"></a>
## 누락된 RandomDay start

**가장 가능성이 제한된 원인:** 잘못된 추출 레이아웃, 비활성화된 모드, 잘못된 패키지 모드 또는 UE4SS Lua 진입점을 로드하지 않았습니다.

**정확한 확인:** 확인 `RandomDay/enabled.txt`, `.randomday_mode`, `.randomday_version` 및 `RandomDay/Scripts/main.lua`; 확인 `RandomDay : 1` `mods.txt`; `UE4SS.log` for `[RandomDay]`.

**예상 결과:** 하나의 시작 줄에 릴리스 ID 및 패키지 모드 이름이 지정됩니다.

**안전한 다음 작업:** 중지된 동안 레이아웃이나 활성화를 수정한 후 한 번 시작하세요.

**추론하지 마세요:** 아니요 RandomDay 줄은 게임 또는 프로필 버그를 증명하지 않습니다.

<a id="confirm-the-restart-boundary"></a>
## 다시 시작 경계를 확인하세요

**가장 가능성이 제한된 원인:** 일반적인 다음 재시작 동작.

**정확한 확인:** 활성 프로파일과 준비된 프로파일을 비교하십시오. family/day `web_export/today.json` 또는 `today.html`.

**예상 결과:** 준비된 프로파일은 활성 프로파일과 다르거나 명시적으로 분리되어 있습니다.

**안전한 다음 작업:** 활성화할 준비가 되었을 때만 다시 시작한 다음 활성 마커를 확인하십시오.

**추론하지 마세요:** 준비된 프로파일은 재시작 후 활성화되지 않습니다. 다시 읽어옵니다.

<a id="stop-repeated-preparation"></a>
## 반복적인 준비 중지

**가장 가능성이 제한된 원인:** 활성 RandomDay 마커가 누락되었습니다. `SandboxSettings.ini`를 다시 작성했습니다.

**정확한 확인:** 샌드박스 파일과 해당 RandomDay 마커를 비교하십시오.RandomDay 파일을 준비한 후 샌드박스 파일과 해당

**예상 결과:** 다음 부팅 시 존재하는 파일은 준비된 마커를 유지합니다.

**안전한 다음 작업:** 신뢰할 수 있는 하나의 샌드박스 소스를 구성하고 충돌하는 패널 재작성을 비활성화합니다.

**추론하지 마세요:** 반복되는 1일 차는 계열을 증명하지 않습니다. 선택기가 무작위로 잘못 지정되었습니다.

<a id="recover-from-failed-preparation"></a>
## 실패한 준비에서 복구

**가장 가능성이 제한된 원인:** 보류 중인 쓰기, 백업, 승격, 프로덕션 다시 읽기, 검증 또는 롤백이 실패했습니다.

**정확한 확인:** 첫 번째 읽기 `[RandomDay] [ERROR]` 줄을 선택하고 명명된 작업 백업을 보존합니다. 검사 `runtime/last_good/manifest.lua` 샌드박스 파일을 사용하기 전

**예상 결과:** 이전 파일이 복원된 것으로 확인되었거나 결과에서 복원 실패를 명확하게 보고합니다.

**안전한 다음 작업:** 서버를 중지한 상태로 유지하고 따르세요 [수동 복구](%EC%9E%91%EC%97%85.md#manual-recovery).

**추론하지 마세요:** 백업 파일의 존재만으로는 의도한 활성 세계 상태와 일치한다고 증명할 수 없습니다.

<a id="diagnose-a-skipped-adapter"></a>
## 건너뛴 어댑터 진단

**가장 가능성이 제한된 원인:** 모드가 없거나 파일이 지원되는 서명과 일치하지 않습니다.

**정확한 확인:** 어댑터 결과를 읽고 설치된 버전과 레이아웃을 [지원되는 Mod 어댑터](%EC%A7%80%EC%9B%90%EB%90%98%EB%8A%94_%EC%96%B4%EB%8C%91%ED%84%B0.md).

**예상 결과:** `not_installed` 또는 `skipped_incompatible` 인식할 수 없는 대상의 경우

**안전한 다음 작업:** 파일을 변경하지 않고 그대로 두거나 해당 어댑터를 비활성화하거나 원래 작성자가 지원하는 정확한 버전을 설치하십시오.

**추론하지 마세요:** 비슷한 파일 이름이나 최신 버전은 호환성을 증명하지 않습니다.

<a id="recover-an-adapter-rollback-failure"></a>
## 어댑터 롤백 실패 복구

**가장 가능성이 제한된 원인:** 쓰기 시도와 자동 복원을 모두 확인할 수 없습니다.

**정확한 확인:** 대상을 보존하세요, 형제 pending/rollback 파일, 어댑터 상태 및 최신 어댑터 백업 `runtime/backups/`.

**예상 결과:** 결과는 다음과 같습니다. `rollback_failed`, 아님 `applied`.

**안전한 다음 작업:** 영향을 받은 것을 중지하십시오 mod/server다음 실행 전에 확인된 백업을 수동으로 복원하세요.

**추론하지 마세요:** RandomDay's 기본 샌드박스 결과는 별도의 어댑터 대상이 정상임을 증명하지 않습니다.

<a id="generate-a-missing-singleplayerlan-file"></a>
## 누락된 항목 생성singleplayer/LAN 파일

**가장 가능성이 제한된 원인:** 전용 패키지가 설치되었거나 모드 마커가 유효하지 않거나 RandomDay 로드되지 않았습니다.

**정확한 확인:** `.randomday_mode` `singleplayer_manual`; 그런 다음 RandomDay 시작 줄을 확인하고 `runtime/singleplayer_manual/SandboxSettings.ini`.

**예상 결과:** 파일이 RandomDay 폴더 내부에만 존재합니다.

**안전한 다음 작업:** 올바른 패키지를 완전히 설치하고 한 번 시작하십시오.

**추론하지 마세요:** RandomDay는 사용자를 대신하여 대상 세계를 검색하거나 작성하지 않습니다.

<a id="diagnose-a-message-problem"></a>
## 메시지 문제 진단

**가장 가능성이 제한된 원인:** 예약된 패스에서 유효한 플레이어 캐릭터를 사용할 수 없거나, 경고 전송을 사용할 수 없거나, 클라이언트 디스플레이가 텍스트를 다르게 래핑했습니다.

**정확한 확인:** `[RandomDay]` 메시지 로그를 검사하고 소스 메시지를 문서화된 길이 제한과 비교하세요.

**예상 결과:** 런타임에서 메시지 패스가 실행되었는지 보고합니다. 소스 검증은 최대 길이를 보고합니다.

**안전한 다음 작업:** 의도한 클라이언트 해상도를 확인하세요. 게임플레이 및 프로필 확인을 메시지 결과와 별도로 유지하세요.

**추론하지 마세요:** 보이는 메시지는 샌드박스 프로필이 적용되었음을 증명하지 않으며, 누락된 메시지는 준비 실패를 증명하지 않습니다.
<a id="four-profile-wide-choices-returned-to-the-shipped-values"></a>
## 프로필 전체의 4가지 선택 사항이 배송된 값으로 반환되었습니다.

**가장 가능성이 제한된 원인:** 생성된 것만 `SandboxSettings.ini`만 또는 동일한 Lua 프로세스가 실행되는 동안 `server.lua`가 변경되었습니다.

**정확한 확인:** 게임 또는 전용 서버를 중지하고, 다음 시작 후 `RandomDay/Scripts/ax_config/server.lua`를 열고 저장된 `sandbox.profile_overrides` 블록에 의도한 4개의 값이 포함되어 있는지 확인하세요.

**예상 결과:** 새로 준비할 때마다 family/day 프로필에는 선택한 값이 포함됩니다. 나중에 프로필 교체 및 서버 시작 시 동일한 블록을 계속 사용합니다.

**안전한 다음 작업:** 블록을 수정하고 한 번 시작한 다음 준비된 프로필을 검사합니다. 나중에 준비하면 대체되므로 생성된 샌드박스 파일만 패치하지 마십시오.

<a id="look-up-an-exact-status"></a>
## 정확한 상태를 찾아보세요

의사결정 트리에서 실패한 단계를 식별한 후 런타임 내보내기에서 정확한 `status`, `transaction_status`, `rollback_status` 또는 `error` 런타임 내보내기의 값입니다. 의미와 안전한 운영자 응답을 보려면 [상태 및 오류 참조](%EC%83%81%ED%83%9C_%EB%B0%8F_%EC%98%A4%EB%A5%98_%EC%B0%B8%EC%A1%B0.md)를 사용하세요. 패널이나 콘솔의 유사한 문구는 내보낸 값을 대체하지 않습니다.

기여자 전용 테스트 환경 실패는 운영자 복구 경로가 아닌 [릴리스 유효성 검사](%EB%A6%B4%EB%A6%AC%EC%8A%A4_%EC%9C%A0%ED%9A%A8%EC%84%B1_%EA%B2%80%EC%82%AC.md#avoid-validation-environment-pitfalls)에 속합니다.
