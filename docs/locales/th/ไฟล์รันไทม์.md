# ค้นหาไฟล์และสถานะรันไทม์

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [RUNTIME_FILES.md](../../RUNTIME_FILES.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


นี่คือรายการเส้นทาง Canonical ที่ผู้ปฏิบัติงานและการติดตามแหล่งที่มาใช้ โดยจะตอบคำถามว่าไฟล์อยู่ที่ไหน ใครเป็นคนเขียน มีการเปลี่ยนแปลงเมื่อใด ระยะเวลาที่ไฟล์คงอยู่ และบทบาทการกู้คืนใดที่ทำหน้าที่ [การอ้างอิงเอาต์พุตรันไทม์](%E0%B9%80%E0%B8%AD%E0%B8%B2%E0%B8%95%E0%B9%8C%E0%B8%9E%E0%B8%B8%E0%B8%95%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md) เป็นเจ้าของสคีมา ความหมายของฟิลด์ สถานะว่าง และการตีความค่าเครื่อง

เส้นทางทั้งหมดในคู่มือนี้สัมพันธ์กับโฟลเดอร์ `RandomDay/` ที่ติดตั้ง เว้นแต่จะระบุไว้เป็นอย่างอื่น เอาต์พุตรันไทม์จะถูกสร้างขึ้นหลังการติดตั้ง โดยจะไม่รวมอยู่ใน ZIP ที่เผยแพร่

| `runtime/singleplayer_manual/SandboxSettings.ini` | ตัวเขียนแซนด์บ็อกซ์ในโหมด `singleplayer_manual` | ถูกแทนที่ธุรกรรมเมื่อแพ็คเกจแบบแมนนวลรัน | สร้างไฟล์ให้สมบูรณ์เพื่อให้ผู้ปฏิบัติงานตรวจสอบและคัดลอกด้วยตนเองเป็นการหยุดหนึ่งไฟล์ world. |

<a id="recognize-empty-and-failed-file-states"></a>
### รับรู้สถานะไฟล์ว่างเปล่าและล้มเหลว

- เป้าหมายหลักหรือมิเรอร์ที่หายไปอาจถูกสร้างขึ้น โปรไฟล์ที่ไม่ถูกต้อง รอการเขียน การเลื่อนระดับ หรือความล้มเหลวในการอ่านกลับที่ใช้งานจริงยังไม่พร้อม ความล้มเหลวของมิเรอร์ไม่ได้เปลี่ยนผลลัพธ์หลักที่ยอมรับ
- `runtime/singleplayer_manual/SandboxSettings.ini` อาจถูกสร้างขึ้นในการรันด้วยตนเองครั้งแรก ความล้มเหลวในการสร้างยังคงมองเห็นได้ในสถานะและเอาต์พุตบันทึก
- `rotation_state.txt` ที่อ่านไม่ได้สามารถถอยกลับไปยังสถานะสุดท้ายที่ใช้งานหรือบูตสแตรปที่ใช้มาร์กเกอร์ การคอมมิตสถานะที่ล้มเหลวทำให้เกิด `degraded_state_persistence`.
- `runtime/last_good/` อาจไม่ปรากฏก่อนเป้าหมายแรกที่ได้รับการยืนยัน หากการอัปเดตรายการคู่ล้มเหลว RandomDay เรียกคืนคู่ที่ยอมรับก่อนหน้านี้
- `runtime/backups/mirror_<operation>/` คือตำแหน่งสำรองข้อมูลเฉพาะมิเรอร์ ไม่มีไฟล์สำรองข้อมูลหลักหรือมิเรอร์อยู่เมื่อเป้าหมายนั้นไม่มีอยู่ก่อนการทำธุรกรรม
- การเปลี่ยนแปลงของอะแดปเตอร์จะไม่เริ่มต้นเมื่อการสร้างการสำรองข้อมูลหรือการอ่านกลับล้มเหลว
- สถานะปัจจุบัน พจนานุกรม หรือไฟล์แสดงตัวอย่างอาจหายไปเมื่อเอาต์พุตสถานะรันไทม์ไม่พร้อมใช้งานหรือไม่สมบูรณ์
- ผลลัพธ์ `export_failed` อาจทำให้ไฟล์เก่ากว่า `today.json` อยู่ในตำแหน่ง การอัปเดตความล้มเหลวของแซนด์บ็อกซ์ JSON แต่ไม่สร้างความล้มเหลวใหม่ HTML หน้า; เปรียบเทียบการประทับเวลาด้วย `UE4SS.log`.
- รถเทียมข้างรถจักรยานยนต์ที่รอดำเนินการเก่าจะถูกลบออกก่อนที่จะพยายามใหม่ ความล้มเหลวในการล้างข้อมูลจะหยุดธุรกรรม หากมีทั้งเป้าหมายการผลิตและไซด์คาร์ย้อนกลับ RandomDay รักษาไบต์การกู้คืนไว้เพื่อตรวจสอบ
- ไม่มี `[RandomDay]` บรรทัดเริ่มต้นใน `UE4SS.log` หมายความว่าการโหลด mod ไม่ได้รับการพิสูจน์

<a id="transaction-sidecars"></a>
## sidecars ธุรกรรม

ผู้เขียนธุรกรรมอาจสร้างไฟล์พี่น้องข้างเป้าหมาย:

| รูปแบบ | สถานะ | การกระทำของตัวดำเนินการ |
|---|---|---|
| `<target>.randomday.pending` | ไบต์ของผู้สมัครก่อนการเลื่อนตำแหน่ง | ปกติจะถูกลบออกโดยการเลื่อนตำแหน่ง เก็บรักษาไว้หากรายงานความล้มเหลวอยู่ระหว่างการล้างข้อมูลหรือปัญหาในการอ่านกลับ |
| `<target>.randomday.rollback` | ไบต์ต้นฉบับถูกเก็บไว้ระหว่างการเปลี่ยน | ปกติจะได้รับการกู้คืนเมื่อเกิดความล้มเหลวหรือถูกลบออกหลังจากยืนยันความสำเร็จแล้ว อย่าลบมันเมื่อมีเป้าหมายอยู่ด้วย ชุดค่าผสมนั้นต้องมีการตรวจสอบ |
| `<target>.randomday.restore.pending` | ไบต์ของตัวเลือกในระหว่างการคืนค่าอะแดปเตอร์ | เก็บรักษาด้วยการสำรองข้อมูลของอะแดปเตอร์หากการกู้คืนล้มเหลว |
| `<target>.randomday.restore.rollback` | ไบต์การกู้คืนที่เก็บไว้ระหว่างการกู้คืนอะแดปเตอร์ | รักษาและหยุดบริการที่ได้รับผลกระทบหากการล้างข้อมูลหรือการกู้คืนไม่ได้รับการยืนยัน |

ไฟล์เหล่านี้สามารถอยู่ด้านข้างเฉพาะ แซนด์บ็อกซ์หรือเป้าหมายอะแด็ปเตอร์ที่ติดตั้งแยกต่างหาก การมีอยู่ของพวกเขาเป็นสถานะของธุรกรรม ไม่ใช่หลักฐานว่าโปรไฟล์ใหม่เปิดใช้งานแล้ว

## ตีความเนื้อหาไฟล์

ใช้ [สถานะรันไทม์และการอ้างอิงเอาต์พุต](%E0%B9%80%E0%B8%AD%E0%B8%B2%E0%B8%95%E0%B9%8C%E0%B8%9E%E0%B8%B8%E0%B8%95%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md) สำหรับสคีมา `rotation_state.txt`, `randomday_status.json` ปัจจุบัน และ `today.json` ที่สมบูรณ์ การอ้างอิงนั้นยังเป็นเจ้าของสถานะว่าง ความหมายของความล้มเหลว เอาต์พุตพจนานุกรม และกฎที่สถานะที่เตรียมไว้ไม่ใช่สถานะใช้งานอยู่ ใช้ [การอ้างอิงสถานะและข้อผิดพลาด](%E0%B8%AA%E0%B8%96%E0%B8%B2%E0%B8%99%E0%B8%B0%E0%B9%81%E0%B8%A5%E0%B8%B0%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%AD%E0%B9%89%E0%B8%B2%E0%B8%87%E0%B8%AD%E0%B8%B4%E0%B8%87%E0%B8%82%E0%B9%89%E0%B8%AD%E0%B8%9C%E0%B8%B4%E0%B8%94%E0%B8%9E%E0%B8%A5%E0%B8%B2%E0%B8%94.md) เมื่อค่าเครื่องจักรที่แน่นอนจำเป็นต้องมีการดำเนินการของผู้ปฏิบัติงาน

## เก็บหลักฐานการกู้คืน

RandomDay เขียนทับสถานะปัจจุบัน สถานะปัจจุบัน สถานะสุดท้ายที่ดี และมุมมองเว็บ สร้างไดเร็กทอรีสำรองข้อมูลการดำเนินการที่ไม่ซ้ำกันและจะไม่ลบไดเร็กทอรีเก่า เลือกนโยบายการเก็บรักษานอกกระบวนการที่กำลังทำงานอยู่ แต่อย่าลบหลักฐานการกู้คืนล่าสุดในขณะที่ปัญหาการเขียน การอ่านกลับ สถานะ หรือการย้อนกลับยังไม่ได้รับการแก้ไข
