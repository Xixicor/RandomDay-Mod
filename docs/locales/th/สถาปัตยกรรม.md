# สถาปัตยกรรมและการไหลของข้อมูล

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [ARCHITECTURE.md](../../ARCHITECTURE.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


RandomDay เป็นเจ้าของงานที่มีขอบเขตหนึ่งงาน: เตรียมโปรไฟล์แซนด์บ็อกซ์ที่สมบูรณ์สำหรับการเริ่มต้นในอนาคตโดยไม่ต้องอธิบายว่าโปรไฟล์นั้นใช้งานอยู่ในระหว่างกระบวนการปัจจุบัน โปรไฟล์ที่ใช้งานมาจากเครื่องหมายในไฟล์แซนด์บ็อกซ์ที่ Abiotic Factor โหลดก่อน UE4SS เริ่มต้น RandomDay. โปรไฟล์ที่เตรียมไว้เป็นสถานะไฟล์ที่ได้รับการตรวจสอบแยกต่างหากสำหรับการรีสตาร์ทครั้งถัดไป

<a id="package-modes"></a>
## โหมดแพ็กเกจ

ตัวสร้างการเผยแพร่จะสร้าง ZIP สองรายการจากแหล่งที่มาที่อนุญาตเดียวกันและตั้งค่า `RandomDay/.randomday_mode` ที่แตกต่างกันในแต่ละอัน

| โหมด | เอาต์พุตหลัก | การเขียนภายนอกอัตโนมัติ |
|---|---|---|
| `dedicated_server` | ได้รับการแก้ไขแล้ว เซิร์ฟเวอร์เฉพาะ `SandboxSettings.ini` | แซนด์บ็อกซ์หลัก มิเรอร์ที่กำหนดค่าโดยเจตนา และอะแดปเตอร์เสริมที่รู้จัก |
| `singleplayer_manual` | `RandomDay/runtime/singleplayer_manual/SandboxSettings.ini` | ไม่มีอยู่นอก RandomDay โฟลเดอร์; มิเรอร์และอะแดปเตอร์ถูกปิดใช้งาน |

`RandomDay/.randomday_version` และ `RandomDay/.randomday_mode` เป็นเครื่องหมายแพ็คเกจที่สร้างขึ้น `RandomDay/Scripts/ax_core/version.lua` อ่าน; ผู้ปฏิบัติงานจะต้องไม่แก้ไขหลังการติดตั้ง

<a id="session-modes"></a>
## โหมดเซสชัน

โหมดแพ็คเกจควบคุมโดยที่ RandomDay อาจเขียน `experience.mode` อธิบายวงจรการใช้งานที่ตั้งใจไว้แยกกัน:

| โหมดเซสชัน | แพ็คเกจ | สัญญาวงจรการใช้งาน |
|---|---|---|
| `persistent_dedicated` | เฉพาะ | ดำเนินการต่อกลุ่มที่มีอยู่และคำสั่งวัน 17 ตำแหน่งในระยะยาว รีสตาร์ท |
| `temporary_dedicated` | เฉพาะ | ถือว่าการเปิดตัวแต่ละครั้งเป็นเซสชันการเล่นที่มีขอบเขตในขณะที่รักษาลำดับคิวระหว่างการเปิดตัว |
| `singleplayer_lan` | คู่มือผู้เล่นคนเดียว | สร้างไฟล์ mod-local สำหรับโลกที่ผู้ให้บริการเลือก ไม่มีการบันทึกการค้นพบหรือการคัดลอกอัตโนมัติ |

`auto` แก้ไขเป็น `persistent_dedicated` ในแพ็คเกจเฉพาะและ `singleplayer_lan` ในแพ็คเกจแบบแมนนวล โหมดเซสชันไม่เปลี่ยนแปลงขอบเขตของกลไก: กระบวนการปัจจุบันโหลดแซนด์บ็อกซ์ก่อน RandomDay ดำเนินการ

<a id="startup-path"></a>
## เส้นทางเริ่มต้น

1. UE4SS โหลด `RandomDay/Scripts/main.lua`.
2. จุดเข้าแก้ไขหนึ่ง `RandomDay/` รูทและโหลด `Scripts/ax_core/init.lua`.
3. `init.lua` โหลดการกำหนดค่า โปรไฟล์ ปฏิทิน ตัวเขียน อะแดปเตอร์ สถานะ การส่งออกเว็บ และโมดูลข้อความของผู้เล่น จะปฏิเสธโหมดแพ็คเกจที่ไม่ถูกต้องหรือปิดใช้งานการล็อคความปลอดภัยของธุรกรรม นอกจากนี้ยังตรวจสอบโหมดเซสชันที่เข้ากันได้กับแพ็คเกจ โหมดวันเริ่มต้น วันเริ่มต้นที่กำหนดค่า และโหมดความคืบหน้าของวัน
4. ทุกตระกูลสร้างตรวจสอบ `sandbox.profile_overrides` จาก `Scripts/ax_config/server.lua` ตัวเลือกทั้งสี่โปรไฟล์จะถูกใช้หลังค่า family/day และก่อนกฎคงที่ที่เหลืออยู่ ดังนั้นทุกโปรไฟล์ที่เตรียมไว้จึงใช้ตัวเลือกที่กำหนดค่าไว้เหมือนกัน
5. รูทรันไทม์และเว็บเอาท์พุตจะยึดอยู่กับโฟลเดอร์ mod ที่แก้ไขแล้ว โหมดผู้เล่นคนเดียวจะถูกลดเหลือเอาต์พุต mod-local เดียวก่อนที่จะเลือก
6. `ax_cycle/calendar.lua` อ่านเครื่องหมายแซนด์บ็อกซ์และสถานะการหมุนที่กู้คืนได้ จากนั้นสร้างการตัดสินใจ active/prepared หนึ่งครั้งสำหรับกระบวนการเกมนี้
7. `ax_sandbox/writer.lua` ทำให้ซีเรียลไลซ์และตรวจสอบโปรไฟล์ที่เตรียมไว้ จากนั้นใช้การแทนที่ธุรกรรมสำหรับเป้าหมายที่เลือก
8. สถานะการหมุนถูกกระทำหลังจาก ธุรกรรมแซนด์บ็อกซ์สำเร็จ ความล้มเหลวในการดำเนินการตามสถานะจะลดลง: อะแดปเตอร์และการส่งข้อความของผู้เล่นที่เตรียมไว้จะถูกข้ามเนื่องจากสถานะแซนด์บ็อกซ์และคิวไม่สอดคล้องกัน
9. ในโหมดเฉพาะ `ax_external/bridge.lua` ประเมินอะแดปเตอร์เสริมกับโปรไฟล์ที่ใช้งานอยู่ ในระหว่างการบูตสแตรปครั้งแรก ไม่มีเครื่องหมายที่ใช้งานอยู่ ดังนั้นโปรไฟล์ configured/random ที่เตรียมไว้จึงเป็นเพียงการแมปอะแด็ปเตอร์ที่มีอยู่เท่านั้น
10. สถานะรันไทม์ JSON/text และ HTML/JSON เว็บวิวจะถูกเขียนใหม่จากการตัดสินใจเดียวกัน ประกาศของผู้เล่นจะถูกติดตั้งครั้งสุดท้าย

ค่าเริ่มต้น `cycle.check_interval_ms=0` รันลำดับนี้หนึ่งครั้งเมื่อเริ่มต้น หากตัวดำเนินการระบุช่วงค่าบวกและ UE4SS เปิดเผย `LoopAsync` การโทรกลับในภายหลังจะใช้การเลือกที่เป็นของกระบวนการอีกครั้ง พวกเขาอาจซ่อมแซมหรือส่งออกตัวเลือกนั้นซ้ำได้ แต่อย่าเลือกวันอื่นในระหว่างกระบวนการเดียวกัน

<a id="rotation-state-machine"></a>
## เครื่องสถานะการหมุน

| สถานะการเลือก | เงื่อนไขการเข้า | ผลลัพธ์ที่เตรียมไว้ | การกู้คืนอย่างปลอดภัย |
|---|---|---|---|
| `bootstrap_prepare_first_family_start_day` | ไม่มีเครื่องหมายที่ใช้งานอยู่และไม่มีการเตรียมการกู้คืน state. | กำหนดค่าหรือสุ่มเลือกตำแหน่งแรกในลำดับวันที่คงอยู่ใหม่ | ให้เซสชันที่มีอยู่ทำงานต่อไป รีสตาร์ทหลังจาก `prepared_ready=true`. |
| `active_marker_found_family_locked_prepare_next_day` | วันที่ใช้งานอยู่ไม่ใช่ตำแหน่งสุดท้ายในลำดับที่เก็บไว้ | ตำแหน่งที่จัดเก็บถัดไปในตระกูลเดียวกัน | หากการคงอยู่ล้มเหลว ให้เซิร์ฟเวอร์หยุดทำงานและกระทบยอดแซนด์บ็อกซ์และสถานะการหมุน |
| `active_marker_found_completed_run_prepare_next_unused_family` | วันที่ใช้งานอยู่คือตำแหน่งสุดท้ายในลำดับที่เก็บไว้ | ตำแหน่งแรกจากคำสั่งซื้อใหม่ในการดำเนินการตระกูลที่มีสิทธิ์ครั้งถัดไป | ยืนยัน family/day/order ใหม่ก่อนรีสตาร์ท |
| `state_recovery_rewrite_prepared_profile_no_reroll` | ไม่มีเครื่องหมายที่ใช้งานอยู่ แต่สถานะการหมุนตั้งชื่อโปรไฟล์ที่เตรียมไว้ | โปรไฟล์ที่อยู่ในคิวเดียวกันจะถูกสร้างขึ้นใหม่ | รักษาไฟล์สถานะ อย่าลบออกเพื่อบังคับให้ทำการสุ่มซ้ำ |
| `supervision_reconfirm_prepared_profile_no_advance` | การเรียกกลับในภายหลังจะทำงานในกระบวนการเดียวกัน | โปรไฟล์ที่เตรียมไว้เหมือนกัน | วินิจฉัยขั้นตอนแรกที่ล้มเหลว การโทรกลับซ้ำไม่ใช่การเลือกใหม่ |

`selected_run` ใช้เสมอ `selected_family`. `rotation_run` จะใช้ลำดับที่มีสิทธิ์ที่กำหนดค่าไว้ `non_repeating_random_run` เลือกจากตระกูลที่มีสิทธิ์ที่เหลืออยู่ และเริ่มพูลใหม่หลังจากที่ทั้งหมดเสร็จสิ้นแล้ว ทุกโหมดจะเก็บหนึ่งตระกูลไว้จนกว่า ID วันที่ไม่ซ้ำกันทั้ง 17 รายการใน `day_order` จะเสร็จสิ้น โหมดต่อเนื่องจะตัดหลังจากวันที่ 17 เมื่อการกำหนดค่าเริ่มต้นไม่ใช่วันที่ 1 โหมดไม่สุ่มซ้ำจะจัดเก็บการเรียงสับเปลี่ยนเพียงครั้งเดียวและจะไม่ม้วนซ้ำในระหว่างการกู้คืน

<a id="sandbox-transaction"></a>
## ธุรกรรมแซนด์บ็อกซ์

ผู้เขียนแสดงคีย์ทั้งหมดตามลำดับแบบบัญญัติและตรวจสอบประเภท ช่วง กฎคงที่ ค่าเครื่องหมาย และข้อมูลประจำตัวของโปรไฟล์ก่อนที่จะเขียน การแทนที่จะเป็นไปตามลำดับนี้:

1. ลบไฟล์เก่าที่รอดำเนินการออกเฉพาะเมื่อทำได้อย่างปลอดภัยเท่านั้น
2. รักษาหรือหยุดการทำงานของไฟล์ช่วยเหลือการกู้คืนที่มีอยู่แล้ว
3. เขียนไบต์ที่รอดำเนินการ
4. อ่านไฟล์ที่รอดำเนินการกลับและตรวจสอบความถูกต้อง
5. สร้างการดำเนินการที่ได้รับการยืนยัน สำรองข้อมูลเมื่อมีเป้าหมาย
6. เก็บต้นฉบับไว้เป็นไฟล์การย้อนกลับธุรกรรม
7. เลื่อนระดับไฟล์ที่รอดำเนินการ
8. อ่านและตรวจสอบความถูกต้องของไฟล์ที่ใช้งานจริง
9. เรียกคืนต้นฉบับที่เก็บไว้หากการตรวจสอบการส่งเสริมหรือการผลิตล้มเหลว
10. เก็บข้อมูลการกู้คืนและรายงานความล้มเหลวหากไม่สามารถล้างข้อมูลได้ ตรวจสอบแล้ว

การเขียนครั้งแรกใช้เส้นทาง pending/readback/validation เดียวกัน เมื่อไม่มีเป้าหมายดั้งเดิม จึงไม่มีอะไรให้กู้คืน ดังนั้นการเขียนครั้งแรกที่ล้มเหลวจะต้องไม่ถูกรายงานเป็นการกู้คืนไฟล์ต้นฉบับ

<a id="adapter-boundary"></a>
## ขอบเขตของอะแดปเตอร์

อะแดปเตอร์คือ RandomDay-owned คำจำกัดความของแพตช์สำหรับ mod ที่ติดตั้งแยกกัน ขั้นแรกบริดจ์ต้องมีเส้นทางเป้าหมายที่ได้รับการยอมรับและลายเซ็นคีย์ที่สมบูรณ์ โดยจะแพตช์การมอบหมายที่มีอยู่เท่านั้น สร้างการสำรองข้อมูลการดำเนินการ ใช้ไฟล์ที่วางแผนไว้ทุกไฟล์เป็นธุรกรรมเดียว และย้อนกลับเป้าหมายที่ได้รับผลกระทบทั้งหมดกลับหากขั้นตอนใดล้มเหลว เป้าหมายที่ขาดหายไปและเข้ากันไม่ได้ถือเป็นผลลัพธ์ทางเลือกตามปกติ

RandomDay ไม่โหลดรหัสบุคคลที่สามลงในแพ็คเกจ รูปแบบที่ได้รับการสนับสนุนฟิกซ์เจอร์พิสูจน์ได้ RandomDay's parser และพฤติกรรมการทำธุรกรรม ไม่ใช่ว่าการเผยแพร่ของบุคคลที่สามโหลดหรือใช้ค่าในกระบวนการเกม

<a id="output-boundary"></a>
## ขอบเขตเอาต์พุต

ไฟล์รันไทม์ถูกสร้างขึ้นด้านล่าง `RandomDay/runtime/` และ `RandomDay/web_export/`; ไม่มีการปล่อยZIP อินพุต ตัวเขียนสถานะจะลบพาธอะแด็ปเตอร์ภายในเครื่องออกจากสาธารณะ JSON การวินิจฉัย เส้นทาง สคีมา จังหวะ และแผนที่การเก็บรักษาที่สมบูรณ์อยู่ใน [ไฟล์รันไทม์และสถานะ](%E0%B9%84%E0%B8%9F%E0%B8%A5%E0%B9%8C%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md).

<a id="failure-ownership"></a>
## การเป็นเจ้าของที่ล้มเหลว

| ขั้นตอนที่ล้มเหลว | ผลลัพธ์ที่เจ้าของมองเห็นได้ |
|---|---|
| โปรไฟล์หรือ INI การตรวจสอบ | ไม่มีการพยายามเขียนข้อมูลจริง |
| รอดำเนินการ write/readback | ไบต์การผลิตที่มีอยู่ยังคงอยู่ |
| การสำรองข้อมูลการดำเนินการ | การเปลี่ยนจะหยุดก่อนที่จะย้ายต้นฉบับ |
| การตรวจสอบความถูกต้องของการส่งเสริมการขายหรือการผลิต | พยายามกู้คืนอัตโนมัติและมีการรายงานผลลัพธ์ |
| การคงอยู่ของสถานะการหมุน | ไบต์แซนด์บ็อกซ์ที่เตรียมไว้อาจมีอยู่ แต่การเปลี่ยนแปลงจะลดลงและ adapters/messages ถูกข้ามไป |
| ความเข้ากันได้ของอะแดปเตอร์ | เป้าหมายจะไม่เปลี่ยนแปลงด้วย `not_installed` หรือ `skipped_incompatible`. |
| อะแดปเตอร์ write/readback | เป้าหมายของอะแดปเตอร์ที่เปลี่ยนแปลงทั้งหมดจะถูกกู้คืนเมื่อเป็นไปได้ |
| สถานะหรือการส่งออกเว็บ | ผลลัพธ์ของแซนด์บ็อกซ์ยังคงเชื่อถือได้ ความล้มเหลวของเอาท์พุตจะถูกบันทึกไว้ และจะต้องไม่ถือว่าเป็นรายงานที่สำเร็จ |

## ขีดจำกัดหลักฐาน

ชุดฟิกซ์เจอร์ Lua ในพื้นที่สามารถพิสูจน์พฤติกรรมของแหล่งที่มา การสร้างค่าคงที่ของโปรไฟล์ สาขาธุรกรรม รูปร่างเอาต์พุต และขอบเขตแพ็คเกจ ไม่ได้พิสูจน์ถึงการสร้าง Abiotic Factor ในปัจจุบัน ซึ่งเป็น UE4SS release, แผงเซิร์ฟเวอร์เฉพาะ, ทุกขนาดการแสดงผล, หรือ mod เวอร์ชันบุคคลที่สามที่ยังไม่ผ่านการทดสอบ การกล่าวอ้างเหล่านั้นยังคงอยู่ `not tested` จนกว่าจะมีการบันทึกการเรียกใช้ความเข้ากันได้ที่มีชื่อ
