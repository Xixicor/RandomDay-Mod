# ใช้งานสถานะใช้งาน เตรียมพร้อม และกู้คืน

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [OPERATIONS.md](../../OPERATIONS.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


RandomDay เปลี่ยนไฟล์แซนด์บ็อกซ์สำหรับการบูตในอนาคต จะไม่เปลี่ยนกฎที่โหลดไว้แล้วในเซสชัน Abiotic Factor ที่ทำงานอยู่

หน้านี้เป็นเจ้าของการตัดสินใจของผู้ปฏิบัติงานและขั้นตอนการกู้คืน ใช้ [อภิธานศัพท์](%E0%B8%AD%E0%B8%A0%E0%B8%B4%E0%B8%98%E0%B8%B2%E0%B8%99%E0%B8%A8%E0%B8%B1%E0%B8%9E%E0%B8%97%E0%B9%8C.md) สำหรับเงื่อนไขมาตรฐาน [ไฟล์รันไทม์](%E0%B9%84%E0%B8%9F%E0%B8%A5%E0%B9%8C%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md) สำหรับการเป็นเจ้าของเส้นทาง และ [เอาต์พุตรันไทม์](%E0%B9%80%E0%B8%AD%E0%B8%B2%E0%B8%95%E0%B9%8C%E0%B8%9E%E0%B8%B8%E0%B8%95%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md) สำหรับสคีมาและความหมายของฟิลด์ที่แน่นอน

<a id="distinguish-active-and-prepared-state"></a>
## แยกแยะสถานะใช้งานและสถานะที่เตรียมไว้

โปรไฟล์ที่เตรียมไว้ไม่ทำงาน จนกว่าการเริ่มต้นใหม่ในภายหลังจะอ่านเครื่องหมายของมัน อย่าใช้ family/day ที่เตรียมไว้เพื่ออธิบายเซสชันปัจจุบัน

ใช้ `web_export/today.html` สำหรับบทสรุปที่อ่านได้ และ `web_export/today.json` สำหรับสถานะที่แน่นอน ยืนยันเครื่องหมายที่ใช้งานอยู่ ข้อมูลระบุตัวตนที่เตรียมไว้ `prepared_ready`, `profile_status` ผลลัพธ์ของธุรกรรม ผลลัพธ์การย้อนกลับ และผลลัพธ์ของการดำเนินการตามสถานะ ก่อนที่จะตัดสินใจรีสตาร์ท

<a id="follow-the-normal-dedicated-server-sequence"></a>
## ปฏิบัติตามลำดับเซิร์ฟเวอร์เฉพาะปกติ

| ก่อน | แอ็คชั่น | หลัง |
|---|---|---|
| ไม่มี RandomDay เครื่องหมาย | เริ่มต้นด้วย RandomDay เปิดใช้งานแล้ว | เซสชันปัจจุบันคงกฎที่มีอยู่ไว้ RandomDay สร้างและคงลำดับวันไว้ จากนั้นเตรียมคำสั่งแรก configured/random ตำแหน่งแรก |
| ตำแหน่งแรกที่เตรียมไว้ | รีสตาร์ท | วันนั้นจะเปิดใช้งาน ตำแหน่งที่เก็บไว้ถัดไปในตระกูลเดียวกันถูกจัดเตรียมไว้ |
| ตำแหน่งกลางที่ใช้งานอยู่ | รีสตาร์ทหลังจากตรวจสอบโปรไฟล์ที่เตรียมไว้ | วันที่เตรียมไว้จะเปิดใช้งานและตำแหน่งที่เก็บไว้ต่อไปนี้ถูกเตรียมไว้ |
| ตำแหน่งสุดท้ายที่ใช้งานอยู่ | รีสตาร์ทหลังจากตรวจสอบตระกูลถัดไป |  ตำแหน่งแรกของคำสั่งซื้อครอบครัวที่มีสิทธิ์อื่นจะใช้งานได้ |

`selected_run` คงตระกูลที่กำหนดค่าไว้ `non_repeating_random_run` เก็บครอบครัวที่ได้รับการสุ่มเลือกไว้ตลอดตำแหน่งทั้ง 17 วัน และหลีกเลี่ยงการใช้ครอบครัวซ้ำจนกว่ารายการที่มีสิทธิ์จะหมด `rotation_run` เป็นไปตามลำดับตระกูลที่กำหนดค่าไว้ `cycle.day_progression_mode` ควบคุมลำดับวันโดยไม่ขึ้นอยู่กับการเลือกครอบครัว

การติดตั้งใหม่ต้องใช้กระบวนการเดียวในการจัดเตรียมและกระบวนการในภายหลังเพื่อเปิดใช้งานเสมอ นี่เป็นเรื่องจริงสำหรับเซิร์ฟเวอร์ถาวร เซิร์ฟเวอร์ชั่วคราว และการสร้าง singleplayer/LAN ด้วยตนเอง

<a id="read-the-right-evidence"></a>
## อ่านหลักฐานที่ถูกต้อง

ใช้ [แผนผังไฟล์รันไทม์](%E0%B9%84%E0%B8%9F%E0%B8%A5%E0%B9%8C%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md) เพื่อค้นหาสถานะการหมุน สถานะปัจจุบัน ไฟล์ที่รู้จักล่าสุด การสำรองข้อมูลการดำเนินการ การส่งออก และ `UE4SS.log`. ใช้ [การอ้างอิงเอาต์พุตรันไทม์](%E0%B9%80%E0%B8%AD%E0%B8%B2%E0%B8%95%E0%B9%8C%E0%B8%9E%E0%B8%B8%E0%B8%95%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md) สำหรับทุกกลุ่มฟิลด์ สคีมา สถานะว่าง ความหมายของความล้มเหลว และกฎการเก็บรักษา HTML และ JSON การส่งออกสรุปสถานะแหล่งที่มา พวกเขาไม่ได้พิสูจน์ว่าโปรไฟล์นั้นถูกใช้โดยไคลเอนต์เกมถ่ายทอดสด

หาก `prepared_ready` เป็น `false` หรือ `profile_status` เป็น `degraded_state_persistence` ให้คงเซิร์ฟเวอร์หยุดทำงานจนกว่าแซนด์บ็อกซ์และสถานะการหมุนจะตกลงกัน การเขียนแซนด์บ็อกซ์ที่ถูกต้องซึ่งมีสถานะคงอยู่ล้มเหลวนั้นไม่ใช่การเตรียมการเปลี่ยนแปลงที่ดี

<a id="respond-to-writer-outcomes"></a>
## ตอบสนองต่อผลลัพธ์ของผู้เขียน

RandomDay เตรียมไบต์ใหม่ในไฟล์พี่น้อง, อ่านกลับ, ตรวจสอบความถูกต้องของแซนด์บ็อกซ์ที่สมบูรณ์, รักษาต้นฉบับเมื่อมีไฟล์อยู่, เลื่อนระดับไฟล์ใหม่ และอ่านกลับอีกครั้ง รายงานจะพร้อมใช้งานหลังจากที่การอ่านกลับการผลิตตกลงแล้วเท่านั้น

หากการตรวจสอบการส่งเสริมการขายหรือการผลิตล้มเหลว RandomDay จะพยายามกู้คืนไฟล์ที่ถือโดยการดำเนินการนั้น ความล้มเหลวในการกู้คืนคือการหยุดชั่วคราว: ให้เซิร์ฟเวอร์หยุดทำงานและกู้คืนด้วยตนเอง แทนที่จะรีสตาร์ทซ้ำๆ

<a id="respond-to-adapter-outcomes"></a>
## ตอบสนองต่อผลลัพธ์ของอะแดปเตอร์

ใช้ [อะแดปเตอร์ที่รองรับ](%E0%B8%AD%E0%B8%B0%E0%B9%81%E0%B8%94%E0%B8%9B%E0%B9%80%E0%B8%95%E0%B8%AD%E0%B8%A3%E0%B9%8C%E0%B8%97%E0%B8%B5%E0%B9%88%E0%B8%A3%E0%B8%AD%E0%B8%87%E0%B8%A3%E0%B8%B1%E0%B8%9A.md#read-an-adapter-result) สำหรับตารางผลลัพธ์หกสถานะตามรูปแบบบัญญัติและการดำเนินการถัดไป รักษา `rollback_failed` เป็นจุดหยุดที่ยาก การสำรองข้อมูลอะแดปเตอร์ที่บันทึกไว้แยกต่างหากเป็นแหล่งการกู้คืน

อะแดปเตอร์จะมีผลกับ mod ที่ติดตั้งแยกกันเท่านั้น โดยจะไม่ทำให้โปรไฟล์แซนด์บ็อกซ์ที่เตรียมไว้ RandomDay ใช้งานอยู่

ในการบูตปกติ ค่าของอแด็ปเตอร์จะถูกเลือกจากโปรไฟล์ที่ใช้งานอยู่ เนื่องจาก mod ที่ติดตั้งแยกต่างหากอาจโหลดในภายหลังในการเริ่มต้นระบบ UE4SS เดียวกัน ในระหว่างการบูตสแตรปครั้งแรก เมื่อไม่มีเครื่องหมาย RandomDay ที่ใช้งานอยู่ โปรไฟล์วันเริ่มต้นที่เตรียมไว้เป็นเพียงการแมปที่พร้อมใช้งานเท่านั้น กฎกำหนดเวลานี้แยกจากขอบเขตแซนด์บ็อกซ์ที่รีสตาร์ทครั้งถัดไป และยังคงขึ้นอยู่กับพฤติกรรมการโหลดของ mod อื่น

<a id="manual-recovery"></a>
## การกู้คืนด้วยตนเอง

1. หยุดเกมหรือเซิร์ฟเวอร์ อย่ากู้คืนไฟล์ในขณะที่ไฟล์อาจเปิดอยู่
2. คัดลอก `SandboxSettings.ini`, `runtime/` ปัจจุบัน และ `web_export/` ไปยังการสำรองข้อมูลการวินิจฉัยแยกต่างหาก
3. ตรวจสอบ `runtime/last_good/manifest.lua` และรายการที่เกี่ยวข้องใหม่ล่าสุดภายใต้ `runtime/backups/` เลือกไฟล์ที่มี family/day และแฮชตรงกับสถานะที่คุณต้องการกู้คืน
4. คัดลอกไฟล์ที่ได้รับการตรวจสอบที่เลือกไปยังพาธแซนด์บ็อกซ์หลักที่กำหนดค่าไว้
5. อ่านกลับและยืนยันว่าเสร็จสมบูรณ์ก่อนที่จะเริ่ม
6. เริ่มต้นหนึ่งครั้งและตรวจสอบเครื่องหมายที่ใช้งานอยู่และสถานะที่เตรียมไว้ อย่าถือว่าการกู้คืนสำเร็จหากไม่มีข้อความแสดงข้อผิดพลาดเพียงอย่างเดียว

หากไม่มีการสำรองข้อมูลที่ได้รับการยืนยัน ให้คืนค่าการสำรองข้อมูลของผู้ให้บริการที่สร้างขึ้นก่อนการติดตั้ง RandomDay ไม่สามารถสร้างไฟล์ที่ไม่เคยอ่านได้ขึ้นมาใหม่

<a id="account-for-control-panel-writes"></a>
## บัญชีสำหรับการเขียนแผงควบคุม

แผงเซิร์ฟเวอร์บางอันสร้างขึ้น `SandboxSettings.ini` ระหว่างการเริ่มต้น RandomDay ไม่สามารถรักษาโปรไฟล์ที่เตรียมไว้ได้หากเครื่องมืออื่นเขียนทับหลังจากการเขียนได้รับการตรวจสอบแล้ว กำหนดค่าแหล่งแซนด์บ็อกซ์ที่เชื่อถือได้หนึ่งแหล่ง และตรวจสอบตัวทำเครื่องหมายไฟล์ทันทีก่อนและหลังรีสตาร์ท เมื่อวินิจฉัยวันที่ 1 ซ้ำหรือการเปลี่ยนแปลงที่หายไป
