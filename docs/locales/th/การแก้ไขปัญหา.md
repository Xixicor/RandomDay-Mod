# การแก้ไขปัญหา

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [TROUBLESHOOTING.md](../../TROUBLESHOOTING.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


หยุดที่การตรวจสอบล้มเหลวครั้งแรก รักษาแซนด์บ็อกซ์ปัจจุบัน `runtime/`, `web_export/` และที่เกี่ยวข้อง `UE4SS.log` ก่อนที่จะพยายามกู้คืน

<a id="try-these-common-fixes-first"></a>
## ลองแก้ไขทั่วไปเหล่านี้ก่อน

1. **RandomDay ไม่เคยปรากฏ:** ยืนยัน `RandomDay` อยู่ภายในโดยตรง `ue4ss/Mods` เปิดใช้งาน `RandomDay : 1` ใน `mods.txt` และเริ่มต้นครั้งเดียว
2. **เซสชันปัจจุบันคงกฎเก่าไว้:** นี่เป็นเรื่องปกติ RandomDay เตรียมโปรไฟล์ถัดไป เกมจะโหลดมันในการเริ่มในภายหลัง
3. **โปรไฟล์เดียวกันยังคงส่งคืน:** แผงเซิร์ฟเวอร์อาจจะแทนที่ `SandboxSettings.ini` ใช้ไฟล์แซนด์บ็อกซ์ที่เชื่อถือได้ไฟล์เดียวและเปรียบเทียบชื่อที่ใช้งานอยู่และชื่อที่เตรียมไว้ใน `web_export/today.html`.
4. **ตัวดัดแปลงเสริมไม่ได้ติดตามโปรไฟล์:** เปิด [ตัวดัดแปลงเสริมที่รองรับ](%E0%B8%AD%E0%B8%B0%E0%B9%81%E0%B8%94%E0%B8%9B%E0%B9%80%E0%B8%95%E0%B8%AD%E0%B8%A3%E0%B9%8C%E0%B8%97%E0%B8%B5%E0%B9%88%E0%B8%A3%E0%B8%AD%E0%B8%87%E0%B8%A3%E0%B8%B1%E0%B8%9A.md). ม็อดเสริมที่หายไป ถูกปิดใช้งาน หรือไม่รู้จักนั้นยังคงไม่เปลี่ยนแปลง
5. **RandomDay รายงานความล้มเหลวในการเขียนหรือเรียกคืน:** หยุดก่อนรีสตาร์ทอีกครั้ง เก็บรักษา `runtime/backups/` และปฏิบัติตามส่วนการกู้คืนที่มีชื่อด้านล่าง

หากการตรวจสอบทั้งห้าครั้งนั้นไม่สามารถระบุปัญหาได้ ให้ดำเนินการตามแผนผังการตัดสินใจโดยละเอียด

<a id="choose-the-first-failed-stage"></a>
## เลือกขั้นตอนแรกที่ล้มเหลว

ใช้แถวแรกที่ตรงกับสิ่งที่คุณสามารถพิสูจน์ได้จริง อย่าเริ่มต้นด้วยคำอธิบายที่รุนแรงที่สุด และอย่ารวมความล้มเหลวของเอาท์พุตที่ไม่เกี่ยวข้องเข้าไว้ในการวินิจฉัยเดียว

| สิ่งที่คุณสังเกตได้ | ตรวจสอบก่อน | ดำเนินการต่อด้วย | ผลลัพธ์ที่คาดหวัง |
|---|---|---|---|
| ไม่มี `[RandomDay]` บรรทัดเริ่มต้นมีอยู่ใน `UE4SS.log`. | ติดตั้งรูท, เครื่องหมายแพ็คเกจ `mods.txt` ปัจจุบัน และ UE4SS การเริ่มต้น Lua | [กู้คืนส่วนที่หายไป RandomDay เริ่มต้น](#restore-a-missing-randomday-start) | บรรทัดเริ่มต้นหนึ่งบรรทัดตั้งชื่อโหมด release และ package หรือความล้มเหลวถูกผูกไว้กับการโหลด |
| RandomDay โหลดแล้ว แต่ไม่มีโปรไฟล์พร้อม | การเริ่มต้นระบบครั้งแรก การกำหนดค่า ข้อผิดพลาดของเป้าหมาย ธุรกรรม หรือสถานะ | [กู้คืนจากการเตรียมการที่ล้มเหลว](#recover-from-failed-preparation) จากนั้น [การอ้างอิงสถานะและข้อผิดพลาด](%E0%B8%AA%E0%B8%96%E0%B8%B2%E0%B8%99%E0%B8%B0%E0%B9%81%E0%B8%A5%E0%B8%B0%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%AD%E0%B9%89%E0%B8%B2%E0%B8%87%E0%B8%AD%E0%B8%B4%E0%B8%87%E0%B8%82%E0%B9%89%E0%B8%AD%E0%B8%9C%E0%B8%B4%E0%B8%94%E0%B8%9E%E0%B8%A5%E0%B8%B2%E0%B8%94.md) | รหัสที่แน่นอนหนึ่งรหัสระบุการดำเนินการถัดไปที่ปลอดภัย |
| มีโปรไฟล์ที่เตรียมไว้ แต่กฎที่กำลังทำงานอยู่ไม่มีการเปลี่ยนแปลง | ID ที่ใช้งานอยู่และเตรียมไว้ใน `today.json` หรือ `today.html`. | [ยืนยันขอบเขตการรีสตาร์ท](#confirm-the-restart-boundary) | เซสชันปัจจุบันยังคงทำงานอยู่ โปรไฟล์ที่เตรียมไว้จะรอการเริ่มต้นในภายหลัง |
| วันที่ 1 หรือวันอื่นจะเกิดซ้ำหลังจากการรีสตาร์ท | เครื่องหมายแซนด์บ็อกซ์ก่อนเริ่มแผง หลังจากเริ่มแผง และหลังการเตรียมการ | [หยุดการเตรียมการซ้ำ](#stop-repeated-preparation) | มีการระบุผู้เขียนที่เชื่อถือได้หรือจุดเขียนทับ |
| แซนด์บ็อกซ์ใช้งานได้ดี แต่ mod เสริมถูกข้ามหรือล้มเหลว | ผลลัพธ์ของอะแดปเตอร์แต่ละตัวและหลักฐานความเข้ากันได้ | [วินิจฉัยอะแดปเตอร์ที่ถูกข้าม](#diagnose-a-skipped-adapter) หรือ [กู้คืนความล้มเหลวในการย้อนกลับของอแด็ปเตอร์](#recover-an-adapter-rollback-failure) | ความสมบูรณ์ของอะแดปเตอร์จะถูกตัดสินใจโดยแยกจากความสมบูรณ์ของแซนด์บ็อกซ์ |
| ไม่มีไฟล์ singleplayer/LAN แบบแมนนวล | โหมดแพ็คเกจและโฟลเดอร์เอาต์พุตที่ถูกผูกไว้ | [สร้างส่วนที่ขาดหายไป singleplayer/LAN ไฟล์](#generate-a-missing-singleplayerlan-file) | ไฟล์ถูกสร้างขึ้นภายใน RandomDay โดยไม่ค้นพบบันทึกส่วนตัว |
| เฉพาะข้อความที่ผู้เล่นเห็นเท่านั้นที่ขาดหายไปหรือตัดอย่างไม่ดี | บันทึกการส่งผ่านข้อความ การแสดงตัวอย่างแหล่งที่มา และข้อจำกัดที่จัดทำเป็นเอกสาร | [วินิจฉัยปัญหาข้อความ](#diagnose-a-message-problem) | การนำเสนอได้รับการทดสอบโดยไม่ถือเป็นการพิสูจน์โปรไฟล์ |

<a id="follow-the-safe-diagnostic-order"></a>
### ปฏิบัติตามการวินิจฉัยที่ปลอดภัย order

1. รักษาหลักฐานปัจจุบันก่อนที่จะเปลี่ยนไฟล์
2. พิสูจน์ว่า RandomDay โหลดแล้ว
3. ค้นหาขั้นตอนแรกที่ไปไม่ถึงผลลัพธ์ที่บันทึกไว้
4. คัดลอกสถานะหรือค่าข้อผิดพลาดที่แน่นอนจากเอาต์พุตรันไทม์
5. ใช้แถวตารางที่ตรงกันด้านล่างเพื่อความปลอดภัย การตอบสนอง
6. อ่านกลับเป้าหมายและสถานะการหมุนก่อนที่จะเริ่มต้นอีกครั้ง

หากไม่มีแถวที่ตรงกัน ให้ใช้ [สถานะรันไทม์และการอ้างอิงเอาต์พุต](%E0%B9%80%E0%B8%AD%E0%B8%B2%E0%B8%95%E0%B9%8C%E0%B8%9E%E0%B8%B8%E0%B8%95%E0%B8%A3%E0%B8%B1%E0%B8%99%E0%B9%84%E0%B8%97%E0%B8%A1%E0%B9%8C.md) เพื่อระบุผู้ผลิตและความหมายของฟิลด์ก่อนที่จะเปลี่ยนการกำหนดค่า

<a id="restore-a-missing-randomday-start"></a>
## กู้คืนส่วนที่หายไป RandomDay เริ่มต้น

**สาเหตุที่เป็นไปได้มากที่สุด:** รูปแบบการแยกข้อมูลไม่ถูกต้อง, ปิดการใช้งาน mod, โหมดแพ็คเกจผิด หรือ UE4SS ไม่ได้โหลดจุดเข้าใช้งาน Lua

**ตรวจสอบให้ถูกต้อง:** ยืนยัน `RandomDay/enabled.txt`, `.randomday_mode`, `.randomday_version` ปัจจุบัน และ `RandomDay/Scripts/main.lua`; ยืนยัน`RandomDay : 1` ใน `mods.txt`; ค้นหา`UE4SS.log` สำหรับ `[RandomDay]`.

**ผลลัพธ์ที่คาดหวัง:** บรรทัดเริ่มต้นหนึ่งบรรทัดจะตั้งชื่อข้อมูลระบุตัวตนของการเปิดตัวและโหมดแพ็คเกจ

**การดำเนินการถัดไปอย่างปลอดภัย:** แก้ไขเค้าโครงหรือการเปิดใช้งานในขณะที่หยุด จากนั้นเริ่มหนึ่งครั้ง

**อย่าสรุป:** ไม่ใช่ RandomDay บรรทัดไม่ได้พิสูจน์เกมหรือข้อบกพร่องของโปรไฟล์

<a id="confirm-the-restart-boundary"></a>
## ยืนยันขอบเขตการรีสตาร์ท

**สาเหตุที่เป็นไปได้มากที่สุด:** ลักษณะการรีสตาร์ทครั้งถัดไปตามปกติ

**ตรวจสอบให้ถูกต้อง:** เปรียบเทียบ family/day ใน `web_export/today.json` หรือ `today.html`.

**ผลลัพธ์ที่คาดหวัง:** โปรไฟล์ที่เตรียมไว้นั้นแตกต่างหรือแยกจากโปรไฟล์ที่ใช้งานอยู่อย่างชัดเจน

**การดำเนินการถัดไปอย่างปลอดภัย:** รีสตาร์ทเฉพาะเมื่อคุณพร้อมที่จะเปิดใช้งานเท่านั้น จากนั้นตรวจสอบเครื่องหมายที่ใช้งานอยู่

**อย่าสรุป:** โปรไฟล์ที่เตรียมไว้จะไม่ทำงานก่อนที่จะอ่านกลับหลังรีสตาร์ท

<a id="stop-repeated-preparation"></a>
## หยุดการเตรียมการซ้ำ

**สาเหตุที่เป็นไปได้มากที่สุด:** ที่ใช้งานอยู่ RandomDay หายไปเนื่องจากแผงเซิร์ฟเวอร์หรือเครื่องมืออื่นเขียนใหม่ `SandboxSettings.ini` ระหว่างการเริ่มต้น

**ตรวจสอบให้ถูกต้อง:** เปรียบเทียบ ไฟล์แซนด์บ็อกซ์และ RandomDay เครื่องหมายทันทีก่อนเริ่มต้น หลังจากที่แผงเริ่มต้น และหลังจาก RandomDay เตรียมไฟล์

**ผลลัพธ์ที่คาดหวัง:** ไฟล์ที่มีอยู่ในการบูตครั้งถัดไปยังคงรักษาเครื่องหมายที่เตรียมไว้

**การดำเนินการถัดไปอย่างปลอดภัย:** กำหนดค่าแหล่งแซนด์บ็อกซ์ที่เชื่อถือได้หนึ่งแหล่งและปิดการใช้งานการเขียนซ้ำพาเนลที่ขัดแย้งกัน

**อย่าสรุป:** ซ้ำวันที่ 1 ไม่ได้พิสูจน์ว่าตัวเลือกตระกูลกำลังสุ่มอย่างไม่ถูกต้อง

<a id="recover-from-failed-preparation"></a>
## กู้คืนจากการเตรียมการที่ล้มเหลว

**สาเหตุที่เป็นไปได้มากที่สุด:** รอการเขียน สำรองข้อมูล เลื่อนระดับ การอ่านกลับการผลิต การตรวจสอบความถูกต้อง หรือ การย้อนกลับล้มเหลว

**ตรวจสอบให้ถูกต้อง:** อ่านไฟล์แรก `[RandomDay] [ERROR]` บรรทัดและรักษาการสำรองข้อมูลการดำเนินการที่มีชื่อไว้ ตรวจสอบ `runtime/last_good/manifest.lua` ก่อนที่จะใช้ไฟล์แซนด์บ็อกซ์

**ผลลัพธ์ที่คาดหวัง:** ไฟล์ก่อนหน้านี้ได้รับการยืนยันว่ากู้คืนแล้วหรือผลลัพธ์รายงานความล้มเหลวในการกู้คืนอย่างชัดเจน

**การดำเนินการถัดไปอย่างปลอดภัย:** ให้เซิร์ฟเวอร์หยุดทำงานและปฏิบัติตาม [การกู้คืนด้วยตนเอง](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%94%E0%B9%8D%E0%B8%B2%E0%B9%80%E0%B8%99%E0%B8%B4%E0%B8%99%E0%B8%81%E0%B8%B2%E0%B8%A3.md#manual-recovery).

**อย่าสรุป:** การมีอยู่ของไฟล์สำรองเพียงอย่างเดียวไม่ได้พิสูจน์ว่ามันตรงกับสถานะโลกที่ใช้งานอยู่ตามที่ตั้งใจไว้

<a id="diagnose-a-skipped-adapter"></a>
## วินิจฉัยอะแดปเตอร์ที่ถูกข้าม

**สาเหตุที่เป็นไปได้มากที่สุด:** ไม่มี mod หรือไฟล์ไม่ตรงกับลายเซ็นที่รองรับ

**ตรวจสอบให้ถูกต้อง:** อ่านผลลัพธ์ของอะแดปเตอร์และเปรียบเทียบเวอร์ชันและเลย์เอาต์ที่ติดตั้งกับ [อะแดปเตอร์ Mod ที่รองรับ](%E0%B8%AD%E0%B8%B0%E0%B9%81%E0%B8%94%E0%B8%9B%E0%B9%80%E0%B8%95%E0%B8%AD%E0%B8%A3%E0%B9%8C%E0%B8%97%E0%B8%B5%E0%B9%88%E0%B8%A3%E0%B8%AD%E0%B8%87%E0%B8%A3%E0%B8%B1%E0%B8%9A.md).

**ผลลัพธ์ที่คาดหวัง:** `not_installed` สำหรับเป้าหมายที่ขาดหายไปหรือ `skipped_incompatible` สำหรับเป้าหมายที่ไม่รู้จัก

**การดำเนินการถัดไปอย่างปลอดภัย:** ปล่อยให้ไฟล์ไม่เปลี่ยนแปลง ปิดการใช้งานอะแดปเตอร์นั้น หรือติดตั้งเวอร์ชันที่รองรับทุกประการจากผู้เขียนดั้งเดิม

**อย่าสรุป:** ชื่อไฟล์ที่คล้ายกันหรือเวอร์ชันที่ใหม่กว่านั้นไม่สามารถพิสูจน์ความเข้ากันได้ได้

<a id="recover-an-adapter-rollback-failure"></a>
## กู้คืนความล้มเหลวในการย้อนกลับของอแด็ปเตอร์

**สาเหตุที่เป็นไปได้มากที่สุด:** ไม่สามารถตรวจสอบทั้งความพยายามในการเขียนและการเรียกคืนอัตโนมัติได้

**ตรวจสอบให้ถูกต้อง:** รักษาเป้าหมายไว้ พี่น้อง pending/rollback สถานะอแด็ปเตอร์ และการสำรองข้อมูลอแด็ปเตอร์ใหม่ล่าสุดภายใต้ `runtime/backups/`.

**ผลลัพธ์ที่คาดหวัง:** ผลลัพธ์คือ `rollback_failed` ไม่ใช่ `applied`.

**การดำเนินการถัดไปอย่างปลอดภัย:** หยุดผลกระทบ mod/server และกู้คืนข้อมูลสำรองที่ยืนยันแล้วด้วยตนเองก่อนที่จะเปิดตัวอีกครั้ง

**อย่าสรุป:** RandomDay's ผลลัพธ์แซนด์บ็อกซ์หลักไม่ได้พิสูจน์ว่าเป้าหมายของอะแดปเตอร์ที่แยกต่างหากนั้นมีประสิทธิภาพดี

<a id="generate-a-missing-singleplayerlan-file"></a>
## สร้างส่วนที่ขาดหายไป singleplayer/LAN ไฟล์

**สาเหตุที่เป็นไปได้มากที่สุด:** ติดตั้งแพ็คเกจเฉพาะแล้ว เครื่องหมายโหมดไม่ถูกต้อง หรือ RandomDay ไม่ได้โหลด

**ตรวจสอบให้ถูกต้อง:** `.randomday_mode` ต้องมี `singleplayer_manual`; จากนั้นยืนยันRandomDay เริ่มต้นบรรทัดและตรวจสอบ `runtime/singleplayer_manual/SandboxSettings.ini`.

**ผลลัพธ์ที่คาดหวัง:** ไฟล์มีอยู่ภายใน RandomDay โฟลเดอร์เท่านั้น

**การดำเนินการถัดไปอย่างปลอดภัย:** ติดตั้งแพ็คเกจที่ถูกต้องอย่างสมบูรณ์และเริ่มต้นครั้งเดียว

**อย่าสรุป:** RandomDay จะไม่ค้นหาหรือเขียนโลกเป้าหมายในนามของคุณ

<a id="diagnose-a-message-problem"></a>
## วินิจฉัยปัญหาข้อความ

**สาเหตุที่เป็นไปได้มากที่สุด:** ไม่มีอักขระของผู้เล่นที่ถูกต้องตามกำหนดเวลา การขนส่งคำเตือนไม่พร้อมใช้งาน หรือหน้าจอไคลเอนต์ห่อข้อความแตกต่างออกไป

**ตรวจสอบให้ถูกต้อง:** ตรวจสอบ `[RandomDay]` บันทึกข้อความและเปรียบเทียบข้อความต้นฉบับกับขีดจำกัดความยาวที่บันทึกไว้

**ผลลัพธ์ที่คาดหวัง:** รันไทม์รายงานว่ามีการส่งผ่านข้อความหรือไม่ การตรวจสอบแหล่งที่มารายงานความยาวสูงสุด

**การดำเนินการถัดไปอย่างปลอดภัย:** ตรวจสอบความละเอียดของไคลเอ็นต์ที่ต้องการ แยกการเล่นเกมและการยืนยันโปรไฟล์ออกจากผลลัพธ์ข้อความ

**อย่าสรุป:** ข้อความที่มองเห็นไม่ได้พิสูจน์ว่ามีการใช้โปรไฟล์แซนด์บ็อกซ์ และข้อความที่หายไปไม่ได้พิสูจน์ว่าการเตรียมการล้มเหลว
<a id="four-profile-wide-choices-returned-to-the-shipped-values"></a>
## ตัวเลือกทั้งสี่โปรไฟล์จะส่งคืนไปยังค่าที่จัดส่ง

**สาเหตุที่เป็นไปได้มากที่สุด:** เฉพาะที่สร้างขึ้น `SandboxSettings.ini` ได้รับการแก้ไขแล้ว หรือ `server.lua` ถูกเปลี่ยนแปลงในขณะที่กระบวนการ Lua เดียวกันยังคงทำงานอยู่

**ตรวจสอบให้ถูกต้อง:** หยุดเกมหรือเซิร์ฟเวอร์เฉพาะ เปิด `RandomDay/Scripts/ax_config/server.lua` และยืนยันการบันทึก `sandbox.profile_overrides` บล็อกประกอบด้วยค่าสี่ค่าที่ต้องการ

**ผลลัพธ์ที่คาดหวัง:** หลังจากเริ่มต้นครั้งถัดไป ทุกรายการที่เตรียมไว้ใหม่ family/day โปรไฟล์มีค่าที่เลือก การหมุนเวียนโปรไฟล์ในภายหลังและเซิร์ฟเวอร์เริ่มใช้บล็อกเดิมต่อไป

**การดำเนินการถัดไปอย่างปลอดภัย:** แก้ไขบล็อก เริ่มต้นหนึ่งครั้ง และตรวจสอบโปรไฟล์ที่เตรียมไว้ อย่าแพตช์เฉพาะไฟล์แซนด์บ็อกซ์ที่สร้างขึ้น เนื่องจากการเตรียมการในภายหลังจะเข้ามาแทนที่

<a id="look-up-an-exact-status"></a>
## ค้นหาสถานะที่แน่นอน

หลังจากที่แผนผังการตัดสินใจระบุขั้นตอนที่ล้มเหลว ให้คัดลอกค่า `status`, `transaction_status`, `rollback_status` หรือ `error` ค่าจากการส่งออกรันไทม์ ใช้ [การอ้างอิงสถานะและข้อผิดพลาด](%E0%B8%AA%E0%B8%96%E0%B8%B2%E0%B8%99%E0%B8%B0%E0%B9%81%E0%B8%A5%E0%B8%B0%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%AD%E0%B9%89%E0%B8%B2%E0%B8%87%E0%B8%AD%E0%B8%B4%E0%B8%87%E0%B8%82%E0%B9%89%E0%B8%AD%E0%B8%9C%E0%B8%B4%E0%B8%94%E0%B8%9E%E0%B8%A5%E0%B8%B2%E0%B8%94.md) สำหรับความหมายและการตอบกลับของผู้ปฏิบัติงานที่ปลอดภัย ข้อความที่คล้ายกันในแผงหรือคอนโซลไม่สามารถทดแทนค่าที่ส่งออกได้

ความล้มเหลวของสภาพแวดล้อมการทดสอบเฉพาะผู้ร่วมให้ข้อมูลอยู่ใน [การตรวจสอบความถูกต้องของการเปิดตัว](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%95%E0%B8%A3%E0%B8%A7%E0%B8%88%E0%B8%AA%E0%B8%AD%E0%B8%9A%E0%B8%84%E0%B8%A7%E0%B8%B2%E0%B8%A1%E0%B8%96%E0%B8%B9%E0%B8%81%E0%B8%95%E0%B9%89%E0%B8%AD%E0%B8%87%E0%B8%82%E0%B8%AD%E0%B8%87%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B9%80%E0%B8%9B%E0%B8%B4%E0%B8%94%E0%B8%95%E0%B8%B1%E0%B8%A7.md#avoid-validation-environment-pitfalls) ไม่อยู่ในเส้นทางการกู้คืนของตัวดำเนินการ
