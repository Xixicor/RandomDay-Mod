# การกำหนดค่า

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [CONFIGURATION.md](../../CONFIGURATION.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


การกำหนดค่าตัวดำเนินการหลักคือ:

```text
RandomDay/Scripts/ax_config/server.lua
```

สำรองไฟล์และเปลี่ยนแปลงทีละส่วน Lua booleans เป็นตัวพิมพ์เล็ก `true` และ `false`; สตริงต้องมีเครื่องหมายคำพูด รายการต้องมีเครื่องหมายจุลภาค หลังจากเริ่มต้นครั้งถัดไป โปรดอ่านหน้าสถานะก่อนที่จะทำการเปลี่ยนแปลงอีกครั้ง ผู้มีส่วนร่วมที่ทำงานจากแหล่งที่มาสามารถใช้ส่วนแยกได้[การตรวจสอบความถูกต้องของการเปิดตัว](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%95%E0%B8%A3%E0%B8%A7%E0%B8%88%E0%B8%AA%E0%B8%AD%E0%B8%9A%E0%B8%84%E0%B8%A7%E0%B8%B2%E0%B8%A1%E0%B8%96%E0%B8%B9%E0%B8%81%E0%B8%95%E0%B9%89%E0%B8%AD%E0%B8%87%E0%B8%82%E0%B8%AD%E0%B8%87%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B9%80%E0%B8%9B%E0%B8%B4%E0%B8%94%E0%B8%95%E0%B8%B1%E0%B8%A7.md) ตรวจสอบก่อนที่จะบรรจุบิลด์ที่แก้ไข

ห้ามแก้ไขด้วยตนเอง `.randomday_mode`, `.randomday_version`, สร้างการอ้างอิงโปรไฟล์, `runtime/` หรือ `web_export/`. ตัวสร้างแพ็คเกจเป็นเจ้าของโหมดแพ็คเกจและเครื่องหมายเวอร์ชัน และตรวจสอบว่าพวกเขาเห็นด้วยกับข้อมูลเมตาที่เผยแพร่

ทุกการตั้งค่าด้านล่างถูกกำหนดไว้ใน `RandomDay/Scripts/ax_config/server.lua`. ตารางจะแยกการตั้งค่าที่แก้ไขได้จากช่องข้อมูลประจำตัวที่เป็นของรุ่นและความเข้ากันได้ที่สงวนไว้ ช่องที่มีอยู่ใน Lua ไม่ได้หมายความว่าการเปลี่ยนแปลงนั้นเป็นพฤติกรรมที่ได้รับการสนับสนุน

<a id="choose-an-experience"></a>
## เลือกประสบการณ์

RandomDay มีสองแพ็คเกจ: หนึ่งแพ็คเกจสำหรับเซิร์ฟเวอร์เฉพาะทุก ๆ ตัวและอีกแพ็คเกจสำหรับ singleplayer/LAN คัดลอกด้วยตนเอง แพ็คเกจเฉพาะมีโหมดการทำงานสองโหมด โหมดเหล่านั้นเป็นการตั้งค่า ไม่ใช่การดาวน์โหลดแยกต่างหาก

| โลกของคุณ | ติดตั้ง | เลือกลักษณะการทำงานนี้ |
| --- | --- | --- |
| เซิร์ฟเวอร์เฉพาะที่ช่วยให้แคมเปญหนึ่งดำเนินต่อไปในการรีสตาร์ทตามปกติ | แพ็คเกจเซิร์ฟเวอร์เฉพาะ | `persistent_dedicated` ดำเนินการลำดับครอบครัวที่บันทึกไว้และโปรไฟล์ต่อ |
| เซิร์ฟเวอร์เฉพาะที่เปิดสำหรับเซสชันการเล่นแต่ละรายการเท่านั้น | แพ็คเกจเซิร์ฟเวอร์เฉพาะเดียวกัน | `temporary_dedicated` เก็บโปรไฟล์ถัดไปที่เตรียมไว้อย่างปลอดภัยระหว่างเซสชัน ในขณะที่การดำเนินการแบบครอบครัวใหม่อาจใช้การเริ่มต้นที่กำหนดค่าไว้หรือแบบสุ่ม |
| ผู้เล่นคนเดียวหรือ LAN world | Singleplayer/LAN แพ็คเกจ | `auto` เลือกพฤติกรรมการคัดลอกด้วยตนเอง หยุดโลกก่อนที่จะคัดลอกไฟล์ที่สร้างขึ้น |

หากคุณไม่แน่ใจ ให้ใช้ `auto`. แพ็คเกจเลือกลักษณะการทำงานปกติสำหรับประเภทการติดตั้ง เลือกรูปแบบการเล่นแบบกว้างใน [การหมุนเวียนครอบครัว](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%AB%E0%B8%A1%E0%B8%B8%E0%B8%99%E0%B9%80%E0%B8%A7%E0%B8%B5%E0%B8%A2%E0%B8%99%E0%B8%84%E0%B8%A3%E0%B8%AD%E0%B8%9A%E0%B8%84%E0%B8%A3%E0%B8%B1%E0%B8%A7.md). ใช้ [ดัชนีครอบครัวที่สร้างขึ้น](%E0%B9%82%E0%B8%9B%E0%B8%A3%E0%B9%84%E0%B8%9F%E0%B8%A5%E0%B9%8C/%E0%B9%80%E0%B8%AD%E0%B8%81%E0%B8%AA%E0%B8%B2%E0%B8%A3%E0%B8%9B%E0%B8%A3%E0%B8%B0%E0%B8%81%E0%B8%AD%E0%B8%9A%E0%B9%82%E0%B8%9B%E0%B8%A3%E0%B9%84%E0%B8%9F%E0%B8%A5%E0%B9%8C.md) เมื่อคุณต้องการค่าการเล่นเกมและแซนด์บ็อกซ์ที่แน่นอน จากนั้นเลือกวันแรกและความคืบหน้า:

- `start_day_mode="configured"` เริ่มต้นที่ `start_day`.
- `start_day_mode="random"` เลือกหนึ่งวันแรกที่ถูกต้องเมื่อเริ่มต้นการดำเนินกิจการแบบครอบครัวใหม่และคงตัวเลือกนั้นไว้
- `day_progression_mode="sequential"` ตัดผ่านทั้ง 17 ตำแหน่ง
- `day_progression_mode="non_repeating_random"` เก็บคำสั่งซื้อแบบสับหนึ่งรายการซึ่งมีทุกวันเพียงครั้งเดียว

ใช้ค่าที่ตั้งล่วงหน้าที่สมบูรณ์ใน [การหมุน](#rotation). การติดตั้งใหม่ยังคงต้องเริ่มต้นเพียงครั้งเดียวเพื่อเตรียมโปรไฟล์แรกที่เลือก และเริ่มต้นใหม่ในภายหลังเพื่อเปิดใช้งาน

<a id="release-identity-and-logging"></a>
## เผยแพร่ข้อมูลประจำตัวและการบันทึก

| การตั้งค่า | ประเภทและมูลค่าการจัดส่ง | การใช้งานที่สนับสนุน | ความล้มเหลวหรือการโต้ตอบ |
|---|---|---|---|
| `version` | สตริงอ่านจาก `.randomday_version` | อ่านอย่างเดียว | เครื่องหมายที่หายไปหรือว่างเปล่าจะกลายเป็น `unversioned`; การตรวจสอบแพ็คเกจขั้นสุดท้ายจะปฏิเสธการเลื่อนข้อมูลประจำตัว |
| `package_mode` | สตริงอ่านจาก `.randomday_mode` | อ่านอย่างเดียว: `dedicated_server` หรือ `singleplayer_manual`. | ค่าอื่นใดจะหยุดการเริ่มต้นก่อนที่เป้าหมายจะเขียน |
| `plan_basis` | สตริง: `RandomDay - Seventeen Suns Rotation + Open World Scope` | ป้ายกำกับการวินิจฉัยเท่านั้น อย่าใช้เป็นคุณลักษณะสลับ | รันไทม์ปัจจุบันไม่มีสาขาในฟิลด์นี้ |
| `logging.level` | สตริง: `info` | `debug`, `info`, `warn` หรือ `error`. | ค่าที่ไม่รู้จักไม่ได้เพิ่มปลายทางการบันทึก เก็บ `info` เว้นแต่จะวิเคราะห์พฤติกรรมการสร้างโปรไฟล์ |

ตัวอย่าง:

```lua
logging = { level = "debug" }
```

ใช้ `debug` ชั่วคราว รักษา `UE4SS.log` ที่เกี่ยวข้องไว้ จากนั้นกลับสู่ `info` บันทึกสามารถมีพาธในเครื่องจากความล้มเหลวระดับต่ำ ตรวจสอบก่อนที่จะแบ่งปัน

<a id="experience-mode"></a>
## โหมดประสบการณ์

`experience.mode` ตั้งชื่อวิธีการดำเนินการติดตั้งนี้ มันไม่ได้ทำให้ขอบเขตความปลอดภัยในการเริ่มต้นครั้งถัดไปอ่อนลง: Abiotic Factor อ่านการตั้งค่าแซนด์บ็อกซ์ก่อน UE4SS โหลด RandomDay ดังนั้นจึงไม่มีโหมดใดที่จะแทนที่กฎของกระบวนการที่กำลังทำงานอยู่ได้

| การตั้งค่า | มูลค่าที่จัดส่ง | ค่าที่รองรับ | ผลกระทบ |
|---|---:|---|---|
| `experience.mode` | `auto` | `auto`, `persistent_dedicated`, `temporary_dedicated`, `singleplayer_lan` | `auto` จะได้รับการแก้ไขจากแพ็คเกจ แพ็คเกจเฉพาะอาจใช้โหมดเฉพาะอย่างใดอย่างหนึ่ง แพ็คเกจการคัดลอกด้วยตนเองยอมรับเพียง `auto` หรือ `singleplayer_lan`. |

- `persistent_dedicated` เก็บคำสั่ง family/day ที่เก็บไว้ในการรีสตาร์ทเซิร์ฟเวอร์ระยะยาวปกติ
- `temporary_dedicated` อธิบายเซิร์ฟเวอร์ที่เริ่มต้นสำหรับเซสชันการเล่นที่มีขอบเขต มันยังคงอยู่ในลำดับที่เตรียมไว้ ดังนั้นการหยุดโฮสต์จะไม่ทำการสุ่มเซสชันถัดไปอีกครั้ง
- `singleplayer_lan` สร้างเฉพาะเอาต์พุตการคัดลอกแบบแมนนวลที่มีขอบเขตเท่านั้น มันไม่เคยค้นพบหรือแก้ไขโฟลเดอร์บันทึกส่วนตัว

ชุดค่าผสม package/experience ที่เข้ากันไม่ได้จะหยุดก่อนที่จะเขียนแซนด์บ็อกซ์

<a id="rotation"></a>
## การหมุน

| การตั้งค่า | มูลค่าที่จัดส่ง | ค่าที่รองรับ | ผลกระทบ |
|---|---:|---|---|
| `cycle.application_mode` | `next_reboot_queue` | `next_reboot_queue` | เก็บการเปลี่ยนแปลงแซนด์บ็อกซ์ทั้งหมดไว้ที่ขอบเขตการรีสตาร์ท |
| `cycle.cycle_length_days` | `17` | `17` สำหรับชุดโปรไฟล์มาตรฐาน | จับคู่ทุกตระกูลและการอ้างอิงที่สร้างขึ้น |
| `cycle.start_day_mode` | `configured` | `configured`, `random` | ใช้ `cycle.start_day` หรือเลือกหนึ่งวันเริ่มต้นที่ถูกต้องหนึ่งครั้งที่จุดเริ่มต้นของการดำเนินกิจการแบบครอบครัว |
| `cycle.start_day` | `1` | จำนวนทั้งหมด `1` ถึง `17` | วันแรกที่ `start_day_mode=configured`. |
| `cycle.day_progression_mode` | `sequential` | `sequential`, `non_repeating_random` | สร้างลำดับที่ห่อไว้หรือหนึ่งลำดับสับเปลี่ยนที่มีทุกวันเพียงครั้งเดียว |
| `cycle.bootstrap_day` | `1` | จำนวนทั้งหมด `1` ถึง `17` | ทางเลือกที่เข้ากันได้ใช้เฉพาะเมื่อ `cycle.start_day` หายไป การกำหนดค่าใหม่ควรใช้ `cycle.start_day`. |
| `cycle.check_interval_ms` | `0` | `0` หรือช่วงเวลาบวกที่มีขอบเขต | `0` เตรียมการหนึ่งครั้งเมื่อเริ่มต้นระบบ ค่าบวกเปิดใช้งานการควบคุมดูแลเป็นระยะเมื่อ UE4SS ให้ `LoopAsync`. |
| `profile_family.mode` | `non_repeating_random_run` | `selected_run`, `non_repeating_random_run`, `rotation_run` | เลือกวิธีเริ่มต้นการรันครอบครัว 17 วันใหม่ |
| `profile_family.selected_family` | `action` | หนึ่ง ID ใน `allowed_families` | ครอบครัวที่ใช้โดย `selected_run` และเป็นทางเลือก |
| `profile_family.default_family` | `action` | หนึ่ง ID ตระกูลที่ลงทะเบียน | ทางเลือกสำรองเมื่อ ID ที่เลือกหายไปหรือไม่ถูกต้อง |
| `profile_family.allowed_families` | ID ตระกูลสาธารณะทั้งหมด 17 ID | ชุดย่อยใด ๆ ที่ไม่ว่างเปล่าของ ID ที่ลงทะเบียน | จำกัดตระกูลที่มีสิทธิ์สำหรับการรันใหม่ |
| `profile_family.preserve_family_until_day_17` | บูลีน: `true` | ฟิลด์ความเข้ากันได้ที่สงวนไว้; Keep `true`. | ปฏิทินปัจจุบันจะเก็บครอบครัวผ่านทุกตำแหน่งในลำดับ 17 วันที่มีอยู่และไม่ได้อ่านฟิลด์นี้เป็นการสลับ |
| `profile_family.reroll_only_after_day_17` | บูลีน: `true` | ฟิลด์ความเข้ากันได้ที่สงวนไว้; Keep `true`. | ปฏิทินปัจจุบันจะเปลี่ยนตระกูลหลังจาก ID ทุกวันเสร็จสิ้นเท่านั้น โดยไม่คำนึงถึงวันสุดท้ายในลำดับที่เก็บไว้ |
| `profile_family.prevent_repeats_until_rotation_complete` | บูลีน: `true` | ฟิลด์ความเข้ากันได้ที่สงวนไว้; Keep `true`. | ตรรกะของพูลที่ไม่ซ้ำในปัจจุบันได้รับการแก้ไขแล้วและไม่อ่านค่านี้เป็นตัวสลับ |

ลำดับวันจะถูกสร้างขึ้นหนึ่งครั้งสำหรับการรันแบบครอบครัวใหม่และเขียนไปที่ `runtime/rotation_state.txt` การกู้คืนและการรีสตาร์ทในภายหลังนำตำแหน่งที่แน่นอนเหล่านั้นกลับมาใช้ใหม่ การแก้ไขการกำหนดค่าจะไม่ทำซ้ำคำสั่งซื้อที่อยู่ระหว่างดำเนินการ ครอบครัวจะเปลี่ยนแปลงหลังจากทำครบ 17 ตำแหน่งแล้วเท่านั้น

<a id="recommended-presets"></a>
### ค่าที่ตั้งล่วงหน้าที่แนะนำ

เซิร์ฟเวอร์เฉพาะถาวร:

```lua
experience = { mode = "persistent_dedicated" }
cycle = {
    application_mode = "next_reboot_queue",
    cycle_length_days = 17,
    start_day_mode = "configured",
    start_day = 1,
    day_progression_mode = "sequential",
    bootstrap_day = 1,
    check_interval_ms = 0,
}
```

เซสชันเฉพาะชั่วคราวที่มีลำดับที่ไม่ซ้ำที่แตกต่างกันต่อการรันตระกูลใหม่:

```lua
experience = { mode = "temporary_dedicated" }
cycle.start_day_mode = "random"
cycle.day_progression_mode = "non_repeating_random"
```

Singleplayer/LAN การคัดลอกด้วยตนเองใช้แพ็คเกจ singleplayer และโดยปกติจะออก `experience.mode="auto"`. คุณสามารถเลือกการควบคุมการเริ่มต้นและความคืบหน้าเดียวกันก่อนที่จะสร้างไฟล์ถัดไป คัดลอกไฟล์ที่สร้างขึ้นไปยังโลกที่หยุดไว้ที่เลือกก่อนที่จะเรียกใช้รุ่นอื่น หากคุณต้องการให้สถานะรันไทม์และโปรไฟล์ที่โหลดของโลกยังคงสอดคล้องกัน

ในการติดตั้งใหม่ กระบวนการแรกสามารถเตรียมวันเริ่มต้นที่เลือกเท่านั้น กระบวนการในภายหลังจะเปิดใช้งาน การสตาร์ทแบบสุ่มหรือที่กำหนดค่าไว้จะไม่ข้ามลำดับการโหลดเครื่องยนต์

ตัวอย่างสำหรับการรัน Builder แบบคงที่:

```lua
profile_family = {
    mode = "selected_run",
    selected_family = "builder",
    default_family = "action",
    allowed_families = { "builder" },
    preserve_family_until_day_17 = true,
    reroll_only_after_day_17 = true,
    prevent_repeats_until_rotation_complete = true,
}
```

ชุดสิทธิ์ที่ว่างเปล่าหรือไม่ทราบค่าจะกลับไปอยู่ในตระกูลที่ลงทะเบียน แทนที่จะสร้างโปรไฟล์ที่ไม่สมบูรณ์

<a id="primary-sandbox-path"></a>
## เส้นทางแซนด์บ็อกซ์หลัก

| การตั้งค่า | ประเภทและมูลค่าการจัดส่ง | การใช้งานที่สนับสนุน | ความล้มเหลวหรือการโต้ตอบ |
|---|---|---|---|
| `paths.runtime_dir` | สตริง: `ue4ss/Mods/RandomDay/runtime` | อ่านเฉพาะในการกำหนดค่าต้นทาง | `init.lua` แทนที่ด้วย mod-root ที่แก้ไขแล้ว `runtime/` เส้นทาง |
| `paths.web_export_dir` | สตริง: `ue4ss/Mods/RandomDay/web_export` | อ่านเฉพาะในการกำหนดค่าต้นทาง | `init.lua` แทนที่ด้วย mod-root ที่แก้ไขแล้ว `web_export/` เส้นทาง |
| `paths.sandbox_path_override` | สตริงหรือ `nil`: `nil` | หนึ่งตัวอักษร `SandboxSettings.ini` เส้นทางสำหรับรูปแบบเฉพาะที่ไม่ได้มาตรฐาน | เป้าหมายที่ไม่ปลอดภัยหรือไม่พร้อมใช้งานล้มเหลวในการเขียน โหมดผู้เล่นคนเดียวจะล้างการแทนที่ |
| `paths.sandbox_candidates` | รายการสตริง: ตัวเลือกทั่วไปเจ็ดรายการ | สั่งผู้สมัครสำรองเซิร์ฟเวอร์เฉพาะแล้ว | `init.lua` นำหน้าผู้สมัครที่ได้รับการติดตั้ง เส้นทางแรกที่มีอยู่จะชนะ |
| `paths.write_sandbox_mirrors` | บูลีน: `true` | อนุญาตให้มิเรอร์กำหนดค่าโดยเจตนา | ไม่มีการเขียนมิเรอร์ในขณะที่รายการมิเรอร์ว่างเปล่าและ `world_name=nil`; กองกำลังโหมดผู้เล่นคนเดียว`false`. |
| `paths.sandbox_mirror_required` | บูลีน: `false` | ฟิลด์ความเข้ากันได้ที่สงวนไว้; Keep `false`. | ผู้เขียนปัจจุบันถือว่ามิเรอร์เป็นทางเลือกและไม่ได้อ่านฟิลด์นี้เป็นเกตที่จำเป็น |
| `paths.world_name` | สตริงหรือ `nil`: `nil` | องค์ประกอบโฟลเดอร์โลกปลอดภัยหนึ่งรายการที่ใช้เพื่อรับตัวเลือกมิเรอร์ทั่วไป | สิ่งใดก็ตามที่อยู่ภายนอกตัวอักษร ตัวเลข ช่องว่าง `_` หรือ `-` จะหยุดการเริ่มต้น; โหมดผู้เล่นเดี่ยวจะเพิกเฉย |
| `paths.sandbox_mirror_candidates` | รายการสตริง: ว่างเปล่า | ไฟล์มิเรอร์ที่เป็นตัวเลือกที่แน่นอน | มิเรอร์ที่มีสิทธิ์แต่ละรายการจะใช้ธุรกรรมของตัวเอง ความล้มเหลวของมิเรอร์จะไม่เปลี่ยนความสำเร็จหลัก |

`paths.sandbox_path_override` มีค่าเริ่มต้นเป็น `nil` เมื่อไม่มีการแทนที่ RandomDay จะตรวจสอบตัวเลือก WindowsServer ทั่วไปที่ยึดกับการติดตั้ง RandomDay ที่ตรวจพบ จากนั้นตรวจสอบตัวเลือกที่กำหนดค่าไว้ หากไม่มีอยู่ ระบบจะใช้ตัวเลือกทั่วไปที่ยึดการติดตั้งตัวแรก ซึ่งจะแก้ไขการติดตั้งเซิร์ฟเวอร์:

```text
AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini
```

ทางเลือกนี้ไม่ได้รับการแก้ไขจากไดเร็กทอรีการทำงานปัจจุบันของกระบวนการ ตั้งค่า `sandbox_path_override` เฉพาะเมื่อการติดตั้งของคุณใช้ไฟล์ตัวอักษรอื่น ชี้ไปที่หนึ่ง `SandboxSettings.ini` ไม่ใช่ไดเร็กทอรี หยุดเซิร์ฟเวอร์และยืนยันว่าไฟล์อยู่ในการติดตั้งที่ต้องการก่อนใช้งาน

<a id="optional-mirrors"></a>
### มิเรอร์เสริม

`paths.write_sandbox_mirrors` จัดส่งเป็น `true` แต่รายการพาธมิเรอร์ว่างเปล่าและ `paths.world_name` เป็น `nil` ดังนั้นค่าเริ่มต้นที่จัดส่งจึงไม่มีการเขียนมิเรอร์เพิ่มเติม ตั้งค่าเป็น `false` เมื่อการติดตั้งต้องเขียนเฉพาะเป้าหมายหลักที่แก้ไขแล้วเท่านั้น เมื่อไม่มีการกำหนดค่าตัวเลือกมิเรอร์หรือชื่อโลก ค่าใดค่าหนึ่งยังคงเขียนเฉพาะไฟล์แซนด์บ็อกซ์หลัก

มิเรอร์จะมีสิทธิ์ก็ต่อเมื่อคุณจงใจเพิ่มรายการที่แน่นอนลงใน `paths.sandbox_mirror_candidates` หรือตั้งค่า `paths.world_name` มิเรอร์เป็นสำเนาความพยายามที่ดีที่สุดสำหรับการติดตั้งที่อ่านเส้นทางแซนด์บ็อกซ์เฉพาะโลกที่สอง ไม่สามารถทดแทนการกำหนดค่าเส้นทางหลักที่ถูกต้องได้

ก่อนเปิดใช้งานมิเรอร์:

1. หยุดเซิร์ฟเวอร์;
2. ระบุไฟล์ที่แน่นอนที่เซิร์ฟเวอร์อ่าน
3. ยืนยันว่าเป้าหมายอยู่ภายในการติดตั้งที่ต้องการ
4. สำรองข้อมูล;
5. เพิ่มเฉพาะเส้นทางนั้น
6. ตรวจสอบผลลัพธ์มิเรอร์หลังจากการจัดเตรียม

แทนที่ตัวอย่างโดยไม่มีมิเรอร์:

```lua
paths = {
    runtime_dir = "ue4ss/Mods/RandomDay/runtime",
    web_export_dir = "ue4ss/Mods/RandomDay/web_export",
    sandbox_path_override = "<server-root>/AbioticFactor/Saved/Config/WindowsServer/SandboxSettings.ini",
    sandbox_candidates = {},
    write_sandbox_mirrors = false,
    sandbox_mirror_required = false,
    world_name = nil,
    sandbox_mirror_candidates = {},
}
```

`<server-root>` เป็นตัวยึดตำแหน่ง แทนที่ในเครื่อง อย่าเผยแพร่เส้นทางเฉพาะเครื่อง

<a id="non-disableable-safety-locks"></a>
## ล็อคเพื่อความปลอดภัยที่ไม่ปิดการใช้งาน

| การตั้งค่า | ค่าที่ต้องการ | ความหมาย |
|---|---:|---|
| `sandbox.backup_before_write` | `true` | รักษาสำเนาที่ตรวจสอบแล้วก่อนที่จะแทนที่ไฟล์หลักที่มีอยู่ |
| `sandbox.restore_last_good_on_failure` | `true` | พยายามกู้คืนอัตโนมัติหลังจากการแทนที่หรืออ่านกลับล้มเหลว |
| `external_mods.patch_only_existing_keys` | `true` | ปฏิเสธที่จะสร้างการตั้งค่าที่ไม่รู้จักในไฟล์ของ mod อื่น |
| `external_mods.backup_before_write` | `true` | รักษาไบต์เป้าหมายก่อนที่จะแก้ไขอะแด็ปเตอร์ทรานแซคชันที่รองรับ |

RandomDay ปฏิเสธการเริ่มต้นระบบหากค่าใดค่าหนึ่งในสี่ค่าเหล่านี้ไม่ใช่ `true` เป็นระบบล็อคนิรภัย ไม่รองรับการสลับผู้ปฏิบัติงาน อย่าปิดใช้งานสิ่งเหล่านี้ รวมถึงในการพัฒนาหรือการแก้ไขปัญหา เนื่องจากการทำเช่นนั้นจะเปลี่ยนขอบเขตการปิดล้มเหลวที่การทดสอบผู้เขียนและอแด็ปเตอร์พิสูจน์ได้

`sandbox.force_rewrite_every_supervision_tick` ยังคงเป็นการตั้งค่าปกติและจัดส่งในรูปแบบ `false` ซึ่งจะทำให้ไฟล์แซนด์บ็อกซ์ที่ตรงกันอยู่แล้วไม่ถูกแตะต้อง มันยอมรับบูลีน การตั้งค่าเป็น `true` บังคับให้ไบต์ที่เตรียมเป็นเจ้าของกระบวนการเดียวกันผ่านตัวเขียนอีกครั้ง มันไม่ก้าวหน้า family/day ใช้สำหรับการทดสอบการกู้คืนแบบมีขอบเขตเท่านั้น เนื่องจากการเขียนซ้ำจะสร้างการสำรองข้อมูลการดำเนินการมากขึ้น

<a id="optional-mod-adapters"></a>
## Mod Adapters เสริม

| การตั้งค่า | มูลค่าที่จัดส่ง | ความหมาย |
|---|---:|---|
| `external_mods.enabled` | `true` | อนุญาตให้อะแดปเตอร์ที่กำหนดค่าเพื่อตรวจสอบเป้าหมายที่ติดตั้งแยกกัน |
| `external_mods.optional_by_default` | `true` | ตัวดัดแปลงเสริมที่ขาดหายไปหรือเข้ากันไม่ได้ จะไม่บล็อก RandomDay. |
| `external_mods.patch_only_existing_keys` | `true` | ล็อคเพื่อความปลอดภัยที่จำเป็น; การเริ่มต้นล้มเหลวหากมีการเปลี่ยนแปลง |
| `external_mods.backup_before_write` | `true` | ล็อคเพื่อความปลอดภัยที่จำเป็น; การเริ่มต้นล้มเหลวหากมีการเปลี่ยนแปลง |
| `external_mods.adapters` | รหัสอะแดปเตอร์สาธารณะสี่รหัส | ขีดจำกัดที่ RandomDay-owned อะแดปเตอร์อาจทำงาน |

ลบรหัสอะแดปเตอร์ออกจากรายการเพื่อปล่อยให้การรวมระบบนั้นอยู่คนเดียวโดยไม่ต้องปิดใช้งานหรือถอนการติดตั้ง mod ของบริษัทอื่น singleplayer/LAN แพ็คเกจปิดใช้งานอะแดปเตอร์ทุกตัวโดยไม่คำนึงถึงรายการนี้

`external_mods.optional_by_default=false` สร้างผลลัพธ์ของอะแดปเตอร์ที่กำหนดค่าไว้นอกเหนือจาก `applied` หรือ `already_current` ล้มเหลวในผลลัพธ์ของอะแดปเตอร์รวม ไม่ทำให้ธุรกรรมแซนด์บ็อกซ์หลักย้อนกลับ เก็บสิ่งที่จัดส่งไว้ `true` เว้นแต่ผู้ปฏิบัติงานมีเหตุผลที่ผ่านการทดสอบแล้วว่าต้องมีการรวมระบบ

ดู [อะแดปเตอร์ Mod ที่รองรับ](%E0%B8%AD%E0%B8%B0%E0%B9%81%E0%B8%94%E0%B8%9B%E0%B9%80%E0%B8%95%E0%B8%AD%E0%B8%A3%E0%B9%8C%E0%B8%97%E0%B8%B5%E0%B9%88%E0%B8%A3%E0%B8%AD%E0%B8%87%E0%B8%A3%E0%B8%B1%E0%B8%9A.md) สำหรับเลย์เอาต์ที่ได้รับการยอมรับและผลลัพธ์ที่เป็นไปได้หกประการ

<a id="optional-chaotic-spawn-engine-scope-fields"></a>
### ฟิลด์ขอบเขต Chaotic Spawn Engine เพิ่มเติม

`world_scope` จัดหาการตั้งค่าส่วนขยายเพิ่มเติมห้ารายการ RandomDay เฉพาะเมื่อ Chaotic Spawn Engine ที่ได้รับการยอมรับ `DynamicSpawns/SharedData.lua` รูปแบบมีฟิลด์เหล่านั้นอยู่แล้ว นี่ไม่ใช่ม็อดหรือการดาวน์โหลดแยกต่างหาก:

| การตั้งค่า | มูลค่าที่จัดส่ง | เอฟเฟกต์ของอะแดปเตอร์ |
|---|---:|---|
| `world_scope.enabled` | `true` | ร้องขอตัวเลือกเสริม RandomDay ประตูขอบเขตโลกภายในที่รู้จัก DynamicSpawns รูปแบบ |
| `world_scope.affect_open_worlds` | `true` | รวมโลกเปิด เว้นแต่ mod เป้าหมายจะใช้กฎโลกที่ได้รับการคุ้มครอง |
| `world_scope.unknown_world_policy` | `allow` | คำขอ `allow` หรือ `block` เมื่อ mod เป้าหมายไม่สามารถจำแนกโลกได้ |
| `world_scope.log_scope_decisions` | `true` | ร้องขอการบันทึก target-mod เพื่อการตัดสินใจเกี่ยวกับขอบเขต |
| `world_scope.protected_worlds` | รายการว่าง | จัดหารูปแบบโลกที่ได้รับการคุ้มครองโดยคั่นด้วยเครื่องหมายจุลภาคให้กับโครงร่างเป้าหมาย |

ค่าเหล่านี้เป็นอินพุตของอะแดปเตอร์ ไม่ใช่ตัวกรองโลกที่ใช้งานโดยผู้เขียนแซนด์บ็อกซ์ของ RandomDay's ผู้เขียนแซนด์บ็อกซ์ สิ่งเหล่านี้จะมีผลเฉพาะเมื่อโครงร่าง Chaotic Spawn Engine ที่ติดตั้งแยกต่างหากมี RandomDay ที่สมบูรณ์อยู่แล้ว `applied` หรือ `already_current`. Chaotic Spawn Engine ยังคงรับผิดชอบในการใช้ฟิลด์เหล่านั้นในขณะรันไทม์ การติดตั้งแบบธรรมดาที่ไม่มีช่องส่วนขยายจะไม่มีการเปลี่ยนแปลง

ทั้งห้าค่าเป็นอินพุตของอะแดปเตอร์ `unknown_world_policy` ยอมรับเฉพาะค่าเป้าหมายที่บันทึกไว้ `allow` หรือ `block`; เค้าโครงเป้าหมายที่ไม่รู้จักถูกข้ามไป เก็บ`protected_worlds` ว่างเปล่าในตัวอย่างเอกสารประกอบ หากโอเปอเรเตอร์ใช้รูปแบบท้องถิ่น จะต้องไม่รวมอยู่ในภาพหน้าจอ ปัญหา หรืออาร์ติแฟกต์ที่เผยแพร่

<a id="player-messages"></a>
## ข้อความของผู้เล่น

การกำหนดค่าเซิร์ฟเวอร์เฉพาะที่จัดส่งมาทำให้สามารถแจ้งการเข้าร่วมแบบกระชับและมีบรรทัดรายวันสั้นๆ โดยจะรอ 30 วินาทีก่อนผ่านครั้งแรก ตรวจสอบผู้เล่นใหม่ทุกๆ 15 วินาที และรอ 10 วินาทีหลังจากการแจ้งเตือนการเข้าร่วมก่อนถึงบรรทัดรายวัน

| การตั้งค่า | มูลค่าที่จัดส่ง |
|---|---:|
| `player_message.enabled` | `true` |
| `player_message.log_on_startup` | `true` |
| `player_message.register_console_command` | `false` |
| `player_message.console_command` | `randomday` |
| `player_message.broadcast_enabled` | `true` |

การตรวจสอบความยาวของข้อความจะตรวจสอบขีดจำกัดแหล่งที่มา ไม่ได้แทนที่การทดสอบด้วยภาพในทุกความละเอียดของไคลเอ็นต์

ค่าการจับเวลาเป็นตัวเลขที่ไม่เป็นลบซึ่งแปลเป็นมิลลิวินาที ยกเว้น `daily_joke_delay_seconds` การตั้งค่าข้อความหรือการออกอากาศที่ปิดใช้งานจะระงับการแจ้งเตือนไคลเอนต์โดยไม่เปลี่ยนแปลงการเตรียมแซนด์บ็อกซ์ คำสั่งคอนโซลจะถูกลงทะเบียนเฉพาะเมื่อมีทั้งการตั้งค่าและตัวจัดการ UE4SS เก็บค่าวิกฤตไว้ที่ระดับการขนส่งที่จัดส่ง เว้นแต่การทดสอบไคลเอ็นต์ที่ระบุชื่อจะพิสูจน์ค่าอื่น

`max_line_chars` ถูกจำกัดไว้ที่ 8 ถึง 64 อักขระโดยนักแปล การตั้งค่าการนับบรรทัดทั้งสามจะจำกัดการรวม คำเตือน และเอาต์พุตบันทึกตามลำดับ ค่าที่จัดส่งตรงกับจำนวนบรรทัดแหล่งที่มาที่มีอยู่ คงขีดจำกัดสี่ประการนี้เป็นค่าเริ่มต้น เว้นแต่ว่าการทดสอบเค้าโครงไคลเอ็นต์จะพิสูจน์การตั้งค่าที่แคบกว่า

## โปรไฟล์และค่าแซนด์บ็อกซ์

ไฟล์ต้นฉบับของตระกูลภายใต้ `RandomDay/Scripts/ax_profiles/families/` กำหนด 17 วันเต็มต่อตระกูล เอกสารที่สร้างขึ้นภายใต้ `docs/profiles/` เป็นเอาต์พุตอ้างอิง ไม่ใช่แหล่งที่มาของการปรับแต่ง

ใช้ [การอ้างอิงคีย์แซนด์บ็อกซ์](%E0%B9%82%E0%B8%9B%E0%B8%A3%E0%B9%84%E0%B8%9F%E0%B8%A5%E0%B9%8C/%E0%B8%84%E0%B8%B5%E0%B8%A2%E0%B9%8C%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%95%E0%B8%B1%E0%B9%89%E0%B8%87%E0%B8%84%E0%B9%88%E0%B8%B2%E0%B9%81%E0%B8%8B%E0%B8%99%E0%B8%94%E0%B9%8C%E0%B8%9A%E0%B9%87%E0%B8%AD%E0%B8%81%E0%B8%8B%E0%B9%8C.md) สำหรับประเภท ช่วง ค่าเริ่มต้นของโปรไฟล์ที่จัดส่ง และค่าคงที่ที่เหลืออยู่ หลังจากแก้ไขแหล่งที่มาของโปรไฟล์แล้ว ให้สร้างใหม่และตรวจสอบชุดค่าผสมทั้งหมด 289 ชุด อย่าแพตช์ Markdown หรือ JSON ด้วยมือ

### ปรับแต่งค่าเริ่มต้นของโปรไฟล์ที่จัดส่ง

เปิด:

```text
RandomDay/Scripts/ax_config/server.lua
```

ค้นหาบล็อกนี้ภายใต้ `sandbox`:

```lua
profile_overrides = {
    HardcoreMode = false,
    AllowIronMode = false,
    StructuralSupportLimit = 0,
    BridgeSupports = 0,
}
```

สิ่งเหล่านี้คือตัวเลือกเริ่มต้นของ RandomDay's ตัวเลือกเริ่มต้น ไม่ใช่กฎ Abiotic Factor ที่ไม่สามารถเปลี่ยนแปลงได้ ตั้งค่าโหมดใดโหมดหนึ่งเป็น `true` หรือ `false` ตั้งค่าการสนับสนุนแต่ละค่าให้เป็นจำนวนเต็มจาก `0` ถึง `1000` หยุดเกมหรือเซิร์ฟเวอร์เฉพาะก่อนที่จะแก้ไขไฟล์ บันทึก จากนั้นเริ่มใหม่อีกครั้งเพื่อให้ Lua โหลดการกำหนดค่าใหม่

RandomDay อ่านบล็อกนี้ทุกครั้งที่สร้างโปรไฟล์ 17 รายการในครอบครัว ค่าที่เลือกจึงถูกนำไปใช้กับทุกตระกูลและทุกวัน รวมถึงโปรไฟล์ที่เตรียมไว้หลังจากการหมุนเวียน และโปรไฟล์ที่สร้างขึ้นใหม่หลังจากเซิร์ฟเวอร์เริ่มทำงานในภายหลัง คุณไม่จำเป็นต้องแก้ไขไฟล์โปรไฟล์ 289 ไฟล์หรือสร้างการอ้างอิงโปรไฟล์ใหม่

การเปลี่ยนเฉพาะไฟล์สด `SandboxSettings.ini` เป็นเพียงชั่วคราวเนื่องจากโปรไฟล์ที่เตรียมไว้ถัดไปจะถูกสร้างขึ้นจาก `server.lua` ประเภทที่ไม่ถูกต้อง คีย์ที่ไม่รู้จัก หรือค่าสนับสนุนภายนอก `0..1000` หยุดการสร้างโปรไฟล์โดยมีข้อผิดพลาดในการกำหนดค่าที่ระบุชื่อ แทนที่จะเปลี่ยนกลับเป็นค่าเริ่มต้นโดยไม่แจ้งให้ทราบ

การอ้างอิงโปรไฟล์ที่สร้างขึ้นยังคงแสดงค่าเริ่มต้นที่จัดส่งต่อไป เป็นข้อมูลอ้างอิงรุ่น ไม่ใช่สำเนาของการกำหนดค่าส่วนตัวของเซิร์ฟเวอร์เครื่องใดเครื่องหนึ่ง
